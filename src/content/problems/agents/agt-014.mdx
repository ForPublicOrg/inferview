    assert refused("/memoriesX/notes.md"), "a sibling directory that shares the prefix is refused"
    assert refused("/etc/passwd"), "an absolute path elsewhere is refused"
    assert refused("/memories/" + chr(92) + ".." + chr(92) + "secrets.env"), "backslashes are refused"
    assert refused("/memories/notes.md" + chr(0) + ".txt"), "a NUL byte is refused"
  solution: |
    from pathlib import PurePosixPath
    from urllib.parse import unquote

    ROOT = PurePosixPath("/memories")

    def safe_memory_path(raw):
        decoded = unquote(raw)
        if chr(92) in decoded or chr(0) in decoded:
            raise PermissionError(f"bad character in path: {raw!r}")
        parts = []
        for part in PurePosixPath(decoded).parts:
            if part in ("/", "."):
                continue
            if part == "..":
                if not parts:
                    raise PermissionError(f"escapes the filesystem root: {raw!r}")
                parts.pop()
            else:
                parts.append(part)
        resolved = PurePosixPath("/", *parts)
        if resolved != ROOT and ROOT not in resolved.parents:
            raise PermissionError(f"outside /memories: {raw!r}")
        return str(resolved)

## Question

<Callout kind="interview" label="Interview question">
"Your agent has a file-based memory tool. The model chooses the paths. Make it safe."
</Callout>

Anthropic's memory tool is client-side: the model sends commands such as `view`, `create` and `str_replace` with a path under `/memories`, and your code stores the files. The model's paths are untrusted input, because the model may be following instructions injected into a document it read.

Write `safe_memory_path(raw)`. It returns the normalized path as a string when the path stays inside `/memories`, and raises `PermissionError` otherwise. It must:

1. Decode percent-encoding first (`%2e%2e` is `..`).
2. Refuse any path containing a backslash or a NUL character.
3. Resolve `.` and `..` segments and repeated slashes logically, without touching the filesystem, and refuse any `..` that would climb above `/`.
4. Treat a relative path as starting from `/`.
5. Accept `/memories` itself and anything below it, and refuse everything else, including `/memoriesX`.

## Hints

<details class="hint"><summary>Hint 1</summary><p>`PurePosixPath(p).parts` splits a path into segments and drops empty and `.` segments for you, but it keeps `..`.</p></details>
<details class="hint"><summary>Hint 2</summary><p>A string prefix check accepts `/memoriesX/notes.md`; compare path parents instead.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Decode before you validate, or the check runs on a string the storage layer will later read differently.</p></details>

## Answer

The reference solution decodes, rejects characters that change meaning on other platforms, then walks the segments with a stack: a normal segment is pushed, `..` pops, and popping an empty stack means the path tried to climb above the filesystem root. The rebuilt path is accepted only if it equals `/memories` or has `/memories` among its parents.

Each rule closes a known hole. Decoding first stops `%2e%2e%2f`, which the Claude docs call out by name. The backslash check stops `..\` on any storage layer that treats backslash as a separator. The NUL check stops truncation in code that passes the path to C APIs. Comparing parents rather than string prefixes stops `/memoriesX`. And resolving `..` logically, instead of asking whether the string contains `..`, keeps legitimate paths like `/memories/a/../b.md` working.

What this does not cover: symbolic links. Once you map the logical path onto a real directory, resolve the real path (for example `Path.resolve()` followed by `relative_to()` on the storage root) and check again, because a symlink inside the memory directory can point anywhere. Run the handler with a filesystem user that can only see the memory directory, so a bug in this function is not the last line of defence.

## Follow-ups

- *Double encoding?* `%252e%252e` decodes once to the literal name `%2e%2e`, which is harmless here as long as the storage layer does not decode again. Decode exactly once, in one place.
- *What else should a memory handler limit?* File size, file count and total bytes per user, so the model cannot fill the disk, and which commands are allowed per agent.
- *How does this relate to memory poisoning?* Path checks stop the model reaching other files; they do nothing about untrusted content being written into memory. That needs provenance and review.

## Common mistakes

- Checking `raw.startswith("/memories")`, which accepts both `/memories/../../etc/passwd` and `/memoriesX`.
- Rejecting any path containing `..`, which breaks legitimate relative segments and still misses encoded forms if you check before decoding.
- Validating the decoded string but passing the raw one to storage.
- Calling `os.path.realpath` on the model's string before validating, which touches the real filesystem with an attacker-chosen path.
