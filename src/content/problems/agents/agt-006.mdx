## Question

<Callout kind="interview" label="Interview question">
"Before we launch, what does one run of this agent cost?"
</Callout>

An agent run makes 30 model calls. Each call re-sends the whole conversation. The system prompt plus tool definitions are 8,000 tokens. Each turn adds 3,000 tokens to the history (the tool result plus the model's previous reply). Each call produces 400 output tokens. The model is Claude Opus 5.5 at $4 per million input tokens and $20 per million output tokens. Assume no prompt caching.

Estimate the cost of one run in US dollars.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Call k sends 8,000 + 3,000 × (k − 1) input tokens. Sum that over 30 calls.</p></details>
<details class="hint"><summary>Hint 2</summary><p>0 + 1 + … + 29 = 29 × 30 / 2 = 435.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Do not forget the output tokens; they are a small share here but priced five times higher.</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>About $6.40. Input: 30 × 8,000 + 3,000 × 435 = 1,545,000 tokens, which is $6.18 at $4 per million. Output: 30 × 400 = 12,000 tokens, which is $0.24 at $20 per million. Total $6.42. Input dominates because every call re-sends the growing history.</p>
</Fragment>
<Fragment slot="long">
<p>Input tokens. The first call sends 8,000. The thirtieth sends 8,000 + 3,000 × 29 = 95,000. The sum is 30 × 8,000 = 240,000 for the repeated prefix, plus 3,000 × (0 + 1 + … + 29) = 3,000 × 435 = 1,305,000 for the growing history, so 1,545,000 tokens. At $4 per million: $6.18.</p>
<p>Output tokens. 30 × 400 = 12,000 tokens at $20 per million: $0.24.</p>
<p>Total: $6.42 per run. At 10,000 runs a day that is $64,200 a day, which is the number that gets a design changed.</p>
<p>With prompt caching. If every call hits the cache, everything already sent is read at $0.20 per million and only new tokens are written at $5 per million. Reads: 1,545,000 − 95,000 = 1,450,000 tokens, $0.29. Writes: the 8,000-token prefix plus 29 × 3,000 = 95,000 tokens, $0.475. Plus the same $0.24 of output: about $1.00, a sixth of the uncached cost.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>What breaks the cache?</em> Anything that changes the prefix: reordering tools, a server changing its tool list, editing the system prompt mid-run, clearing old tool results, compaction.</li>
<li><em>How does cost scale with run length?</em> Quadratically in calls for input. Doubling to 60 calls multiplies input tokens by about 3.75.</li>
<li><em>What else would you cut?</em> Tool output size (paginate, return ids), the number of calls (better tools, fewer retries), and the model for sub-steps that do not need the largest one.</li>
</ul>
</Fragment>
</Depth>

The arithmetic is the easy part. What the interviewer listens for is the shape: input cost grows with the square of the number of calls, the final context (95,000 tokens) understates the billed input (1,545,000) by a factor of about 16, and output tokens barely matter in an agent loop even though they cost five times more per token.

Any answer from $5.50 to $7.50 counts. The common wrong answers are $0.62 (pricing only the last call's 95,000 tokens plus output, which ignores that every earlier call was billed too) and about $1.00 (assuming caching that the question ruled out).

## Follow-ups

- *Latency budget.* If each call takes about two seconds and the user waits for the whole run, 30 sequential calls is a minute. Which calls can run in parallel, and which can move to a smaller, faster model?
- *Doubling check.* Recompute input tokens for 60 calls: 60 × 8,000 + 3,000 × 1,770 = 5,790,000, about 3.75 times the 30-call figure.
- *Budget enforcement.* Where in the loop do you check spend, and how do you estimate the next call's cost before making it?

## Common mistakes

- Pricing only the final context instead of the sum over all calls.
- Forgetting that the system prompt and tool definitions are re-sent on every call.
- Treating output tokens as the main cost because of their higher price.
- Quoting the cached figure without stating the assumption that every call hits the cache.
