## Question

<Callout kind="interview" label="Interview question">
"Your agent takes 47 model calls to complete a task that should take 5. How do you debug this?" Here is the trace summary and the harness config. Find the cause.
</Callout>

The task: "The invoice total is off by one cent for discounted orders. Fix it." A good run searches once, reads two or three files, edits one, runs the tests, and answers. This run succeeded, eventually. The trace below is synthetic, written for this problem.

```text
harness config
  model_step_cap        = 60
  parallel_tool_calls   = false
  context_editing       = clear_tool_uses(trigger_input_tokens=4000, keep=1)
  system prompt + tools = about 3,200 tokens

tool calls in the run (46 tool calls + 1 final answer = 47 model calls)
  read_file   29   distinct paths: 4
                   src/billing.py 9, src/discounts.py 8, src/money.py 7, tests/test_billing.py 5
  search       6
  run_tests    7
  edit_file    4

excerpt, calls 11 to 14
  [11] assistant  calls read_file("src/money.py")
  [11] tool       [tool result cleared to save context]
  [12] assistant  I need the rounding helper from billing.py again; the earlier result was cleared.
                  calls read_file("src/billing.py")
  [12] tool       [tool result cleared to save context]
  [13] assistant  Re-reading discounts.py to confirm how the discount is applied.
                  calls read_file("src/discounts.py")
  [13] tool       [tool result cleared to save context]
  [14] assistant  Checking billing.py once more before editing.
                  calls read_file("src/billing.py")
```

Note that the excerpt shows the history as the model sees it at call 15: every tool result except the newest has already been replaced.

## Answer

The context-editing policy is destroying the agent's working set. With a 3,200-token system prompt, a 4,000-token trigger fires as soon as one or two files are in context, and `keep=1` replaces every tool result but the newest with a placeholder. An agent that needs to hold three files in mind to fix a rounding bug can only ever see one, so it reads them in rotation. Twenty-nine reads of four files means 25 re-reads, and each one is a model call that also re-sends the growing history.

Tool-result clearing is a good tool used with the wrong numbers. Claude's built-in strategy defaults to triggering at 100,000 input tokens and keeping the 3 most recent tool uses, and lets you exclude tools whose results must survive. The fix: raise the trigger to something near the real context limit, keep more results, exclude `read_file` for files the agent is editing (or keep the latest read of each path rather than the latest N results), and let the agent write notes so cleared facts survive as a short summary.

Why the wrong picks are tempting. A bigger model sounds like the fix for "loses track", but the information is gone from the context, and no model recalls text it was never shown. Disabling parallel calls does cost calls, but only for independent reads issued together; it saves three, not forty. Lowering the step cap would have turned a slow success into a failure.

## Follow-ups

- *How would you find this without reading the whole trace?* Track repeated reads of the same path per run as a metric, and alert when the ratio of total reads to distinct paths goes above a small number.
- *What is the cost of the fix?* More tool results in context means more input tokens per call, but far fewer calls. Measure tokens per resolved task, not tokens per call.
- *Clearing also breaks prompt caching. Why does that matter here?* Each clearing rewrites history that the cache had stored, so the next call misses the cache from that point; clearing every turn means missing every turn.

## Common mistakes

- Reading only the last few steps. The pattern is visible only as counts across the run.
- Blaming the model for "forgetting" without checking what the harness removed from its context.
- Fixing it in the prompt ("do not re-read files"). The model re-reads because it needs the contents; forbidding that makes it guess.
- Turning clearing off entirely, which fixes this run and overflows the context on long ones.
