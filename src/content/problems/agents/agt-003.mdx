  solution: |
    import json
    from collections import Counter

    def run_agent(model, tools, user_msg, max_steps=6, max_cost=0.10, cost_per_call=0.01, max_repeat=2):
        messages = [{"role": "user", "content": user_msg}]
        seen = Counter()
        spent = 0.0
        for step in range(max_steps):
            if spent + cost_per_call > max_cost:
                return {"status": "stopped", "reason": "budget", "steps": step}
            reply = model(messages)
            spent += cost_per_call
            if reply["type"] == "final":
                return {"status": "done", "answer": reply["text"], "steps": step + 1}
            key = (reply["name"], json.dumps(reply["args"], sort_keys=True))
            seen[key] += 1
            if seen[key] > max_repeat:
                return {"status": "stopped", "reason": "repeated call", "steps": step + 1}
            fn = tools.get(reply["name"])
            if fn is None:
                result = {"error": f"unknown tool {reply['name']}"}
            else:
                try:
                    result = fn(**reply["args"])
                except Exception as exc:
                    result = {"error": str(exc)}
            messages.append({"role": "assistant", "tool_call": reply})
            messages.append({"role": "tool", "name": reply["name"], "content": json.dumps(result)})
        return {"status": "stopped", "reason": "max_steps", "steps": max_steps}

## Question

<Callout kind="interview" label="The prompt, as public interview guides describe it">
"Implement a tool-use orchestrator in Python. It takes a model, a set of tools and a user message, runs tool calls until the model answers, and must not run forever." A third-party guide reports a version of this as a 60-minute phone screen at Anthropic; it is a candidate report, not a confirmed question.
</Callout>

Write `run_agent(model, tools, user_msg, ...)`. The model is a plain function standing in for an LLM: given the message list, it returns either a final answer `{"type": "final", "text": ...}` or a tool call `{"type": "tool", "name": ..., "args": {...}}`. Your loop must:

1. Start the message list with the user message, and call the model with the whole list each turn.
2. Return `{"status": "done", "answer": text, "steps": n}` when the model gives a final answer, where `n` counts model calls.
3. Run the requested tool with `**args`, then append the call as `{"role": "assistant", "tool_call": reply}` and the result as `{"role": "tool", "name": name, "content": json.dumps(result)}`.
4. Turn an unknown tool name or an exception raised by the tool into `{"error": "..."}` and give it back to the model, rather than crashing. For an unknown tool, the message is `unknown tool <name>`.
5. Before each model call, stop with reason `"budget"` if `spent + cost_per_call` would exceed `max_cost`.
6. Stop with reason `"repeated call"` when the same tool with the same arguments (argument order ignored) is requested more than `max_repeat` times.
7. Stop with reason `"max_steps"` after `max_steps` model calls without a final answer.

## Hints

<details class="hint"><summary>Hint 1</summary><p>A stable key for "the same call" is the tool name plus `json.dumps(args, sort_keys=True)`.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Check the budget before calling the model, not after, or the call that breaks the budget has already been paid for.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Count steps as model calls made, so a run stopped by the budget before its first call reports 0.</p></details>

## Answer

The reference solution is a `for` loop over `max_steps` with three early exits. The order of checks inside the loop is the interesting part.

The budget check comes first, because the model call is the expensive thing and you want to refuse it, not regret it. In a real system `cost_per_call` is not constant: later calls carry more context, so you would estimate the next call's cost from the current token count.

The final-answer check comes next, before the repeat detector, so a model that answers is never stopped for repeating itself.

The repeat detector counts `(name, canonical args)` with a `Counter`. Sorting keys matters: `{"a": 1, "b": 2}` and `{"b": 2, "a": 1}` are the same call, and without `sort_keys=True` the model can loop forever by reordering arguments.

Unknown tools and tool exceptions become error results the model can read. That keeps a hallucinated tool name or a bad argument from crashing the request, and gives the model a chance to correct itself on the next turn. What this version does not do, and what an interviewer will ask about next, is tell a retryable error from a permanent one: a permanent error should end the run with a message for the user, which is the bug in [Agent loops forever](/problems/agt-002).

Every exit returns a status and a reason. That is what lets the caller show a useful message and lets you count stops by reason in production.

## Follow-ups

- *Make the cost real.* Replace `cost_per_call` with a price per input and output token and the token counts from each response. The budget check then needs an estimate of the next call's input size.
- *Run independent tool calls in parallel.* If the model returns several calls in one turn, run them concurrently (for example with `asyncio.gather`) and append results in the order of the calls, each tagged with its call id.
- *Add a wall-clock timeout per tool.* A tool that hangs should become an error result, not a hung request.
- *How would you test this against a real model?* Keep the scripted model for unit tests, and replay recorded traces from production as regression tests.

## Common mistakes

- Checking the budget after the call, which pays for the call that breaks it.
- Keying repeated calls on `str(args)`, which depends on argument order.
- Letting a `KeyError` from an unknown tool escape the loop.
- Appending the tool result as a user message, which makes many models behave as if no tool result arrived.
- Counting loop iterations instead of model calls, so the reported steps are off by one on early exits.
