    import json


    class Editor:
        """The one tool. Keeps a line index per file, rebuilt only when that file's text object changes."""

        def __init__(self, files, window):
            self.files, self.window = files, window
            self.lines = {}     # path -> (the text object the index was built from, its lines)
            self.version = 0    # bumped on every successful edit; repeat detection keys on it

        def _lines(self, path):
            text = self.files[path]
            cached = self.lines.get(path)
            if cached is None or cached[0] is not text:
                cached = (text, text.split("\n"))
                self.lines[path] = cached
            return cached[1]

        def view(self, path, start=1):
            if path not in self.files:
                return f"error: no such file {path}"
            lines = self._lines(path)
            if not isinstance(start, int) or start < 1 or start > len(lines):
                return f"error: start {start} is outside {path}, which has {len(lines)} lines"
            shown = lines[start - 1:start - 1 + self.window]
            body = "\n".join(f"{start + i}: {line}" for i, line in enumerate(shown))
            rest = len(lines) - (start - 1 + len(shown))
            return body + (f"\n({rest} more lines)" if rest > 0 else "")

        def create(self, path, text):
            if path in self.files:
                return f"error: {path} already exists; edit it with str_replace"
            self.files[path] = text
            self.version += 1
            return f"created {path}"

        def str_replace(self, path, old, new):
            if path not in self.files:
                return f"error: no such file {path}"
            if not old:
                return "error: old must not be empty"
            count = self.files[path].count(old)
            if count != 1:
                return f"error: old text appears {count} times in {path}; it must appear exactly once, so add context"
            self.files[path] = self.files[path].replace(old, new, 1)
            self.version += 1
            return f"edited {path}"

        def __call__(self, args):
            command = args.get("command")
            handler = {"view": self.view, "create": self.create, "str_replace": self.str_replace}.get(command)
            if handler is None:
                return f"error: unknown command {command!r}; use view, create or str_replace"
            params = {k: v for k, v in args.items() if k != "command"}
            try:
                return handler(**params)
            except TypeError as e:
                return f"error: bad input for {command}: {e}"


    def run(model, task, files, max_turns=50, max_repeats=2, window=100):
        editor = Editor(files, window)
        messages = [{"role": "user", "content": task}]
        last_run = {}   # call key -> editor version when that exact call last ran
        repeats = {}    # call key -> repeats since it last ran
        for turn in range(1, max_turns + 1):
            reply = model(messages)
            calls = reply.get("calls") or []
            messages.append({"role": "assistant", "content": reply.get("text", ""), "calls": calls})
            if not calls:
                return {"status": "done", "text": reply.get("text", ""), "turns": turn}
            for c in calls:
                key = (c.get("name"), json.dumps(c.get("input"), sort_keys=True))
                if last_run.get(key) == editor.version:
                    repeats[key] = repeats.get(key, 0) + 1
                    if repeats[key] > max_repeats:
                        return {"status": "repeated", "text": reply.get("text", ""), "turns": turn}
                    out = "repeat: this exact call already ran and no file has changed since; its result is above. Try something else."
                elif c.get("name") != "editor":
                    out = f"error: unknown tool {c.get('name')!r}; the only tool is editor"
                elif not isinstance(c.get("input"), dict):
                    out = "error: input must be an object"
                else:
                    out = editor(c["input"])
                    last_run[key], repeats[key] = editor.version, 0
                messages.append({"role": "tool", "id": c.get("id"), "content": out})
        return {"status": "max_turns", "text": "", "turns": max_turns}

## Question

<Callout kind="interview" label="The prompt, as a candidate report describes it">
"You have only a model API and an editor. Build the agent. How do you stop it calling the same tool over and over?" A candidate reported this from a Baidu second-round interview; the report names VS Code as the editor. This version replaces the editor with an in-memory tool so it runs in the browser.
</Callout>

Write `run(model, task, files, max_turns=50, max_repeats=2, window=100)`. `files` is a dict of path to text, which the agent edits in place. `model(messages)` stands in for the API and returns `{"text": str, "calls": [{"id", "name", "input"}]}`.

**The loop.** Start the messages with `{"role": "user", "content": task}`. Each turn, call the model with the messages, append `{"role": "assistant", "content": text, "calls": calls}`, then one `{"role": "tool", "id": call_id, "content": str}` per call, in call order. A reply with no calls ends the run with status `"done"`. After `max_turns` model calls, the status is `"max_turns"`. Return `{"status", "text", "turns"}`, where `turns` counts model calls.

**The one tool**, named `"editor"`, with `input["command"]` one of:

- `view` with `path` and optional `start` (default 1): up to `window` lines from `start`, each written `N: text`, joined with newlines, and a last line `(K more lines)` when lines remain after the window.
- `create` with `path` and `text`: fails if the file exists.
- `str_replace` with `path`, `old` and `new`: replaces `old` only when it appears exactly once; otherwise an error saying how many times it appears, for example `appears 2 times`.

Every problem (unknown command, unknown tool, missing file, missing or bad argument) comes back to the model as a string starting with `error`. Nothing raises.

**Repeats.** A call is a repeat when the same tool with the same input, ignoring key order, has already run and nothing has changed since that could change its result. Do not run a repeat; answer it with a message containing the word `repeat`. When one call has been repeated more than `max_repeats` times with no change in between, stop with status `"repeated"`. What counts as "a change that could change its result" is your decision; state it.

**Scale.** The workspace can hold generated files of a few hundred thousand lines, and a model may page through one with thousands of views in one run. The hidden tests time that.

## Answer

The reference solution has two parts: an `Editor` class that owns the file operations and their errors, and the loop that owns repeat detection.

**Repeat detection keys on state, not on the call alone.** A call's key is its tool name plus `json.dumps(input, sort_keys=True)`, so key order cannot make a call new. The editor keeps a version counter that every successful `create` or `str_replace` bumps. `last_run[key]` records the version at which that exact call last ran. If the version has not moved, the call cannot return anything new, so it is a repeat: the loop answers with a note and counts it. Any edit resets the picture, so view, edit, view is three real calls, which is the pattern a working agent produces all the time. A failed `str_replace` changes nothing, so retrying it unchanged is a repeat, which is the loop the interview question is really about.

**The decision you were asked to make**, and two defensible answers:

- *One global version (the reference).* Any edit anywhere makes every call new again. Cost: an agent that edits `b.py` and then re-views the unchanged `a.py` gets a real view, a wasted turn but never a wrong refusal.
- *A version per file.* A view of `a.py` is a repeat until `a.py` changes. It catches more loops, but it only works for calls that read one known file. A `pytest` run reads everything, so a real harness with a shell tool needs the global version, or a fingerprint of what the command reads, for those calls anyway.

**The failure mode of the reference:** the version only sees edits made through this editor. If a formatter, a build or the user changes a file, the harness still believes nothing changed and refuses a view that would now return something new. With a real filesystem, key on a content fingerprint or modification time of the files a call reads, which costs a stat or a hash per call.

**The constraint conflict** is cost against autonomy. Every repeat you let through costs a turn and tokens; every repeat you refuse wrongly blocks a legitimate retry, and the obvious one is re-running a flaky test, where repetition is the point. `max_repeats` is the dial. 1 to 3 is reasonable: 0 refuses the first legitimate retry, and above 3 the loop pays for several identical failures before stopping. The repeat note matters as much as the count, because the note is what gives the model a reason to change course before the stop.

**The performance constraint.** A naive `view` splits the whole file on every call. On a 300,000-line file that is a full scan per view, and 3,000 views take close to a minute: with only that change, the hidden tests took 52 s under CPython 3.12 on the laptop that checked this problem on 2026-10-28, against 0.4 s for the reference. The timed test allows 3 s, which leaves the reference room for Pyodide being slower than CPython. The reference keeps a line index per path, tagged with the exact string object it was built from, and rebuilds it only when that path's text object changes, which any edit does. Views then cost a slice of `window` lines.

`window=100` follows SWE-agent, whose ablation on SWE-bench Lite with GPT-4 Turbo reports 18.0% resolved with a 100-line viewer against 14.3% with 30 lines and 12.7% with the whole file; that is one model in 2024, so treat it as a starting point.

## Follow-ups

- *Run this against a real model API. What changes?* Tool definitions in the provider's schema and tool-use ids from the response; several calls per turn that you may run in parallel; a token budget instead of a turn count; paths checked against the workspace root so `../` cannot escape; and a real filesystem whose changes the version counter cannot see.
- *Your detector refused a second `pytest` run after a flaky failure, and the run stopped. Do you exempt the shell tool, key on the output, or keep the refusal and rely on the note? Which risk do you accept?*
- *What would you need to see in production to remove repeat detection and rely on the turn cap alone?* Replays in which the model, shown identical output, almost always changes approach on its own.
- *Two engineers disagree: one wants per-file versions, the other a global one. How do you decide without deciding by rank?* Replay recorded runs through both and count wrong refusals against turns saved.

## Common mistakes

- Keying repeats on `str(input)`, which depends on key order.
- Blocking every identical call, so view, edit, view is refused at the second view.
- Re-splitting a large file on every view.
- Raising on a bad command or a missing file instead of returning an error the model can read.
- Stopping on the first repeat with no note, which gives the model no chance to change course.
