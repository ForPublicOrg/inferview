## Question

<Callout kind="interview" label="Estimate, 20 minutes">
Your coding agent connects the same five MCP servers Anthropic used in its advanced tool use post: 58 tools and about 55K tokens of definitions. A colleague says prompt caching makes the definitions nearly free, so deferred loading is not worth the extra moving part. Estimate what the definitions cost per session loaded upfront and loaded on demand, and say when your conclusion would flip.
</Callout>

Published inputs, from the sources below: GitHub 35 tools at about 26K tokens, Slack 11 at about 21K, Sentry 5 at about 3K, Grafana 5 at about 3K, Splunk 2 at about 2K (Anthropic, 2025-11-24). The tool search tool costs about 500 tokens. Cache writes with the 5-minute lifetime cost 1.25 times the base input price and cache reads 0.1 times (Anthropic pricing docs, checked 2026-10-28).

Scenario inputs, not measurements: a session is 40 model requests, each within five minutes of the last, so the cache never expires mid-session. In the deferred setup you keep some tools loaded and the rest are discovered by search; which ones you keep, how many the session discovers and when are yours to choose. Assume the session uses between 4 and 12 distinct deferred tools.

Express cost in input-token equivalents: tokens multiplied by their price relative to one uncached input token. Give the saving per session from deferring, in thousands.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask which requests in the session pay full price for the definitions, which pay the write premium and which pay the read price.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Request the per-server breakdown before you choose which tools to keep loaded: are the tools you would keep cheap ones or expensive ones?</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>Upfront, the 55K tokens are written to the cache once at 1.25x and read on each of the other 39 requests at 0.1x: about 283K input-token equivalents per session, three quarters of it in cache reads. Deferred, with four small tools kept loaded and eight discovered around request 10, the session pays about 43K. The saving is about 240K per session. Caching cuts the per-request price of the definitions by 90 percent; it does not remove them, and over 40 requests the reads dominate.</p>
</Fragment>
<Fragment slot="long">
<p>Upfront. Request 1 writes the prefix: 55K × 1.25 = 68.75K. Requests 2 to 40 read it: 55K × 0.1 × 39 = 214.5K. Total 283.25K. The dominant term is the reads, not the write, which is the part the "caching makes it free" argument misses.</p>
<p>Deferred prefix. The cheapest tools to keep loaded are GitHub's, at 26K / 35 ≈ 0.74K each; Slack's average 21K / 11 ≈ 1.9K each. Keeping four GitHub tools plus the search tool gives a prefix of 0.5K + 4 × 0.74K ≈ 3.5K, which pays the same 1.25 + 0.1 × 39 = 5.15 multiplier: 3.5K × 5.15 ≈ 18K.</p>
<p>Discovered tools. A discovered definition is appended inline in the conversation, so it is written once at 1.25x on the request that discovers it and read at 0.1x on every later request; the prefix is untouched. Choose eight tools, six from GitHub and two from Sentry: 6 × 0.74K + 2 × 0.6K ≈ 5.7K. Discovered around request 10, each token pays 1.25 + 0.1 × 30 = 4.25: 5.7K × 4.25 ≈ 24K. The search calls and their result blocks are a few hundred tokens per search, about 1K more over the session.</p>
<p>Deferred total ≈ 18K + 24K + 1K = 43K. Saving ≈ 283K − 43K ≈ 240K per session.</p>
<p>The band. Keep three Sentry tools loaded (prefix 0.5K + 3 × 0.6K = 2.3K, × 5.15 ≈ 12K) and discover four GitHub tools late (request 20) and the saving is about 260K. Keep five Slack tools (prefix 0.5K + 5 × 1.9K = 10K, × 5.15 ≈ 52K) and discover twelve tools of about 1K each early (request 5, multiplier 4.75, ≈ 57K) and it is about 173K. Anything between roughly 160K and 270K follows from defensible choices.</p>
<p>Break-even. Token cost alone does not flip at this size. A deferred tool costs at most what it would have cost upfront, so deferral only loses on tokens through extra requests: a search that misses and forces another model call re-reads the whole context. At a 60K context that is about 6K per extra request, so the 240K saving survives about 40 extra requests, one per request in the session. With a 150K context it is about 16. The assumption that flips the decision is not the price; it is a tool needed on most requests being deferred (keep it loaded) or a model or platform without tool search (Claude Opus 4.1 and earlier, or Bedrock's Converse API), where the choice is made for you.</p>
<p>Failure mode of the recommendation. Deferral moves the cost from tokens to selection: if the search misses the right tool, the agent may solve the task with a worse tool instead of failing loudly. Track how often a session ends without discovering a tool your eval says it needed.</p>
</Fragment>

### Choices that are not reasonable

- Ignoring caching: 55K × 40 = 2.2M per session upfront and a saving near 2.15M. The cache exists in both setups; leaving it out compares a setup nobody runs.
- Treating the definitions as free after the first request. Reads cost 0.1x, and 39 of them are most of the bill.
- Assuming a discovered tool invalidates the cache. It is appended inline and the prefix is untouched; that is why the feature preserves caching.
- Using the post's 77K-to-8.7K example as the saving. That setup has more than 50 tools at about 72K and counts other context; the five-server figure is the one that matches this question.

## Follow-ups

- *Your colleague now argues that tool search adds a step to every discovery and slows the agent. How would you measure whether that latency matters, and against what?*
- *Twelve of the 58 tools are used in more than half of sessions. How many do you keep loaded, and what number in your traces decides it?*
- *The platform team wants one MCP configuration for three agents with very different tool use. Do you defer per agent or per server, and who owns that list?*

## Common mistakes

- Reporting the cost before the first message (55K against about 3.5K) as the whole answer. The per-session cost depends on how many requests read that prefix.
- Choosing the tools to keep loaded by how often they are used without looking at their size: one Slack tool averages the cost of two and a half GitHub tools.
- Forgetting that discovered definitions are billed as input tokens on every later request, like any other context.
