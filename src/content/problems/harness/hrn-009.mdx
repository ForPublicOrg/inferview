    def shape_result(chunks, ok, sink, inline_max=30_000, preview_max=2_000, fail_max=10_000):
        """Turn a finished command's output into the text the model sees.

        chunks: an iterable of str, the command output in arrival order. It can be far
                larger than the memory you are willing to hold; iterate it once.
        ok:     True when the harness treats the result as valid, False for a failure.
        sink:   has .write(str) and .path; whatever is written becomes the saved file.

        Valid result: if the output has at most inline_max characters, return it whole.
        Otherwise write the whole output to sink and return a note that names sink.path
        and the total size in characters, plus a preview: a prefix of the output of at
        most preview_max characters. The returned text never exceeds inline_max.

        Failure: never write to sink and never name a path. At most fail_max characters
        are returned whole. Past that, return head + marker + tail, where head is a prefix
        and tail a suffix of the output, each at least fail_max // 4 characters, and the
        marker states how many characters were omitted. The text never exceeds fail_max.

        An empty output still returns non-empty text.

        Return a dict: text (str), truncated (bool), path (str or None),
        total (characters in the output), omitted (output characters not in text).
        """
        raise NotImplementedError

  solution: |
    def _prefix(parts, n):
        out, have = [], 0
        for p in parts:
            if have >= n:
                break
            out.append(p[: n - have])
            have += len(out[-1])
        return "".join(out)

    def _suffix(parts, n):
        out, have = [], 0
        for p in reversed(parts):
            if have >= n:
                break
            piece = p[-(n - have):]
            out.append(piece)
            have += len(piece)
        return "".join(reversed(out))

    def shape_result(chunks, ok, sink, inline_max=30_000, preview_max=2_000, fail_max=10_000):
        limit = inline_max if ok else fail_max
        reserve = 64                          # marker room; enough for counts up to 20 digits
        head_n = (fail_max - reserve) // 2
        tail_n = fail_max - reserve - head_n
        buf, buf_len = [], 0                  # held only while the output still fits inline
        head = tail = ""
        total = 0
        over = False
        for chunk in chunks:
            if not chunk:
                continue
            total += len(chunk)
            if not over:
                buf.append(chunk)
                buf_len += len(chunk)
                if buf_len <= limit:
                    continue
                over = True
                if ok:
                    for part in buf:
                        sink.write(part)
                    head = _prefix(buf, preview_max)
                else:
                    head = _prefix(buf, head_n)
                    tail = _suffix(buf, tail_n)
                buf = None
                continue
            if ok:
                sink.write(chunk)
            elif len(chunk) >= tail_n:
                tail = chunk[-tail_n:]
            else:
                tail = (tail + chunk)[-tail_n:]

        if not over:
            text = "".join(buf)
            if not text:
                text = ("(the command succeeded and printed nothing)" if ok
                        else "(the command failed and printed nothing)")
            return {"text": text, "truncated": False, "path": None, "total": total, "omitted": 0}

        if ok:
            cut = head.rfind("\n")
            preview = head[: cut + 1] if cut >= len(head) // 2 else head
            note = (f"[output was {total} characters, over the {inline_max}-character inline limit; "
                    f"saved in full to {sink.path}; the first {len(preview)} characters follow; "
                    f"read or search that file for the rest]\n")
            return {"text": note + preview, "truncated": True, "path": sink.path,
                    "total": total, "omitted": total - len(preview)}

        omitted = total - len(head) - len(tail)
        marker = f"\n[... {omitted} of {total} characters omitted ...]\n"
        return {"text": head + marker + tail, "truncated": True, "path": None,
                "total": total, "omitted": omitted}

## Question

<Callout kind="interview" label="Coding, 35 minutes">
Your coding agent's shell tool streams command output to a working file. When the command finishes, the harness turns that output into the tool result the model reads. Write <code>shape_result</code> to the contract in the starter: a valid result goes inline up to one budget and otherwise becomes a saved file plus a preview; a failure goes inline up to a smaller budget and otherwise becomes a head-and-tail excerpt with no file. The result carries a truncation flag and the counts the model needs to decide whether to read further.
</Callout>

The default budgets are Claude Code's documented values as of 2026-10-28: roughly 30,000 characters inline for a valid result, a preview of up to 2,000 characters past that, and roughly 10,000 characters for a failure, cut as head and tail. The tests use smaller budgets so they run quickly.

Part of the policy is yours: how the failure budget splits between head and tail (each side keeps at least a quarter), the wording of the note and the marker, whether the preview ends on a line boundary, and what an empty result says. The tests check invariants, not one output.

One constraint is not in the visible tests. Build logs and test suites can print tens of megabytes, and your function may hold only a bounded amount of the output, a few budgets' worth, however much the command printed.

## Answer

The reference solution makes one pass over the chunks. While the output still fits the relevant budget it buffers chunks, because a result that fits is returned whole. The first chunk that pushes the output over the budget switches mode. For a valid result it flushes the buffered chunks to the sink, then streams every later chunk straight through and keeps only the preview. For a failure it keeps a fixed head and a rolling tail of `tail_n` characters and drops the middle. Memory is bounded by the budget plus one chunk, which is what the hidden memory test measures with `tracemalloc` on 48 MiB of output.

The two branches differ for a reason the model can use. A valid result over budget has a file, so the note names the path and the size, and the model can search or page through it. A failure gets no file, and the excerpt keeps the two ends because a failing build or test run usually puts the command echo at the top and the final error at the bottom. The marker states how many characters are gone, so the model knows the excerpt is partial and can rerun a narrower command.

```python
if ok:
    sink.write(chunk)                        # past the budget: stream to the file, keep only the preview
elif len(chunk) >= tail_n:
    tail = chunk[-tail_n:]                   # a large chunk replaces the tail outright
else:
    tail = (tail + chunk)[-tail_n:]          # small chunks roll into it
```

The policy choices in the reference: the marker reserves 64 characters and the rest splits evenly between head and tail, and the preview is cut back to the last newline when that keeps at least half of it, so the model does not read half a line as a whole one. A tail-heavy split, one third head and two thirds tail, is as defensible for test runners that print their summary last and passes the same tests. A head-heavy split is the weaker choice: the line that explains a failure is rarely the first one.

Where this design fails. A failure over budget loses its middle for good, and the middle is where a compiler prints the first error of a long cascade. If traces show the model rerunning the same failing command to recover the middle, either save failures to a file as well or give the tool a flag that does. The character budget is also a proxy: 10,000 characters of minified JSON and 10,000 characters of English prose are different token counts, so a token budget measured with the serving tokenizer is the accurate version, at the price of tokenizing every result.

## Follow-ups

- *Your failure excerpt cut away the first compiler error and the agent reran the build three times to find it. Do you raise the failure budget, save failures to a file, or change the split, and what does each cost per turn?*
- *The model keeps reading the saved file back into context page by page. What would you measure before concluding that the preview is too short rather than that the task needs the whole log?*
- *A teammate wants the budgets in tokens instead of characters. When is that worth a tokenizer call on every tool result?*
- *What changes to run this inside a real harness?* The reader gets bytes, not strings, and a multi-byte UTF-8 character can split across two chunks, so decode with an incremental decoder. Decide whether ANSI escapes reach the model. Cap the saved file (Claude Code truncates it past 64 MiB and kills a command past 5 GB of output) and clean up the session directory.

## Common mistakes

- Joining the chunks into one string first. It passes every small test and holds the whole log in memory.
- Saving failures, or not saving long valid results, so the model is told about a file that does not exist or is never told about one that does.
- Counting the budget on the output but not on the note or marker, so the returned text overshoots the budget it claims to respect.
- Rebuilding the tail with `tail + chunk` on every chunk regardless of chunk size, which copies a megabyte for each large chunk.
