    import math
    from array import array

    QMIN, QMAX = -128, 127


    def choose_params(lo, hi, symmetric=False):
        if not (math.isfinite(lo) and math.isfinite(hi)) or lo > hi:
            raise ValueError("lo and hi must be finite with lo <= hi")
        lo, hi = min(lo, 0.0), max(hi, 0.0)  # widen to include 0.0 so it has an exact code
        if symmetric:
            m = max(-lo, hi)
            return (m / 127 if m > 0 else 1.0), 0  # codes -127..127 keep x and -x mirror images
        if hi == lo:
            return 1.0, 0  # only 0.0 was observed; any positive scale represents it exactly
        scale = (hi - lo) / (QMAX - QMIN)
        zp = round(QMIN - lo / scale)
        return scale, min(QMAX, max(QMIN, zp))


    def quantize(xs, scale, zero_point=0):
        if not (scale > 0 and math.isfinite(scale)):
            raise ValueError("scale must be positive and finite")
        if int(zero_point) != zero_point or not QMIN <= zero_point <= QMAX:
            raise ValueError("zero_point must be an integer in [-128, 127]")
        below, above = QMIN - zero_point - 1, QMAX - zero_point + 1

        def one(x):
            v = x / scale
            if v != v:
                raise ValueError("NaN has no int8 code")
            if v < below:
                return QMIN  # saturate before round(), which cannot take an infinity
            if v > above:
                return QMAX
            q = round(v) + zero_point  # Python's round: ties to even
            return QMIN if q < QMIN else QMAX if q > QMAX else q

        return array("b", [one(x) for x in xs])  # one byte per code


    def dequantize(qs, scale, zero_point=0):
        return [scale * (q - zero_point) for q in qs]


    def quantize_rows(rows, symmetric=True):
        codes, params = [], []
        for row in rows:
            s, z = choose_params(min(row, default=0.0), max(row, default=0.0), symmetric)
            codes.append(quantize(row, s, z))
            params.append((s, z))
        return codes, params


    def clip_range(xs, bits=8):
        # Policy: shrink min/max by a common factor and keep the factor with the lowest squared error at this bit width.
        xs = [x for x in xs if math.isfinite(x)]
        if not xs:
            return 0.0, 0.0
        lo, hi = min(xs), max(xs)
        top = 2 ** bits - 1

        def sse(a, b):
            a, b = min(a, 0.0), max(b, 0.0)
            if a == b:
                return 0.0
            st = (b - a) / top
            zz = round(-a / st)
            total = 0.0
            for x in xs:
                q = round(x / st) + zz
                q = 0 if q < 0 else top if q > top else q
                total += (st * (q - zz) - x) ** 2
            return total

        best = min((sse(f * lo, f * hi), f) for f in [1 - i / 40 for i in range(33)])[1]
        return best * lo, best * hi

## Question

<Callout kind="interview" label="As reported by a candidate">
Write the numeric core of an int8 inference path: symmetric and asymmetric quantization of FP32 tensors, the scale and zero point from an observed range, saturation, per-channel scales, and what clipping and outliers do to the error.
</Callout>

The reported prompt asks for NumPy. This version uses the standard library, which makes the memory cost of the result your problem rather than NumPy's. Implement five functions:

- `choose_params(lo, hi, symmetric)` returns `(scale, zero_point)` for signed int8 covering `[lo, hi]`, with 0.0 exactly representable.
- `quantize(xs, scale, zero_point)` rounds, adds the zero point and saturates to `[-128, 127]`.
- `dequantize(qs, scale, zero_point)` returns the floats the codes stand for.
- `quantize_rows(rows, symmetric)` gives every row its own scale and zero point.
- `clip_range(xs, bits)` returns the range to quantize with: your range-setting policy.

The constraints:

- **Memory.** 250,000 codes may hold at most 600,000 bytes, measured with `tracemalloc`. int8 exists to cut memory to a quarter of FP32, and a container that costs more than the floats did defeats it.
- **One policy, two bit widths.** `clip_range` is graded by the mean squared error of the asymmetric quantize-dequantize round trip over the whole input, against plain min/max. At 4 bits on a long-tailed sample it must cut that error by at least 40%. The hidden tests also run it at 8 bits and require that it is never more than 5% worse than min/max.

Three decisions are yours, and the starter's docstrings ask you to state them:

- the tie rule;
- what NaN does (raise `ValueError`, or map to the zero point);
- what a range with no width returns.

The hidden tests accept any of these choices. Symmetric quantization uses `scale = max(|lo|, |hi|) / 127`. Infinities and values past the range must saturate.

## Answer

**Parameters.** The reference widens the range to include 0.0, so the zero point is the integer code that 0.0 maps to and dequantizes to exactly `scale * 0`. That matters because padding and ReLU outputs are exact zeros, and an inexact zero adds a bias to every padded position. Asymmetric: `scale = (hi - lo) / 255` and `zero_point = round(-128 - lo / scale)`, clamped. Rounding the zero point moves the covered range by at most half a step, which is why the round-trip bound is `scale / 2` across the whole observed range. Symmetric: `zero_point = 0` and `scale = max(|lo|, |hi|) / 127`. The reference gives up code -128 so that x and -x map to mirror-image codes. A degenerate range returns scale 1.0, which represents the only value seen, 0.0, exactly.

**Quantize.** Saturation is checked before `round()`, which raises on an infinity. Python's `round` ties to even, so 0.5 and 1.5 steps round to 0 and 2; ties away from zero is the other common rule, and any rule stays inside the half-step bound. The result is an `array('b')`, one byte per code. On CPython 3.12, `sys.getsizeof(-100)` is 28 bytes, and a list of 250,000 such codes held 5,515,808 bytes under `tracemalloc` in a measurement for this problem, against 250,108 for the array. The list is 22 times the array and about 5.5 times the 1,000,000 bytes of the FP32 values it replaced.

**Per-row scales.** One scale per output channel, so the row with a weight of 100 in the hidden test does not stretch the step size of its neighbours. Per-channel suits weights because the scale of output channel j multiplies every term of that channel's dot product and factors out after the int32 accumulation: y_j = s_x s_j Σ q_x q_w. A per-channel scale on activations would vary along the reduction dimension, inside the sum, so it cannot factor out. Activations get per-tensor or per-token scales, and outlier features are handled another way. LLM.int8() moves the outlier dimensions to a 16-bit path and keeps more than 99.9% of values in 8-bit.

**The decision: symmetric or asymmetric activations.** Both are defensible.

- Asymmetric spends all 256 codes on a skewed range. On the hidden test's ReLU6 data its worst-case error is half of symmetric's, because symmetric wastes the negative half. The cost is in the kernel. With q̂_x = q_x - z_x, the sum Σ q̂_x q_w = Σ q_x q_w - z_x Σ q_w, and the Σ q_w term is a per-channel constant of the weights that can be precomputed. If the weights carry a zero point too, the cross terms add a per-row sum of the activations at run time.
- Symmetric weights with asymmetric activations keep one extra term. Symmetric everywhere keeps none and accepts the lost code range.

The answer depends on whether the activation range is skewed and whether the integer kernel you have supports a zero point at all. The constraint conflict is accuracy against kernel cost.

**Clipping.** min/max wastes steps on values that almost never occur. Clipping shrinks the step, and every clipped value then carries an error that grows with its distance past the edge. The balance moves with the bit width.

- At 4 bits the steps are coarse, and rounding error dominates. In the measurement behind the tests, a 99.9th-percentile clip cut the Laplace error to 0.47 of min/max.
- At 8 bits the steps are fine, and clipping error dominates. The same percentile clip made the error 7.7 times worse on Laplace data and 2.7 times worse on Gaussian data.

No fixed percentile passes both tests. The reference searches 33 shrink factors from 1.0 down to 0.2 and keeps the one with the lowest squared error at the requested width. That landed at 0.38 of min/max for 4-bit Laplace and at 0.94 to 0.96 for 8-bit data. Each search costs 33 passes over the data, which is fine at 20,000 values and is the first thing to replace with a histogram at calibration-set scale.

**How this policy fails.** It minimises mean squared error over all values. That objective is wrong when a few large values carry the signal: LLM.int8() reports that emergent outlier features dominate attention and predictive performance. An MSE-optimal clip of an activation with such a feature removes the part the model needs and looks better on the metric it was chosen by. The check is a task metric before and after on a calibration set, per layer, not the reconstruction error.

**Integer accumulation.** An int8 by int8 product is at most 128 × 128 = 16,384 = 2^14 in magnitude. An int32 accumulator holds 2^31 - 1, so a dot product of worst-case terms can overflow past 2^31 / 2^14 = 131,072 terms. Real reductions are shorter and the terms are rarely all extreme, but a test for it costs one line. Requantizing back to int8 multiplies by s_x s_w / s_y, which kernels apply as a fixed-point multiplier and shift.

## Follow-ups

- *Your MSE search picks a clip that cuts activation error by 30% at 8 bits, and a downstream eval drops two points on long-context tasks. Do you ship the clip, ship min/max, or keep one layer at 16 bits, and what risk do you accept in writing?*
- *What would you need to see to move from per-tensor to per-token activation scales?* A kernel that applies a per-row scale after accumulation at no measurable cost at your batch shapes, and an eval gain on the tasks that regressed with per-tensor scales.
- *Two engineers disagree: one wants symmetric everywhere for kernel simplicity, the other wants asymmetric activations for accuracy. How do you decide without deciding by rank?* Measure both on the activations of the layers with the most skewed ranges, and price the zero-point term in the kernel you actually ship.
- *What changes to run this in a real engine?* Vectorised kernels with the scale applied after int32 accumulation, calibration over a few hundred representative batches with a histogram instead of 33 passes, per-channel weight scales stored next to the packed codes, and a regression test that pins rounding and saturation on the boundary values.

## Common mistakes

- Choosing `scale = max|x| / 127` for data that is never negative, which wastes half the codes.
- Letting `round()` see an infinity or a NaN, or letting out-of-range values wrap through a cast instead of saturating.
- A zero point that is not an integer, or a range that excludes 0.0, so zero padding dequantizes to a small nonzero bias.
- Returning a list of Python ints, which holds more memory than the FP32 input.
- One clipping percentile for every bit width, tuned on 4-bit results and applied at 8 bits.
- Per-channel scales on activations along the reduction dimension, which cannot factor out of the dot product.
