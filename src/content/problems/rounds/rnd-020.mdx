  solution: |
    # Tie policy for the running maximum: the earliest position that reached the maximum keeps it, which is what a
    # forward pass that only replaces the running max on a strict increase computes; split or latest are also valid
    # subgradients, and the choice only matters where the loss is not differentiable.


    def cumprod(a):
        y, p = [], 1
        for v in a:
            p = p * v
            y.append(p)
        return y


    def cumprod_backward(a, g):
        # dL/da[k] = P[k-1] * S[k], where P[k-1] = a[0]...a[k-1] and S[k] = sum over i >= k of g[i] * a[k+1]...a[i].
        # S runs right to left: S[k] = g[k] + a[k+1] * S[k+1]. No division, so zeros need no special case.
        n = len(a)
        grad = [0] * n
        s = 0
        for k in range(n - 1, -1, -1):
            s = g[k] + (a[k + 1] * s if k + 1 < n else 0)
            grad[k] = s
        p = 1
        for k in range(n):
            grad[k] = p * grad[k]
            p = p * a[k]
        return grad


    def cummax_backward(a, g):
        grad = [0.0] * len(a)
        best = None
        for i, v in enumerate(a):
            if best is None or v > a[best]:
                best = i
            grad[best] += g[i]
        return grad

## Question

<Callout kind="interview" label="Coding round">
"y[i] is the product of a[0] through a[i]. Given the upstream gradient g[i] = dL/dy[i], return dL/da. Linear time, and you may not divide by elements of a: they can be zero."
</Callout>

Write three functions:

- `cumprod(a)`: the forward pass.
- `cumprod_backward(a, g)`: dL/da[k] for every k, in O(n), without dividing by any element of `a` (the hidden tests pass elements that raise if divided by), exact when `a` holds one zero, two zeros or only zeros, and without modifying `a`.
- `cummax_backward(a, g)`: the same for y[i] = max(a[0], ..., a[i]), also O(n).

One decision is yours: when several positions share the running maximum, which of them receives g[i]. The earliest, the latest, or an even split are all accepted; the hidden tests check that the gradient sums to the sum of g, lands only on positions that hold the running maximum, matches finite differences where there are no ties, and follows one of the three policies consistently. The comment above `cummax_backward` says which and why.

The hidden tests time both backward functions on inputs growing to 200,000 elements and allow 1.5 seconds in total.

## Answer

**The derivation.** Write P[k] = a[0] … a[k], with P[−1] = 1. Each y[i] with i ≥ k contains a[k] once, so

```text
dL/da[k] = sum over i >= k of g[i] × product of a[j] for j <= i, j != k
         = P[k-1] × S[k],   where S[k] = sum over i >= k of g[i] × a[k+1] … a[i]
S[k]     = g[k] + a[k+1] × S[k+1],   S[n-1] = g[n-1]
```

One pass from the right builds S, one pass from the left multiplies by P[k − 1]. Nothing is divided, so a zero needs no special case: it zeroes the prefix for everything to its right and the S terms that reach past it, which is exactly the true gradient. On a = [2, 3, 4], g = [1, 1, 1]: S = [16, 5, 1], prefixes [1, 2, 6], gradient [16, 10, 6].

The division version, gradient = (sum over i ≥ k of g[i] y[i]) / a[k], is O(n) and right when no element is zero. With one zero it needs the product of the other elements at that position; with two it needs to know that every position after the first zero has a zero gradient; each case is code that the recurrence does not have. The O(n²) version, one forward walk per k, took 1.1 s at 6,400 elements in CPython 3.12.6 when this problem was checked; the reference took 0.035 s at 204,800.

**The memory decision.** The reference recomputes the prefix products in the backward pass from `a`, so it keeps nothing from the forward pass beyond the input. Saving y from the forward pass avoids n multiplications and holds n more floats until backward runs. In an autograd engine that already saves inputs for every op, recomputing is the cheaper side; in a memory-bound training step the trade reverses only if the multiplications show up in a profile, which at one multiply per element they rarely do.

**How the reference fails.** Float64 tops out at 1.797e308, about 2^1024, so a row of 1,024 values equal to 2.0 overflows its prefix to infinity. Then P[k − 1] × S[k] is infinity times zero wherever S[k] is zero, and the reference returns NaN where the true gradient is 0: with a = [2.0] × 1,100 and only g[0] = 1, it returned 76 NaNs. The alternative is a log-domain version that carries log |a|, a sign and a zero count; it never overflows, but it brings back the zero case analysis and rounds every product through `exp` and `log`. For rows short enough to stay in range the recurrence is exact and simpler; for long rows of values away from 1, the log domain is the defensible choice, and the decision rests on the largest |log P| measured on real inputs.

**The running maximum.** y[i] equals a[m(i)] for the position m(i) holding the maximum so far, so g[i] goes to m(i): one pass, tracking the current argmax. On a tie the function has no derivative, so any split of g[i] across the tied positions is a valid subgradient. The reference gives it to the earliest position, which is what a forward pass computes when it replaces the maximum only on a strict increase. Splitting evenly is symmetric, but done naively it walks the whole tie group at every step, which is O(n²) on an input of equal values; an O(n) split keeps a running sum of g[i] divided by the group size and charges each member the part of that sum after it joined. Ties are rare in float inputs and common in quantised or integer ones, which is where the choice changes training.

## Follow-ups

- *What changes on a GPU, over a batch of rows?* The recurrence S[k] = g[k] + a[k+1] × S[k+1] is a linear recurrence, so it can run as an associative scan over pairs (multiplier, addend) in logarithmic depth, one scan per row; the prefix products are a second scan. The overflow question becomes sharper in bf16 or fp16, whose ranges are far smaller than float64's.
- *Pushback: rows are 50,000 long in production and the forward pass already overflows. The interviewer proposes the log domain; you lose exactness and gain a sign and zero-count path. What do you accept, and what do you write down?* Accept the log domain for rows whose measured |log P| leaves the format's range, keep the recurrence for the rest, and record the relative error of the log version against the exact one on rows that fit.
- *Reversal: what would make you change the tie policy from earliest to split?* Integer or heavily quantised inputs where ties are frequent and the earliest position collects gradient that should be shared, seen as a training difference in an ablation.
- *Backward of the prefix sum?* Each a[k] appears in every y[i] with i ≥ k with coefficient 1, so the gradient is the reverse cumulative sum of g.

## Common mistakes

- Dividing the total by a[k], which fails on the first zero.
- Special-casing one zero and missing two.
- Computing every gradient with its own walk, O(n²).
- Mutating `a` while building prefix products in place.
- Replacing the running maximum on `>=` in the forward pass and on `>` in the backward pass, so the gradient goes to a position the forward pass did not pick.
