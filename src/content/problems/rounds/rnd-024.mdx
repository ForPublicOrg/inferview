  solution: |
    class _Node:
        __slots__ = ("name", "parent", "children", "content")

        def __init__(self, name, parent, is_dir):
            self.name = name
            self.parent = parent
            self.children = {} if is_dir else None   # None marks a file
            self.content = None if is_dir else ""


    class FileSystem:
        def __init__(self):
            self.root = _Node("", None, True)
            self.cwd = self.root      # the directory itself, not its path

        def _start(self, path):
            if not isinstance(path, str) or not path:
                raise ValueError("a path is a non-empty string")
            node = self.root if path.startswith("/") else self.cwd
            return node, [p for p in path.split("/") if p not in ("", ".")]

        def _step(self, node, part, path):
            if part == "..":
                return node.parent or node            # .. at the root stays at the root
            if node.children is None:
                raise NotADirectoryError(path)
            child = node.children.get(part)
            if child is None:
                raise FileNotFoundError(path)
            return child

        def _lookup(self, path):
            node, parts = self._start(path)
            for part in parts:                         # a loop, not recursion: paths can be thousands deep
                node = self._step(node, part, path)
            return node

        def _target(self, path):
            """(parent directory, name, existing node or None) for a path that may not exist yet."""
            node, parts = self._start(path)
            if not parts or parts[-1] == "..":
                found = self._lookup(path)
                return found.parent, found.name, found
            for part in parts[:-1]:
                node = self._step(node, part, path)
            if node.children is None:
                raise NotADirectoryError(path)
            return node, parts[-1], node.children.get(parts[-1])

        def mkdir(self, path, parents=False):
            if parents:
                node, parts = self._start(path)
                for part in parts:
                    if part == "..":
                        node = node.parent or node
                        continue
                    if node.children is None:
                        raise NotADirectoryError(path)
                    child = node.children.get(part)
                    if child is None:
                        child = node.children[part] = _Node(part, node, True)
                    node = child
                if node.children is None:
                    raise FileExistsError(path)
                return
            parent, name, existing = self._target(path)
            if existing is not None:
                raise FileExistsError(path)
            parent.children[name] = _Node(name, parent, True)

        def touch(self, path):
            parent, name, existing = self._target(path)
            if existing is None:
                parent.children[name] = _Node(name, parent, False)
            elif existing.children is not None:
                raise IsADirectoryError(path)

        def write(self, path, text):
            self.touch(path)
            self._lookup(path).content = text

        def read(self, path):
            node = self._lookup(path)
            if node.children is not None:
                raise IsADirectoryError(path)
            return node.content

        def ls(self, path="."):
            node = self._lookup(path)
            if node.children is None:
                return [node.name]
            return sorted(node.children)

        def cd(self, path):
            node = self._lookup(path)
            if node.children is None:
                raise NotADirectoryError(path)
            self.cwd = node

        def pwd(self):
            names, node = [], self.cwd
            while node.parent is not None:
                names.append(node.name)
                node = node.parent
            return "/" + "/".join(reversed(names))

        def mv(self, src, dst):
            node = self._lookup(src)
            if node is self.root:
                raise ValueError("the root cannot be moved")
            parent, name, existing = self._target(dst)
            if existing is not None and existing.children is not None:
                parent, name = existing, node.name     # into an existing directory, keeping the name
                existing = parent.children.get(name)
            ancestor = parent
            while ancestor is not None:
                if ancestor is node:
                    raise ValueError("a directory cannot move inside itself")
                ancestor = ancestor.parent
            if existing is node:
                return
            if existing is not None:
                if existing.children is not None:
                    raise IsADirectoryError(dst) if node.children is None else FileExistsError(dst)
                if node.children is not None:
                    raise NotADirectoryError(dst)
                del parent.children[name]              # file over file: replace, as rename(2) does
            del node.parent.children[node.name]
            node.name, node.parent = name, parent
            parent.children[name] = node

## Question

<Callout kind="interview" label="Coding round">
"Implement an in-memory file system as a class. We'll add to it in stages."
</Callout>

Three stages grow one `FileSystem` class. Each stage runs its visible tests and then hidden tests against your whole program, and the next brief appears only after the current stage passes. Plan for about 50 minutes.

The errors are Python's built-in `OSError` subclasses (`FileNotFoundError`, `FileExistsError`, `NotADirectoryError`, `IsADirectoryError`) plus `ValueError` for moves that can never be valid. Two choices are yours:

- How you represent the tree: nodes with parent pointers, a map from absolute path to node, or both.
- In stage 3, whether a file moved onto an existing file replaces it or is refused.

Also decide one number before stage 2 ends: how many entries one directory can hold before you stop sorting its children on every `ls` and keep them sorted as they are created instead. State the ratio of `ls` calls to creations at which you would switch.

## Answer

The reference solution is a tree. Each node has a name, a parent and either a `children` dict (a directory) or text content (a file). The working directory is a node reference, not a string.

- **Path resolution.** Every path is resolved with a loop over its components that starts at the root or the working directory. `.` is skipped, `..` moves to the parent (the root is its own parent), and stepping into a file raises `NotADirectoryError`.
- **`_target(path)`.** This helper returns the parent directory, the final name and the existing node, if there is one. Every creating call and every move needs those three things.
- **`pwd`.** It walks parent pointers up to the root.
- **`mv`.** It resolves the source, works out the target (inside `dst` when `dst` is an existing directory), refuses the move when the target's parent is the source or below it, and then applies the conflict table. It only touches the tree once every check has passed, so a refused move changes nothing. The move itself is a relink of one node: `O(depth)` for the ancestor check and `O(1)` for the change.

Each later stage defeats an earlier shortcut:

- **Stage 2 defeats the flat map's `ls`.** A flat map from absolute path to content has to scan every key to list a directory. The visible test's 30,000 calls over 30,000 files would need up to 900 million key checks. The tree answers each call by sorting its 100 children.
- **The hidden tests defeat recursion.** They use paths 1,500 directories deep, so a recursive resolver fails. CPython 3.12.6 in this harness reports `sys.getrecursionlimit()` as 1000, and Pyodide sets its own limit, so check it there before relying on recursion.
- **Stage 3 defeats the flat map's `mv`.** In a flat map, moving a directory rewrites the key of every descendant. A run of that design on the visible test's 500 moves of a 30,000-file directory, in this harness's local CPython, took 4.97 seconds against a 2-second budget. The tree took 0.0006 seconds.
- **Stage 3 also defeats a string working directory.** After `mv /archive /proj/old`, a cwd stored as `"/archive/src"` names a path that no longer exists, while a node reference follows the move. POSIX shells behave the same way, because their working directory is a directory, not a name.

The representation has two defensible answers:

- **A tree with parent pointers.** Lookups cost `O(depth)` and moves cost `O(depth)`.
- **A map from absolute path to node, plus a children index.** Absolute lookups are `O(1)`, but every move rewrites every descendant's key, `O(subtree)`.

When reads of deep absolute paths dominate and moves are rare, the map wins on latency. In a round whose third stage is `mv`, the tree is the safer bet.

The overwrite decision is the constraint conflict, data safety against compatibility. The POSIX `rename` specification removes an existing target and requires the replacement to be atomic, which is what makes "write a temp file, then rename it over the original" a safe update. The reference follows it. Refusing with `FileExistsError` protects a user from losing a file by mistake, but it breaks that idiom. The hidden tests accept either answer, provided a refusal changes nothing.

For the sorting threshold:

- **Sort on every `ls`.** This costs `O(k log k)` per listing and nothing per creation.
- **Keep the children sorted.** This costs an `O(k)` insertion per creation (the Python `bisect` docs note that `insort` is dominated by the linear insertion step) and nothing extra per listing.

At k = 30,000, `log2 k` is about 15. Sorting costs about 15 comparisons per child per listing; a sorted insertion costs up to k element moves per creation, done by a block memory copy. Measure both on your runtime before you pick the crossover. Reasonable answers keep sorting per call until directories reach tens of thousands of entries and are listed more often than they change. Committing to either approach without a measurement is unreasonable.

**How the recommended answer fails.** This spec is stricter than `rename(2)` in one place. A directory landing on an existing empty directory raises `FileExistsError` here, where POSIX would replace the empty directory, so a script written against POSIX semantics fails on this file system. The tree also makes `pwd` cost `O(depth)` on every call, which a client polling it at depth 1,500 pays each time.

## Follow-ups

- *What changes to make this a real file system?* Concurrency first. Two moves that cross each other (`mv /a /b/x` while another client runs `mv /b /a/y`) can create a cycle unless the ancestor check and the relink happen under one lock, or under locks taken in a fixed order. Persistence needs an inode table and a journal, so that a move is one atomic journal record. Symlinks break the rule that `..` means the parent: a path then has a lexical form and a physical form, and the two can resolve to different directories.
- *Pushback: 95 percent of calls are reads of absolute paths 40 levels deep, and the product team wants them `O(1)`. Do you add a path cache, and what invalidates it on `mv`?* A cache from path to node, with entries invalidated by prefix on every move of a directory. Accept in writing that a move of a large subtree is now `O(cached descendants)`, and measure the cache's hit rate before keeping it.
- *Reversal: what would make you switch the file-over-file rule from replace to refuse?* Incident reports of files lost to accidental overwrites, together with evidence that no caller depends on the write-then-rename pattern. If some callers do depend on it, add an explicit `replace=True` flag instead of changing the default.

## Common mistakes

- Storing the working directory as a string.
- Resolving paths with recursion.
- Applying part of a move before discovering it must be refused.
- Treating `mv dir existing_dir` as a rename, when it moves `dir` inside.
- Forgetting that `..` at the root stays at the root.
- Letting `mkdir(path, parents=True)` succeed when the path is an existing file.
