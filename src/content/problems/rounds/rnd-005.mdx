## Question

An interviewer asks you to match decoding strategies to tasks, and to say when each one fails. Pick the statement that is correct.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask whether the task has one right answer grounded in the input, or many acceptable continuations.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Work out what each extreme setting reduces to: top-p of 1.0, and top-k of 1.</p></details>

## Answer

The correct pairing is beam search or greedy for input-grounded tasks such as summarisation and translation, and temperature plus top-p sampling for open-ended generation. The Hugging Face generation guide describes beam search as keeping several candidate sequences per step and returning the one with the highest overall probability, and calls it best suited for input-grounded tasks. Holtzman et al. found that maximising likelihood in open-ended generation produces text that is bland and repetitive, which is the motivation for nucleus sampling.

Why the wrong picks tempt people. "Beam search for stories" sounds right because higher probability sounds better; the paper's finding is that the highest-probability continuation is not what people judge as good text. "Top-p 1.0 is deterministic" mixes up the filter with the draw: the filter keeps everything and the draw is still random. "Top-k 1 differs from greedy" fails once you trace one step: a single candidate is the argmax.

## Follow-ups

- *Beam search returns the most probable sequence. Is that the best answer?* Not necessarily; it is the most probable under the model, which is a different thing from correct. Length normalisation exists because summed log-probabilities favour short outputs.
- *What does temperature do to top-p?* Higher temperature flattens the distribution, so the nucleus for the same p contains more tokens.
- *Your structured-output endpoint returns invalid JSON one time in a hundred at temperature 0.8. What do you change first?* Lower the temperature for that call and use constrained decoding or a strict schema mode if the provider has one, then measure again.

## Common mistakes

- Saying "temperature 0" is a setting the math supports. It is a special case that libraries implement as argmax.
- Treating beam width as a quality knob for chat. Wider beams make open-ended text more generic, not better.
- Proposing beam search without checking that the API you call exposes it. Read its parameter list first; the knobs you can actually turn may be only temperature and top-p.
