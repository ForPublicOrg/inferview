    import heapq
    import time


    class Database:
        def __init__(self, clock=time.monotonic):
            self.clock = clock
            self.records = {}     # key -> {field: (value, expires_at or None)}
            self.index = {}       # (field, value) -> set of keys, live fields only
            self.expiries = []    # heap of (expires_at, key, field); stale entries are skipped
            self.backups = {}
            self.backup_seq = 0

        def _now(self):
            now = self.clock()
            heap = self.expiries
            while heap and heap[0][0] <= now:
                expires_at, key, field = heapq.heappop(heap)
                entry = self.records.get(key, {}).get(field)
                if entry is not None and entry[1] == expires_at:
                    self._remove(key, field)
            return now

        def _remove(self, key, field):
            record = self.records[key]
            value, _ = record.pop(field)
            keys = self.index[(field, value)]
            keys.discard(key)
            if not keys:
                del self.index[(field, value)]
            if not record:
                del self.records[key]

        def _put(self, key, field, value, expires_at):
            if field in self.records.get(key, {}):
                self._remove(key, field)
            self.records.setdefault(key, {})[field] = (value, expires_at)
            self.index.setdefault((field, value), set()).add(key)
            if expires_at is not None:
                heapq.heappush(self.expiries, (expires_at, key, field))

        def set(self, key, field, value, ttl=None):
            if value is None:
                raise ValueError("None is not a storable value")
            if ttl is not None and ttl <= 0:
                raise ValueError("ttl must be positive")
            now = self._now()
            self._put(key, field, value, None if ttl is None else now + ttl)

        def get(self, key, field):
            self._now()
            entry = self.records.get(key, {}).get(field)
            return None if entry is None else entry[0]

        def delete(self, key, field):
            self._now()
            if field not in self.records.get(key, {}):
                return False
            self._remove(key, field)
            return True

        def scan(self, key, prefix=""):
            self._now()
            record = self.records.get(key, {})
            return sorted((f, v) for f, (v, _) in record.items() if f.startswith(prefix))

        def find(self, field, value):
            self._now()
            return sorted(self.index.get((field, value), ()))

        def backup(self):
            now = self._now()
            snapshot = {
                key: {f: (v, None if exp is None else exp - now) for f, (v, exp) in record.items()}
                for key, record in self.records.items()
            }
            self.backup_seq += 1
            self.backups[self.backup_seq] = snapshot
            return self.backup_seq

        def restore(self, backup_id):
            snapshot = self.backups[backup_id]          # KeyError for an unknown id
            now = self._now()
            self.records, self.index, self.expiries = {}, {}, []
            for key, record in snapshot.items():
                for field, (value, remaining) in record.items():
                    self._put(key, field, value, None if remaining is None else now + remaining)

## Question

<Callout kind="interview" label="Coding round">
"Build an in-memory database. I'll give you the requirements one stage at a time. Each stage has tests, and the next stage opens when they pass."
</Callout>

Four stages grow one `Database` class. Stage n runs its visible tests and then hidden tests against your whole program, and the brief for the next stage appears only after the current one passes. Plan for about an hour in total.

Two choices are yours, and the hidden tests accept any design that keeps the stated behaviour inside the time budgets:

- How an expired field leaves your structures: from a heap of expiry times, when something touches it, or in a periodic sweep.
- What a backup costs: a full copy each time, or a structure that shares unchanged data between backups.

Before stage 4, write down one number: in a scenario where the live data takes 1 GB inside a 4 GB process, how many backups your design can hold before it runs out of memory, and what you would change past that number.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask how often find is called compared with set, and over how many records.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Ask whether the clock can go backwards, and what the database should do if it does.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Ask how large a backup can be and how many are kept at once.</p></details>

## Answer

The reference solution keeps three structures. `records` maps a key to `{field: (value, expires_at)}`, with `expires_at` set to `None` for a permanent field. `index` maps `(field, value)` to the set of keys holding it, for live fields only, and every write and removal updates it. `expiries` is a min-heap of `(expires_at, key, field)`. Each public method starts by popping the heap entries that are due. A popped entry removes its field only if the stored expiry still equals the popped one, so a later `set` with a new ttl makes the old entry stale without a search. `backup` saves each live field with its remaining time, `expires_at - now`. `restore` rebuilds all three structures, setting each field's expiry to `now + remaining`.

Each stage is built to break a design that only fitted the stage before:

- **Stage 2 breaks the scan-everything `find`.** Scanning every record for each `find` is 20,000 × 20,000 = 400 million record visits in the visible test. A run of that design in this harness's local CPython 3.12.6 took 25.0 seconds against the 3-second budget. With the index, the same 20,000 calls took 0.018 seconds.
- **Stage 3 breaks an index that was never told about expiry.** Filtering expired keys out at read time gives the right answer, but the dead keys stay in the index. Five thousand finds over 20,000 expired keys is 100 million liveness checks, and the filtering design measured 6.8 seconds. Removing a field from the index when it expires costs one heap pop and one set removal per expiry, once.
- **Stage 4 breaks three shortcuts.** Absolute expiry times saved in a backup are already in the past when the backup is restored later; the stage 4 test restores 46 seconds after the backup, and everything with a ttl comes back expired. `dict(self.records)` copies only the outer dict, so a `set` after the backup changes the backup through the shared inner dicts. A restore that does not rebuild the index leaves `find` answering from the pre-restore data.

The expiry decision has two defensible answers:

- **Heap.** The reference pays `O(log n)` per ttl write and keeps `find` proportional to its result, at the cost of one heap entry per ttl write, stale entries included.
- **Expire on touch, plus a sweep.** This makes writes cheaper and needs no heap, but expired data holds memory until something reads it or the sweep reaches it. The sweep's batch size becomes a number you tune against the latency it adds to the call that runs it.

Either passes the tests. In a 60-minute round the heap is the shorter path to code that stays correct through stage 4.

The backup decision is the constraint conflict in this problem: the round's clock against memory. A full copy is a few lines and is correct by construction, but every backup costs as much as the live data, plus Python's per-object overhead. In the 1 GB scenario, the live data and two copies already take 3 GB, and the per-object overhead of the copies makes a third doubtful, so the answer is one or two. "As many as the user asks for" is the unreasonable answer. Past two, share structure between backups: keep a version counter per field and copy a field only when it is written after a backup, or use a persistent map. That turns `backup` into `O(1)` and makes every write after a backup pay for a copy.

**How the recommended answer fails.** A field rewritten with a fresh ttl every second leaves one stale heap entry per write until each entry's original expiry passes. That is ttl ÷ write interval entries per hot field, so a 3,600-second ttl refreshed every second holds 3,600 entries for a single field. If stale entries ever outnumber live ones by a factor you choose, rebuild the heap from `records`.

The clock matters too. `time.monotonic` is the right default inside one process, but it is meaningless across a restart: a persisted database has to store absolute wall-clock expiry and accept that a wall-clock step changes which fields are live.

## Follow-ups

- *What changes to run this as a real service?* Persistence: write each backup to disk as a snapshot and every later write to an append-only log, so a restart loads the snapshot and replays the log. Concurrency: put one lock around each operation, or route all writes through a single writer, because the index and the heap must change together with the record. Memory: account for the index, which holds one more entry per live field.
- *Pushback: the index doubles the memory for a `find` that runs a few times an hour. Do you keep it, and what do you accept in writing?* Drop it and let `find` scan. Write down the scan's measured latency at today's record count and the count at which it crosses the latency objective, and set an alert for that count.
- *Reversal: what would you need to see in production to move from full-copy backups to shared structure?* Backup latency or peak memory during a backup that is measured above budget, or a requirement to keep more backups than the memory arithmetic above allows. Without one of those, keep the version that is easier to verify.
- *Stage 5 adds transactions. Which of your structures must the undo log cover?* Records and the index, together. Heap entries can stay, because stale ones are already skipped. Backups taken inside a transaction need a rule: either refuse them, or record the backup as of the last commit.

## Common mistakes

- Updating the index on `set` but not on `delete`, on overwrite, or on expiry.
- Filtering expired fields at read time and never removing them from the index.
- Saving absolute expiry times in a backup instead of remaining time.
- Copying only the outer dict when taking a backup.
- Allowing `None` as a stored value while `get` uses `None` to mean "missing".
- Calling `time.time()` directly instead of the injected clock, which makes expiry untestable.
