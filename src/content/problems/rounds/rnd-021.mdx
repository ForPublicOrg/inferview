    import math, random

    # tanh: smooth everywhere, so the finite-difference check has no kink to straddle. Its cost is saturation, which
    # shrinks gradients as pre-activations grow, so W1 starts at scale 1 / sqrt(D) and W2 at 1 / sqrt(H).
    ACTIVATION = "tanh"


    def init_params(D, H, seed=0):
        rng = random.Random(seed)
        return {
            "W1": [[rng.gauss(0, 1 / math.sqrt(D)) for _ in range(H)] for _ in range(D)],
            "b1": [0.0] * H,
            "W2": [rng.gauss(0, 1 / math.sqrt(H)) for _ in range(H)],
            "b2": 0.0,
        }


    def _hidden(params, X):
        cols = list(zip(*params["W1"]))            # H columns of length D
        return [[math.tanh(sum(x * w for x, w in zip(row, col)) + b) for col, b in zip(cols, params["b1"])] for row in X]


    def forward(params, X):
        W2, b2 = params["W2"], params["b2"]
        return [sum(h * w for h, w in zip(hr, W2)) + b2 for hr in _hidden(params, X)]


    def _softplus(z):
        # log(1 + e^z) without overflow: max(z, 0) + log1p(e^-|z|).
        return max(z, 0.0) + math.log1p(math.exp(-abs(z)))


    def _sigmoid(z):
        if z >= 0:
            return 1.0 / (1.0 + math.exp(-z))
        e = math.exp(z)
        return e / (1.0 + e)


    def loss(params, X, y):
        # -[y log s(z) + (1 - y) log(1 - s(z))] equals softplus(z) - y z, which never takes the log of a rounded 0 or 1.
        zs = forward(params, X)
        return sum(_softplus(z) - t * z for z, t in zip(zs, y)) / len(y)


    def grads(params, X, y):
        N = len(y)
        hs = _hidden(params, X)
        W2 = params["W2"]
        D, H = len(params["W1"]), len(W2)
        gW1 = [[0.0] * H for _ in range(D)]
        gb1, gW2, gb2 = [0.0] * H, [0.0] * H, 0.0
        for row, hr, t in zip(X, hs, y):
            z = sum(h * w for h, w in zip(hr, W2)) + params["b2"]
            dz = (_sigmoid(z) - t) / N                  # d loss / d z2 for one example of the mean
            gb2 += dz
            for j in range(H):
                gW2[j] += dz * hr[j]
                da = dz * W2[j] * (1.0 - hr[j] * hr[j])  # tanh' written in terms of tanh's output
                gb1[j] += da
                for i, x in enumerate(row):
                    gW1[i][j] += x * da
        return {"W1": gW1, "b1": gb1, "W2": gW2, "b2": gb2}


    def _slots(params):
        # Every scalar parameter as (key, index path).
        out = [("W1", (i, j)) for i in range(len(params["W1"])) for j in range(len(params["W1"][0]))]
        out += [("b1", (j,)) for j in range(len(params["b1"]))]
        out += [("W2", (j,)) for j in range(len(params["W2"]))]
        return out + [("b2", ())]


    def _get(p, key, idx):
        v = p[key]
        for k in idx:
            v = v[k]
        return v


    def _set(p, key, idx, value):
        if not idx:
            p[key] = value
            return
        v = p[key]
        for k in idx[:-1]:
            v = v[k]
        v[idx[-1]] = value


    def grad_check(params, X, y, grad_fn=grads, eps=1e-5):
        g = grad_fn(params, X, y)
        worst = {"W1": 0.0, "b1": 0.0, "W2": 0.0, "b2": 0.0}
        for key, idx in _slots(params):
            old = _get(params, key, idx)
            try:
                _set(params, key, idx, old + eps)
                up = loss(params, X, y)
                _set(params, key, idx, old - eps)
                dn = loss(params, X, y)
            finally:
                _set(params, key, idx, old)      # restore exactly, even if loss raises
            num, ana = (up - dn) / (2 * eps), _get(g, key, idx)
            # Relative to the larger of the two, with a floor so a pair of true zeros is not 0 / 0.
            err = abs(num - ana) / max(abs(num), abs(ana), 1e-8)
            worst[key] = max(worst[key], err)
        return worst

## Question

<Callout kind="interview" label="Coding round">
"Binary classifier, one hidden layer, sigmoid output, mean cross-entropy. Derive every gradient by hand, write them, and prove them with a finite-difference check. Standard library only."
</Callout>

Parameters are a dict: `W1` (D rows of H), `b1` (H), `W2` (H), `b2` (one float). `X` is N rows of D and `y` is N labels in {0, 1}. Write:

- `init_params(D, H, seed)`: deterministic for a seed, different across seeds.
- `forward(params, X)`: one logit per example, z = act(X W1 + b1) W2 + b2.
- `loss(params, X, y)`: mean binary cross-entropy of sigmoid(z) against y, finite for every finite logit.
- `grads(params, X, y)`: the analytic gradient, shaped like `params`.
- `grad_check(params, X, y, grad_fn=grads, eps=1e-5)`: the largest relative error per parameter between `grad_fn` and central differences of `loss`, leaving `params` exactly as it found them.

Three choices are yours and go in the comment at the top: the hidden activation (`ACTIVATION`, ReLU or tanh), the initial weight scale, and the step and error formula inside `grad_check`. The hidden tests accept either activation and check the gradients against their own finite differences, check that `grad_check` flags a gradient function with one parameter's gradient doubled or zeroed, and train a small XOR-shaped set to check the gradients point downhill.

The visible tests end with `grads` on 1,000 examples of 8 features and 16 hidden units within 1 second.

## Answer

**The loss in logits.** −[y log σ(z) + (1 − y) log(1 − σ(z))] simplifies to softplus(z) − y z, and softplus(z) = max(z, 0) + log1p(exp(−|z|)) never exponentiates a positive number. The probability form fails on the visible test: at z = 800, σ(z) rounds to 1.0, 1 − σ(z) is 0, and `math.log(0)` raises; the reference returns 800 for label 0 and 0 for label 1.

**The gradients, with shapes.** For the mean over N examples, dL/dz = (σ(z) − y) / N, one value per example. Then, with A = act(X W1 + b1) of shape N × H:

```text
dW2 = Aᵀ dz              (H)        db2 = sum of dz            (scalar)
dA  = dz W2ᵀ             (N × H)
dU  = dA ⊙ act'(U)       (N × H)    tanh' = 1 − A²,  ReLU' = 1 where U > 0
dW1 = Xᵀ dU              (D × H)    db1 = column sums of dU    (H)
```

Writing tanh' from the stored output A saves recomputing the pre-activation. The reference accumulates these example by example in one pass. Computing the gradient by finite differences instead is the naive version: 161 parameters at D = 8, H = 16, two loss evaluations each. When this problem was checked in CPython 3.12.6 that took 5.6 s on the visible test's 1,000 examples; the analytic version took 0.021 s.

**The check, and the step you choose.** A central difference has truncation error proportional to eps² and rounding error proportional to u / eps, where u is the format's unit roundoff; the two balance near eps = u^(1/3). In float64, u = 2^−52 = 2.2e−16, so the best step is near 6e−6 and errors near u^(2/3) = 4e−11 are reachable when the derivatives are of order one; 1e−5 or 1e−6 are both reasonable, 1e−10 is not (rounding dominates) and 1e−2 is not (truncation dominates). The relative error divides by the larger of the two magnitudes with a floor, because both can be exactly zero, as they are for every weight into a dead ReLU unit. In float32, u = 2^−23 = 1.2e−7, the best step is near 5e−3 and the error floor near 2e−5, which is why the check runs in float64.

**ReLU or tanh.** ReLU is cheaper and does not saturate for positive inputs; He initialisation, standard deviation sqrt(2 / D), is the usual pairing. Its costs here: the check fails spuriously when a pre-activation lies within eps of zero, because the central difference straddles the kink and sees a slope between 0 and 1; and a unit that is negative for every example gets zero gradient for good. Tanh is smooth, so the check has no kink to straddle; its cost is saturation, where large pre-activations push 1 − A² towards zero and slow learning, which is why its initial scale is smaller (the reference uses 1 / sqrt(D) for W1). The reference picks tanh because the check is the deliverable in this round; a ReLU network checked in tests with biases offset away from zero is the equally defensible answer for production.

**Where the reference fails.** The check only covers the code paths the check's data reaches. With tanh in the check and ReLU in production, or with a batch on which no unit is ever inactive, a wrong mask in the ReLU branch passes. And a pass at 20 examples says nothing about the vectorised version a team writes next; the check has to run against that code, on a batch small enough to finish.

## Follow-ups

- *What changes to train this for real?* Arrays instead of lists, float32 or bf16 for the forward and backward passes, the loss written as one fused binary-cross-entropy-with-logits op, and the gradient check kept as a unit test on a tiny batch in float64.
- *Pushback: the check costs two forward passes per parameter, and the real model has millions. Which half do you cut, and what risk do you accept in writing?* Check a random direction v instead of every coordinate: compare g · v with (L(θ + εv) − L(θ − εv)) / 2ε, two forward passes per direction, a few directions per parameter tensor. Write down that a bug confined to a few coordinates can hide inside a random projection.
- *Reversal: what would make you switch the network from tanh to ReLU?* A training run on the real data where ReLU reaches the same loss in fewer steps, with the gradient check moved to a configuration where no pre-activation sits near zero.
- *The batch size doubles. What changes and what do you watch?* The variance of the mean gradient halves, since it averages twice as many examples; the learning rate usually moves with it, and the loss curve in the first few hundred steps shows whether the change was too aggressive.

## Common mistakes

- Taking the log of a rounded sigmoid, which returns infinity or raises at large logits.
- Forgetting the 1 / N of the mean, so every gradient is N times too large.
- Writing `b1`'s gradient as dU for one example instead of its sum over the batch.
- Initialising every weight to the same value, so every hidden unit gets the same gradient and they never differ.
- Choosing eps by habit: 1e−10 in float64 measures rounding noise.
