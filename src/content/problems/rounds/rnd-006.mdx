  solution: |
    import json

    class SSEParser:
        def __init__(self):
            self.buf = ""
            self.event = ""
            self.data = []

        def _next_line(self):
            # Return (line, rest) or None if no complete line is buffered yet.
            for i, ch in enumerate(self.buf):
                if ch == "\n":
                    return self.buf[:i], self.buf[i + 1:]
                if ch == "\r":
                    if i + 1 == len(self.buf):
                        return None            # might be the first half of CRLF
                    skip = 2 if self.buf[i + 1] == "\n" else 1
                    return self.buf[:i], self.buf[i + skip:]
            return None

        def feed(self, chunk):
            self.buf += chunk
            events = []
            while True:
                nxt = self._next_line()
                if nxt is None:
                    return events
                line, self.buf = nxt
                if line == "":
                    if self.data:
                        events.append((self.event or "message", "\n".join(self.data)))
                    self.event, self.data = "", []
                elif line.startswith(":"):
                    continue
                else:
                    field, _, value = line.partition(":")
                    if value.startswith(" "):
                        value = value[1:]
                    if field == "event":
                        self.event = value
                    elif field == "data":
                        self.data.append(value)

    def tool_inputs(events):
        partial, result = {}, {}
        for _, data in events:
            msg = json.loads(data)
            kind = msg.get("type")
            if kind == "content_block_start" and msg["content_block"]["type"] == "tool_use":
                partial[msg["index"]] = ""
            elif kind == "content_block_delta" and msg["delta"].get("type") == "input_json_delta":
                partial[msg["index"]] += msg["delta"]["partial_json"]
            elif kind == "content_block_stop" and msg["index"] in partial:
                text = partial.pop(msg["index"])
                result[msg["index"]] = json.loads(text) if text else {}
        return result

    def output_tokens(events):
        last = 0
        for _, data in events:
            msg = json.loads(data)
            if msg.get("type") == "message_delta" and "usage" in msg:
                last = msg["usage"]["output_tokens"]
        return last

## Question

<Callout kind="interview" label="The prompt">
"Write a streaming parser for an LLM's server-sent events. The network can split the bytes anywhere. Then pull out the tool call arguments and the final token count."
</Callout>

The stream follows the Claude Messages streaming format: `message_start`, then for each content block a `content_block_start`, one or more `content_block_delta` events and a `content_block_stop`, then `message_delta` and `message_stop`. `ping` events can appear anywhere, and new event types may be added at any time.

Write three things:

1. `SSEParser.feed(chunk)`, which buffers text and returns every event completed by this chunk, as `(event_name, data)`.
2. `tool_inputs(events)`, which joins the `partial_json` fragments of each tool-use block and parses them when the block stops.
3. `output_tokens(events)`, which returns the final output token count.

The tests split the stream at every possible position, including between a `\r` and its `\n`, and also feed it one character at a time.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Chunk boundaries have nothing to do with line boundaries. Keep a buffer and only consume complete lines.</p></details>
<details class="hint"><summary>Hint 2</summary><p>A `\r` at the very end of the buffer might be the first half of `\r\n`. Wait for the next chunk before deciding.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Read the docs sentence on usage in `message_delta` twice: the counts there are cumulative.</p></details>

## Answer

The parser is a line splitter plus a tiny state machine, following the WHATWG rules. Lines end at CRLF, LF or a lone CR. A blank line dispatches the event built so far. A line starting with a colon is a comment, which servers use as a keep-alive. Otherwise the line is `field: value`, with exactly one leading space removed from the value, and repeated `data` lines are joined with a newline. An event with no `event:` field is named `message`, and a final event that never got its blank line is not dispatched.

The one subtle case is a buffer that ends in `\r`. If you treat it as a line ending immediately, a chunk split between `\r` and `\n` produces an extra empty line, which dispatches early and then dispatches an empty event. The reference `_next_line` refuses to decide until it sees the next character. The split-everywhere test catches this; a test with one or two hand-picked chunk sizes usually does not.

`tool_inputs` treats each `partial_json` fragment as text, not JSON. The fragments `{"city": "Par` and `is"}` are not valid JSON on their own, which is why the docs say to accumulate them and parse at `content_block_stop`.

`output_tokens` takes the last `message_delta` usage value. The docs state that those counts are cumulative, so summing the deltas here would report 17 instead of 12.

Unknown event types such as `future_event` and `ping` pass through `tool_inputs` and `output_tokens` without effect, because both functions dispatch on the types they know and ignore the rest.

## Follow-ups

- *The HTTP status was 200 but the stream contains an `error` event. What do you do?* Errors such as `overloaded_error` can arrive mid-stream, after the 200. Surface them from the parser as an event, stop, and decide whether to retry; a status-code check alone misses them.
- *The connection drops halfway through a long answer. How do you resume?* The OpenAI Python SDK does not retry stream consumption automatically, because replaying the request could duplicate output. For Claude, the docs describe resuming by sending the partial output back; on Claude 4.6 and later that goes in a user message with an instruction to continue, because assistant prefill returns a 400 there.
- *Make it work on bytes.* Decode UTF-8 incrementally, because a multi-byte character can also be split across chunks. Python's `codecs.getincrementaldecoder("utf-8")` handles it.
- *How would you show partial tool arguments in a UI before the block ends?* Use a tolerant partial-JSON parser for display only, and still parse strictly at the stop event before executing anything.

## Common mistakes

- Splitting each chunk on `\n\n` and assuming every chunk holds whole events.
- Calling `.strip()` on values, which removes meaningful leading spaces from streamed text.
- Parsing every `partial_json` fragment with `json.loads` and crashing on the first one.
- Summing `output_tokens` across `message_delta` events.
- Raising on an unknown event type, which breaks the client the day the provider adds one.
