    assert full[0][2] > 0, "without the mask, position 0 attends to the future"

  solution: |
    import math

    def attention(Q, K, V, causal=True):
        T, d_k = len(Q), len(Q[0])
        scale = math.sqrt(d_k)
        weights = []
        for i in range(T):
            row = []
            for j in range(len(K)):
                if causal and j > i:
                    row.append(float("-inf"))      # mask before softmax
                else:
                    row.append(sum(q * k for q, k in zip(Q[i], K[j])) / scale)
            m = max(row)
            e = [math.exp(s - m) if s != float("-inf") else 0.0 for s in row]
            total = sum(e)
            weights.append([x / total for x in e])
        out = [[sum(weights[i][j] * V[j][c] for j in range(len(V))) for c in range(len(V[0]))]
               for i in range(T)]
        return out, weights

## Question

<Callout kind="interview" label="The prompt">
"Implement scaled dot-product attention with a causal mask. No libraries. Then tell me what you'd test." Open-source interview question banks list it among their from-scratch coding questions.
</Callout>

`Q`, `K` and `V` are lists of lists, one row per position. Return the output rows and the attention weights. With `causal=True`, position `i` may attend to positions `0` to `i` and nothing later.

Say the shapes out loud before you write a loop: `QK^T` is T by T, the weights are T by T, and the output is T by d_v.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Divide each dot product by the square root of d_k, the width of a query or key row.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Set masked scores to negative infinity before the softmax. Zeroing weights after the softmax leaves rows that no longer sum to 1.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Subtract the row maximum before exponentiating. The last test uses scores large enough to overflow `exp` otherwise.</p></details>

## Answer

The reference solution builds one row of scores at a time. For each pair it takes the dot product of query `i` and key `j` and divides by `sqrt(d_k)`. Vaswani et al. give the reason for the divisor: for large d_k the dot products grow in magnitude and push the softmax into regions with very small gradients. In the base Transformer, d_k is 64, so the scale is 8.

Masked positions get negative infinity before the softmax, so `exp` turns them into exactly zero and the row still sums to 1. The softmax subtracts the row maximum first. The diagonal is never masked, so every row has at least one finite score and the maximum is finite.

The output row `i` is the weighted sum of the value rows. Test by invariant rather than by golden output: rows sum to 1, the upper triangle is zero, position 0 copies `V[0]`, and one hand-computed weight pins the scale. That last test is the one that catches `/ d_k` or `/ sqrt(d_model)`: here row 2 has scores 1, 1 and 2 before scaling, so its first weight is `e^(1/√2) / (2e^(1/√2) + e^(2/√2))`.

Complexity is O(T² · d) time and O(T²) memory for the weights, which is the quadratic cost that long-context work tries to avoid.

## Follow-ups

- *Make it multi-head.* Split d_model into h heads of width d_model / h, run attention per head, concatenate, project. Then convert to grouped-query attention: several query heads share one key and value head, which shrinks the KV cache, not the number of query heads.
- *Add a padding mask.* Combine it with the causal mask. A row whose positions are all masked has no finite score, so the softmax divides zero by zero; decide what that row should return.
- *Decode one token at a time.* Cache K and V for the prefix and attend with a single new query. The output must equal the last row of the full recompute; write that as the test.
- *Where does the memory go at long context?* The T by T weight matrix. Ask about computing the softmax in blocks with a running maximum and normaliser (the online softmax trick).

## Common mistakes

- Masking with `j >= i`, which hides each token from itself and leaves row 0 with nothing to attend to.
- Applying the mask after the softmax by multiplying with zero.
- Scaling by d_k or by the model width instead of the square root of the key width.
- Transposing the wrong matrix and getting a d by d result that happens to be square in a toy example.
- Testing only with T = 1, where every mask bug passes.
