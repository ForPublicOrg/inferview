    TRUSTED = frozenset({"user"})


    class Refused(Exception):
        def __init__(self, tool, tainted):
            super().__init__("%s refused: untrusted data in %s" % (tool, ", ".join(tainted)))
            self.tool, self.tainted = tool, tuple(tainted)


    class Labeled:
        """A value (.value) and the frozenset of sources it was computed from (.sources). A source is "user" or
        "tool:<name>"; only the sources in TRUSTED are trusted. Printing or formatting a Labeled must not show its value."""

        def __init__(self, value, sources):
            raise NotImplementedError


    def label(value, source):
        raise NotImplementedError


    def sources_of(x):
        """Every source in x: a Labeled, a constant written by the planner (no sources), or a list, tuple or dict of them."""
        raise NotImplementedError


    def derive(fn, *args):
        """fn applied to the plain values of args, as a Labeled."""
        raise NotImplementedError


    def quarantine(model, instruction, *args):
        """Ask the quarantined model, which has no tools: model(instruction, *plain_args) returns text. Return a Labeled."""
        raise NotImplementedError


    class Gateway:
        def __init__(self, tools, outbound, approve=None):
            """tools: name to callable. outbound: the names of tools that send data out of the system.
            approve(tool, tainted, plain_args) -> bool is asked when a call would be refused."""
            raise NotImplementedError

        def call(self, name, **kwargs):
            """Run the tool on plain values and return its result as a Labeled from "tool:<name>". An outbound call with
            any argument computed from an untrusted source raises Refused, unless approve says yes. .calls lists the
            tools that ran, in order."""
            raise NotImplementedError

                stack.extend(item)
            elif isinstance(item, dict):
                stack.extend(item.values())

## Question

<Callout kind="interview" label="Coding, 45 minutes">
"Our agent's tool gateway should refuse any outbound call built from untrusted data, the way CaMeL does with capabilities, but as a library in our existing Python service. Write the labels, the propagation and the gateway check. The model that summarises web pages and mail is quarantined: it has no tools."
</Callout>

Every value the agent handles is a `Labeled`: the value and the frozenset of sources it was computed from. A source is `"user"` or `"tool:<name>"`, and only `"user"` is trusted. Plain constants written by the planner carry no sources. `derive` runs ordinary code on labelled values; `quarantine` asks the quarantined model about them. `Gateway.call` runs a tool on plain values and returns its result labelled with the tool; a call to an outbound tool with any argument computed from an untrusted source raises `Refused`, unless the optional `approve` callback says yes after seeing the plain arguments.

Two rules are yours to decide and defend: whether a tool's result also carries the sources of its arguments, and what a refusal tells the caller. The tests check properties, not one output. The hidden tests include laundering through a summary and through a yes-or-no answer, values nested in containers, and values built by reusing earlier values many times over; a check that walks a value's history every time is too slow for them.

## Answer

The labels are computed once, when a value is made: `derive` and `quarantine` union the sources of everything they read, so checking a value costs the size of its source set, not the size of its history. A design that stores parents and walks them at check time fails twice in the hidden tests: a value reused twice per step for 60 steps has 2<sup>60</sup> paths through its history, and a chain of 200,000 derivations exceeds Python's recursion limit. `sources_of` uses an explicit stack, so a list of 200,000 labelled rows is one pass.

            found |= item.sources
        elif isinstance(item, (list, tuple)):

        elif isinstance(item, dict):

    if isinstance(x, dict):

    return x

**Laundering.** The tempting mistake is to treat the quarantined model as a new origin and label its answer `"tool:quarantine"` or, worse, trusted. A summary of an untrusted page is a function of the page; so is a yes-or-no answer about it, and so is a string the planner's code picks based on that answer. CaMeL records exactly this: a value depends on the values it was computed from, including through the quarantined model. The hidden tests send each of these to `send_email` and expect a refusal.

**The two decisions.** This solution labels a tool's result with the tool only. Adding the arguments' sources is also defensible and stricter: a search run on an attacker's query returns results the attacker chose. Its cost is that more values become untrusted and more calls need approval. The refusal names the tool and the tainted argument names, and the approver sees the plain arguments, because a person asked "allow send_email?" without the recipient and body is approving blind.

**Constraint conflict.** Treating every tool result as untrusted refuses benign flows: "email me a summary of my inbox" is refused, because the inbox is `"tool:read_inbox"`. That is the utility cost CaMeL reports as 77 against 84 percent of AgentDojo tasks. The alternatives are a second label for private data with a policy per tool (inbox data may go to the user's own address), or approval prompts, which trade refusals for fatigue.

**Where this design fails.** A library cannot stop code from reading `.value` and building a plain string; the label is gone and the gateway sees a constant. Python control flow leaks too: `if flag.value == "yes": body = "Call me"` makes `body` depend on the page with no label to show it. CaMeL runs the plan in its own interpreter for both reasons, and tracks control-flow dependencies in its strict mode. Labels also say nothing about text-only attacks: a summary that misleads the user is correctly labelled and still misleads.

## Follow-ups

- *Pushback: the product team says the refusal rate on the beta is high enough that users disable the assistant. Which refusals do you turn into approvals, which into per-tool policies, and what do you accept in writing?*
- *Reversal: what would you need to see in production logs to stop treating results of your own internal search tool as untrusted?*
- *Two senior engineers disagree: one wants results to carry their arguments' sources, the other says it makes everything untrusted within three steps. How do you decide without deciding by rank?*
- *What changes to run this in a real agent client?* The plan has to execute in an interpreter you control rather than as Python the model wrote; labels must cross the process boundary to MCP servers, so tool results are labelled at the gateway that calls them; and approvals need a user interface that shows plain arguments and their sources.

## Common mistakes

- Labelling the quarantined model's output with a fresh source, which launders everything it read.
- Storing parents and walking them per check, which is exponential when values are reused.
- Checking only top-level arguments, so an untrusted value inside a list or dict goes out.
- Defining `__str__` to return the value, so any f-string turns a labelled value into an unlabelled one.
