    import base64
    import binascii
    import re


    class CanaryScanner:
        def __init__(self, canaries):
            """canaries: the canary strings seeded into prompts and documents, such as
            "cnry-7f3a9c2e1b4d", one per tenant; there can be tens of thousands."""
            raise NotImplementedError

        def scan(self, output):
            """Return the set of canaries that leak in output, in any of these forms:
            - as written, with case changed, or with non-alphanumeric characters inserted
              (spaces, dashes, dots, newlines, zero-width spaces);
            - reversed;
            - split into two pieces, in order, with other text between them, each piece at
              least 6 letters or digits long once separators are dropped;
            - inside base64 (standard or URL-safe, padded or not) or hex of text that
              contains the canary in one of the forms above.
            A single fragment is not a leak. Return an empty set when nothing leaks."""
            raise NotImplementedError

  solution: |
    import base64
    import binascii
    import re

    MIN_PIECE = 6
    _B64_RUN = re.compile(r"[A-Za-z0-9+/_-]{16,}={0,2}")
    _HEX_RUN = re.compile(r"[0-9A-Fa-f]{16,}")


    def _norm(s):
        return "".join(ch for ch in s.lower() if ch.isalnum())


    class CanaryScanner:
        def __init__(self, canaries):
            # Every split of every canary into a head and a tail of at least MIN_PIECE characters.
            # A whole copy is the split where the tail starts right after the head.
            self.heads = {}
            self.tails = {}
            self.lengths = set()
            for c in canaries:
                t = _norm(c)
                if len(t) < 2 * MIN_PIECE:
                    raise ValueError("canary too short to split safely: " + c)
                for k in range(MIN_PIECE, len(t) - MIN_PIECE + 1):
                    self.heads.setdefault(t[:k], []).append((c, k))
                    self.tails.setdefault(t[k:], []).append((c, k))
                    self.lengths.update((k, len(t) - k))

        def _views(self, output):
            yield output
            for run in _B64_RUN.findall(output):
                body = run.rstrip("=").replace("-", "+").replace("_", "/")
                for skip in range(4):
                    part = body[skip:]
                    if len(part) % 4 == 1:
                        part = part[:-1]
                    try:
                        yield base64.b64decode(part + "=" * (-len(part) % 4)).decode("utf-8", "ignore")
                    except (binascii.Error, ValueError):
                        pass
            for run in _HEX_RUN.findall(output):
                for skip in range(2):
                    part = run[skip:]
                    part = part[: len(part) - len(part) % 2]
                    yield bytes.fromhex(part).decode("utf-8", "ignore")

        def _scan_text(self, text, found):
            n = len(text)
            first_head_end = {}
            tail_starts = []
            for length in self.lengths:
                for i in range(n - length + 1):
                    piece = text[i:i + length]
                    for key in self.heads.get(piece, ()):
                        if first_head_end.get(key, n + 1) > i + length:
                            first_head_end[key] = i + length
                    hits = self.tails.get(piece)
                    if hits:
                        tail_starts.append((i, hits))
            for start, hits in tail_starts:
                for key in hits:
                    if first_head_end.get(key, n + 1) <= start:
                        found.add(key[0])

        def scan(self, output):
            found = set()
            for view in self._views(output):
                t = _norm(view)
                self._scan_text(t, found)
                self._scan_text(t[::-1], found)
            return found

## Question

<Callout kind="interview" label="Coding, adapted from a public question list">
Every tenant's system prompt and private documents carry a canary such as <code>cnry-7f3a9c2e1b4d</code>. Write <code>CanaryScanner(canaries)</code> with a method <code>scan(output)</code> that returns the set of canaries leaked in one output, including copies the model has lightly disguised: case changed, separators inserted, reversed, split in two, or encoded as base64 or hex. A single fragment of a canary is not a leak.
</Callout>

The scanner runs on every response before it is shown and over stored transcripts at night, with one canary per tenant: plan for 20,000 canaries and outputs of about 200 KB. The docstring lists the forms the tests check. Two things are yours to decide and defend: whether to catch copies split into three or more pieces, and whether to accept pieces shorter than 6 characters. Each one buys recall and costs false alarms or time.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask how the canaries are generated: their length, their alphabet, and which part is the same for every tenant.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Measure how long your first version takes with 20,000 canaries before you optimise anything, and ask which loop multiplies by the canary count.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Ask the team that reads the alerts how many false alarms a week they will act on, and what a false alarm costs them.</p></details>

## Answer

The reference solution makes one comparison do the work of four. Both sides are normalised to lower-case letters and digits, which collapses case changes and every inserted separator, zero-width spaces included. A whole copy is then the special case of a split copy in which the second piece starts right after the first, so the scanner only looks for splits: for every canary and every split point that leaves two pieces of at least 6 characters, it indexes the head and the tail in two dictionaries.

```python
for k in range(MIN_PIECE, len(t) - MIN_PIECE + 1):
    self.heads.setdefault(t[:k], []).append((c, k))
    self.tails.setdefault(t[k:], []).append((c, k))
```

`scan` builds the views of the output (the text itself, then the decoding of every long base64 or hex run, trying each alignment because a run cut from the middle of an encoding starts off its 4-byte or 2-byte boundary), normalises each view, and walks it once forwards and once reversed. At each position it slices the window lengths that occur among the pieces (6 to 10 characters for this canary format) and looks each slice up in the two dictionaries. A canary leaks when one of its tails starts at or after the earliest end of the matching head. The cost is a few dictionary lookups per character of output, independent of how many canaries there are; the hidden tests time 20,000 canaries over about 200 KB.

The version most people write first loops over the canaries and calls `find` for each split point. It is correct and passes every form test, and it is slow: each canary rescans every view of the output once per split point. On the hidden timing case it took about 14 seconds in local CPython, where the indexed version took under half a second. Building an index over the canaries is the step that removes the canary count from the scan.

The choice of 6 as the shortest piece matters for false alarms. Every canary here starts with the same four letters, `cnry`, so a head of 6 characters carries only 2 random hex digits, and the tail carries the rest. Pieces that short are still safe only because the tail must be long and random. Accepting 4-character pieces would let `cnry` alone count as a head, and a tail of 12 hex digits elsewhere in a transcript full of commit hashes becomes a plausible accident. Catching three-piece splits multiplies the index by the number of ways to cut, and each extra cut makes the pieces shorter and the false alarms more likely; I would not add it until a red-team case shows a three-piece leak.

What this does not catch: a canary translated into words ("seven f three a"), encoded in base32 or rot13, spread across separate responses, or summarised. A canary is a detector for the leaks you anticipated. It raises an alarm; it does not stop the text from reaching the user unless the response is held until the scan finishes, and the stronger control is keeping the tenant's secrets out of the model's context in the first place.

## Follow-ups

- *The gateway streams tokens to the user. What changes to run this scanner on the stream, and what does it cost in latency?* Keep the last few normalised characters of the previous chunk so a canary that straddles a chunk boundary is still seen, buffer base64 and hex runs until they end, and decide whether to hold output until the scan clears or to scan behind the stream and alert after the fact.
- *A tenant asks you to rotate their canary weekly. What happens to the index, and to the nightly scan of old transcripts?*
- *Security wants three-piece splits caught. What do you measure on a week of real transcripts before agreeing?*

## Common mistakes

- Matching the raw string, so any case or spacing change slips past.
- Scanning once per canary, which is correct and too slow once canaries are per tenant.
- Decoding base64 from the start of each run only, which misses an encoded canary when the run was cut mid-block.
- Firing on a single fragment, which floods the alert channel with matches on commit hashes and ids.
