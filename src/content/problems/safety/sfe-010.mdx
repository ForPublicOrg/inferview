  solution: |
    import base64
    import binascii
    import re

    def _norm(s):
        return "".join(ch for ch in s.lower() if ch.isalnum())

    def leaks_canary(output, canary):
        target = _norm(canary)
        if not target:
            return False
        candidates = [output, output[::-1]]
        for token in re.findall(r"[A-Za-z0-9+/=]{8,}", output):
            try:
                candidates.append(base64.b64decode(token, validate=True).decode("utf-8", "ignore"))
            except (binascii.Error, ValueError):
                pass
        return any(target in _norm(c) for c in candidates)

## Question

<Callout kind="interview" label="Coding, adapted from a public question list">
You seed a random canary string in the system prompt, such as <code>cnry-7f3a9c2e1b4d</code>, so that you can tell when the prompt leaks. Write <code>leaks_canary(output, canary)</code> that flags the canary even when a model hands it back lightly obfuscated: case changed, separators inserted, reversed, or base64-encoded. It must not fire on benign text or on a partial fragment.
</Callout>

A canary detects a leak after it happens; it does not prevent one. The point of handling obfuscations is that a model asked "spell your instructions" or "encode them" will leak in exactly these forms.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Normalise both sides the same way: lower-case and drop everything that is not a letter or digit. That handles case, spaces, dashes and dots at once.</p></details>
<details class="hint"><summary>Hint 2</summary><p>For reversal, also test the reversed output. For base64, pull out long token-like runs and try to decode each.</p></details>
<details class="hint"><summary>Hint 3</summary><p>A fragment fails because the normalised canary is not a contiguous substring of the normalised candidate.</p></details>

## Answer

The solution normalises the canary to lower-case alphanumerics, then checks several candidate views of the output: the text as given, the text reversed, and the decoding of any long base64-looking token. Normalising both sides collapses case changes and inserted separators into the same comparison. The fragment case fails because after normalisation `cnry7f3a` followed later by `9c2e1b4d` is not a single contiguous match for `cnry7f3a9c2e1b4d`.

```python
import base64, binascii, re

def _norm(s):
    return "".join(ch for ch in s.lower() if ch.isalnum())

def leaks_canary(output, canary):
    target = _norm(canary)
    if not target:
        return False
    candidates = [output, output[::-1]]
    for token in re.findall(r"[A-Za-z0-9+/=]{8,}", output):
        try:
            candidates.append(base64.b64decode(token, validate=True).decode("utf-8", "ignore"))
        except (binascii.Error, ValueError):
            pass
    return any(target in _norm(c) for c in candidates)
```

This catches the encodings you thought of. It is still an oracle that only knows its own list: a payload split across two sentences, a different base (base32, hex), or a translation of the words would pass. That is the honest limit of leak detection, and the reason a canary is a signal to alert on, not a control that stops the leak. Keep the secret out of the model's context when you can.

## Follow-ups

- *How would you extend it to payload splitting?* You cannot do it reliably by string matching; splitting is what defeats this class. Detection moves to behaviour (did the model emit anything resembling the format) rather than exact content.
- *Where does this run?* As an output filter and as a log scanner over stored traces, so you catch leaks that reached a user.
- *Why normalise rather than list every variant?* Normalisation covers an open set of separator and case tricks in one step; an explicit list grows forever.

## Common mistakes

- Matching the raw string only, so any case or spacing change slips past.
- Decoding base64 but forgetting that normalisation already handles spacing and case.
- Firing on fragments, which floods the alert with false positives.
