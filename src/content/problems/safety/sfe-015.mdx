## Question

<Callout kind="interview" label="As an interview question list phrases it">
"Your LLM does not admit when it does not know the answer. How do you make it say 'I don't know'?"
</Callout>

Use the scoring rule from Kalai and colleagues: a correct answer scores 1, "I don't know" scores 0, and a wrong answer costs t/(1-t) points. If a wrong answer in your product costs three times as much as a right answer is worth, above what confidence (as a percentage) should the model answer rather than abstain? Enter the percentage, then read the method.

## Hints

<details class="hint"><summary>Hint 1</summary><p>The penalty for a wrong answer is set to t/(1-t). If that equals 3, solve for t.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Answering beats abstaining exactly when the model's chance of being right exceeds t.</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>Set t/(1-t) = 3, so t = 0.75: answer only above 75% confidence. The deeper point is that a model guesses because accuracy-only grading rewards it; "I don't know" scores the same as a wrong answer, so a guess is never worse. You change that by penalising wrong answers (in the eval and, where you can, in training), getting a confidence signal, and checking that the signal is calibrated before you set a threshold on it.</p>
</Fragment>
<Fragment slot="long">
<p>The calculation. Expected score of answering is p - (1 - p) × t/(1-t), where p is the chance the answer is right. Break-even is where that equals 0, which simplifies to p = t. A three-times penalty means t/(1-t) = 3, so t = 0.75. Check: at p = 0.75, score = 0.75 - 0.25 × 3 = 0. Above 75% confidence, answering has positive expected value; below it, abstaining wins.</p>
<p>Why the model does not abstain by default. Kalai and colleagues argue that benchmarks score right or wrong and give abstention the same zero as a wrong answer, so optimising the score means never leaving a question blank. The fix is to change the scoring: penalise wrong answers in your eval, and prompt the grader and the model with the rule.</p>
<p>Getting a confidence signal. Options: the model's own stated confidence, agreement across several samples, a verifier model's score, or retrieval coverage (did we even find a source). Each needs calibration: bucket answers by stated confidence and check that, say, the 0.8 bucket is right about 80% of the time on your data. If the model says 0.9 and is right half the time, no threshold works until you recalibrate.</p>
<p>Product wiring. Set the penalty per route from the real cost of a wrong answer, raise the threshold where mistakes are expensive, and give "I don't know" a useful next step: a source link, a form, or a handoff. Track coverage (share answered) alongside accuracy, because a high threshold trades coverage for safety.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>What if confidences are not calibrated?</em> The threshold is meaningless; calibrate first using labelled data, or use sample agreement as the signal instead.</li>
<li><em>How does this interact with RAG?</em> Treat empty or contradictory retrieval as low confidence and abstain or escalate.</li>
<li><em>Does telling the model "say I don't know if unsure" in the prompt work?</em> Weakly and inconsistently; it has no cost signal behind it. The scoring change and a real confidence signal are what move behaviour.</li>
</ul>
</Fragment>
</Depth>

## Follow-ups

- *Your PM wants maximum coverage. How do you argue for abstention?* Show the error rate at full coverage versus a threshold, in the cost units of the domain, and let them pick the point for the low-stakes routes while policy fixes the high-stakes ones.
- *How would you measure improvement?* Error rate and coverage per route, before and after, not a single accuracy number.

## Common mistakes

- Setting a threshold on confidences that were never checked for calibration.
- Believing a prompt instruction alone makes a model abstain.
- Reporting accuracy without coverage, hiding how much was refused.
