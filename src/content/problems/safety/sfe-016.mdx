## Question

<Callout kind="interview" label="Debug round">
A RAG assistant retrieves the correct passage, you can see it in the logged context, and the answer still states something the passage does not say. Retrieval is working. Find the cause and fix it.
</Callout>

The logged context for a failing question holds, in order: two older chunks that describe a previous version of the policy, then the current chunk with the right answer near the end, close to where the context is truncated. The prompt is "Answer the user's question using your knowledge and the context below." There is no citation requirement.

## Hints

<details class="hint"><summary>Hint 1</summary><p>The right chunk is present. What else is present, and what does the prompt tell the model to do when sources disagree?</p></details>
<details class="hint"><summary>Hint 2</summary><p>"Using your knowledge and the context" lets the model fall back on training data. Is that what you want here?</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>This is a grounding failure, not a retrieval failure. The context contains the right chunk and two conflicting older ones, the current chunk sits near the truncation edge where it gets less weight, and the prompt invites the model to use its own knowledge and never tells it to answer only from the sources, cite, or abstain when they conflict. Fix the prompt to require grounding and citation, handle conflicts (prefer the newest, or surface the disagreement), order the strongest chunk where it is not truncated, and verify that cited spans actually support each claim.</p>
</Fragment>
<Fragment slot="long">
<p>Diagnosis. Retrieval did its job, so the bug is in how the context is used. Three things combine: conflicting chunks (old and new policy) with nothing telling the model which wins; the correct chunk near the truncation boundary, so part of it may be cut and the rest carries less weight; and a prompt that says "using your knowledge and the context", which licenses the model to answer from training data that predates the policy change. A system with retrieval can still contradict its own context, which is why this failure needs its own check.</p>
<p>Fix, in layers. Prompt: "Answer only from the context below. If the context does not contain the answer, say you do not know. If sources conflict, prefer the most recent and note the conflict." Require a citation for each claim. Conflict handling: deduplicate and prefer the current version at retrieval time, by filtering on an effective-date field rather than hoping the model sorts it out. Placement and budget: put the highest-ranked chunk where it will not be truncated, and size the context so the answer-bearing chunk is never cut. Verification: if you use a citation feature, remember it guarantees a valid pointer into the documents, not that the cited span supports the sentence, so run a support check (a classifier or judge reading claim and span together).</p>
<p>What not to do: lowering temperature makes the wrong answer repeatable, and adding more retrieved chunks adds more conflicting material.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>How do you catch this in evals?</em> A faithfulness metric that checks each claim against the retrieved context, plus cases with deliberately conflicting chunks.</li>
<li><em>The two policies are both current for different regions. Now what?</em> Retrieve with the user's region as a filter so only the applicable policy is in context.</li>
<li><em>A citation is attached but the claim is still wrong. How?</em> The pointer is valid and the span does not support the claim; that is why support must be checked separately.</li>
</ul>
</Fragment>

## Follow-ups

- *Would a bigger model fix it?* It may blend sources less, but without a grounding instruction and conflict handling the same failure remains.
- *How do you measure the fix?* Faithfulness and the rate of "I don't know" on questions the context cannot answer, before and after.

## Common mistakes

- Chasing retrieval quality when the right chunk was already retrieved.
- Trusting a citation as proof the claim is supported.
- Letting the prompt invite the model's own knowledge in a grounded system.
- Stuffing more chunks in, adding conflicts near the truncation edge.
