## Question

<Callout kind="interview" label="Critique, 30 minutes">
"On Friday afternoon someone added one line to the support assistant's system prompt. On Monday escalations to human agents were up. Here is the release process we wrote in June; it was reviewed and approved. Tell me everything wrong with it."
</Callout>

The document and the numbers in it are constructed for this problem.

```text
Support assistant: prompt release process, v3 (approved 2026-06-02)

Registry
  Prompts live in Langfuse Cloud (Core plan). Every save creates an immutable version; the app fetches
  the version labelled production. Prompts are also mirrored in the prompts/ directory of the monorepo;
  a nightly job pushes repo changes to Langfuse and opens a pull request for edits made in the UI.
  Everyone on the support-ai project has the member role, so PMs can iterate without waiting on engineers.

Testing
  A pull request to prompts/ runs the regression suite:
    golden set    120 conversations sampled in January 2025 from tickets marked resolved
    judge         the assistant's own model, one sample per conversation, scores helpfulness 1 to 5
    gate          mean judge score >= 4.0 (current production version scores 4.31)
  Prompt edits made in the Langfuse UI are covered by the same suite through the nightly pull request.

Release
  Moving the production label is the release; it takes effect for all traffic at once.
  The SDK is configured with cache_ttl_seconds=3600 to keep Langfuse off the request path.
  Prompt changes and model upgrades go out together in the monthly release when both are ready.
  Fallback: a copy of the prompt text is bundled in the container image for when Langfuse is unreachable.

Monitoring
  Escalation rate, CSAT and handle time are reviewed in the Monday support-ops meeting.
  Traces are sent to Langfuse with the conversation id and the model name.

Rollback
  Move the production label back to the previous version.
```

Friday's change was made in the Langfuse UI at 16:40 and labelled production at 16:52. It added one line: "Do not promise refunds; refer refund questions to the billing policy page." Monday's meeting saw the escalation rate at 15% for the weekend against 11% the weekend before (scenario numbers). List every flaw you can find, rank them by how much each contributed to Monday, and say what you would change first. Then open the checklist.

<details class="hint"><summary>Hint 2</summary><p>Ask how many of the 120 golden conversations involve refunds, and what the suite's mean would be if every one of them scored 2.</p></details>

## Answer

**How the edit reached production.** The edit was made in the UI and labelled production twelve minutes later. The suite runs on pull requests, and UI edits reach a pull request only when the nightly sync opens one, which is after the label moved. The process has two writers, the UI and the repo, and the gate sits on one of them. Every member can move the production label, and protected labels, which stop the member role from moving it, are not available on the Core plan. This is the first-ranked flaw: nothing measured Friday's version before customers saw it.

**Why the suite would have passed it anyway.** Suppose the sync had run first. Say 6 of the 120 golden conversations are refund questions (the hint asks for the real count; this is an assumption) and each falls from 4.5 to 2.0 under the new line. The mean falls by 6 × 2.5 / 120 = 0.125, from 4.31 to 4.19, which clears 4.0. An absolute bar on the mean admits any regression that is concentrated in a slice smaller than the margin allows. Two changes fix different halves: a paired comparison against the current production version on the same conversations, which reports the per-conversation losses, and per-slice minimums for the slices the business cares about (refunds, cancellations, outages).

**Why the golden set cannot see escalations.** It was sampled from tickets marked resolved, so a conversation that ended in an escalation is not in it by construction, and the property that regressed on Monday is the one the set excludes. It is also 21 months old. Add escalated conversations, sampled by reason, and refresh on a schedule.

**The judge.** It is the assistant's own model with one sample per conversation, scoring helpfulness. Nobody has measured its agreement with human labels, and a refusal to promise a refund, politely worded, can score as helpful. A judge in the gate is acceptable if its true and false positive rates against human labels are measured and rechecked when either model changes; without that, the 4.31 is a number without an error bar.

**Rollback that takes an hour.** The SDK caches for 3,600 seconds instead of the default 60, and serves the stale prompt while it revalidates. Moving the label back on Monday changes what the API returns at once and what each process serves only when its cache entry expires, so the last process can serve Friday's version for up to an hour. This is the flaw a reviewer misses because the line reads as a performance setting.

**Monitoring that waits for Monday.** Escalation rate is a weekly meeting item and has no alert, and traces carry the model name but not the prompt version. Langfuse aggregates latency, tokens, cost and scores per prompt version only when generations are linked to the prompt. Without the link, Monday's rise cannot be attributed to Friday's version from the traces; someone has to line up timestamps by hand.

**Smaller flaws.** Prompt and model changes ship together "when both are ready", so a regression in a monthly release has two candidate causes. The bundled fallback is a copy made at image build time and drifts from the registry. The production label moves for all traffic at once; a second label served to a hashed slice of conversations would have exposed the change to a fraction of customers first.

**The ranking.** First the ungated UI path, because it let an unmeasured version ship; second the mean threshold and the resolved-only golden set, because together they would have passed it; third the missing per-version escalation alert, because it turned an hour of exposure into a weekend. The cache TTL ranks fourth for Monday, but it would have dominated if anyone had noticed on Friday evening.

**What to change first, with two defensible answers.** One answer: make the repo the only writer, have a release job move the production label after the paired suite passes, and buy protected labels so members cannot bypass it. The cost is the PMs' iteration speed and a plan upgrade. The other: keep UI editing, but have the app read a label that only the release job moves (say `released`) while PMs move `production` freely in a sandbox project. The cost is a naming convention someone will break. The first is stronger; the second can ship this week.

**How the fix fails.** A paired suite with slice minimums will start blocking releases on slices of three or four conversations, where one judge disagreement flips the result. Within a month someone lowers the minimums or adds a skip flag. Set slice sizes before the thresholds: a slice too small to measure is a slice the gate should report, not block on.

## Follow-ups

- *Pushback: the PMs say the gate will turn a ten-minute prompt fix into a two-day release, and they own customer outcomes. Which edits do you let through without the paired suite, and what do you write down about the risk you accept?*
- *Reversal: what would you need to see after six months to drop the per-slice minimums and go back to a single threshold?* For example, no slice regression caught by the minimums that the paired comparison did not also flag.
- *Operating: the model behind the assistant is retired in sixty days and 9 of 30 prompts regress on the new one. Which ship degraded, and who signs off?*

## Common mistakes

- Proposing a better test suite without noticing that Friday's edit never went through the suite.
- Accepting the 4.0 bar because production scores 4.31, without asking how much a slice can fall before the mean notices.
- Treating rollback as instant because the label move is instant.
- Blaming the line itself; the line may be the right policy, and the process gave nobody the evidence to decide.
