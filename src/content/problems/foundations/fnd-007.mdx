  solution: |
    import math

    def softmax(logits, temperature=1.0):
        if temperature <= 0:
            raise ValueError("temperature must be positive; use argmax for greedy decoding")
        scaled = {t: v / temperature for t, v in logits.items()}
        m = max(scaled.values())
        exps = {t: math.exp(v - m) for t, v in scaled.items()}
        z = sum(exps.values())
        return {t: e / z for t, e in exps.items()}

    def top_p_filter(probs, p):
        ranked = sorted(probs.items(), key=lambda kv: (-kv[1], kv[0]))
        kept, total = [], 0.0
        for token, q in ranked:
            kept.append((token, q))
            total += q
            if total >= p:
                break
        z = sum(q for _, q in kept)
        return {t: q / z for t, q in kept}

    def sample(probs, r):
        ranked = sorted(probs.items(), key=lambda kv: (-kv[1], kv[0]))
        acc = 0.0
        for token, q in ranked:
            acc += q
            if r < acc:
                return token
        return ranked[-1][0]

## Question

<Callout kind="interview" label="The round, as candidate reports describe it">
Implement top-p (nucleus) sampling, and explain how it differs from top-k. Reported from onsite rounds in NumPy; here in plain Python so it runs in your browser.
</Callout>

Logits arrive as a dictionary from token to score. Write three functions.

- `softmax(logits, temperature=1.0)` returns probabilities. It must not overflow on large logits and must raise `ValueError` for a temperature of 0 or below (greedy decoding is an argmax, not a softmax).
- `top_p_filter(probs, p)` sorts tokens by probability, highest first (ties by token string), keeps the smallest prefix whose cumulative probability is at least `p`, and renormalises the kept tokens so they sum to 1.
- `sample(probs, r)` takes a number `r` in [0, 1) instead of calling a random generator, walks the tokens from most to least likely, and returns the first token where the running total exceeds `r`. Passing `r` in makes the function testable; in production it comes from a seeded generator.

The boundary convention is stated above. If you are asked this live, state yours: some libraries keep the token that crosses p, others drop it.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Divide logits by the temperature, then subtract the maximum before `math.exp`.</p></details>
<details class="hint"><summary>Hint 2</summary><p>In `top_p_filter`, add the token first and then check whether the running total has reached p, so the top token is always kept.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Guard `sample` against floating-point round-off: if the loop ends without returning, return the last token.</p></details>

## Answer

The reference solution scales by temperature, subtracts the max, exponentiates and normalises. `top_p_filter` sorts by descending probability (ties by token), appends tokens until the running sum reaches p, and divides each kept probability by the kept total. `sample` walks the same order and returns the token where the running sum first exceeds r.

On the test logits at temperature 2.0 the probabilities are Paris 0.549, Lyon 0.202, Nice 0.157, "the" 0.074 and banana 0.017. Paris plus Lyon is 0.752, below 0.9; adding Nice gives 0.909, so the nucleus is those three, and after renormalising Paris is 0.549 / 0.909 = 0.604.

Top-k versus top-p, the explanation half of the question: top-k keeps a fixed number of tokens whatever the distribution looks like, so it admits unlikely tokens when the model is confident and cuts good options when it is not. Top-p keeps a variable number, sized by how spread out the distribution is. Min-p, a later variant, keeps tokens above a fraction of the top token's probability.

## Follow-ups

- *Where does temperature go relative to top-p?* Usually before, because top-p works on probabilities. Libraries differ, so name the order you use.
- *How do you make it fast over a 200,000-token vocabulary?* Partial sort: take the top few hundred with a heap or `argpartition` first, since the nucleus is usually small.
- *Does temperature 0 make the output deterministic?* Not on a busy server. Problem fnd-008 covers why.

## Common mistakes

- Checking the threshold before adding the token, which can return an empty set when the top token alone exceeds p.
- Forgetting to renormalise, so the sampler's running total never reaches 1.
- Sorting ascending and keeping the tail.
- Handling temperature 0 by dividing by zero instead of switching to argmax.
