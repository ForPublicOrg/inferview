  solution: |
    import bisect, math

    def softmax(logits, temperature=1.0):
        z = {t: v / temperature for t, v in logits.items()}
        m = max(z.values())
        e = {t: math.exp(v - m) for t, v in z.items()}
        s = sum(e.values())
        return {t: v / s for t, v in e.items()}

    def _ranked(probs):
        # Policy: ties broken by token string, so the kept set is reproducible.
        return sorted(probs.items(), key=lambda kv: (-kv[1], kv[0]))

    def _renorm(items):
        s = sum(q for _, q in items)
        return {t: q / s for t, q in items}

    def top_p_filter(probs, p):
        kept, mass = [], 0.0
        for t, q in _ranked(probs):
            kept.append((t, q))
            mass += q
            if mass >= p:
                break
        return _renorm(kept)

    def min_p_filter(probs, p_base):
        cut = p_base * max(probs.values())
        return _renorm([(t, q) for t, q in probs.items() if q >= cut])

    def make_sampler(probs):
        ranked = _ranked(probs)
        tokens = [t for t, _ in ranked]
        cdf, acc = [], 0.0
        for _, q in ranked:
            acc += q
            cdf.append(acc)
        last = len(tokens) - 1

        def draw(r):
            i = bisect.bisect_right(cdf, r * acc)
            return tokens[min(i, last)]

        return draw

## Question

<Callout kind="interview" label="The round, as candidate reports describe it">
Candidate reports describe onsite rounds that ask for top-p sampling and its difference from top-k. This version adds min-p and a draw that has to stay fast; it runs in plain Python in the browser.
</Callout>

Probabilities arrive as a dictionary from token to probability (the `softmax` helper is given). Write three functions.

- `top_p_filter(probs, p)` keeps the smallest set of most likely tokens whose total probability reaches `p`, and renormalises it.
- `min_p_filter(probs, p_base)` keeps every token whose probability is at least `p_base` times the largest probability, and renormalises.
- `make_sampler(probs)` returns a function `draw(r)` that maps a uniform `r` in [0, 1) to a token by walking the distribution's cumulative probabilities, most likely token first. `r` is a parameter so tests can pin it; in production it comes from a seeded generator.

`make_sampler` will be built once and called many times on distributions with tens of thousands of tokens, and the tests time it. How you break ties between equal probabilities is your decision; make it deterministic and say what it is.

## Answer

The reference solution ranks tokens by descending probability with ties broken by token string. `top_p_filter` appends tokens and their probabilities until the running mass reaches p, checking after appending so the top token always survives; then it divides each kept probability by the kept mass. `min_p_filter` computes the cutoff from the maximum and keeps everything at or above it. `make_sampler` builds the ranked token list and its cumulative sums once, and each draw is a binary search for `r` scaled by the final cumulative value, clamped to the last index so round-off cannot run off the end.

The hidden tests check properties rather than outputs, so any tie-break passes. Top-p's kept set must be a top set (no dropped token more likely than a kept one), must reach p, and must be minimal (removing its least likely member drops it below p). Min-p must keep exactly the tokens at or above the cutoff. Both must preserve probability ratios among kept tokens. Top-p must keep at least as many tokens as temperature rises, which follows from softmax: raising the temperature lowers the ratio of every more likely token to every less likely one, so the mass of any top set falls. And draws over an evenly spaced grid of r must reproduce the probabilities.

The performance test is 20,000 draws over 50,000 tokens. A draw that walks the ranked list costs on average half the vocabulary per call, roughly 20,000 x 25,000 = 500 million steps, far over the budget; the binary search costs about 16 comparisons per draw after one sort.

The test distributions are worth working by hand once. On the peaked one at temperature 2, the running mass is 0.577, 0.742, 0.859 and 0.906, so top-p 0.9 keeps four tokens; min-p 0.1 cuts at 0.058 and keeps three. On the flat one at temperature 1, top-p 0.9 needs six verbs (0.949) and min-p 0.1 keeps seven because its cutoff is 0.021.

## Common mistakes

- Checking the mass before appending the token, which returns an empty set when the top token alone exceeds p.
- Forgetting to renormalise, so draws never reach the tail of the kept set.
- Computing the min-p cutoff from the renormalised top-p output instead of the input distribution when both are applied, without saying so.
- Building the cumulative sums inside `draw`, which passes small tests and fails the timed one.
