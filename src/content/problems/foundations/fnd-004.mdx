  solution: |
    import math

    def softmax_row(row):
        m = max(row)
        if m == float("-inf"):            # every key masked: no valid weights
            return [0.0] * len(row)
        exps = [math.exp(x - m) for x in row]
        total = sum(exps)
        return [e / total for e in exps]

    def attention(Q, K, V, causal=True, key_mask=None):
        d_k = len(K[0])
        scale = 1 / math.sqrt(d_k)
        weights = []
        for i, q in enumerate(Q):
            row = []
            for j, k in enumerate(K):
                blocked = (causal and j > i) or (key_mask is not None and not key_mask[j])
                row.append(float("-inf") if blocked else sum(a * b for a, b in zip(q, k)) * scale)
            weights.append(softmax_row(row))
        d_v = len(V[0])
        out = [[sum(w[j] * V[j][c] for j in range(len(V))) for c in range(d_v)] for w in weights]
        return out, weights

## Question

<Callout kind="interview" label="The round, as a candidate report describes it">
Implement attention yourself: masks, a numerically stable softmax, the scaling, and then talk about its complexity.
</Callout>

Implement single-head scaled dot-product attention in plain Python (no NumPy; the tests run in your browser).

- `attention(Q, K, V, causal=True, key_mask=None)` returns `(output, weights)`.
- Scores are the dot product of each query row with each key row, divided by the square root of the key dimension.
- With `causal=True`, query i may only attend to keys 0 to i.
- `key_mask` is an optional list of booleans, one per key; `False` marks a padding key that no query may attend to.
- Softmax must not overflow on large scores.
- A query whose every key is masked gets a row of zero weights and a zero output vector, not NaN.

Then say what the time and memory cost is for n tokens of dimension d.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Use minus infinity for blocked positions; `math.exp(float("-inf"))` is 0.0.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Subtract the row maximum before exponentiating; softmax is unchanged by a constant shift.</p></details>
<details class="hint"><summary>Hint 3</summary><p>If the row maximum is itself minus infinity, every key is blocked: return zeros before you divide by a zero sum.</p></details>

## Answer

The reference solution builds one row of scores per query. A key is blocked when it is in the future (`causal and j > i`) or marked as padding; blocked scores are minus infinity and open ones are the dot product times 1/√d_k. The row softmax subtracts the row maximum so `exp` never sees a large positive number, and short-circuits to zeros when the maximum is minus infinity, because minus infinity minus minus infinity is NaN. The output row is the weighted sum of the value rows.

On the test data, query 1 sees keys 0 and 1 with scaled scores 0 and 1/√2 ≈ 0.707, which softmax turns into 0.330 and 0.670. Query 0 sees only itself, so its weights are exactly [1, 0, 0].

Cost. The score matrix has n × n entries per head and each costs d multiplications, so time is O(n² d) per layer, and the naive version stores all n² scores. FlashAttention computes the same exact result in tiles without materialising the full matrix, so memory becomes linear in n while the arithmetic stays O(n² d). During generation with a KV cache, each new token costs O(n d) and the cache grows by one key and one value per layer per token.

## Follow-ups

- *Make it multi-head.* Split d_model into h slices, run this function per slice, concatenate the outputs and apply an output projection. With grouped-query attention, several query heads read the same key and value slice.
- *Why the 1/√d_k?* Dot products of unit-variance components have variance d_k, which saturates softmax. Problem fnd-003 covers it.
- *What changes at inference?* With a KV cache, the newest token's query attends to all cached keys, so the causal mask is implicit.

## Common mistakes

- Masking after the softmax by zeroing weights, which leaves rows that no longer sum to 1.
- Masking with a large negative number such as -1e9 and then failing the fully masked row, which comes out uniform instead of zero.
- Dividing by d_k instead of √d_k.
- Forgetting the max subtraction and overflowing on scores near 1,000.
