    def _rank_oracle(word, ranks):
        s = list(word) + ["</w>"]
        while True:
            found = [(ranks[(s[i], s[i + 1])], i) for i in range(len(s) - 1) if (s[i], s[i + 1]) in ranks]
            if not found:
                return s
            i = min(found)[1]
            s[i:i + 2] = [s[i] + s[i + 1]]

        while i < len(sym):

                out.append(sym[i] + sym[i + 1]); i += 2
            else:
                out.append(sym[i]); i += 1

  solution: |
    from collections import Counter, defaultdict

    END = "</w>"

    def _merge(symbols, pair, joined):
        out, i = [], 0
        while i < len(symbols):
            if i + 1 < len(symbols) and symbols[i] == pair[0] and symbols[i + 1] == pair[1]:
                out.append(joined)
                i += 2
            else:
                out.append(symbols[i])
                i += 1
        return tuple(out)

    def train_bpe(word_freqs, num_merges):
        words = [tuple(w) + (END,) for w in word_freqs]
        freqs = [word_freqs[w] for w in word_freqs]
        pairs = Counter()
        where = defaultdict(set)
        for idx, symbols in enumerate(words):
            for p in zip(symbols, symbols[1:]):
                pairs[p] += freqs[idx]
                where[p].add(idx)
        merges = []
        for _ in range(num_merges):
            live = [p for p, n in pairs.items() if n > 0]
            if not live:
                break
            best = min(live, key=lambda p: (-pairs[p], p))
            merges.append(best)
            joined = best[0] + best[1]
            for idx in list(where[best]):
                old = words[idx]
                new = _merge(old, best, joined)
                if new == old:
                    continue
                f = freqs[idx]
                for p in zip(old, old[1:]):
                    pairs[p] -= f
                    where[p].discard(idx)
                for p in zip(new, new[1:]):
                    pairs[p] += f
                    where[p].add(idx)
                words[idx] = new
        return merges

    def encode(word, ranks):
        symbols = list(word) + [END]
        while len(symbols) > 1:
            best, best_rank = -1, None
            for i in range(len(symbols) - 1):
                r = ranks.get((symbols[i], symbols[i + 1]))
                if r is not None and (best_rank is None or r < best_rank):
                    best, best_rank = i, r
            if best < 0:
                break
            symbols[best:best + 2] = [symbols[best] + symbols[best + 1]]
        return symbols

    def decode(tokens):
        text = "".join(tokens)
        if not text.endswith(END):
            raise ValueError("token sequence does not end a word")
        return text[: -len(END)]

## Question

<Callout kind="interview" label="Reported round">
A candidate report from a Glean software engineer technical screen describes this exercise: learn merges by repeatedly joining the most frequent adjacent pair, then turn text into tokens and back. The version below adds the constraint that separates a toy from an encoder you could ship.
</Callout>

Write three functions, standard library only.

`train_bpe(word_freqs, num_merges)` takes a dictionary from word to count, such as `{"low": 5, "lower": 2, "newest": 6, "widest": 3}`. Each word starts as its characters plus an end-of-word symbol `"</w>"`. Each round, count adjacent pairs weighted by word frequency, merge the most frequent pair everywhere, and record it. Stop after `num_merges` rounds or when no pair is left. You choose the tie-break, but the merges must not depend on the iteration order of `word_freqs`.

`encode(word, ranks)` receives `ranks`, a dictionary from merge pair to its position in the merge list. It starts from the characters plus `"</w>"` and repeatedly merges the adjacent pair with the lowest rank, leftmost on a tie, until no adjacent pair has a rank. `decode(tokens)` inverts it for one word.

The encoder runs against merge tables with tens of thousands of entries: 2,000 unseen words against 20,000 merges must finish inside 1.5 seconds in the browser. Hidden tests also check your merges and your encoder against properties, not against one canonical list.

## Answer

Training keeps each distinct word as a tuple of symbols with its frequency, counts pairs weighted by frequency, and picks `min(pairs, key=lambda p: (-count[p], p))`: highest count first, then the pair that sorts first. Sorting on the pair rather than relying on insertion order is what makes the result independent of how `word_freqs` was built. Two training runs that disagree on one tie produce vocabularies whose ids diverge from that point on, and every downstream artefact keyed by token id (embeddings, cached prompts, logit biases) becomes invalid.

The reference solution also keeps an index from each pair to the words containing it, so a merge rewrites only those words and adjusts their pair counts instead of recounting the corpus. On the toy dictionary that saves nothing; on a corpus with millions of distinct words and tens of thousands of merges it is the difference between a full corpus scan per merge and work proportional to the words each merge touches. Picking the best pair is still a scan over live pairs here; a production trainer keeps a heap with lazy deletion.

Encoding by rank looks up each adjacent pair in `ranks`, merges the lowest, and repeats. Each pass is linear in the current word length and there are at most that many passes, so the cost is quadratic in the word and independent of the table size. Replaying every merge in order gives the same output on ordinary tables but costs a pass per merge: 2,000 words against 20,000 merges is 40 million merge attempts, which no Python interpreter finishes in 1.5 seconds. Skipping merges whose symbols are absent from the word still visits all 20,000 entries per word.

On the toy dictionary, `e+s` and `s+t` tie at 9 (6 from newest plus 3 from widest). Either may come first, and the first three merges build `est</w>` both ways. "lowest" never appears in training but encodes as `low` and `est</w>`, built from learned pieces; characters never seen stay single symbols. Byte-level BPE removes even that case, because the base alphabet is the 256 byte values.

The failure mode of the rank encoder is that it is only equivalent to replay when every merged symbol has exactly one way to be built. If a table learns `a+bc` and later `ab+c`, the string `abc` exists by two paths, and a rank encoder can apply a pair whose rank is lower than the merge that created one of its symbols. tiktoken defines encoding as rank order, so rank order is the spec and replay is the approximation; the hidden tests compare against a rank-order oracle.

## Follow-ups

- *What changes to run this in a real client?* Bytes instead of characters as the base alphabet, a pre-tokenisation regex so merges never cross word or digit boundaries, special tokens that are only emitted when the caller allows them, and an encoder written in a compiled language with a cache for repeated words.
- *The merge table is 200,000 entries and the service is cold-started per request. What do you load, and when?* Loading and hashing the table dominates short requests; the options are a long-lived process, a memory-mapped table, or a precomputed perfect hash, each with its own deployment cost.
- *Your tie-break changed between two training runs on identical data. What breaks downstream, and how would you detect it before a model is trained on the new vocabulary?* A diff of the two merge lists from the first divergence, plus a check that a fixed probe set encodes to identical ids.

## Common mistakes

- Breaking ties with `max(pairs, key=pairs.get)`, which follows dictionary insertion order and makes the vocabulary depend on how the input was built.
- Counting each distinct word once instead of weighting by its frequency.
- Encoding by replaying the whole merge list, which is correct on these tables and orders of magnitude too slow on a real one.
- Merging overlapping occurrences: `a a a` with the pair `a+a` must give `aa a`, scanning left to right.
