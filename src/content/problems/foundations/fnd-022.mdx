  solution: |
    import math

    def _unit(rows):
        out = []
        for r in rows:
            n = math.sqrt(sum(x * x for x in r))
            if n == 0.0:
                raise ValueError("a zero vector has no direction; drop the row before batching")
            out.append([x / n for x in r])
        return out

    def clip_loss(img, txt, temperature=0.07):
        if len(img) != len(txt) or not img:
            raise ValueError("need two non-empty batches of the same size")
        if temperature <= 0:
            raise ValueError("temperature must be positive")
        if any(len(r) != len(img[0]) for r in img + txt):
            raise ValueError("every vector needs the same dimension")
        a, b = _unit(img), _unit(txt)
        n, scale = len(a), 1.0 / temperature
        col_max = [-math.inf] * n   # running max of each column's logits
        col_sum = [0.0] * n         # sum of exp(logit - col_max) seen so far
        diag_total, row_total = 0.0, 0.0
        for i in range(n):
            row = [scale * sum(x * y for x, y in zip(a[i], bj)) for bj in b]
            m = max(row)
            row_total += m + math.log(sum(math.exp(v - m) for v in row))
            diag_total += row[i]
            for j, v in enumerate(row):
                if v > col_max[j]:
                    col_sum[j] = col_sum[j] * math.exp(col_max[j] - v) + 1.0
                    col_max[j] = v
                else:
                    col_sum[j] += math.exp(v - col_max[j])
        col_total = sum(m + math.log(s) for m, s in zip(col_max, col_sum))
        return ((row_total - diag_total) + (col_total - diag_total)) / (2 * n)

## Question

Write `clip_loss(img, txt, temperature)`. `img` and `txt` are lists of N vectors of the same dimension, and row i of one is the match for row i of the other. Return the symmetric contrastive loss: the image-to-text cross-entropy over each row of the cosine similarity matrix divided by the temperature, averaged with the text-to-image cross-entropy over each column, with the diagonal as the label in both.

Constraints:

- Standard library only.
- The hidden tests call it on a batch of 400 vectors of dimension 16 and measure peak allocation with `tracemalloc`. The budget is 2,000,000 bytes. A materialised 400 by 400 matrix of Python floats is 160,000 floats; on 64-bit CPython a float object is 24 bytes and its list slot 8 more, so 160,000 × 32 = 5,120,000 bytes before list headers. Normalised copies of the inputs fit: 800 × 16 = 12,800 floats.
- The temperature can be as small as 1e-5. With cosine in [-1, 1], logits then reach 1 / 1e-5 = 100,000, and `math.exp` overflows above about 709.
- A zero vector has no direction. Choose what your function does with one and say why in the docstring; the tests accept a `ValueError` or a finite loss.

The hidden tests check properties of the loss rather than one canonical output.

## Answer

Normalise both sides once, then walk the similarity matrix one row at a time. Each row gives its own log-sum-exp directly, with the row maximum subtracted before `exp`. Columns are the difficulty, because a column is complete only after the last row. Keep, per column, the largest logit seen so far and the sum of `exp(logit - max)`; when a new logit beats the max, rescale the sum by `exp(old_max - new_max)` before adding 1. That is the online softmax recurrence, and it makes each column's log-sum-exp exact in O(N) state. The diagonal logits are shared by both directions, so the loss is `(sum of row LSE - trace) + (sum of column LSE - trace)` divided by 2N.

Time is N² × d multiply-adds, the same as the naive version. Memory beyond the normalised inputs is one row of N logits plus two arrays of N, which is what the 2,000,000-byte budget admits.

The properties the hidden tests check, each derivable from the definition:

- Swapping the arguments swaps rows and columns, so the loss is symmetric.
- Permuting both batches with the same permutation leaves it unchanged.
- Scaling any row by a positive number leaves it unchanged, because only cosine enters.
- If every row of each side is identical, every candidate ties, and each cross-entropy is log N.
- Orthonormal pairs at a small temperature give a loss near 0, and swapping two texts raises it.

There is a real decision in the memory budget, with two defensible answers. The one-pass online version above stores no matrix and computes each similarity once. A two-pass version computes all rows for the row losses, then recomputes all similarities column by column: twice the multiply-adds, no rescaling logic, and easier to review. Under a memory budget with time to spare, the two-pass version is the safer code; under a time budget, the online version wins. Materialising the matrix is the right call on an accelerator for moderate N, because one matrix multiply beats N² Python dot products by orders of magnitude, and it is what the budget here rules out.

The failure mode of this solution is in the labels, not the arithmetic. The diagonal is the only positive per row, so if the same caption appears twice in a batch, each copy is a negative for the other's image and the loss cannot fall below log 2 for those rows however good the model is. The function computes that loss correctly and trains the wrong thing. Deduplicate before batching, or pass a mask of known positives and take the log-sum-exp of the positives in the numerator.

On the zero vector: raising is the safer choice for a training loop, because a silent constant row would contribute log N of loss with zero gradient to the encoder and hide an upstream bug such as an empty caption.

## Follow-ups

- Your online version and the reference implementation differ in the ninth decimal place on a 32,768 batch. A reviewer wants exact equality before merging. What do you accept in writing, and what test replaces equality?
- What changes to run this in a real trainer? The matrix lives on the accelerator in bfloat16 or float16, the temperature is a learned log scale clipped as CLIP clips it at 100, and with data parallelism each device needs the other devices' embeddings to see N - 1 negatives. At CLIP's batch of 32,768, the full logits matrix is 32,768² ≈ 1.07 billion entries, 2.1 GB at 2 bytes each, so say which device holds which block.
- The training team proposes a fixed temperature of 0.01 to save a parameter. What would you need to see in the loss curves or retrieval metrics to reverse your answer?
- Two captions in a batch are paraphrases, not duplicates. Your mask catches exact duplicates only. How do you decide whether to mask paraphrases, given that some are hard negatives the model should learn to separate?

## Common mistakes

- Averaging only the image-to-text direction, which the visible symmetry test does not catch on a symmetric input.
- Dividing by the temperature after `exp` instead of before, or subtracting a global maximum instead of a per-row and per-column one.
- Shuffling one side of the batch without the other, which breaks the diagonal labels silently.
- Normalising inside the pair loop, which repeats the norm N times per vector.
