## Question

<Callout kind="interview" label="The prompt">
Your support assistant uses dense retrieval only, with a good general-purpose embedding model over your product documentation. Which of these queries is most likely to fail on dense retrieval and succeed with BM25?
</Callout>

## Hints

<details class="hint"><summary>Hint 1</summary><p>Where does the meaning of each query live: in its wording or in one exact token?</p></details>
<details class="hint"><summary>Hint 2</summary><p>BM25's IDF term is largest for a token that appears in very few documents.</p></details>

## Answer

The error-code query. Its meaning is carried by `ERR_SSL_PROTOCOL_ERROR` and `4.18.2`, strings that appear in very few documents. An embedding model compresses the query into one vector that lands near every document about SSL errors and SDK upgrades; the one page that names that exact error in that exact version has no special pull. BM25 scores rare tokens by IDF, so the page containing them rises to the top. A 2025 paper adds a theoretical reason: single-vector embeddings cannot represent every possible top-k set, and on its deliberately adversarial LIMIT set BM25 reached 93.6 recall@100 against 18.9 for the best single-vector model.

Why the others are tempting. The refund paraphrase is the mirror image: dense retrieval succeeds and BM25 may fail, since none of its words need appear in the documents. The vague dashboard question fails for both, which feels like a dense-retrieval failure but is a query problem; rewriting or asking a clarifying question helps more than lexical search. The API-key question uses the same words the documentation uses, so both retrievers usually manage.

## Follow-ups

- *What would you change?* Add BM25 alongside dense retrieval and fuse with RRF; make sure the tokenizer keeps identifiers like `ERR_SSL_PROTOCOL_ERROR` and `4.18.2` intact.
- *Can fine-tuning the embedding model fix it?* It narrows the gap on your jargon, but exact identifiers that were never in training data still favour lexical matching.
- *How do you show the gap?* Segment the eval set into identifier queries and natural-language queries and report recall@k per retriever per segment.

## Common mistakes

- Claiming dense retrieval is strictly better than BM25 with a good enough model.
- Assuming hybrid search fixes vague queries; it fixes exact-term queries.
- Letting a tokenizer split version numbers and error codes into pieces that match everything.
