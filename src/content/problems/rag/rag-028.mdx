## Question

<Callout kind="interview" label="Debug round">
Your support assistant runs a retrieve, grade, rewrite loop. Since Tuesday's release the mean cost per question has nearly doubled while the median fell, and some customers wait more than two minutes for a reply. Which defect explains the cost jump? Rank the others.
</Callout>

The loop after the release:

```python
MAX_REWRITES = 3
BUDGET_USD = 0.25
ABSTAIN = "I could not find this in the documentation."


def answer(question, user):
    state = {"question": question, "original": question, "spent": 0.0}
    attempts = defaultdict(int)
    while True:
        docs = retrieve(state["question"], acl=user.groups, k=8)
        verdict, cost = grade(state["question"], docs[:1])
        state["spent"] += cost
        if verdict == "yes":
            text, cost = generate(state["original"], docs)
            state["spent"] += cost
            return Answer(text, cost=state["spent"])
        attempts[state["question"]] += 1
        if attempts[state["question"]] > MAX_REWRITES:
            return Answer(ABSTAIN, cost=state["spent"])
        state["question"], cost = rewrite(state["question"])
        state["spent"] += cost
        if state["spent"] > BUDGET_USD:
            raise BudgetExceeded(state["spent"])
```

## Answer

The cap never fires. `attempts` is keyed by `state["question"]`, and the line after the increment replaces `state["question"]` with a rewrite. Every iteration therefore increments a fresh key from 0 to 1, `1 > 3` is false, and the abstain branch is unreachable for any question whose rewrites are all distinct, which is every question a rewriter produces. Only `BUDGET_USD` stops the loop. Before Tuesday the key was `state["original"]`, constant for the question, so the fourth failed grade returned the abstain message.

The dashboard fits this and nothing else. The abstain share went from 8.9 percent to zero and the `BudgetExceeded` share from zero to 8.7 percent: the same unanswerable questions, now ending differently. Priced from the trace, one iteration is a one-document grade and a rewrite, $0.00225 + $0.00090 = $0.00315, so the budget is crossed at iteration 80, 80 × $0.00315 = $0.252, as the trace shows. Before Tuesday those questions cost four four-document grades and three rewrites, about $0.029. The mean moves by roughly 0.087 × ($0.252 − $0.029) ≈ $0.019, which is the gap between $0.022 and $0.040. The median fell because most questions are answered on the first pass and the one-document grade is cheaper. The p99 latency is 80 iterations of retrieval and two model calls.

The ranking:

1. **Attempts keyed by the current question** explains the symptom. Reverting those two lines alone restores the abstain path.
2. **Grading only the top document** is real and is the second change of the week: answered-after-a-rewrite nearly doubled, from 6.1 to 11.4 percent, because a set whose relevant chunk ranks second now grades no. It raises the cost of answerable questions by a rewrite or two and, worse, can send an answerable question to abstain once the cap works again. It does not produce `BudgetExceeded`.
3. **Rewriting the previous rewrite** is real and visible in the trace: "SLA on the Atlas Gold plan" becomes "enterprise support escalation timelines". The LangGraph tutorial this loop resembles rewrites from the original question. It predates Tuesday, and with a working cap it costs three wasted rewrites, not eighty.
4. **The budget check after the rewrite** lets a question overrun by one call, the $0.002 between $0.25 and $0.252. Move it before each call, but it is not the jump.
5. **A binary grader** is a design limit, not a defect. CRAG's evaluator returns a confidence that can stop rewriting when retrieval is hopeless rather than weak; that saves rewrites, and it is the second option for the fix below.

**The evidence is incomplete.** One trace out of about 3,500 `BudgetExceeded` questions a day, no record of `attempts`, and no grader verdicts on labelled questions. Collect: the iteration count for every `BudgetExceeded` question (a log line at raise time is enough), a replay of a sample of last week's abstained questions against the current code, and the grader's verdicts with `docs[:1]` and `docs[:4]` on a labelled set to size defect 2. Without any of it, the two-line revert is safe to ship today: it restores last week's behaviour, whose cost is known.

### The fix: two defensible answers

- **A count cap that cannot be bypassed.** Keep a plain integer counter in the loop state, add a hard iteration limit that does not depend on it, and check the budget before each call. Cost: every answerable question that needed one more rewrite abstains, and the cap is a number someone has to choose.
- **A corrective evaluator in the CRAG style.** Replace the binary grade with a scored one and three outcomes: relevant (answer), ambiguous (rewrite, from the original question), irrelevant (abstain, or try another source). Cost: thresholds to calibrate on labelled data, and a scorer whose calibration drifts with the corpus.

The quantity to choose is the cap. Choose it from last month's logs: for each k, the share of questions that reach the k-th rewrite and are then answered. If the fourth rewrite answers 1 in 100 of the questions that reach it, it costs $0.00315 / 0.01 = $0.315 per answer gained, more than ten times a normal answer. A cap of 2 or 3 is reasonable when that curve flattens there; a cap of 10 is unreasonable whatever the curve says, because the drifted rewrites by then are no longer the user's question. The conflict is cost against answer rate, and abstaining on a question the documentation does answer is the cost you accept in writing.

I would ship the revert today, then the count cap with the budget check moved, then reconsider the evaluator once there is a labelled set.

**Where the fix fails.** A per-question cap bounds one call to `answer`, not the customer. When the reply is "I could not find this", the customer asks again in other words, and each attempt gets its own budget. Track spend and abstains per conversation, and treat a run of abstains on one topic as a documentation gap to report rather than a retrieval problem to retry.

## Follow-ups

- *Pushback: the PR author argues the one-document grade saved 18 percent on the median and should stay. What do you need to see before you keep it, and what do you accept in writing if you do?*
- *Reversal: what would you need to see in production to drop the cap and rely on the evaluator alone?* A month in which the evaluator's irrelevant verdicts on a labelled sample were wrong less often than the cap's abstains on answerable questions, with the hard iteration limit still in place as a backstop.
- *The team wants to move this loop to LangGraph. Does the framework stop a loop like this one?* Since 1.0.6 the default recursion limit is 1000 super-steps, so not before the budget; the cap has to live in the graph's state, and a node can read `RemainingSteps` to finish with an abstain instead of an error.
- *Support says the abstain message is losing customers and asks for the cap to go to 10. What do you show them?*

## Common mistakes

- Blaming the one-document grade because it is the change with "cost" in the PR title, when the median fell after it.
- Raising the budget or lowering it as the fix; the budget is the only stop left, and it is doing its job.
- Reading the trace's drifting rewrites as the root cause and fixing the rewrite prompt, which leaves the loop uncapped.
- Fixing the key and keeping only the dictionary, so the next refactor that changes the key reopens the loop; an iteration limit independent of the key is the backstop.
