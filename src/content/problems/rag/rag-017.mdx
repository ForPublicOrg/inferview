## Question

<Callout kind="interview" label="The prompt">
You need to rescore 200 first-stage candidates per query under a tight latency budget. You can afford extra storage at index time. You want the rescoring to compare query and document token by token rather than as two single vectors. Which approach fits?
</Callout>

## Hints

<details class="hint"><summary>Hint 1</summary><p>Which approaches let you compute anything about the documents before the query arrives?</p></details>
<details class="hint"><summary>Hint 2</summary><p>Of those, which keeps more than one vector per document?</p></details>

## Answer

ColBERT-style late interaction. The documents are encoded once, one vector per token, and stored. At query time the query is encoded, each query token takes its maximum similarity over the document's token vectors, and the maxima are summed. The ColBERT paper reports four orders of magnitude fewer FLOPs per query than BERT-based rankers; the cost moved into storage, which ColBERTv2's compression cuts by 6 to 10 times. Qdrant documents this as a two-stage query: prefetch dense candidates, rescore them with a ColBERT multivector.

Why the others are tempting. A cross-encoder is the most accurate classic reranker and does compare tokens, but because query and document go through the model together, none of the document work can be done ahead of time, so 200 candidates is 200 full passes per query. Single-vector cosine is cheap and precomputed, but it is the first-stage retriever again. An LLM reranker can follow instructions such as "prefer documents from 2026" and is the right call when that matters more than latency.

## Follow-ups

- *What does late interaction cost in storage?* One vector per token instead of one per chunk, before compression; budget it like a second index.
- *When would you still pick a cross-encoder?* For a short candidate list (tens, not hundreds) where accuracy matters most and storage is constrained.
- *Where does ColPali fit?* It applies the same late interaction to patches of page images, so slides and scanned forms can be searched without text extraction.

## Common mistakes

- Calling ColBERT a cross-encoder.
- Assuming a cross-encoder's output can be cached per document.
- Ignoring the storage cost of per-token vectors.
