  solution: |
    def recall_at_k(ranked, relevant, k):
        if not relevant:
            raise ValueError("recall needs at least one labelled relevant document")
        return len(set(ranked[:k]) & set(relevant)) / len(set(relevant))

    def faithfulness(claims, context_ids):
        if not claims:
            return None
        context = set(context_ids)
        supported = sum(1 for _, support in claims if context & set(support))
        return supported / len(claims)

    def evaluate(cases, k=5):
        recalls, faiths, triage = [], [], {}
        for case in cases:
            context = case["ranked"][:k]
            r = recall_at_k(case["ranked"], case["relevant"], k)
            f = faithfulness(case["claims"], context)
            recalls.append(r)
            if f is not None:
                faiths.append(f)
            if r < 1.0:
                triage[case["id"]] = "retrieval"
            elif f is not None and f < 1.0:
                triage[case["id"]] = "generation"
            else:
                triage[case["id"]] = "ok"
        return {
            "recall@k": sum(recalls) / len(recalls) if recalls else 0.0,
            "faithfulness": sum(faiths) / len(faiths) if faiths else None,
            "triage": triage,
        }

## Question

<Callout kind="interview" label="The take-home, as a public interview guide describes it">
"Here are 50 markdown docs. Build a Q&A system, an eval set of 20 questions, and report recall@5 and faithfulness."
</Callout>

This problem is the scoring half of that take-home, cut down so it runs in the browser with no model calls. Your pipeline has already run on 8 labelled questions over 12 documents (`d01` to `d12`). For each question you have the gold document ids, the ranked list your retriever returned, and the answer split into claims. A reviewer has labelled, for each claim, which documents in the corpus support it (an empty list means no document does). The model saw the top `k` documents as context.

Write three functions:

- `recall_at_k`: the fraction of gold documents in the top k. Not hit rate.
- `faithfulness`: the fraction of claims supported by a document that was actually in the context. A claim supported only by a document the model never saw is unfaithful, even if it happens to be true.
- `evaluate`: means over the set, plus a triage label per question that blames the first broken stage.

## Hints

<details class="hint"><summary>Hint 1</summary><p>A question with no claims (a refusal) has undefined faithfulness; leave it out of the mean rather than counting it as 0 or 1.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Triage checks retrieval first: if any gold document is missing from the context, the generation stage never had a fair chance.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Use sets for membership, and count relevant documents once even if a list repeats one.</p></details>

## Answer

The reference solution is three small functions; the judgement is in the definitions.

**recall@5 is 0.6875.** Per question: q1 1, q2 0.5 (`d03` is at rank 6), q3 1, q4 0 (`d06` at rank 6), q5 1, q6 1, q7 1, q8 0. That is 5.5 / 8. Hit rate@5 on the same data would be 6 / 8 = 0.75, which is why the take-home asks you to say which one you report.

**Faithfulness is 0.667.** Seven answers make claims: q1 1, q2 0.5 (the receipts claim needs `d03`, which the model never saw), q3 0.5 (the WireGuard claim has no support anywhere), q5 1, q6 2/3 (the laptop purchase claim is in `d12`, which was not in context), q7 1, q8 0. The sum is 14/3 and the mean 14/21. q4 is a refusal with no claims and is excluded; counting it as 1 would reward refusing, and counting it as 0 would punish an honest "I don't know" for a retrieval miss.

**Triage blames the first broken stage.** q2, q4 and q8 are retrieval failures because a gold document never reached the context; their faithfulness numbers are a consequence, not a cause. q3 and q6 had all their gold evidence and still made unsupported claims, so they are generation failures. Note q6: its unsupported claim is in the corpus, just not in the context, so it may well be true. Faithfulness flags it anyway, because the model asserted something it was not shown.

What the write-up should say next: fix retrieval first (three questions), since generation cannot be judged fairly on those; for q3 and q6, tighten the prompt to cite only provided documents and add a citation check; and report hit rate, recall, faithfulness and correctness separately.

## Follow-ups

- *In the real take-home, who labels the claims?* An LLM extracts and verifies claims (as Ragas does) or a classifier such as HHEM; hand-check a sample and report agreement, because the judge is noisy.
- *Faithfulness is high but users still get wrong answers. How?* The context itself can be stale or wrong; faithfulness only measures agreement with the context. Add correctness against reference answers.
- *How would you make 20 questions representative?* Include identifier queries, multi-document questions and a few unanswerable ones, and write them from the documents before tuning the pipeline.

## Common mistakes

- Computing hit rate and calling it recall@5.
- Treating a claim as faithful because it is true somewhere in the corpus.
- Counting refusals as faithfulness 0 or 1.
- Blaming generation for questions whose evidence never reached the prompt.
