## Question

<Callout kind="interview" label="The prompt">
"Long context windows keep getting cheaper. When should we still build retrieval, when should we put everything in the context window, and where does cache-augmented generation fit?"
</Callout>

## Hints

<details class="hint"><summary>Hint 1</summary><p>Split the decision into quality, cost, freshness and access control.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Prompt caching changes the cost side of stuffing a large, stable prefix into every call.</p></details>
<details class="hint"><summary>Hint 3</summary><p>What does the published evidence say about accuracy as the input gets longer?</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>It depends on corpus size, stability, question type and access control, and the published comparisons agree there is no universal winner. A small, stable corpus that every user may see (Anthropic's rough line is about 200,000 tokens) can go in a cached prompt, which is cache-augmented generation. A large, fast-changing or permissioned corpus needs retrieval. In between I measure both on my own eval set, because accuracy drops with input length and distractors.</p>
</Fragment>
<Fragment slot="long">
<p>Quality. Li et al. found long context generally better on QA, especially Wikipedia-based, and RAG better on dialogue-based and general queries. LaRA, testing 11 models on 2,326 cases, concluded the choice "depends on a complex interplay of factors". Chroma's Context Rot study of 18 models found performance "consistently degrades with increasing input length" and that one distractor already hurts. So stuffing is not free accuracy.</p>
<p>Cost, computed. A 150,000-token handbook in every prompt at Claude Sonnet 5.5's $2.00 per million input tokens is $0.30 per query; five 800-token chunks are 4,000 tokens, $0.008. With the handbook as a cached prefix read at $0.10 per million, the stuffed prompt is $0.015 per query, under twice the RAG cost, with no retrieval stack to run. That is the CAG argument.</p>
<p>Freshness. A cached prefix is invalidated by any edit before the end of the cached span, so a corpus that changes hourly pays cache writes constantly. Retrieval updates one chunk.</p>
<p>Access control. Retrieval can filter per user. A single cached prompt holds the whole corpus, so it only works when every user may see every document, or with one cache per permission group.</p>
<p>Latency. A long prompt takes longer to process before the first token; caching shortens this for the cached prefix, so measure time to first token at your real context size.</p>
<p>The decision. Stable, small, shared corpus and lookup questions: CAG. Large, changing or permissioned corpus: RAG. Global questions over a large corpus: neither alone; consider precomputed summaries.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>How would you prove the choice?</em> Run the same eval set both ways and compare accuracy, cost per query and p95 time to first token.</li>
<li><em>Where do you put the question in a long prompt?</em> After the documents; Anthropic's prompting guide recommends documents first and the query at the end.</li>
<li><em>Can you combine them?</em> Yes: retrieve a generous set of whole sections rather than small chunks, and cache the stable system prompt and instructions.</li>
</ul>
</Fragment>
</Depth>

A strong answer avoids both slogans, "RAG is dead" and "long context does not work", and instead names the four axes, cites that the evidence is mixed, and does the cost arithmetic with caching on the table.

## Follow-ups

- *What is the first cache write going to cost?* Cache writes cost more than plain input (Claude lists $2.50 per million for 5-minute writes on Sonnet 5.5), so 150,000 tokens is $0.375 once per cache window.
- *Does position in the context matter?* The 2023 "lost in the middle" result found a U-shape on 2023 models; Chroma's 2025 report saw no notable position effect in its setup. Test on your model.
- *What about a 10-million-token corpus?* Far past any threshold here; retrieval or a summary index is required.

## Common mistakes

- Comparing uncached long-context cost with RAG cost and declaring RAG 37 times cheaper.
- Ignoring per-user permissions when proposing one shared cached prompt.
- Quoting a context window size as if quality held constant up to it.
