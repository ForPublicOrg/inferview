  solution: |
    import math
    from collections import Counter

    def tokenize(text):
        return text.lower().split()

    def bm25_scores(query, docs, k1=1.2, b=0.75):
        toks = [tokenize(d) for d in docs]
        n = len(toks)
        if n == 0:
            return []
        avgdl = sum(len(t) for t in toks) / n
        df = Counter(term for t in toks for term in set(t))
        q_terms = tokenize(query)
        scores = []
        for t in toks:
            tf = Counter(t)
            s = 0.0
            for q in q_terms:
                if q not in tf:
                    continue
                idf = math.log(1 + (n - df[q] + 0.5) / (df[q] + 0.5))
                norm = k1 * (1 - b + b * len(t) / avgdl) if avgdl else k1
                s += idf * tf[q] * (k1 + 1) / (tf[q] + norm)
            scores.append(s)
        return scores

    def top_k(query, docs, k):
        scores = bm25_scores(query, docs)
        order = sorted(range(len(docs)), key=lambda i: (-scores[i], i))
        return [i for i in order[:k] if scores[i] > 0]

## Question

<Callout kind="interview" label="The prompt">
"Implement BM25 scoring over a list of documents, then a `top_k` function on top of it. Use whitespace tokenisation and lowercase everything. Talk me through each term of the formula as you write it."
</Callout>

For every query term that appears in a document, BM25 adds

`idf(q) * tf * (k1 + 1) / (tf + k1 * (1 - b + b * len(doc) / avg_len))`

where `tf` is the term's count in the document. Use Lucene's IDF, `log(1 + (N - df + 0.5) / (df + 0.5))`, with `N` documents of which `df` contain the term, and Lucene's defaults `k1 = 1.2`, `b = 0.75`. The tests check the scores on a four-document corpus where the query "E1234 timeout" should rank the one document containing the rare error code first.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Compute document frequencies once over the set of terms in each document, not over every occurrence.</p></details>
<details class="hint"><summary>Hint 2</summary><p>A query term absent from a document contributes nothing, so skip it before computing anything.</p></details>
<details class="hint"><summary>Hint 3</summary><p>For ties, sort by the pair (negative score, index).</p></details>

## Answer

The solution tokenises every document once, computes the average length and a document-frequency counter (each term counted once per document), then sums the BM25 term for every query term the document contains.

Each part of the formula has a job you should name while writing it. IDF makes `E1234`, in one of four documents, worth log(1 + 3.5 / 1.5) = 1.204, while "timeout", in two, is worth log(1 + 2.5 / 2.5) = 0.693; that is why the runbook wins with 1.183 against 0.681. The `1 +` inside Lucene's logarithm keeps IDF positive even for a term in every document; the classic Robertson form can go negative and silently push documents down for matching a common word. The saturation term `tf * (k1 + 1) / (tf + ...)` approaches `k1 + 1` as `tf` grows, so keyword stuffing stops paying. The length factor with `b` scales `k1` up for long documents, so a long document needs more occurrences to score the same.

`top_k` sorts by `(-score, index)` for deterministic ties and drops zero scores: a document that shares no term with the query should not be returned as a "result" just because k was larger than the number of matches.

## Follow-ups

- *How would this scale to millions of documents?* An inverted index from term to postings with term frequencies, document lengths stored once, and only the postings of query terms scanned. Scoring the whole corpus per query, as here, is the full-table-scan version.
- *Why might you change k1 or b?* Short, uniform documents (titles, product names) often want less length normalisation; long, varied documents may want more. Tune on labelled queries, not intuition.
- *Postgres has full-text search. Is that BM25?* No. Its ranking functions use no corpus-wide statistics, so there is no IDF. Use an extension or a search engine if you need BM25.

## Common mistakes

- Counting document frequency per occurrence instead of per document.
- Using the IDF variant without the `1 +`, which makes very common terms reduce the score.
- Computing `avg_len` over the query or over matching documents only.
- Returning zero-score documents to fill k.
