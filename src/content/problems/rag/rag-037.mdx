  solution: |
    import heapq
    import math
    import random


    def distance(a, b):
        return math.dist(a, b)


    class HNSW:
        def __init__(self, M=8, ef_construction=64, seed=0):
            self.M, self.ef_construction = M, ef_construction
            self.mL = 1.0 / math.log(M)
            self.rng = random.Random(seed)
            self.vectors, self.levels, self.layers = {}, {}, []
            self.entry = None
            self.groups = {}       # graph node -> every key stored at exactly that vector
            self.node_of = {}      # vector -> graph node, so exact duplicates share one node

        def level(self, key):
            return self.levels[self.node_of[self.vectors[key]]]

        def neighbours(self, key, layer):
            return list(self.layers[layer].get(self.node_of[self.vectors[key]], ()))

        def _search_layer(self, q, entry_points, ef, layer):
            visited = set(entry_points)
            candidates = [(distance(q, self.vectors[e]), e) for e in visited]
            heapq.heapify(candidates)
            best = [(-d, e) for d, e in candidates]
            heapq.heapify(best)
            links = self.layers[layer]
            while candidates:
                d, node = heapq.heappop(candidates)
                if len(best) >= ef and d > -best[0][0]:
                    break
                for n in links[node]:
                    if n in visited:
                        continue
                    visited.add(n)
                    dn = distance(q, self.vectors[n])
                    if len(best) < ef or dn < -best[0][0]:
                        heapq.heappush(candidates, (dn, n))
                        heapq.heappush(best, (-dn, n))
                        if len(best) > ef:
                            heapq.heappop(best)
            return sorted((-d, e) for d, e in best)

        def _select(self, candidates, m):
            # Keep a candidate only if it is closer to the base node than to every neighbour already kept,
            # then fill free slots with the nearest pruned candidates.
            chosen = []
            for d, key in candidates:
                if len(chosen) == m:
                    break
                v = self.vectors[key]
                if all(d < distance(v, self.vectors[c]) for c in chosen):
                    chosen.append(key)
            for _, key in candidates:
                if len(chosen) == m:
                    break
                if key not in chosen:
                    chosen.append(key)
            return chosen

        def _descend(self, q, stop_at):
            entry = [self.entry]
            for layer in range(self.levels[self.entry], stop_at, -1):
                entry = [self._search_layer(q, entry, 1, layer)[0][1]]
            return entry

        def insert(self, key, vector):
            if key in self.vectors:
                raise ValueError(f"{key!r} is already indexed; this index does not move vectors")
            q = tuple(vector)
            self.vectors[key] = q
            if q in self.node_of:
                # An exact duplicate joins the existing node. Linking it as a node of its own would put many nodes at
                # distance 0 from each other, and pruning full neighbour lists can then leave some with no inbound link.
                self.groups[self.node_of[q]].append(key)
                return
            self.node_of[q], self.groups[key] = key, [key]
            level = int(-math.log(1.0 - self.rng.random()) * self.mL)
            self.levels[key] = level
            while len(self.layers) <= level:
                self.layers.append({})
            for layer in range(level + 1):
                self.layers[layer][key] = []
            if self.entry is None:
                self.entry = key
                return
            top = self.levels[self.entry]
            entry = self._descend(q, level)
            for layer in range(min(top, level), -1, -1):
                found = self._search_layer(q, entry, self.ef_construction, layer)
                cap = 2 * self.M if layer == 0 else self.M
                self.layers[layer][key] = self._select(found, self.M)
                for other in self.layers[layer][key]:
                    theirs = self.layers[layer][other]
                    theirs.append(key)
                    if len(theirs) > cap:
                        v = self.vectors[other]
                        ranked = sorted((distance(v, self.vectors[n]), n) for n in theirs)
                        self.layers[layer][other] = self._select(ranked, cap)
                entry = [k for _, k in found]
            if level > top:
                self.entry = key

        def search(self, q, k, ef):
            if self.entry is None:
                return []
            found = self._search_layer(q, self._descend(q, 0), max(ef, k), 0)
            return [key for _, node in found for key in self.groups[node]][:k]

## Question

<Callout kind="interview" label="The prompt">
"Implement HNSW insert and search in plain Python. I will measure your recall against brute force at a fixed efSearch."
</Callout>

Write `HNSW` with `insert(key, vector)`, `search(q, k, ef)`, `level(key)` and `neighbours(key, layer)`. Standard library only. The tests hold you to these properties:

- **A recall floor.** On 3,000 random 16-dimension vectors, recall@10 against brute force at `ef = 64` is at least 0.95. The same floor holds on 2,000 vectors packed into 30 tight clusters, which is closer to what real embeddings of a few product lines look like.
- **A cost ceiling.** A search computes fewer than 30% of the index's distances. Every distance goes through the module-level `distance()`, called by that name, because the tests replace it with a counter. A brute-force search computes 100%.
- **A memory ceiling.** No node holds more than `2 * M` links on layer 0 or `M` on any layer above, and a node links only to nodes that exist on that layer.
- **Exact duplicates.** The same chunk is often ingested twice. Every key you insert stays findable, including twenty keys with the same vector.
- **Results.** Distinct keys, nearest first, `min(k, n)` of them; an empty index returns `[]`.

One decision is yours: what `insert` does with a key that is already indexed. Raise `ValueError`, or move the key to its new vector; either passes if the index stays consistent. Say which you chose and what it costs.

## Answer

The reference solution is about a hundred lines. The design choices are in four places.

**Levels.** A node's top layer is `int(-ln(1 - U) * mL)` with `mL = 1 / ln(M)`, drawn from a seeded `random.Random`, so about one node in M reaches layer 1 and one in M squared layer 2. Using `1 - U` keeps the logarithm defined when `U` is 0. Any decaying distribution passes the tests; this one is the paper's.

**Search.** `_search_layer` is best-first search with two heaps: candidates by distance (a min-heap) and the best `ef` found (a max-heap). It stops when the nearest unexpanded candidate is farther than the worst of the best `ef`; that stopping rule is what keeps a search at about 570 distance calls on the 3,000-vector test instead of 3,000. `search` descends the upper layers with `ef = 1`, then runs layer 0 with `max(ef, k)`.

**Neighbour selection.** This is the part the clustered test checks. Keeping a node's M nearest candidates links each node to its own cluster and nothing else; on the clustered data, a variant of the reference solution with that rule left 1,315 of 2,000 nodes unreachable from the entry point and reached recall@10 of 0.785 (measured locally in CPython 3.12). The paper's heuristic keeps a candidate only if it is closer to the new node than to every neighbour already kept, so the second link points away from the first, and long links between clusters survive. The same rule prunes a neighbour list that overflows its cap, which is where most links between clusters would otherwise be lost. Free slots are filled with the nearest pruned candidates, so sparse regions keep their degree. The heuristic costs build time: on the uniform test data the reference solution makes about 900 distance calls per insert against about 515 for the M-nearest rule.

**Duplicates and re-inserts.** Twenty nodes at distance 0 from each other defeat the heuristic, since no candidate is strictly closer to the new node than to a kept neighbour, and pruning by key order cuts the last few nodes off with no inbound link. The reference solution gives each distinct vector one graph node and keeps a list of keys per node, so duplicates cost a dictionary entry and no links. An existing key raises `ValueError`.

**The decision you make, and the cost of each answer.** Raising on a re-insert keeps the graph immutable: correct, simple, and the caller must delete and re-add, which in this index means repairing every link that pointed at the old node. Moving the key is friendlier to the caller, but if the vector is shared with duplicates you split the group, and if it is not you leave a dead node in the graph until a rebuild, which is what pgvector's vacuum and Faiss's lack of removal are both about. For an index rebuilt nightly from a source of truth, raise; for one that takes edits all day, move, and budget for the dead nodes.

**The constraint conflict** is build cost against recall. The heuristic nearly doubles build-time distance calls to keep clusters connected; a larger `ef_construction` would buy recall the same way. The tests leave you room to spend either.

**Where this solution fails.** Collapsing duplicates by exact vector equality misses near-duplicates: two chunks that differ by one whitespace character embed to vectors a hair apart, and enough of them in one place recreate the unreachable-node problem. A production index needs a deduplication step upstream, or a check after each build that every node has an inbound link on layer 0.

## Follow-ups

- *Pushback: your build makes about 900 distance calls per insert and the nightly rebuild of 20 million vectors misses its window. Which do you cut, `ef_construction` or the heuristic, and what recall do you accept in writing?*
- *Reversal: what would you need to see in a recall sweep to drop the heuristic for the M-nearest rule on your production data?*
- *How do you delete a node from this graph without a rebuild, and what do you do about the nodes whose only inbound link came from it?*
- *What changes to run this in a real engine?* Vectors in one contiguous float array with SIMD distance kernels instead of tuples and `math.dist`; a lock per node's link list so inserts run concurrently; integer node ids instead of arbitrary keys; persistence through a memory-mapped file; and a filter applied during traversal rather than after it.

## Common mistakes

- A search loop with no stopping rule, which visits the whole layer and passes recall while failing the cost ceiling.
- Keeping the M nearest candidates and never testing on clustered data.
- Forgetting to prune the neighbour's list when the back-link overflows it.
- Updating the entry point before the descent that inserts the new node, so the node searches from itself.
- Testing recall on queries that are exact copies of indexed vectors.
