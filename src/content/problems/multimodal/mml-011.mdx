## Question

<Callout kind="interview" label="Interview question">
"A vendor's architecture deck says: 'Multi-head latent attention cuts the KV cache by 93.3% (DeepSeek-V2), so converting our GQA-8 model would shrink its cache roughly fifteenfold.' The 93.3% in the DeepSeek-V2 abstract compares what with what?"
</Callout>

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask for the baseline model's config, specifically its number of key-value heads.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Ask what precision each model's cache was stored at when the figure was computed.</p></details>

## Answer

The abstract names DeepSeek 67B as the baseline. Its config has 95 layers, 64 query heads and 8 key-value heads of dimension 128, so it is a dense (no experts) GQA-8 model caching 2 × 8 × 128 × 95 = 194,560 values per token, 389,120 bytes in BF16. DeepSeek-V2 caches 512 + 64 = 576 values on each of 60 layers, 34,560 values per token, and its deployment section stores each KV element in about 6 bits on average: 25,920 bytes. 1 − 25,920 / 389,120 = 0.9334, which is the 93.3%. At equal BF16 precision the same pair gives 82.2%.

So the figure bundles a layout change, 35 fewer layers and cache quantisation. The vendor's "fifteenfold" (1 / 0.067) for converting a GQA-8 model at the same depth and precision is wrong; the like-for-like layout ratio from DeepSeek-V3's config is 2,048 against 576 values per layer, about 3.6 times.

Why the wrong options are tempting:

- "Full multi-head attention" is the common reading of "dense model", and the abstract does not state the baseline's KV head count.
- The MHA ablation exists in the same paper, so it is easy to assume the headline comes from it.
- The same-depth GQA-8 comparison is the one a careful engineer would run, which makes it easy to assume the paper ran it.

## Follow-ups

- Recompute the vendor's claim for your own model at equal precision. What number goes in the deck instead?
- DeepSeek-V2 also reports 5.76 times the maximum generation throughput of DeepSeek 67B. List the differences between the two deployments that contribute to it besides MLA.

## Common mistakes

- Reading "dense" as "multi-head attention"; dense here means no mixture of experts.
- Quoting a percentage reduction without the baseline's layout, depth and cache precision.
- Applying a reduction measured against one baseline to a different model.
