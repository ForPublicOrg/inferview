## Question

<Callout kind="interview" label="Debugging round">
"Our VLM answers single-image questions well but fails on multi-page documents. Find out why and fix it."
</Callout>

The product, as a scenario: lawyers ask questions about supplier contracts of 5 to 60 pages, and the assistant answers with page citations. Last sprint it moved from extracted text to page images, rendered from the PDF and sent to Claude Opus 5.5 with a label before each page. Single-page tests and the one-page fixtures in CI pass. Since the switch, reviewers report answers that cite a page where the clause is not, and wrong answers to questions about clauses that continue across a page break. You have the code below and twelve reviewer reports with the question, the answer and the correct page. You do not have the payloads or any breakdown of failures by document.

```python
DPI = 150  # 8 pt clause numbers stay legible at this density

def render_pages(pdf_path, out_dir):
    for n, page in enumerate(open_pdf(pdf_path), start=1):
        page.render(dpi=DPI).save(f"{out_dir}/page_{n}.png")

def build_content(out_dir, question):
    content = []
    for i, name in enumerate(sorted(os.listdir(out_dir)), start=1):
        content.append({"type": "text", "text": f"Page {i}:"})
        content.append(image_block(os.path.join(out_dir, name)))
    content.append({"type": "text", "text": question})
    return content
```

An A4 page at 150 DPI renders at 1240 × 1754 px.

Pick the cause of the wrong citations. Then rank the other three by how much each would matter once the cause is fixed, and say what you would collect and what you would ship without it.

## Answer

The cause is `sorted(os.listdir(out_dir))`. The renderer writes `page_1.png` to `page_60.png` without zero padding, and a string sort orders them `page_1, page_10, page_11, …, page_19, page_2, page_20, …`. In a 60-page contract the image labelled "Page 2:" is page 10 and page 2 is sent twelfth, labelled "Page 12:". The model's citations are correct with respect to the labels it was given and wrong with respect to the document, and any clause that runs from page 40 to page 41 is still split across consecutive labels only by luck (here 35 and 36). Documents of nine pages or fewer sort correctly, which is why single-page fixtures and short amendments pass.

Hint 3 is the fastest confirmation: if the cited page in each report is the document page whose position in the string sort matches the cited label, the cause is proven without any payload.

**The rest, ranked for after the fix.**

1. *Dilution over sixty pages* matters next. Sixty pages at 2,835 tokens each are 170,100 image tokens per question, $0.68 at Opus 5.5's $4 per million. Meta's Llama 4 post reports post-training tested with good results up to eight images; for a model with no published many-page evidence, measure accuracy by the page position of the evidence before trusting a sixty-page request.
2. *Downscaling* does not happen on this model: 1240 × 1754 is within the high-resolution tier's limits. It would on a standard-tier model, which caps an image at 1,568 tokens, so it matters if someone switches to a cheaper model to save money.
3. *The many-image limit* fails loudly, not silently. It would show up as a 400, which reviewers did not report.

**What to collect, and what to ship without it.** The file order of one failing request, the failure rate for documents under ten pages against ten or more, and accuracy by evidence position. Ship today without them: page numbers carried from the renderer rather than recovered from file names, and a test that builds content for a 12-page document and asserts the labels follow document order.

```python
def render_pages(pdf_path, out_dir):
    paths = []
    for n, page in enumerate(open_pdf(pdf_path), start=1):
        path = f"{out_dir}/page_{n:04d}.png"
        page.render(dpi=DPI).save(path)
        paths.append((n, path))
    return paths
```

**The decision after the fix.** Two defensible designs. Keep sending every page: no retrieval misses, cross-page clauses always present, $0.68 and 170,100 tokens per question on a 60-page contract. Or retrieve the top pages per question over page images (ColPali's authors report nDCG@5 of 81.3 against 67.0 for the best text pipeline on their benchmark) and send the top six: 6 × 2,835 = 17,010 tokens, a tenth of the full document, at the cost of answers that are wrong whenever retrieval misses the page, and of clauses that continue onto a page retrieval did not return. Choose by measuring accuracy by evidence position on full documents first; if accuracy holds at sixty pages, the cost alone may not justify retrieval.

**How the fix fails.** The labels now match PDF page indexes, but lawyers cite printed page numbers. A contract with a cover sheet and a roman-numbered table of contents has PDF page 12 printed as page 10, and the assistant will cite "page 12" for a clause the lawyer finds on page 10. Label each image with both, or with the printed number read during rendering.

## Common mistakes

- Blaming long-context degradation because the failing documents are long, without checking the order the pages were sent in.
- Raising DPI, which costs tokens and fixes nothing here.
- Fixing the sort with zero-padded names and no test, so the next renderer change reintroduces it.
- Treating PDF page index and printed page number as the same thing.
- Testing only on single-page fixtures, which cannot exercise ordering at all.
