    import math
    import random


    class LoRALinear:
        def __init__(self, W, bias=None):
            self.d_out = len(W)
            self.d_in = len(W[0])
            self.base = [list(map(float, row)) for row in W]
            self.W = [row[:] for row in self.base]
            self.bias = list(bias) if bias is not None else [0.0] * self.d_out
            self.adapters = {}
            self.merged = None

        def add_adapter(self, name, r, alpha, seed=0):
            if name in self.adapters:
                raise ValueError("adapter %r exists" % name)
            rng = random.Random(seed)
            bound = 1.0 / math.sqrt(self.d_in)
            A = [[rng.uniform(-bound, bound) for _ in range(self.d_in)] for _ in range(r)]
            B = [[0.0] * r for _ in range(self.d_out)]
            self.adapters[name] = {"A": A, "B": B, "r": r, "scale": alpha / r}

        def set_weights(self, name, A, B):
            ad = self.adapters[name]
            r = ad["r"]
            if len(A) != r or any(len(row) != self.d_in for row in A):
                raise ValueError("A must be r x d_in")
            if len(B) != self.d_out or any(len(row) != r for row in B):
                raise ValueError("B must be d_out x r")
            if self.merged == name:
                raise RuntimeError("unmerge before changing a merged adapter")
            ad["A"] = [list(map(float, row)) for row in A]
            ad["B"] = [list(map(float, row)) for row in B]

        def _delta(self, ad, x):
            # x A^T (length r), then B (length d_out), scaled: never builds B A
            h = [sum(a * xi for a, xi in zip(row, x)) for row in ad["A"]]
            s = ad["scale"]
            return [s * sum(b * hk for b, hk in zip(row, h)) for row in ad["B"]]

        def forward(self, X, adapters):
            if len(adapters) != len(X):
                raise ValueError("one adapter entry per row")
            for name in adapters:
                if name is not None and name not in self.adapters:
                    raise KeyError(name)
            out = []
            for x, name in zip(X, adapters):
                # policy: a named adapter is always applied to the base weights,
                # so rows naming an adapter ignore whatever is merged
                Wm = self.W if name is None else self.base
                y = [sum(w * xi for w, xi in zip(row, x)) + b for row, b in zip(Wm, self.bias)]
                if name is not None:
                    d = self._delta(self.adapters[name], x)
                    y = [a + b for a, b in zip(y, d)]
                out.append(y)
            return out

        def merge(self, name):
            if self.merged is not None:
                raise RuntimeError("adapter %r is already merged" % self.merged)
            ad = self.adapters[name]
            s, A, B = ad["scale"], ad["A"], ad["B"]
            cols = list(zip(*A))  # d_in columns of A, each length r
            self.W = [[w + s * sum(bk * ak for bk, ak in zip(brow, col)) for w, col in zip(wrow, cols)]
                      for wrow, brow in zip(self.base, B)]
            self.merged = name

        def unmerge(self):
            self.W = [row[:] for row in self.base]
            self.merged = None

## Question

Implement `LoRALinear`: one frozen linear layer that serves several named LoRA adapters, where every row of a batch can name a different adapter or none. Each adapter adds `(alpha / r) * B A x` to the base output, with `A` drawn from a seeded uniform distribution and `B` starting at zero.

Requirements:

- A fresh adapter changes nothing until its weights change, at any rank.
- Rows are independent: a row's output depends only on that row and the adapter it names.
- `merge(name)` folds one adapter into the weights for adapter-free serving; `unmerge()` restores the base. While an adapter is merged, what a row that names an adapter gets is your decision; whatever you choose must never produce a wrong number.
- A batch of 4 rows on a 256 x 256 layer, each row with a different rank-16 adapter, must cost about as much as the base matmul for those rows, measured against a plain Python reference.

Standard library only. The visible tests cover the basic contract; hidden tests check properties on random shapes, the merged state, and the time budget.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask how many multiply-adds the adapter term costs per row if you never form a d_out x d_in matrix, and compare it with the base matmul.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Ask what a row that names the merged adapter should receive, and count how many times that adapter's update would be added.</p></details>

## Answer

The adapter term is computed right to left: `h = A x` has length `r`, then `B h` has length `d_out`, scaled by `alpha / r`. That is `r * (d_in + d_out)` multiply-adds per row, 8,192 for the 256 x 256, rank-16 test, against 65,536 for the base matmul. Forming `B A` first costs `d_out * d_in * r` = 1,048,576 multiply-adds per adapter, 16 times the base row, which is what the timing test catches when every row names a different adapter.

At initialisation `B` is zero, so the delta is exactly zero whatever `A` is: the layer is the base layer at step 0, which is why training starts from the pretrained model's behaviour. The `alpha / r` scale is stored per adapter because adapters of different rank share the layer.

The reference keeps an untouched copy of the base weights. `merge` writes `base + (alpha / r) B A` into the working weights once, which is the one place forming `B A` is right: it is paid once, not per request. `unmerge` copies the base back rather than subtracting, so repeated cycles cannot accumulate rounding error.

The policy decision is the merged state. The reference applies a named adapter to the base weights, ignoring the merge, so a row naming the merged adapter gets its update once and a row naming another adapter is still correct. Raising an error is equally defensible and simpler to reason about in a server; it costs availability during a merge window. The failure the hidden tests reject is the obvious implementation that adds the adapter's delta to the merged weights, so the merged adapter is applied twice and silently.

How the reference can still fail: `set_weights` on a merged adapter would leave the merged weights stale, so it refuses; a server that hot-swaps adapter weights needs the same rule or a re-merge.

## Follow-ups

- *In a real serving engine, rows naming different adapters are grouped so each adapter's `A` and `B` run as one batched matmul per group, or a kernel gathers per-row adapter weights. What does each cost when 500 adapters are loaded and a batch of 64 names 60 of them?*
- *A team wants to merge the adapter into a 4-bit quantised base for deployment. What changes in the numbers your merged forward produces, and how would you measure whether it matters?*
- *Your service keeps 200 adapters resident on one GPU. Which policy for the merged state would you ship, and what would make you reverse it?*

## Common mistakes

- Forming `B A` per row or per request, which turns a cheap term into one larger than the base matmul.
- Initialising both `A` and `B` randomly, so the model changes before training starts.
- Applying the merged adapter's delta again to rows that name it.
- Scaling by `alpha` instead of `alpha / r`, which makes the right learning rate depend on rank.
- Subtracting the delta to unmerge, which drifts after many cycles; keep the base.
