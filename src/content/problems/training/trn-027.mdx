        """Return the set of bad node ids, or None when the test results cannot identify it.

        run_tests(groups) runs one round: groups are disjoint lists of at least two node ids,
        and the result is one bool per group, True when every node in the group is good.
        """

  tests: |
    def make_cluster(n, bad):
        bad = set(bad)
        log = {"rounds": 0, "tests": 0}
        def run_tests(groups):
            seen = set()
            for g in groups:
                assert len(g) >= 2, "a test needs at least two nodes"
                for x in g:
                    assert 0 <= x < n and x not in seen, "groups in one round must be disjoint"
                    seen.add(x)
            log["rounds"] += 1
            log["tests"] += len(groups)
            return [not (set(g) & bad) for g in groups]
        return run_tests, log

  solution: |
    def _first_good_round(n, run_tests):
        # Round-robin pairing (circle method): n - 1 rounds cover every pair once.
        ring = list(range(n)) + ([None] if n % 2 else [])
        m = len(ring)
        for _ in range(m - 1):
            pairs = [[ring[i], ring[m - 1 - i]] for i in range(m // 2)]
            pairs = [p for p in pairs if None not in p]
            found = set()
            for p, ok in zip(pairs, run_tests(pairs)):
                if ok:
                    found.update(p)
            if found:
                return found
            ring = [ring[0], ring[-1]] + ring[1:-1]
        return None


    def find_bad_nodes(n, run_tests):
        if n < 2:
            return None
        nodes = list(range(n))
        k = max(1, min(n // 2, 32))
        size = n // k
        blocks = [nodes[i * size:(i + 1) * size] for i in range(k)]
        blocks[-1].extend(nodes[k * size:])
        good, suspect = set(), []
        for b, ok in zip(blocks, run_tests(blocks)):
            if ok:
                good.update(b)
            else:
                suspect.append(b)
        if suspect and not good:
            found = _first_good_round(n, run_tests)
            if found is None:
                return None  # fewer than two good nodes: every test fails
            good |= found
            suspect = [[x for x in b if x not in good] for b in suspect]
        bad = set()
        work = [(b, True) for b in suspect if b]  # (nodes, known to hold a bad node)
        while work:
            tests, owners, later = [], [], []
            pool = iter(sorted(good))
            for g, has_bad in work:
                if has_bad and len(g) == 1:
                    bad.add(g[0])
                    continue
                halves = [g[:len(g) // 2], g[len(g) // 2:]] if has_bad else [g]
                for h in halves:
                    if len(h) >= 2:
                        tests.append(h)
                        owners.append(h)
                    else:
                        partner = next(pool, None)
                        if partner is None:
                            later.append((h, False))
                        else:
                            tests.append(h + [partner])
                            owners.append(h)
            nxt = later
            if tests:
                for h, ok in zip(owners, run_tests(tests)):
                    if ok:
                        good.update(h)
                    else:
                        nxt.append((h, True))
            work = nxt
        return bad

## Question

<Callout kind="interview" label="Interview question">
"A 512-node job keeps hanging and the traces do not name a node. Write the search that finds every bad node with test jobs, and tell me how many rounds it takes."
</Callout>

There are `n` nodes, numbered `0` to `n - 1`, with `n >= 2`. Some unknown set of them is bad. The only diagnostic is a test job on a group of nodes, which fails if any node in the group is bad and passes otherwise. Tests run in rounds through one call:

```python
run_tests(groups: list[list[int]]) -> list[bool]   # one round; True means the group passed
```

Within one round, no node may appear in two groups, and every group must have at least two nodes (a single node cannot run the multi-node collective the test uses). Tests are deterministic and node status does not change during the search.

Write `find_bad_nodes(n, run_tests)` that returns the exact set of bad nodes. If the results cannot identify the bad set, return `None` instead of a guess.

Two budgets apply on a cluster where tests are job launches, and the hidden tests enforce both on inputs with at most five bad nodes: at most `40 + 3 * d * ceil(log2(n))` tests for `d` bad nodes, and at most `2 * ceil(log2(n)) + 2` rounds. For 4,096 nodes and three bad nodes that is 148 tests and 26 rounds. The visible tests show the harness and one budget case; the hidden tests check other sizes, dense failures and the unidentifiable cases. Your block sizes, split order and padding policy are your choice; only the result and the budgets are checked.

## Answer

<Depth>
<Fragment slot="short">
<p>Test large disjoint blocks first; every passing block yields known-good nodes. Split each failing block in half and test both halves in the same round, padding a one-node half with a distinct known-good node, which turns it into a test of that node alone. A failing one-node half is bad. If no block passes, test disjoint pairs in a round-robin schedule until one passes; if every pair fails, fewer than two nodes are good and the bad set is not identifiable. For d bad nodes in blocks of size b this costs about (blocks) + 2d log2(b) tests and 1 + log2(b) rounds.</p>
</Fragment>
<Fragment slot="long">
<p><b>Why a known-good node matters.</b> A failed group only says "at least one bad node here". A group of one suspect and one known-good node fails exactly when the suspect is bad. The search therefore has two phases: find good nodes, then use them as padding.</p>
<p><b>Phase 1, blocks.</b> The reference splits the nodes into up to 32 contiguous blocks and tests them in one round. With few bad nodes most blocks pass, and their nodes become the padding pool. For 4,096 nodes and three bad nodes the reference uses 74 tests and 8 rounds.</p>
<p><b>Phase 2, halving.</b> Each group known to hold a bad node is split in half, and both halves are tested in the same round. A passing half is cleared; a failing half is known to hold a bad node and is split again; a failing group of one is bad. A half of one node is padded with a distinct good node from the pool; if the pool runs out in a round, that half waits for the next round. Testing both halves wastes one test when the first half passes (the second must then fail), and saves a round when both hold bad nodes; testing one half and inferring the other is the alternative, at about half the tests and up to twice the rounds.</p>
<p><b>Dense failures.</b> If no block passes there is no padding. The reference then runs a round-robin pairing (the circle method, n - 1 rounds that together cover every pair) until some pair passes. That is quadratic in the worst case, and the worst case is inherent: with exactly two good nodes, every group of three or more fails, so only the one good pair can pass and every pair may need testing. With zero or one good node every test fails whatever the bad set is, so the function returns <code>None</code>.</p>
<p><b>The decision.</b> Two strategies are defensible. Pairs-then-pad tests n/2 disjoint pairs in round 1 and resolves failing pairs against good partners in round 2: two rounds, about n/2 + 2d tests. Blocks-then-halve takes about 1 + log2(b) rounds and far fewer tests. If a round is a fixed-length burn-in on nodes that are idle anyway, pairs win; if every test is a job launch or pulls nodes out of a running job, halving wins. The budgets in this question make tests the cost, so pairs-then-pad fails them: 2,048 tests for 4,096 nodes.</p>
<p><b>Failure mode of the reference.</b> Its block count is fixed at 32. With many bad nodes, say one in eight, nearly every block of 128 fails, phase 1 finds no good nodes, and the search falls into round-robin pairing with thousands of tests. A production version would choose the first block size from the expected bad fraction (from the scheduler's own failure log) and fall back to smaller blocks before falling back to pairs.</p>
</Fragment>

The reference solution, in the order it runs:

1. Split the nodes into at most 32 blocks of at least two nodes and test them all in one round.
2. If no block passed, run round-robin pairs until a round has a passing pair; if none ever passes, return `None`. Remove the newly found good nodes from the failing blocks, which still each hold a bad node.
3. Keep a work list of groups, each marked "holds a bad node" or "unknown". Each round, a marked group of one is bad; a marked larger group is split into two unknown halves; an unknown group of two or more is tested as is, and an unknown group of one is tested with a distinct good partner or deferred.
4. Passing groups join the good pool, failing groups go back on the list marked, and the loop ends when the list is empty.

The hidden tests check properties, not a canonical trace: the result equals the true bad set, `None` exactly when fewer than two nodes are good, the round and test budgets on sparse inputs up to 20,000 nodes, and correctness on dense random inputs.

## Follow-ups

- *Test time grows with group size because larger groups cross more switches. How do you pick the first-round block size now?* Minimize total time, not tests: the first round of large blocks is the slowest, so smaller blocks trade tests for time.
- *Nodes join and leave while the search runs. Which of your inferences become invalid?* A pass clears a node only for the moment it ran; a node that left and returned has to be retested.
- *A bad node passes 10% of the time under light load. What happens to the search, and what do you change in the test before you change the algorithm?*

## Common mistakes

- Testing a single node alone, which the rules forbid, or reusing the same good partner for two suspects in one round.
- Treating a failed pair as proof that both nodes are bad.
- Returning all nodes as bad when every test fails, which is wrong whenever exactly one node is good.
- Counting tests and ignoring rounds, or the reverse, without asking which one costs.
- Sequential binary search one test per round, which can meet the test budget and still miss the round budget, because every bad node costs about log2(n) sequential rounds.
