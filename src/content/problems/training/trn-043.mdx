## Question

<Callout kind="interview" label="Interview question">
"DeepSeek-V3 does not rely on an auxiliary loss as its main load balancer. What quantity does it adjust during training to keep expert load even?"
</Callout>

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask whether the report drops tokens when an expert is over capacity.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Ask which number the router uses to scale an expert's output, and whether balancing is allowed to change it.</p></details>

## Answer

Each expert has a bias that is added to its affinity score only for the top-K selection. At the end of every step, an overloaded expert's bias goes down by gamma and an underloaded expert's bias goes up by gamma; the report uses gamma = 0.001 for the first 14.3T tokens and 0 for the last 500B. The gate value that multiplies the expert's output still comes from the original sigmoid affinity, normalised over the selected experts. A small sequence-wise balance loss, alpha = 0.0001, remains as a backstop for individual sequences.

The design separates two jobs that an auxiliary loss mixes. The loss gradient never sees the bias, so the router's parameters are trained only for fit, and balance is enforced by a controller acting on selection.

**Why the others are tempting.** Putting the bias in the gate value is the natural first implementation, and it would make balancing change what each expert contributes to the output, which is what the report avoids. The capacity factor is how Switch-style routers handle overflow, and engineers who learned MoE from Switch expect it, but DeepSeek-V3 drops nothing. An annealed or adaptive loss coefficient is a common tuning answer to "the aux loss hurts quality", and it keeps the coupling the report removes. A router temperature is a reasonable knob for a softmax router, but this one uses a sigmoid.

## Follow-ups

- The report freezes the bias for the last 500B tokens. What could go wrong if it kept updating while the learning rate decays?
- The bias balances counts over a batch. What happens to load inside one long sequence, and which part of the design handles it?
- At inference the traffic mix differs from training. Does the frozen bias still balance it, and what does DeepSeek-V3 do instead?

## Common mistakes

- Describing the method as "no balancing loss at all"; a sequence-wise loss with a small alpha remains.
- Assuming the bias changes the expert's output weight.
- Carrying the Switch capacity-factor model into a dropless design.
