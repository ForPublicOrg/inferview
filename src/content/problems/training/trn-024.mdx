## Question

<Callout kind="interview" label="As a candidate report relays it">
A PracHub entry posted on 2026-09-01 lists this for a Mistral AI software engineer technical screen: explain Adam and AdamW, and why an L2 penalty differs from decoupled weight decay under Adam. The scenario below is written for this site.
</Callout>

Explain the difference. Then: a colleague doubled the peak learning rate of a PyTorch AdamW run from 2 × 10^−4 to 4 × 10^−4 and left `weight_decay` at 0.1, and the run's weight norms now fall faster than in every earlier run. You have one more run before the configuration freezes. What do you set, and why?

## Hints

<details class="hint"><summary>Hint 1</summary><p>Ask which quantity the framework's decay step multiplies the weight by, written out from its documentation.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Ask for the gradient-magnitude distribution of the parameters whose norms moved most.</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>Under Adam, an L2 penalty's gradient λθ goes through the same per-parameter division by √v̂ as the data gradient, so parameters with large gradients get almost no decay and parameters with small gradients get far more than λ. AdamW applies decay to the weights directly, outside the moments, so every parameter shrinks by the same factor per step. In PyTorch that factor is 1 − lr·λ, so doubling the learning rate doubled the decay; to keep the old decay per step I would set λ to 0.05.</p>
</Fragment>
<Fragment slot="long">
<p>Adam's step is lr · m̂ / (√v̂ + ε). With L2, the gradient is g + λθ, and λθ enters both m̂ and v̂. For a parameter whose data gradients are large, √v̂ is large and the decay term is divided down to almost nothing; for one whose gradients are small, √v̂ is dominated by λθ itself and each step removes close to a full learning rate. Loshchilov and Hutter showed the two forms are equivalent for SGD, where nothing divides the gradient, and not for Adam. A small simulation makes it concrete: from θ = 1, with lr 10^−3 and λ = 0.01 over 2,000 steps, a parameter whose gradients have magnitude 0.001 ends near 0.02 under L2, and one with magnitude 10 ends near 1.0; AdamW leaves both at about 0.98.</p>
<p>The schedule: PyTorch's AdamW decay step is θ ← θ − lr·λ·θ, so the survival of a weight that gradients do not defend is about exp(−λ · Σ lr_t). With Kimi K2's published constant phase, lr 2 × 10^−4, λ 0.1 and 149,254 steps, that is exp(−2.985) ≈ 0.05; doubling the learning rate makes it exp(−5.97) ≈ 0.003. That is the faster fall in the weight norms.</p>
<p>Two settings are defensible for the last run. Keep the decay per step: λ = 0.05 with the new learning rate, so lr·λ stays at 2 × 10^−5. Cost: the run tests the learning-rate change alone, but if the earlier λ was itself under-regularising, this preserves the error. Keep λ = 0.1: the run tests the new learning rate with stronger decay, which may be what the higher learning rate needs, at the cost of changing two things in the run that has to be trusted. I would choose λ = 0.05, because the last run before a freeze should change one variable, and I would write down that λ was set by matching lr·λ, not tuned.</p>
<p>How the recommendation fails: matching lr·λ matches the decay of undefended weights, not the balance between decay and gradient updates, which also changed with the learning rate. If the weight norms now rise instead of fall, the matched λ was too weak for the new step size, and that is a finding for the next model, not this run.</p>
</Fragment>

The core of the answer is where λθ enters. In Adam with L2 it is part of the gradient, so it is normalised per parameter like everything else in the gradient. In AdamW it bypasses the moments, and PyTorch's documentation states that it does not accumulate in them. Everything else, including the schedule coupling, follows from writing the decay step out.

## Follow-ups

- *When do Adam with L2 and AdamW give nearly the same result?* Work out the condition from the update rule, and say whether it holds for a transformer's parameters.
- *A colleague claims weight decay barely matters for a run of 150,000 steps.* Answer with the survival arithmetic, and say what a weight would need from its gradients to keep its norm.

## Common mistakes

- Saying AdamW "adds weight decay to Adam", when Adam with L2 already decays, just unevenly.
- Forgetting that PyTorch multiplies the decay by the learning rate, so learning-rate sweeps with λ fixed are sweeps over decay too.
- Treating λ as portable between frameworks without checking how each applies it.
