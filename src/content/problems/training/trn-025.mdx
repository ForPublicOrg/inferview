    import math
    import random


    def cross_entropy(logits, labels, ignore_index=-100):
        used = sum(1 for y in labels if y != ignore_index)
        if used == 0:
            return 0.0, [[0.0] * len(row) for row in logits]
        inv = 1.0 / used
        losses = []
        grad = []
        for row, y in zip(logits, labels):
            if y == ignore_index:
                grad.append([0.0] * len(row))
                continue
            m = max(row)
            exps = [math.exp(v - m) for v in row]
            s = sum(exps)
            losses.append(m + math.log(s) - row[y])
            g = [e / s * inv for e in exps]
            g[y] -= inv
            grad.append(g)
        return math.fsum(losses) * inv, grad


    def _row_loss(row, y):
        m = max(row)
        return m + math.log(sum(math.exp(v - m) for v in row)) - row[y]


    def check_gradient(logits, labels, grad, probes=50, eps=1e-4, seed=0, ignore_index=-100):
        n = len(logits)
        c = len(logits[0]) if n else 0
        used = [i for i, y in enumerate(labels) if y != ignore_index]
        inv = 1.0 / len(used) if used else 0.0
        rng = random.Random(seed)
        if n * c <= probes:
            picks = [(i, j) for i in range(n) for j in range(c)]
        else:
            picks = set()
            for i in rng.sample(used, min(len(used), probes // 2)):
                picks.add((i, labels[i]))
            while len(picks) < probes:
                picks.add((rng.randrange(n), rng.randrange(c)))
            picks = sorted(picks)
        scale = max((abs(g) for i, _ in picks for g in grad[i]), default=0.0)
        floor = max(1e-7, 1e-6 * scale)
        worst, where = 0.0, None
        for i, j in picks:
            if labels[i] == ignore_index:
                numeric = 0.0
            else:
                row = list(logits[i])
                row[j] += eps
                up = _row_loss(row, labels[i])
                row[j] -= 2 * eps
                down = _row_loss(row, labels[i])
                numeric = (up - down) / (2 * eps) * inv
            a = grad[i][j]
            err = abs(a - numeric) / max(abs(a), abs(numeric), floor)
            if err > worst:
                worst, where = err, (i, j)
        return {"max_rel_error": worst, "checked": len(picks), "worst": where}

## Question

<Callout kind="interview" label="The task, as a question bank relays it">
A PracHub entry posted on 2026-09-20 lists, for an OpenAI machine-learning engineer onsite, the mean softmax cross-entropy over an N × C batch of logits and its gradient, written by hand with a stable forward pass and a finite-difference check. OpenAI has not confirmed it. The version below is written for this site, in pure Python because the runner has no NumPy.
</Callout>

Write two functions.

`cross_entropy(logits, labels, ignore_index=-100)` takes `logits`, a list of N rows of C floats, and `labels`, a list of N class indices. It returns `(loss, grad)`: the mean cross-entropy over the rows whose label is not `ignore_index`, and the gradient of that mean with respect to every logit, as a list of lists with the shape of `logits`.

1. Logits can be as large as 10^308 in magnitude. Nothing may overflow, and the loss must be finite whenever the inputs are.
2. Rows with `ignore_index` contribute nothing to the loss, nothing to the gradient, and are not counted in the mean.
3. What a batch in which every label is ignored returns as its loss is your decision, but it must not raise and its gradient must be all zeros.
4. Do not modify the inputs.

`check_gradient(logits, labels, grad, probes=50, eps=1e-4, seed=0, ignore_index=-100)` checks a gradient against central finite differences and returns `{"max_rel_error": float, "checked": int, "worst": (i, j)}`. It must probe at least `min(probes, N × C)` entries. Which entries it probes, and how it defines relative error for entries near zero, are your decisions; a hidden test feeds it a correct gradient, which must score below 10^−4, and three wrong ones, which must each score above a threshold.

Performance: on a 300 × 1000 batch, `cross_entropy` and a 60-probe `check_gradient` each have four seconds in the browser runner.

## Answer

**The forward pass.** Subtract the row maximum before exponentiating: log Σ exp(x_j) = m + log Σ exp(x_j − m) with m = max(x). Every exponent is then at most 0, so nothing overflows, and the largest term is exactly 1, so the sum is at least 1 and its log is safe. Computing softmax first and taking `log(p[y])` is the tempting version, and it fails twice: `exp(1000)` raises `OverflowError` in Python, and a probability that underflows to 0 makes the log −∞. The loss per row is `m + log(s) − x[y]`, never a log of a probability.

**The gradient.** For one row, ∂ℓ/∂x_j = softmax(x)_j − [j = y]. The mean over the counted rows divides every entry by their count, not by N. The reference divides once per row by `used`, the number of rows that are not ignored, and fills ignored rows with zeros. Two properties fall out and make good assertions: each counted row's gradient sums to zero, and only the label entry is negative.

**The policy for an all-ignored batch.** The reference returns 0.0. NaN is the honest value for an empty mean, and it poisons any sum it enters, including a gradient-accumulation buffer. Returning 0.0 keeps accumulation safe and hides a data-pipeline bug that emits empty batches. Either is defensible; the cost of each lands in a different place, and the tests accept both.

**The check: where to probe.** Perturbing logit (i, j) changes only row i's loss, so each probe needs two evaluations of one row, O(C), not two evaluations of the whole batch, O(N × C). The naive check that re-runs `cross_entropy` per probe needs 120 full passes over 300,000 logits for 60 probes and misses the four-second budget. Uniform sampling has a subtler failure: the classic derivation mistake, forgetting the −1 at the label, corrupts only N of the N × C entries, and 60 uniform probes over 300 × 1000 land on a label entry with probability about 60 × 300 / 300,000 = 6%. The reference spends half its probes on label entries of sampled rows and half uniformly.

**The check: relative error near zero.** Non-label entries of a confident row are tiny: with a 40-logit margin the softmax entry is about e^−40 ≈ 4 × 10^−18. The numeric derivative of a loss near 5 has rounding noise around 10^−16 × 5 / 10^−4 ≈ 5 × 10^−12 before the 1/N scale, which swamps it. |a − n| / max(|a|, |n|) then reports a correct gradient as 100% wrong. The reference uses a floor, `max(1e-7, 1e-6 × the largest probed gradient entry)`, in the denominator, so entries far below the gradient's own scale are judged in absolute terms.

**The quantity you choose: `eps`.** Central differences have truncation error proportional to eps² and rounding error near 2^−52 × |loss| / eps. For a loss and third derivative of order 1 the two balance near eps = (2^−52)^(1/3) ≈ 6 × 10^−6, and anything from 10^−3 to 10^−5 keeps both well under the 10^−4 bar for logits of order 1 to 10. The reference uses 10^−4. An eps that is large compared with the logits' scale is biased by curvature; with logits spread over tens of units the softmax is far from linear over a step of 10^−1.

**How the reference fails.** The floor that rescues tiny entries also hides errors in them: a gradient wrong by 10^−9 on an entry of size 10^−10 passes. A check is evidence about the entries it probed and the errors larger than its floor, and the report should say so rather than return one number with no context.

## Follow-ups

- *Run this in a real engine.* PyTorch autocasts `cross_entropy` and `log_softmax` to float32 under mixed precision. Your model computes the loss in a fused kernel that takes BF16 logits over a 128k vocabulary. What do you check about its internal accumulation, and how would you test it without reading the kernel?
- *The vocabulary is 256k and the batch is 1M tokens.* Materialising softmax for the backward pass is 256 billion values. What do you recompute instead of storing, and what does the backward pass then cost?
- *A colleague proposes label smoothing of 0.1.* What changes in the gradient, which property in the hidden tests stops holding, and what replaces it?
- *Your check passes on 60 probes and a reviewer asks for confidence that every entry is right.* What can a sample prove, and what would you run instead?

## Common mistakes

- Computing softmax and then its log, which overflows on large logits and returns −∞ on underflowed probabilities.
- Dividing by N instead of the number of counted rows when some labels are ignored.
- Re-running the whole batch per probe, which is quadratic in the batch.
- Sampling probes uniformly, which almost never tests the label entries where derivation mistakes live.
- Pure relative error with no floor, which flags correct gradients on confident rows.
