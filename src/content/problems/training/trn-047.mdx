  solution: |
    import math


    def _softplus(z):
        return max(z, 0.0) + math.log1p(math.exp(-abs(z)))


    def _sigmoid(z):
        if z >= 0:
            return 1.0 / (1.0 + math.exp(-z))
        e = math.exp(z)
        return e / (1.0 + e)


    def _log_softmax(row):
        m = max(row)
        lse = m + math.log(sum(math.exp(x - m) for x in row))
        return [x - lse for x in row]


    def dpo_loss_and_grad(logits, ref_logits, batch, beta, vocab, masked=frozenset()):
        # Cache one log-softmax per distinct context row; a row missing from the table is all zeros.
        zero = [0.0] * vocab
        cache, ref_cache = {}, {}

        def lsm(table, store, ctx):
            if ctx not in store:
                store[ctx] = _log_softmax(table.get(ctx, zero))
            return store[ctx]

        def seq(seq_tokens):
            """Summed log-prob under policy and reference, plus target counts per context."""
            lp = lr = 0.0
            counts = {}
            for prev, tok in zip(seq_tokens, seq_tokens[1:]):
                if tok in masked:
                    continue
                lp += lsm(logits, cache, prev)[tok]
                lr += lsm(ref_logits, ref_cache, prev)[tok]
                row = counts.setdefault(prev, {})
                row[tok] = row.get(tok, 0) + 1
            return lp, lr, counts

        n = len(batch)
        loss = 0.0
        # coef[ctx][tok]: weight on onehot(tok); total[ctx]: weight on -softmax(row ctx).
        coef, total = {}, {}
        for pair in batch:
            pc, rc, cc = seq(pair["chosen"])
            pr, rr, cr = seq(pair["rejected"])
            m = beta * ((pc - rc) - (pr - rr))
            loss += _softplus(-m) / n
            w = -beta * _sigmoid(-m) / n
            for counts, sign in ((cc, 1.0), (cr, -1.0)):
                for ctx, row in counts.items():
                    dst = coef.setdefault(ctx, {})
                    for tok, k in row.items():
                        dst[tok] = dst.get(tok, 0.0) + sign * w * k
                        total[ctx] = total.get(ctx, 0.0) + sign * w * k
        grad = {}
        for ctx, row in coef.items():
            probs = [math.exp(x) for x in cache[ctx]]
            t = total[ctx]
            g = [-t * p for p in probs]
            for tok, c in row.items():
                g[tok] += c
            grad[ctx] = g
        return loss, grad

## Question

<Callout kind="interview" label="The prompt">
"Write the DPO loss and its gradient by hand for a toy language model. No autograd. Then make it fast enough to run on a real-sized batch."
</Callout>

The policy is a bigram model: `logits[c]` is a list of `vocab` next-token logits for context token `c`, and a row missing from the table means all zeros. The reference has the same shape and is frozen. Each pair has a chosen and a rejected token sequence; the log-prob of a sequence is the sum, from position 1, of log softmax(row of the previous token) at the next token. Targets in `masked` (header and end-of-turn tokens, which appear in both responses) are excluded from both log-probs, as Llama 3 does; they still act as context for the token after them.

Return the mean DPO loss over the batch and the gradient with respect to every policy logit, as a dict from context token to a row of `vocab` floats. How you represent zero rows is your choice.

The batch you must handle: 64 pairs of 200-token sequences over a 3,000-token vocabulary, with 40 distinct context tokens, in under 3 seconds of Python in the browser. Derive the gradient first, then count the work your implementation does per token before you run it.

## Answer

**The loss.** For pair i, the margin is m = β[(log π(chosen) − log π_ref(chosen)) − (log π(rejected) − log π_ref(rejected))] and the loss is softplus(−m), averaged over pairs. `softplus(z) = max(z, 0) + log1p(exp(−|z|))` stays finite for margins in the thousands, where `-log(sigmoid(m))` returns inf or nan.

**The gradient.** dL/dm = −σ(−m), so for one pair, dL/d log π(chosen) = −βσ(−m)/n and dL/d log π(rejected) = +βσ(−m)/n. Each scored position contributes log softmax(L_c)[t], whose derivative with respect to row c is onehot(t) − softmax(L_c). So the gradient of row c is

Σ over positions with context c of s · (onehot(t) − p_c)

where s is the pair's coefficient with the sign of its side. Split the sum: the onehot part is a sparse count of (c, t) weighted by s, and the softmax part is p_c times the sum of s over every position with context c. One softmax per distinct row is enough.

**The cost, counted.** A per-position implementation computes a 3,000-entry softmax at 64 × 2 × 199 = 25,472 positions for the policy and again for the reference: about 150 million exponentials. Timed on one laptop in CPython 3.12, the forward pass alone of that version, extrapolated from 8 of the 128 sequences, took about 16 seconds, before any gradient; Pyodide is slower than CPython. The aggregated version computes 40 softmaxes for each table (240,000 exponentials) plus one dictionary update per position. A dense V × V gradient is also out: at V = 3,000 it is 9 million floats to allocate and fill per call, when at most 40 rows are non-zero.

**The tests.** Visible: log 2 when the policy equals the reference, a hand-computed gradient entry, and a finite-difference check of every entry on a small vocabulary. Hidden: finite differences on random tables with masked tokens; each returned row sums to zero (adding a constant to a row changes no softmax); swapping the labels of one pair gives exp(−loss) + exp(−loss swapped) = 1; masked targets contribute nothing; and the time budget on the 64-pair batch.

**Where this fails.** The aggregation assumes the softmax of a row is the same at every position, which holds for a bigram table and for no real transformer. It shows the shape of the computation (sum per-token terms, weight by the pair's σ) but nothing about memory in a real trainer, where the cost is the forward and backward pass through the network for chosen and rejected sequences.

## Follow-ups

- What changes to run this in a real trainer: the reference log-probs come from a cached forward pass of the frozen model, chosen and rejected are concatenated into one batch so they share a forward pass, and the masked-token rule becomes a loss mask over the label tensor. Which of these would you test first, and how?
- Your gradient check passes at β = 0.1 and fails at β = 5 with relative errors near 1e-4. Is the gradient wrong, or is the check? What would you change in the check before touching the code?
- A colleague wants to normalise each sequence log-prob by its token count so that long responses do not dominate. What does that change in the implicit reward, and what would you need to see to accept it?
- The masked set is passed per call. Two teams render the chat template differently and disagree on which tokens are formatting. How do you decide without deciding by rank, and what do you write down?

## Common mistakes

- Computing `-log(sigmoid(m))` directly, which overflows for large negative margins.
- Dropping masked positions as context as well as targets, which changes the next token's row.
- Forgetting the 1/n in the coefficient, so the gradient scales with batch size and the finite-difference check fails by exactly n.
- Building the gradient by finite differences of the loss "to be safe": that is 9 million loss evaluations at this vocabulary.
