  solution: |
    import hashlib
    from array import array

    K, BANDS, ROWS = 128, 16, 8


    def shingles(text, n=5):
        words = text.split()
        if len(words) < n:
            return {tuple(words)} if words else set()
        return {tuple(words[i:i + n]) for i in range(len(words) - n + 1)}


    def jaccard(a, b):
        inter = len(a & b)
        union = len(a) + len(b) - inter
        return inter / union if union else 1.0


    def signature(shingle_set):
        # One SHAKE-128 call per shingle gives K independent 64-bit hashes; the column minimums are the signature.
        rows = []
        for sh in shingle_set:
            row = array("Q")
            row.frombytes(hashlib.shake_128(" ".join(sh).encode()).digest(8 * K))
            rows.append(row)
        return list(map(min, zip(*rows)))


    def dedup(docs, threshold=0.8):
        sets = [shingles(d) for d in docs]
        tables = [{} for _ in range(BANDS)]
        kept, empty_seen = [], False
        for i, s in enumerate(sets):
            if not s:
                # Empty documents are identical to each other: keep the first.
                if not empty_seen:
                    kept.append(i)
                    empty_seen = True
                continue
            sig = signature(s)
            keys = [tuple(sig[b * ROWS:(b + 1) * ROWS]) for b in range(BANDS)]
            checked, duplicate = set(), False
            for table, key in zip(tables, keys):
                for j in table.get(key, ()):
                    if j in checked:
                        continue
                    checked.add(j)
                    # A band collision is evidence, not a verdict: verify the exact similarity.
                    if jaccard(s, sets[j]) >= threshold:
                        duplicate = True
                        break
                if duplicate:
                    break
            if duplicate:
                continue
            kept.append(i)
            # Only kept documents enter the index, so every drop points at a document that survives.
            for table, key in zip(tables, keys):
                table.setdefault(key, []).append(i)
        return kept

## Question

<Callout kind="interview" label="The prompt">
"Write near-duplicate removal for a web crawl. Exact hashing misses pages that differ by one word, and comparing every pair is too slow. Make it fast enough for the set we give you."
</Callout>

Similarity is the Jaccard index of word 5-gram sets, the measure Lee et al. and FineWeb use. Words are the whitespace-separated tokens with case kept; a document shorter than five words is one shingle of all its words. `dedup(docs, threshold)` returns the ascending indices of the documents to keep. The contract has one rule: a document is dropped only when a document you keep is at or above the threshold with it. Which copy of a cluster survives, how many hash functions you use, how you split them into bands, and whether you verify candidates are yours to choose and defend.

The set the hidden tests time: 5,100 pages of 40 words, each ending in one of three 10-word footers (the boilerplate every page on a site carries), 100 of them exact copies, in under 10 seconds of Python in the browser. Pyodide runs slower than CPython, so leave headroom. Before you write the index, work out how many pairs an all-pairs pass compares on that set, and how many candidate pairs a shingle-level inverted index produces when a third of the pages share a footer.

## Answer

**The counts first.** All-pairs on 5,100 pages is 5,100 × 5,099 / 2 = 13,002,450 comparisons. A shingle inverted index looks better until the footer: a 10-word footer contributes 6 shingles that lie wholly inside it, so every page lands in the posting lists of about 1,700 others and the candidate set is still quadratic. Timed on one laptop in CPython 3.12 against the hidden set, a greedy all-pairs version took about 35 seconds and the inverted-index version about 17; the reference below took about 2.

**MinHash.** For a random hash function, the probability that two sets have the same minimum is their Jaccard index. K independent minimums form a signature whose fraction of agreeing positions estimates the index. The reference gets 128 independent 64-bit hashes per shingle from one `shake_128` call and takes column minimums with `map(min, zip(*rows))`, which keeps the inner loop in C. A loop of `(a * h + b) % p` over 128 parameter pairs per shingle is correct and ran about three and a half times slower in one timing of 2,000 pages.

**LSH bands.** Split the signature into b bands of r rows; two documents are candidates if any band matches exactly. The probability is 1 − (1 − s^r)^b. With 16 bands of 8 rows the curve crosses one half near (1/16)^(1/8) = 0.71, and the numbers that matter at threshold 0.8 are:

| similarity s | 0.5 | 0.74 | 0.8 | 0.9 |
|---|---|---|---|---|
| 16 bands × 8 rows (128 hashes) | 0.061 | 0.78 | 0.947 | 0.9999 |
| 20 bands × 6 rows (120 hashes) | 0.27 | 0.97 | 0.998 | 1.0 |

Lee et al. used 450 bands of 20 (9,000 hashes), which gives 0.995 at 0.8 and 0.30 at 0.7. FineWeb used 14 bands of 8 and reports 92% at 0.8. Those are the published points on the same trade.

**Verification.** At 0.74, 78% of pairs become candidates under 16 × 8. Without an exact Jaccard check they are dropped, which breaks the contract; one hidden test plants 40 such pairs. Lee et al. verify with exact Jaccard and then edit similarity above 0.8.

**The keep policy.** The reference is greedy in input order and indexes only kept documents, so every drop points at a survivor. Union-find over all candidate edges is the common alternative, and it fails the chain test: A and B at 0.86, B and C at 0.86, A and C at 0.73. One component, one survivor, and C is dropped against a kept A it is not similar to. Greedy returns A and C; keeping only B is also valid.

**The decision with two defensible answers.** *16 × 8 with verification*: 5.3% of pairs exactly at 0.8 are missed and few candidates need checking (6% at 0.5). *20 × 6 with verification*: 0.2% missed at 0.8, but 27% of pairs at 0.5 become candidates, and on real web text, where many pairs sit near 0.5 because of templates, that is far more exact Jaccard work and more shingle sets to hold. The first is right when verification memory is the limit; the second when the target is memorisation and train-test overlap, where a missed copy is the cost that matters.

**How the reference fails.** Greedy depends on order: the first copy seen survives, which is usually the oldest crawl, not the cleanest page. It keeps every kept document's shingle set in memory for verification, which does not scale to one worker per snapshot. And `shake_128` per shingle is fast here only because the inner loop is in C; at crawl scale the hash family is computed in a compiled pipeline.

**The tests.** Visible: an exact copy, one word changed in 120, two unrelated pages. Hidden: 150 shuffled clusters with up to three one-word variants and shared footers (at least 146 must collapse to one page, every cluster keeps one); every dropped page has a kept page at or above the threshold; 40 pairs at 0.74 both kept; the chain; and the 5,100-page timing with the 100 exact copies removed.

## Follow-ups

- To run this over 96 snapshots on a cluster: signatures become a map step, band keys become a shuffle, and Python's salted `hash()` cannot be used because two workers would disagree. What else changes in the keep policy when there is no single input order?
- Verification holds every kept page's shingle set, which at your corpus size is more than the cluster's memory. Do you drop verification and accept band-only drops, or drop recall at the threshold by using fewer bands? Write down the error you accept.
- FineWeb found per-snapshot dedup beat global dedup in its ablations. What would you need to see in your own ablations to reverse that and dedup globally?
- Two engineers disagree on which copy of a cluster to keep: the oldest URL or the page with the highest quality score. How do you decide without deciding by rank?

## Common mistakes

- Dropping on a band collision without verifying, so pairs well below the threshold disappear.
- Using union-find components and keeping one member, which drops pages that are not near any survivor.
- Computing 128 hash functions as 128 Python-level loops over shingles, then shrinking K until it fits the budget and losing recall.
- Trusting a shingle inverted index on web text, where boilerplate makes the candidate set quadratic.
