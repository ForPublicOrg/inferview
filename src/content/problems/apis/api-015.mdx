## Question

<Callout kind="interview" label="The prompt">
"How do you cap tool calls and spend per request so one runaway session can't cost fifty dollars?" Start with the number: what step limit enforces a given budget?
</Callout>

Scenario numbers. An agent runs on Claude Opus 5.5 at $4.00 per million input tokens and $20.00 per million output tokens. Every step is one model call that re-sends the whole context. The first call sends 8,000 tokens (system prompt, tools, task). Each step then adds 3,000 tokens to the context (the model's output plus the tool result). Each call generates 400 output tokens. Ignore prompt caching for now.

**What is the largest number of steps that keeps one session at or under $2.00?**

## Hints

<details class="hint"><summary>Hint 1</summary><p>Call *k* (counting from 0) sends 8,000 + 3,000 × *k* input tokens.</p></details>
<details class="hint"><summary>Hint 2</summary><p>The input over *n* calls is an arithmetic series: 8,000 × *n* + 3,000 × *n*(*n* − 1) / 2.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Output is flat: 400 × $20 per million is $0.008 a step.</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>15 steps. Fifteen steps cost $1.86 and sixteen cost $2.08, because input grows with the square of the step count: each step re-sends everything before it.</p>
</Fragment>
<Fragment slot="long">
<p>Per step, output costs 400 × $20 / 1,000,000 = $0.008. Input for call <i>k</i> costs (8,000 + 3,000<i>k</i>) × $4 / 1,000,000 = $0.032 + $0.012<i>k</i>.</p>
<p>Summed over <i>n</i> calls: cost(<i>n</i>) = 0.032<i>n</i> + 0.012 × <i>n</i>(<i>n</i> − 1)/2 + 0.008<i>n</i> = 0.04<i>n</i> + 0.006<i>n</i>(<i>n</i> − 1) dollars.</p>
<p>cost(15) = 0.60 + 0.006 × 210 = 0.60 + 1.26 = $1.86. cost(16) = 0.64 + 0.006 × 240 = 0.64 + 1.44 = $2.08. So the cap is 15 steps.</p>
<p>The shape matters more than the number. Doubling the steps roughly quadruples the input bill, so a step cap is a cost cap, and a session that loops is far more expensive than a linear estimate suggests. Enforce the dollar budget directly as well: track spend from the usage fields after every call and stop when the next call would cross it.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>Now turn on prompt caching. Roughly how many steps fit?</em> If each call reads the previous context from cache at $0.20 per million and writes the 3,000 new tokens at $5 per million, a step costs about 0.2 × (8,000 + 3,000<i>k</i>)/1,000,000 + 3,000 × 5/1,000,000 + $0.008, so around $0.025 plus $0.0006<i>k</i>, and the same $2 buys about 50 steps. Recompute with your real hit rate.</li>
<li><em>Which limit do you enforce: steps, tokens or dollars?</em> All three, at different layers: a step cap in the loop, a token budget per call, and a dollar budget per session and per user per day in the gateway.</li>
<li><em>What should the agent do when it hits the cap?</em> Stop calling tools, return what it has with a clear message, and log the session for review.</li>
</ul>
</Fragment>
</Depth>

The accepted band is 14 to 16 steps. An answer near 50 priced every call at the first call's $0.04, a linear model of a cost that grows with the square of the steps.

## Follow-ups

- *Where does the $50 session in the prompt come from?* A loop. Keep going past 15 steps in this model and cost(50) = 2.00 + 0.006 × 2,450 = $16.70, and the session passes $50 at step 89. A repeated identical tool call is the usual cause.
- *How do you detect a runaway before the cap?* Count identical tool calls per session and alert on spend per session at a high percentile, not the mean.
- *What changes for a reasoning model?* Thinking tokens are billed as output, so the flat output term grows and varies with effort.

## Common mistakes

- Pricing every step at the first step's input size, a linear model of a quadratic cost.
- Capping steps without ever checking dollars.
- Forgetting output tokens, which are five times the input price per token here.
- Enforcing the cap only in the prompt ("stop after 15 tool calls").
