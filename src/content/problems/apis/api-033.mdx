    import re

    def terms(text):
        """Lowercase terms: runs of a-z and 0-9."""
        return re.findall(r"[a-z0-9]+", text.lower())

    
    class Retriever:
        def __init__(self, docs):
            """docs: dict of doc_id (str) to text. Expect tens of thousands of documents."""
            raise NotImplementedError

            """Return up to k doc ids, best first.

            Rank by the number of distinct query terms a document contains, highest first.
            Documents sharing no term with the query are never returned. Break ties among
            equal counts however you choose, but the result must not depend on the order
            the documents were inserted in.
            """
            raise NotImplementedError

        def __init__(self, routes, default):
            """routes: dict of route name to a list of example phrases. default: a route name."""
            raise NotImplementedError

            """Return the route whose best example shares the most distinct terms with the query.

            No shared term returns the default. When several routes tie for the best,
            pick a policy (the default, or one of the tied routes) and apply it deterministically.
            """

  solution: |
    import re
    import heapq
    from collections import defaultdict

    _TERM = re.compile(r"[a-z0-9]+")

    
    def terms(text):
        return _TERM.findall(text.lower())

    
    class Retriever:
        def __init__(self, docs):
            self.docs = dict(docs)
            self.postings = defaultdict(dict)          # term -> {doc_id: count}
            self.length = {}
            for doc_id, text in self.docs.items():
                ts = terms(text)
                self.length[doc_id] = len(ts)
                for t in ts:
                    p = self.postings[t]
                    p[doc_id] = p.get(doc_id, 0) + 1

        def search(self, query, k=5):
            q = set(terms(query))
            if k <= 0 or not q:
                return []
            matched = defaultdict(int)
            freq = defaultdict(int)
            for t in q:
                for doc_id, c in self.postings.get(t, {}).items():
                    matched[doc_id] += 1
                    freq[doc_id] += c
            # distinct matches first, then term frequency per length, then doc id for a stable tie-break
            key = lambda d: (-matched[d], -freq[d] / (self.length[d] or 1), d)
            return heapq.nsmallest(k, matched, key=key)

    
    class Router:
        def __init__(self, routes, default):
            self.default = default
            examples = {}
            self.route_of = {}
            for name, phrases in routes.items():
                for i, phrase in enumerate(phrases):
                    ex_id = (name, i)
                    examples[ex_id] = phrase
            self.examples = examples
            self.postings = defaultdict(set)
            for ex_id, phrase in examples.items():
                for t in set(terms(phrase)):
                    self.postings[t].add(ex_id)

        def route(self, query):
            q = set(terms(query))
            hits = defaultdict(int)
            for t in q:
                for ex_id in self.postings.get(t, ()):
                    hits[ex_id] += 1
            best = {}
            for (name, _), n in hits.items():
                if n > best.get(name, 0):
                    best[name] = n
            if not best:
                return self.default
            top = max(best.values())
            winners = [name for name, n in best.items() if n == top]
            return winners[0] if len(winners) == 1 else self.default

## Question

<Callout kind="interview" label="The prompt">
"Rebuild the router and the retriever from our support pipeline without the framework. Keep the behaviour; I will run my own tests against it."
</Callout>

Implement `Retriever` and `Router` in plain Python, standard library only.

`Retriever(docs).search(query, k)` returns up to `k` document ids, ranked first by the number of distinct query terms each document contains. A document that shares no term with the query is never returned. How you order documents with the same count is yours to decide, but the result must not change if the documents are inserted in a different order.

`Router(routes, default).route(query)` picks the route whose best example phrase shares the most distinct terms with the query, returns `default` when nothing is shared, and applies a deterministic policy of your choice when routes tie.

The interviewer's corpus has 30,000 documents and replays 1,000 queries. Building the index has a budget of a few seconds, and the 1,000 queries together must finish in about a second and a half in the browser. A version that scans every document per query takes many times longer.

## Hints

<details class="hint"><summary>Hint 1</summary><p>For a typical query, how many of the 30,000 documents contain at least one of its terms?</p></details>
<details class="hint"><summary>Hint 2</summary><p>Ask what the router should do when two routes match a query equally well, and who handles the default route's traffic.</p></details>

## Answer

The reference solution builds an inverted index once: for each term, a dictionary of document id to term count, plus each document's length. A query touches only the postings of its own terms, counts distinct matches and total frequency per candidate, and takes the top `k` with `heapq.nsmallest` on the key (fewer distinct matches last, then lower frequency per length, then document id). With a vocabulary large enough that each term appears in a few dozen documents, a three-term query looks at under a hundred candidates instead of 30,000, which is the whole performance difference. The document id as the last key is what makes the result independent of insertion order; a solution that relies on dictionary order passes the visible tests and fails the hidden ones.

The router reuses the same idea over example phrases: postings from term to examples, a distinct-match count per example, the best count per route. The reference returns the default route on a tie, on the reasoning that an ambiguous query sent to a specialised prompt is worse than one sent to the general path. Returning a tied route with a fixed preference order is equally acceptable to the tests; what fails is a policy that depends on hash or insertion order.

The hidden tests check properties, not one output: results are unique, at most `k`, all share a term with the query, are ordered by distinct-match count, and no document left out has a higher count than the last one returned; results are identical after reversing insertion order and after changing case and punctuation; every example phrase routes to its own route; ties land on the default or a tied route; and the 1,000-query timing holds at 30,000 documents.

## Follow-ups

- *The distinct-term count treats "refund" and "refunds" as different terms. What do you change, and what does it cost at query time?*
- *Product wants the router to call a model when the keyword router returns the default. Where does that call sit, and what is its timeout and fallback?*
- *To run this in a real client, what changes?* Tokenisation that matches the corpus language, BM25 or embeddings for the secondary score, an index that is built offline and loaded rather than rebuilt per process, and a log of every routing decision with the matched example so misroutes can be replayed.

## Common mistakes

- Rescanning every document per query, which passes the visible tests and misses the time budget.
- Ties broken by dictionary insertion order, which changes results when the corpus is reloaded in a different order.
- Counting term occurrences instead of distinct terms for the primary rank, so one repeated word outranks a document matching the whole query.
- Returning documents with zero shared terms to fill up `k`.
