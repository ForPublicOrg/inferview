## Question

<Callout kind="interview" label="The prompt">
"Here is the architecture section of a proposal a team brought to review. List what you would push back on before you read the checklist."
</Callout>

> **Support assistant v2: architecture**
>
> We will adopt three well-supported frameworks so that we write as little plumbing as possible.
>
> **Orchestration: LangGraph.** A graph with nodes `classify`, `agent`, `await_approval` and `respond`, checkpointed to Postgres per conversation. Each node has a retry policy of 3 attempts with backoff, so transient provider errors never reach the user. Refunds above the threshold wait in `await_approval` for a team lead, which can take overnight.
>
> **Agent: OpenAI Agents SDK.** The `agent` node runs `Runner.run(support_agent, input, session=SQLAlchemySession(conversation_id, engine))` with default settings. `support_agent` has four tools: `search_kb`, `get_order`, `issue_refund` (with `needs_approval=True`) and `escalate`. When `issue_refund` needs approval, the node stores the run state and the graph moves to `await_approval`. Sessions give the agent memory across turns.
>
> **Retrieval: a RAG library.** `search_kb` calls the library's query engine over our help-centre index and returns its response to the agent.
>
> **Provider strategy.** All three libraries support multiple providers, so the design is provider-agnostic and we can move to another vendor without code changes.
>
> **Observability.** We add a Langfuse trace processor with `add_trace_processor` so every span lands in our Langfuse project. Customer messages may contain account details; our data agreement says they stay in our systems and the model vendor's API.
>
> **Cost.** One model call per user turn, at our expected traffic, gives the monthly figure in the appendix.
>
> **Maintenance.** Dependabot opens weekly upgrade pull requests for all three libraries; CI runs the unit tests and merges on green.

## Answer

Two flaws are easy to miss on a first read because each framework is used as documented; the problem is the nesting. The `agent` node runs an agent SDK loop whose default turn cap is 10. A long conversation raises `MaxTurnsExceeded`, and a retry policy that does not filter exception types retries the node up to three times, re-running every tool call made before the cap. And the approval pause lives inside the agent SDK run while the graph's durability lives in LangGraph: if the process restarts or the node retries, LangGraph re-runs the node from its start, the agent run starts over, and the agent can reach `issue_refund` again. The fix is one pause mechanism: let the agent SDK run end when approval is needed, move the refund into its own LangGraph node after an `interrupt()`, and give it an idempotency key.

The data section contradicts the observability section. `add_trace_processor` adds Langfuse beside the default exporter; it does not replace it, so traces with inputs and outputs still go to OpenAI's trace backend. The proposal needs `set_trace_processors` or tracing disabled.

History is held twice, in LangGraph's checkpoints and in the agent SDK's session, with no statement of which is the source of truth. The cost estimate counts one call per turn while the retrieval tool calls a query engine that writes its own answer with a model call, and approvals add more turns. The provider-agnostic claim is weaker than stated: the agent SDK's model provider defaults to OpenAI and its tooling is built around the Responses API. Weekly automatic merges of a pre-1.0 SDK (0.24.0 on 15 October 2026), gated by unit tests and no eval, will change behaviour without anyone deciding to.

Two parts are acceptable with conditions. LangGraph is a reasonable home for an overnight approval if the pause uses its interrupt and the side effect sits after it. The RAG library is reasonable if it indexes and retrieves documents and the agent writes the answer, so there is one model deciding what to say.

## Common mistakes

- Objecting to the number of frameworks without naming a concrete interaction between them.
- Treating "default settings" as safe without reading the defaults.
- Assuming an added trace processor replaces the default exporter.
- Flagging the RAG library as redundant when the real issue is the extra synthesis call.
