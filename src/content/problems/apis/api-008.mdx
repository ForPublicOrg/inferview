    def run(call_model, user_msg, tools, max_steps=5):
        """Drive a tool-use conversation until the model answers in text.

        call_model(messages) returns {"content": [blocks]} where a block is
        {"type": "text", "text": ...} or
        {"type": "tool_use", "id": ..., "name": ..., "input": {...}}.

        Append each assistant reply to messages. If it has tool_use blocks,
        run every one (tools maps name to a function), and append ONE user
        message whose content is a list of
        {"type": "tool_result", "tool_use_id": ..., "content": str, "is_error": bool},
        one per call, in call order. Successful results are json.dumps of the
        return value. Unknown tools and exceptions become is_error results.
        With no tool_use blocks, return (joined text, messages).
        Raise RuntimeError after max_steps model calls without a final answer.
        """
        raise NotImplementedError

    import json
    def get_order(order_id):
        if order_id == "missing":
            raise KeyError(order_id)
        return {"order_id": order_id, "status": "shipped"}

    def get_weather(city):
        return {"city": city, "temp_c": 18}

    TOOLS = {"get_order": get_order, "get_weather": get_weather}

    def scripted(*replies):
        seen = []
        it = iter(replies)
        def model(messages):
            seen.append([dict(m) for m in messages])
            return next(it)
        return model, seen

    def use(id_, name, **args):
        return {"type": "tool_use", "id": id_, "name": name, "input": args}

    def text(t):
        return {"type": "text", "text": t}

    model, seen = scripted({"content": [use("t1", "get_order", order_id="A7")]},
                           {"content": [text("Order A7 has shipped.")]})
    answer, msgs = run(model, "Where is A7?", TOOLS)
    assert answer == "Order A7 has shipped."
    assert [m["role"] for m in msgs] == ["user", "assistant", "user", "assistant"], "assistant turns are appended too"
    assert msgs[2]["content"][0]["tool_use_id"] == "t1" and msgs[2]["content"][0]["is_error"] is False
    assert json.loads(msgs[2]["content"][0]["content"]) == {"order_id": "A7", "status": "shipped"}

    model, seen = scripted({"content": [text("Checking both."), use("a", "get_order", order_id="A7"), use("b", "get_weather", city="Pune")]},

    answer, msgs = run(model, "two things", TOOLS)
    results = msgs[2]["content"]

    assert len(seen[1]) == 3, "the second model call sees user, assistant, tool results"

    model, _ = scripted({"content": [use("x", "get_order", order_id="missing")]}, {"content": [text("Not found.")]})
    answer, msgs = run(model, "q", TOOLS)

    model, _ = scripted({"content": [use("y", "delete_everything")]}, {"content": [text("I can't do that.")]})

  solution: |
    import json

    def run(call_model, user_msg, tools, max_steps=5):
        messages = [{"role": "user", "content": user_msg}]
        for _ in range(max_steps):
            reply = call_model(messages)
            messages.append({"role": "assistant", "content": reply["content"]})
            calls = [b for b in reply["content"] if b["type"] == "tool_use"]
            if not calls:
                text = "".join(b["text"] for b in reply["content"] if b["type"] == "text")
                return text, messages
            results = []
            for call in calls:
                fn = tools.get(call["name"])
                if fn is None:
                    out, is_error = f"unknown tool: {call['name']}", True
                else:
                    try:
                        out, is_error = json.dumps(fn(**call["input"])), False
                    except Exception as e:
                        out, is_error = f"{type(e).__name__}: {e}", True
                results.append({"type": "tool_result", "tool_use_id": call["id"],
                                "content": out, "is_error": is_error})
            messages.append({"role": "user", "content": results})
        raise RuntimeError(f"no final answer after {max_steps} steps")

## Question

<Callout kind="interview" label="As a third-party guide describes the phone screen">
"Implementing a tool-use orchestrator", in Python, in under an hour, talking as you go.
</Callout>

Write `run(call_model, user_msg, tools, max_steps=5)`. It drives a conversation in Claude's block format:

- `call_model(messages)` returns `{"content": [blocks]}`. A block is `{"type": "text", "text": ...}` or `{"type": "tool_use", "id": ..., "name": ..., "input": {...}}`.
- Append every assistant reply to `messages` as `{"role": "assistant", "content": blocks}`.
- If the reply has `tool_use` blocks, run each one with `tools[name](**input)` and append one user message whose content is a list of `{"type": "tool_result", "tool_use_id": ..., "content": str, "is_error": bool}`, one per call, in call order. A successful result is `json.dumps` of the return value.
- An unknown tool, or a tool that raises, becomes a result with `is_error: True` and a message the model can read. The loop must not crash.
- A reply with no `tool_use` blocks ends the loop: return the joined text and the message list.
- After `max_steps` model calls without a final answer, raise `RuntimeError`.

The tests drive `run` with scripted fake models, including one reply with two tool calls and a model that never stops calling tools.

## Hints

<details class="hint"><summary>Hint 1</summary><p>The assistant turn goes into `messages` before the tool results, even when it contains only tool calls.</p></details>
<details class="hint"><summary>Hint 2</summary><p>All results for one assistant turn go back in a single user message, matched by `tool_use_id`, not by position.</p></details>
<details class="hint"><summary>Hint 3</summary><p>`tools.get(name)` returns `None` for a tool the model invented.</p></details>

## Answer

The loop is short: call the model, append its turn, collect `tool_use` blocks, stop if there are none, otherwise build one result per call and append them as one user turn. The reference solution wraps each tool in `try/except Exception` and turns the exception into an `is_error` result, so the model can see what went wrong and correct itself, and treats a missing tool the same way.

The details that the tests, and interviewers, check:

- **Pairing by id.** Each `tool_result` carries the `tool_use_id` of its call. Claude rejects a turn whose results do not match the calls; OpenAI's Responses API uses the same idea with `function_call_output` items and `call_id`.
- **The assistant turn is kept.** Dropping the assistant message and sending only results breaks the pairing, because the API needs to see the calls the results answer.
- **Errors are data.** A tool exception goes back as an error result rather than crashing the request. That lets the model retry with corrected arguments, and it is also how loops start, which is why the step cap exists.
- **A step cap.** The model is not guaranteed to stop calling tools. The last test is a model that calls the same tool forever.

## Follow-ups

- *Two tool calls in one turn are independent reads. Make them faster.* Run them concurrently, then append results in call order.
- *One of the tools sends an email. What changes?* Gate it: validate arguments in code, require confirmation for side effects, and pass an idempotency key so a retried step cannot send twice.
- *The model starts thinking before tool calls. Anything to change?* Pass the assistant content back unmodified. On Claude, thinking and redacted thinking blocks must be returned unchanged when tools are in use, so a loop that filters content down to text and tool calls gets a 400.
- *The model calls the same tool with the same arguments three times in a row. What do you add?* A repeat guard keyed on tool name and arguments, and typed errors that say whether a failure is worth retrying.

## Common mistakes

- Sending results without appending the assistant turn first.
- One user message per tool result instead of one per assistant turn.
- Letting a tool exception propagate and kill the request.
- No step cap, or a cap that silently returns the last text instead of signalling failure.
