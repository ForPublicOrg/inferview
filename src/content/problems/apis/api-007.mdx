## Question

<Callout kind="interview" label="The prompt">
"What is the difference between structured output and function calling?" Answer it by picking the right mechanism for three jobs.
</Callout>

1. A nightly job extracts invoice number, date, currency and total from PDFs into a typed table. A missing field or a wrong type breaks the load.
2. A support assistant chats with customers. Sometimes it needs an order's status, which only your order service knows; most messages need no lookup.
3. The same invoice extraction must also run on an older model behind your gateway that offers JSON mode but no schema enforcement.

Which combination fits?

## Hints

<details class="hint"><summary>Hint 1</summary><p>Which of these jobs needs your code to run something in the middle of the conversation?</p></details>
<details class="hint"><summary>Hint 2</summary><p>What exactly does JSON mode promise, and what does it leave to you?</p></details>

## Answer

The first choice is correct. Structured output answers "give me data in this shape": the provider constrains decoding to your schema, so the nightly load gets the fields and types it needs. Tool calling answers "you may ask my code to do something": the model returns a call, your code decides whether to run it, and the result goes back into the conversation. With `tool_choice` set to `auto`, the model can skip the tool when a message needs no lookup. The older model offers syntax only, so the schema check moves into your code, with a capped loop that sends validation errors back for a corrected reply.

Why the others are tempting. JSON mode sounds like a guarantee, but it is about syntax; OpenAI's own guide recommends Structured Outputs over JSON mode when possible. A boolean "should I look this up" field reinvents tool calling without the protocol, and you still have to make a second call. Forcing a tool to obtain a shape was a well-known trick before native structured outputs, and it now fails outright on the newest Claude models.

## Follow-ups

- *When would you use both in one request?* A tool-using assistant whose final answer must match a schema: tools during the conversation, structured output for the last turn.
- *Can a tool's arguments be strict too?* Yes. Claude tools and OpenAI functions both accept `strict: true`, which applies the same grammar constraint to the arguments.
- *What does tool calling cost that structured output does not?* At least one extra round trip per tool call, plus the tokens of the tool definitions on every request.

## Common mistakes

- Treating JSON mode as schema enforcement.
- Using tool calling purely to get a shape and then never executing anything.
- Assuming forced tool choice works on every provider and model.
