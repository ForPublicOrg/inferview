## Question

<Callout kind="interview" label="Interview question">
"Design a platform that runs coding agents for customers: a user assigns an issue, the agent works in the customer's private repository for up to two hours, and it opens a pull request. Cover session state, sandboxes, credentials, network egress and cost per task."
</Callout>

Operating constraints (scenario): four engineers, a launch in one quarter, and a first enterprise customer whose security team forbids long-lived credentials inside any container that runs generated code. Finance wants a cost-per-merged-pull-request figure before launch, and you choose the budget you defend.

## Hints

<details class="hint"><summary>Hint 1</summary><p>What share of sessions in the beta needed a container in their first turn, and how long did a cold container take to start?</p></details>
<details class="hint"><summary>Hint 2</summary><p>Which tools in the customer's workflow sign requests or exchange a secret for a token, and which send a static key in a header?</p></details>
<details class="hint"><summary>Hint 3</summary><p>Which hosts on the proposed egress allowlist accept writes from any account holder?</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>Three components with narrow interfaces. The session is an append-only event log in a durable store; the harness is stateless and any worker can resume a session from the log; sandboxes are provisioned on the first tool call that needs one. No credential sits in a sandbox: the repository token is used at clone time and held by the git remote, MCP tokens live in a vault behind a proxy, other secrets are placeholders substituted at egress. The egress proxy enforces a host list and forwards writes only with platform-issued identities. Cost per merged pull request is tokens plus runtime divided by merge rate, gated per release.</p>
</Fragment>
<Fragment slot="long">
<p><strong>State.</strong> A two-hour session cannot live in one process. The harness writes every model response, tool call and tool result to the session log before acting on it. A crashed harness is replaced: the scheduler wakes a new worker, which rebuilds context from the log. Side-effecting calls (push, open pull request, comment) carry an idempotency key of session id plus event index, because a resumed harness may re-issue the last one.</p>
<p><strong>Sandboxes.</strong> Provision on first need. Anthropic reports roughly 60 percent lower p50 and over 90 percent lower p95 time to first token after moving to lazy provisioning. The sandbox holds the clone, runs the build and tests, and has no network route except the egress proxy. Repository hooks, setup scripts and instruction files run inside it only, because the repository is untrusted input.</p>
<p><strong>Credentials: the decision.</strong> Two defensible designs for tools that need secrets. (a) Egress substitution: the sandbox sees a placeholder, the proxy swaps in the secret for allowed hosts. Cost: breaks clients that sign requests (SigV4) and leaks tokens obtained by exchange, since substitution is outbound only. (b) Brokers: secret-holding tools run outside the sandbox as MCP servers or platform services. Cost: every tool is engineering work, and four engineers have one quarter. I would use substitution for header-authenticated APIs and brokers only for the customer's cloud SDK, and list every other tool as unsupported at launch in the risk note.</p>
<p><strong>Egress.</strong> Deny by default, a per-environment host list, and identity binding on every write-capable host. Anthropic's Cowork incident is the reason: an allowlisted API accepted an upload authenticated with the attacker's own key. The proxy forwards to the code host and the model provider only with credentials the platform issued to this session.</p>
<p><strong>Cost per task (the reader chooses the budget).</strong> On Claude Sonnet 5.5, a task that reads 2M cached tokens ($0.20), writes 150k to the cache ($0.375) and emits 40k output tokens ($0.40) costs about $0.98 in tokens; 20 minutes of runtime at $0.08 per session-hour adds $0.027. If 50 percent of pull requests merge, a merged pull request costs about $2. Any budget between about $1 and $5 per merged pull request is defensible if it is stated with the merge rate it assumes; a budget per attempt without a merge rate is not, because failed attempts are paid in full.</p>
<p><strong>Constraint conflict and what I give up.</strong> Security forbids secrets in containers; the customer's deploy scripts call a cloud CLI that signs requests. I give up running those scripts in the agent at launch: the agent can edit them but not execute them, and the pull request's CI runs them with CI's own credentials.</p>
<p><strong>Failure mode of this design.</strong> The session log holds every file the agent read and every command output, including secrets printed by a misconfigured test. It is the most sensitive store on the platform, so it needs per-tenant encryption keys, a retention limit and a scrubbing pass on tool results before they are written. A design review that approves the vault and forgets the log has moved the secret, not removed it.</p>
<p><strong>Written artefact: risk note (excerpt).</strong> "At launch, tools that sign requests or exchange credentials do not run inside sandboxes. Session logs are encrypted per tenant and retained 30 days (scenario value, set with the customer). Residual risk: a secret printed to stdout is stored in the log until the retention limit unless the scrubber matches it. Owner: platform lead. Review: before the second enterprise customer."</p>
</Fragment>

### Rubric

- Puts session state in a durable log outside the harness and explains how a new worker resumes a session
- Adds idempotency keys to side-effecting tool calls because resumes repeat the last call
- Provisions sandboxes lazily and says when a warm pool would be needed instead
- Keeps every credential out of the sandbox and names at least two tool classes that egress substitution cannot serve
- Binds write-capable allowlisted hosts to platform-issued identities rather than trusting a host list
- Computes cost per merged pull request from a stated merge rate and defends a budget
- States what is given up at launch and writes a risk note with an owner
- Names the session log as a sensitive store with retention and encryption

## Follow-ups

- *The customer asks for an audit trail of every command the agent ran.* The session log is the audit trail; what changes is retention and who can read it, which moves the log under the customer's data-processing terms.
- *A harness upgrade breaks resume for sessions started on the old version.* Record the harness version as the first event and resume on the version that started the session until it drains.
- *Finance asks why cost per merged pull request rose after a model upgrade with the same per-token price.* Ask for output tokens per task and merge rate before and after; a tokenizer change or longer reasoning moves cost without a price change.

## Common mistakes

- Putting the repository token in an environment variable "because the agent needs to push", which makes it readable by any code the agent writes.
- Treating a host allowlist as exfiltration control when hosts on the list accept uploads from any account.
- Quoting cost per attempt without the merge rate.
- Persisting the harness's in-memory state instead of the event log, so a crash loses everything since the last snapshot.
