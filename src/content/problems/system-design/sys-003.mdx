## Question

<Callout kind="interview" label="Interview question">
"Estimate the daily model cost of our RAG assistant, and tell me what prompt caching does to it."
</Callout>

Numbers the interviewer gives you when you ask:

- 1,000,000 queries a day.
- Every request starts with the same 2,000-token prefix (system prompt, tool definitions, examples).
- Then 1,500 tokens of retrieved chunks and the user's question, different every time.
- Answers average 300 output tokens.
- Prices (Claude Sonnet 5 list, checked 28 Oct 2026), per million tokens: $2 input, $10 output, $2.50 to write the 5-minute cache, $0.20 to read it.
- With the prefix cached, 90 percent of requests hit the cache. A miss writes it.

What is the daily cost with caching on? Give dollars per day.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Only the 2,000-token prefix is cacheable; the other 1,500 input tokens are billed at full price every time.</p></details>
<details class="hint"><summary>Hint 2</summary><p>Work out the cost of one request, then multiply by a million.</p></details>
<details class="hint"><summary>Hint 3</summary><p>The cache write is 1.25 times the input price and the read 0.1 times, so the prefix costs 0.9 × 0.1 + 0.1 × 1.25 of its uncached price.</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>About <b>$6,860 a day</b>. Without caching each request is 3,500 input tokens at $2 and 300 output at $10 per million, one cent, so $10,000 a day. Caching makes the prefix cost 0.215 of its list price on average, which saves $3,140 a day. The remaining bill is split evenly between the uncached input and the output.</p>
</Fragment>
<Fragment slot="long">
<p>Per request, uncached: input 3,500 × $2 / 1,000,000 = $0.0070; output 300 × $10 / 1,000,000 = $0.0030; total $0.0100, so $10,000 a day.</p>
<p>With caching, the prefix multiplier is 0.9 × 0.1 (hits) + 0.1 × 1.25 (misses that write) = 0.215. Prefix: 2,000 × $2 × 0.215 / 1,000,000 = $0.00086. Other input: 1,500 × $2 / 1,000,000 = $0.0030. Output: $0.0030. Total $0.00686 a request, $6,860 a day.</p>
<p>What I'd say next: the cache now covers about 13 percent of the bill and the rest is retrieved context and output, about 44 percent each, so the next savings come from sending fewer chunks, shorter answers, or a cheaper model for easy questions. The cache pays off only above a hit rate of about 21.7 percent, where 0.1h + 1.25(1 − h) = 1, so I would put everything volatile after the prefix and alert on the cache-read ratio.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>What if the hit rate is 20 percent?</em> $10,080 a day, more than with no cache.</li>
<li><em>What about Batch?</em> Anything that can wait for a batch job gets 50 percent off input and output on Anthropic's price list, and the discounts stack with caching.</li>
<li><em>How do you check this after launch?</em> Sum cache-read, cache-write and uncached input tokens from the usage fields per request and compare with the plan daily.</li>
</ul>
</Fragment>
</Depth>

The accepted band, $6,000 to $7,500 a day, covers rounding and the common simplification of pricing a miss at the plain input rate instead of the write rate ($6,760). Answers near $10,000 forgot the cache; answers near $3,900 forgot the output tokens.

## Follow-ups

- *Where does a 90 percent hit rate come from?* Traffic high enough that the same prefix is read again within the cache lifetime, and a prefix that is byte-identical across requests. Measure it; do not assume it.
- *How does the answer change on a model with a 0.05x cache read?* The prefix drops further (to $6,680 a day with these numbers), which matters less than you would think because the prefix is already a small share.
- *What would make the estimate badly wrong?* Conversation history re-sent every turn, agent loops with several calls per query, and a model whose tokenizer turns the same text into more tokens.

## Common mistakes

- Applying the cache discount to all input, including the retrieved chunks that change every request.
- Forgetting that a miss writes the cache at a premium.
- Quoting a cost per token instead of per request and per day.
- Hard-coding prices without the date they were checked.
