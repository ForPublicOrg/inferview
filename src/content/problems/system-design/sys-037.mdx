## Question

<Callout kind="interview" label="Interview question">
"You ship a coding agent that runs on developers' laptops. Design its product telemetry so that it can never upload repository contents or secrets, and so that the privacy setting means what it says."
</Callout>

Operating constraints (scenario): the agent team wants full transcripts to debug failed sessions; legal has promised enterprise customers that no source code leaves the laptop except as model context the user requested; the client ships weekly and older versions stay installed for months.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Which processes in the client can open a network connection today, and which libraries in it auto-instrument HTTP calls or capture crash context?</p></details>
<details class="hint"><summary>Hint 2</summary><p>What questions does the agent team actually answer with transcripts, and how many of them need the text rather than counts and timings?</p></details>
<details class="hint"><summary>Hint 3</summary><p>When the privacy setting is off, which component checks it: the client, or the server that receives the data?</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>Make leakage impossible by construction, not by filtering. Telemetry events are typed records whose fields are enums, bounded integers and durations; there is no field that accepts free text, so code, paths and error messages cannot be put in one. The privacy setting is enforced in the client at the point of egress, and no server flag can widen collection. Model context and telemetry are separate channels with separate consent. Crash reports drop stack-frame locals and messages. A canary test plants secrets in a repository and the environment and fails the release if any canary byte leaves the machine. Transcripts for debugging are opt-in per session, uploaded only by an explicit user action.</p>
</Fragment>
<Fragment slot="long">
<p><strong>The decision.</strong> (a) A schema allowlist: only typed fields, no strings except members of enums compiled into the client. Strong guarantee, cheap to audit, but the agent team loses the text of failures and debugs from counts, timings and error classes. (b) Redacted traces: full transcripts passed through a secret scanner and path redaction. Rich debugging, but the guarantee is only as good as the scanner, and a scanner cannot recognise proprietary source code as sensitive. The requirement says "never", which only (a) can meet, so the default channel is (a) and text leaves only through (c): a user-initiated "send this session" action that shows the payload before upload.</p>
<p><strong>Enforcement point.</strong> One egress module owns every outbound connection from the client. It accepts two message types: model requests (to the configured provider, carrying the context the user's task needs) and telemetry records (typed). It reads the privacy setting locally on every send. Server-side configuration can reduce what is collected but cannot add fields, because a field the client binary does not know cannot be serialised. Third-party libraries that auto-instrument HTTP or capture breadcrumbs are configured to drop bodies and headers, and the release test proves it.</p>
<p><strong>Quantity to defend.</strong> A size bound per telemetry record. If every field is an enum, a bounded integer or a duration, a record of 30 fields (scenario count) with keys and values of at most 16 bytes each is at most 30 × 32 = 960 bytes, so a 1 KB bound fits every valid record. Any record above the bound is a schema violation and is dropped and counted, so a code path that starts stuffing content into a field is caught by size before anyone reads it. Choose the bound from the schema, not from observed traffic; a bound picked from traffic grows with every leak.</p>
<p><strong>Proof, not policy.</strong> Every release runs a canary test: a fixture repository and environment seeded with unique canary strings in source files, a `.env` file, git history and an environment variable; scripted sessions exercise every tool and a forced crash; a recording proxy captures all outbound bytes, and the release fails if any canary appears outside model requests the session made by design. Anthropic used the same idea operationally, planting a canary string in a Slack thread once it learned its agents could read Slack.</p>
<p><strong>Constraint conflict and what I give up.</strong> Debuggability against a legal promise. I give up routine access to failure text; the agent team gets error classes, tool names, step counts and timings, plus opted-in sessions. Their mean time to diagnose rises, and I write that down.</p>
<p><strong>Failure mode of the recommended answer.</strong> Error classes are enums, but an exception class can be defined by the user's code: the agent runs the user's tests, and their exception names, test names and file paths are user-defined strings. If the enum mapping falls back to "use the class name" for unknown errors, repository-defined names leak. The mapping must fall back to "other". A second gap: model context itself. The guarantee covers telemetry; the model request carries code by design, so the user-visible log of outbound requests (destination, byte count, purpose) is part of the design, not a feature.</p>
<p><strong>Written artefact: decision memo (excerpt).</strong> "Telemetry carries no strings outside compiled enums. Transcripts leave only by user action. Cost: slower diagnosis of field failures. Reversal condition: if more than a set share of severity-one bugs (threshold agreed with the agent team) cannot be diagnosed from telemetry and opted-in sessions within a quarter, revisit an on-device summariser with a reviewed output schema."</p>
</Fragment>

### Rubric

- Chooses a typed schema with no free-text fields over redact-then-send, and states why only that meets "never"
- Enforces the privacy setting in the client at egress, and prevents the server from widening collection
- Separates model context from telemetry with separate consent
- Handles third-party auto-instrumentation and crash reporters explicitly
- Proves the property with a canary test in the release pipeline
- Picks and defends a size bound per record
- Names user-defined identifiers (exception, test and file names) as the leak path in the enum mapping
- States what the agent team gives up and the condition for revisiting it

## Follow-ups

- *Can you use hashed repository identifiers to count active repositories?* A salted per-install hash avoids cross-install linking; an unsalted hash of a public repository name is reversible by anyone who hashes the public list.
- *An enterprise wants the telemetry sent to its own collector instead.* The egress module gets a configured destination; the schema does not change.

## Common mistakes

- A server-side flag that decides whether to store data the client already sent.
- Relying on a secret scanner to keep source code out, when source code is not a secret pattern.
- Testing the privacy toggle in the UI rather than at the network boundary.
