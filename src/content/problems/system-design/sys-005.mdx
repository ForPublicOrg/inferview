## Question

<Callout kind="interview" label="Interview question">
"Our LLM endpoint's p99 latency doubled after Tuesday's deploy. We didn't change the model. Diagnose it."
</Callout>

The service calls a hosted model with a long system prompt marked for caching. The organization's input-token limit is 10,000,000 tokens a minute. You pull the same peak hour from the week before and the week after the deploy. The numbers are synthetic but internally consistent.

The deploy diff touched one file:

```diff
 def build_request(user, question, chunks):
     return {
         "model": MODEL,
         "tools": TOOLS,
         "system": [{
             "type": "text",
-            "text": SYSTEM_PROMPT,
+            "text": f"Current time: {datetime.now().isoformat()}\nCustomer: {user.name}\n\n" + SYSTEM_PROMPT,
             "cache_control": {"type": "ephemeral"},
         }],
         "messages": [{"role": "user", "content": render(chunks, question)}],
     }
```

Pick the root cause. The answer opens once you pick correctly.

## Answer

The deploy put a timestamp and a customer name at the very start of the cached system block. A provider prompt cache matches an exact prefix, so a prefix that begins with the current time is new on every request: each one pays to write the cache (5,150 tokens of creation) and none reads it (0 tokens of cache read). The model now processes the full prefix every time, which is why time to first token roughly doubled at both P50 and P99.

The 429s come from the same change. Only uncached input counts toward the input-token limit on most Anthropic models. Before: (40 + 1,060) × 1,500 = 1,650,000 uncached tokens a minute. After: (5,150 + 1,050) × 1,500 = 9,300,000, close enough to the 10,000,000 limit that bursty minutes cross it.

Why the wrong picks are tempting. Provider overload is the first thing on-call suspects, but it returns 529, and it cannot change the cache fields in your own logs. A larger `max_tokens` would show up in output tokens and in generation time, not time to first token. Traffic growth is ruled out by the flat request rate. Longer retrieval would raise total input, which is identical.

### The fix

```diff
         "system": [{
             "type": "text",
-            "text": f"Current time: {datetime.now().isoformat()}\nCustomer: {user.name}\n\n" + SYSTEM_PROMPT,
+            "text": SYSTEM_PROMPT,
             "cache_control": {"type": "ephemeral"},
         }],
-        "messages": [{"role": "user", "content": render(chunks, question)}],
+        "messages": [{"role": "user", "content":
+            f"Current time: {datetime.now().isoformat()}\nCustomer: {user.name}\n\n" + render(chunks, question)}],
```

Everything that varies per request goes after the cached prefix. Then make the regression impossible to miss: alert when the cache-read share of input drops below its normal band, and add a CI test that builds two requests for different users at different times and asserts the bytes before the last cache breakpoint are identical.

## Follow-ups

- *Would rolling back have fixed it?* Yes, and it is the right first move during the incident. The root cause still needs the layout rule and the test, or the next template change does it again.
- *What else in a prompt silently breaks caching?* Tool definitions that change order or content (tools come first, so they invalidate everything after them), per-request experiment flags, and non-deterministic serialization such as unordered JSON keys.
- *How would you have caught this in staging?* Staging traffic is often too thin to keep a cache warm, so read the cache fields on two back-to-back identical requests in an integration test instead.

## Common mistakes

- Opening a ticket with the provider before comparing your own usage fields across the deploy.
- Raising the rate-limit tier to make the 429s go away, which pays for the bug instead of fixing it.
- Reading only `input_tokens`, which counts tokens after the last breakpoint and hides the shift from cached to uncached.
- Looking at averages only; the P99 doubled too, which rules out a few slow outliers.
