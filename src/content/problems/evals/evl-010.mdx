## Question

<Callout kind="interview" label="The question behind this one">
A public question bank asks which metric a reliability target for a customer-facing support agent should use: pass^k, pass@k or pass@1. Answering "pass^k" is the easy part. Computing it correctly is the part that catches people.
</Callout>

You run a support agent on three tasks, eight trials each, with fresh environments between trials:

```text
task              trials   successes
reset password      8         8
change address      8         6
refund partial      8         2
```

Estimate **pass^4** for this suite, in percent: the probability that four independent trials of a task all succeed, averaged over the three tasks.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Compute it per task first. For a task with c successes in n trials, the chance that 4 trials drawn from the n are all successes is C(c, 4) / C(n, 4).</p></details>
<details class="hint"><summary>Hint 2</summary><p>A task with only 2 successes cannot produce 4 successes in a row from those trials.</p></details>
<details class="hint"><summary>Hint 3</summary><p>Do not pool the 24 trials into one success rate. Compare the two answers when you are done.</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>About 40.5%. Per task: 1 for the task that always succeeds, C(6, 4) / C(8, 4) = 15/70 = 0.214 for the second, and 0 for the third, which has only 2 successes. The average is 1.214 / 3 = 0.405. Pooling all trials into one rate of 16/24 = 0.667 and raising it to the fourth power gives 0.198, which understates reliability by half because it pretends every task is equally flaky.</p>
</Fragment>
<Fragment slot="long">
<p>The estimator. tau-bench defines pass^k over tasks as the average of C(c, k) / C(n, k): the probability that k trials sampled without replacement from the n recorded are all successes. It is unbiased for p^k when trials are independent with a fixed per-task success rate p.</p>
<p>The arithmetic. C(8, 4) = 70. Task 1: C(8, 4) / 70 = 1. Task 2: C(6, 4) = 15, so 15/70 = 0.2143. Task 3: C(2, 4) = 0. Mean: (1 + 0.2143 + 0) / 3 = 0.4048.</p>
<p>Why pooling is wrong. Pooled p = 16/24 = 0.6667 and p^4 = 0.1975. Raising an average to a power is not the average of the powers; with uneven tasks, the shortcut punishes the reliable task for the hopeless one's failures.</p>
<p>What to say next. The suite's reliability is concentrated: one task is solid, one is shaky, one is broken. The per-task view tells you to read the refund transcripts first, and with 2 of 8 successes, to check whether the task or grader itself is at fault before blaming the agent.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>What is pass@4 for the same suite?</em> Per task 1 - C(n - c, 4) / C(8, 4): task 1 gives 1, task 2 gives 1 because only 2 failures exist, task 3 gives 1 - C(6, 4)/70 = 1 - 15/70 = 0.786. Mean 0.929. Same agent, 93% versus 40%.</li>
<li><em>Which one goes in the reliability target?</em> pass^k, with k set by how often a customer repeats the task, because the customer experiences every attempt.</li>
<li><em>What if trials share a cache?</em> They are no longer independent, so pass^k comes out too high. Reset state and avoid cached responses between trials.</li>
</ul>
</Fragment>

### Worked calculation

- C(8, 4) = 8 × 7 × 6 × 5 / 24 = 70
- Task 1, 8 of 8: C(8, 4) / C(8, 4) = 1.000
- Task 2, 6 of 8: C(6, 4) / C(8, 4) = 15 / 70 = 0.214
- Task 3, 2 of 8: C(2, 4) = 0, so 0.000
- pass^4 = (1.000 + 0.214 + 0.000) / 3 = 0.405, or 40.5%

The accepted band, 38 to 43%, allows for rounding. The pooled shortcut, 0.667^4 = 19.8%, is outside it on purpose.

For scale, tau-bench reported that gpt-4o with function calling had a pass^1 of 61.2% on its retail domain, while its pass^8 there was under 25%. That gap between "works once" and "works every time" is the reason the metric exists.

## Follow-ups

- *How many trials per task do you need?* At least k, since C(n, k) needs n ≥ k, and more for a stable estimate. Eight trials for k = 4 leaves some room; for k = 8 you would want more than 8.
- *The independent-trial formula p^k gave 0.75^3 = 42% in Anthropic's example. When is that fine?* As intuition for a single task with a known rate. For a suite of uneven tasks, use the per-task estimator.
- *How would you raise pass^4 here fastest?* Fix or remove the broken refund task if it is a grader problem; otherwise, read the transcripts of the change-address failures to find the variance.

## Common mistakes

- Pooling trials across tasks and raising the pooled rate to the power k.
- Reporting pass@k as reliability, which rewards the agent for any single success.
- Running fewer than k trials and extrapolating.
- Forgetting that a 0-success or near-zero task may be a broken task, not a weak agent.
