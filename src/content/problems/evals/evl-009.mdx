    def judge_report(human, judge):
        if len(human) != len(judge):
            raise ValueError("human and judge must have the same length")
        n = len(human)
        tp = sum(h == "fail" and j == "fail" for h, j in zip(human, judge))
        fn = sum(h == "fail" and j == "pass" for h, j in zip(human, judge))
        tn = sum(h == "pass" and j == "pass" for h, j in zip(human, judge))
        fp = sum(h == "pass" and j == "fail" for h, j in zip(human, judge))
        if tp + fn == 0 or tn + fp == 0:
            raise ValueError("need at least one human pass and one human fail")
        agreement = (tp + tn) / n
        p_h = (tp + fn) / n          # share the human calls a failure
        p_j = (tp + fp) / n          # share the judge calls a failure
        p_e = p_h * p_j + (1 - p_h) * (1 - p_j)
        return {
            "agreement": round(agreement, 3),
            "tpr": round(tp / (tp + fn), 3),
            "tnr": round(tn / (tn + fp), 3),
            "kappa": round((agreement - p_e) / (1 - p_e), 3),
        }


    def corrected_pass_rate(p_obs, tpr, tnr):
        denom = tpr + tnr - 1
        if denom <= 0:
            raise ValueError("judge is no better than chance")
        return min(1.0, max(0.0, (p_obs + tpr - 1) / denom))

## Question

<Callout kind="interview" label="As a public interview guide describes the exercise">
Build an automated eval for a quality criterion on a small set of sample outputs, then tune it against the human labels you are given.
</Callout>

You have human labels and an LLM judge's verdicts on the same outputs, each `"pass"` or `"fail"`. Write two functions.

`judge_report(human, judge)` returns a dict with four numbers, each rounded to 3 decimals. Failure is the positive class, because the judge's job is to find failures:

- `agreement`: the share of outputs where judge and human agree.
- `tpr`: of the outputs the human failed, the share the judge also failed.
- `tnr`: of the outputs the human passed, the share the judge also passed.
- `kappa`: Cohen's kappa, (p_o - p_e) / (1 - p_e), where p_o is the agreement and p_e is the agreement expected by chance from each side's rate of saying "fail".

Raise `ValueError` if the lists differ in length, or if the human labels do not include at least one pass and one fail (TPR or TNR would be undefined).

`corrected_pass_rate(p_obs, tpr, tnr)` takes the share of unlabelled production outputs the judge passed and returns an estimate of the true pass rate, (p_obs + tpr - 1) / (tpr + tnr - 1), clamped to the range 0 to 1. Raise `ValueError` when tpr + tnr is at most 1, because then the judge is no better than chance and the formula is meaningless.

Standard library only.

## Hints

<details class="hint"><summary>Hint 1</summary><p>Count the four cells of the confusion matrix first: both fail, human fail and judge pass, both pass, human pass and judge fail.</p></details>
<details class="hint"><summary>Hint 2</summary><p>p_e = p_h × p_j + (1 - p_h) × (1 - p_j), where p_h and p_j are the shares the human and the judge call "fail".</p></details>
<details class="hint"><summary>Hint 3</summary><p>For the correction, write the observed pass rate as true passes the judge keeps plus true failures it lets through, then solve for the true pass rate.</p></details>

## Answer

The confusion matrix does all the work. With failure as positive, the cells are true positives (both fail), false negatives (human fail, judge pass), true negatives (both pass) and false positives (human pass, judge fail). TPR is tp / (tp + fn), TNR is tn / (tn + fp), and agreement is (tp + tn) / n.

Kappa corrects agreement for chance. If the human calls 10% of outputs failures and the judge calls none, chance agreement is 0.1 × 0 + 0.9 × 1 = 0.9, observed agreement is also 0.9, and kappa is (0.9 - 0.9) / (1 - 0.9) = 0. That is the first test: a judge that always says pass agrees 90% of the time and is worthless. The second test is a judge that catches 8 of 10 failures and wrongly fails 6 of 90 good outputs: agreement 0.92, TPR 0.8, TNR 84/90 = 0.933, and kappa 0.623. The agreement barely moved; TPR and kappa show the real difference.

The correction comes from writing the observed rate in terms of the true rate θ. The judge passes a true pass with probability TNR and a true failure with probability 1 - TPR, so p_obs = θ × TNR + (1 - θ) × (1 - TPR). Solving gives θ = (p_obs + TPR - 1) / (TPR + TNR - 1). With p_obs = 0.785, TPR = 0.6 and TNR = 0.95: (0.785 + 0.6 - 1) / (0.6 + 0.95 - 1) = 0.385 / 0.55 = 0.70. The judge reported 78.5% passing; the estimate of the truth is 70%, because the judge lets 40% of failures through. Clamping matters because sampling noise can push the raw estimate outside 0 to 1.

```python
def judge_report(human, judge):
    if len(human) != len(judge):
        raise ValueError("human and judge must have the same length")
    n = len(human)
    tp = sum(h == "fail" and j == "fail" for h, j in zip(human, judge))
    fn = sum(h == "fail" and j == "pass" for h, j in zip(human, judge))
    tn = sum(h == "pass" and j == "pass" for h, j in zip(human, judge))
    fp = sum(h == "pass" and j == "fail" for h, j in zip(human, judge))
    if tp + fn == 0 or tn + fp == 0:
        raise ValueError("need at least one human pass and one human fail")
    agreement = (tp + tn) / n
    p_h = (tp + fn) / n
    p_j = (tp + fp) / n
    p_e = p_h * p_j + (1 - p_h) * (1 - p_j)
    return {
        "agreement": round(agreement, 3),
        "tpr": round(tp / (tp + fn), 3),
        "tnr": round(tn / (tn + fp), 3),
        "kappa": round((agreement - p_e) / (1 - p_e), 3),
    }


def corrected_pass_rate(p_obs, tpr, tnr):
    denom = tpr + tnr - 1
    if denom <= 0:
        raise ValueError("judge is no better than chance")
    return min(1.0, max(0.0, (p_obs + tpr - 1) / denom))
```

Because the human labels must contain both classes, p_h is strictly between 0 and 1, so p_e is always below 1 and kappa never divides by zero.

## Follow-ups

- *The judge's TPR came from 12 labelled failures. How confident are you in the corrected rate?* Not very. Bootstrap: resample the labelled set and the production sample, recompute the corrected rate each time, and report the 2.5th and 97.5th percentiles. The judgy library does this.
- *Which class is "positive" in the judgy library?* The README does not state the convention; its formula only works if pass is the positive class, so its TPR is P(judge pass | human pass), what this problem calls TNR. Mixing conventions silently inverts the correction, so write the convention next to every number.
- *What would you change in the judge if TPR is 0.6?* Read the false negatives and their critiques, narrow the criterion, add expert examples of the missed failures from the training split, and re-measure on dev.

## Common mistakes

- Treating "pass" as positive in one function and "fail" in the other.
- Reporting agreement alone, which rewards a judge that never flags anything.
- Dividing by zero when every human label is the same, instead of refusing to compute an undefined rate.
- Applying the correction with TPR and TNR measured on the same examples used in the judge's prompt, which overstates the judge's accuracy.
