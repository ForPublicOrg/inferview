    import random


    def judge_rates(human, judge):
        if len(human) != len(judge):
            raise ValueError("human and judge must have the same length")
        tp = fn = tn = fp = 0
        for h, j in zip(human, judge):
            if h not in ("pass", "fail") or j not in ("pass", "fail"):
                raise ValueError(f"labels are 'pass' or 'fail', got {h!r} and {j!r}")
            if h == "fail":
                if j == "fail":
                    tp += 1
                else:
                    fn += 1
            elif j == "pass":
                tn += 1
            else:
                fp += 1
        if tp + fn == 0 or tn + fp == 0:
            raise ValueError("the human labels need at least one pass and one fail")
        return {"tpr": tp / (tp + fn), "tnr": tn / (tn + fp), "failures": tp + fn, "passes": tn + fp}


    def _theta(p_obs, tpr, tnr):
        return min(1.0, max(0.0, (p_obs + tpr - 1) / (tpr + tnr - 1)))


    def corrected_pass_rate(human, judge, production, confidence=0.95):
        r = judge_rates(human, judge)
        if r["tpr"] + r["tnr"] <= 1:
            raise ValueError("the judge is no better than chance on the labelled set")
        n_prod = len(production)
        if n_prod == 0:
            raise ValueError("no production verdicts")
        k_prod = production.count("pass")
        if k_prod + production.count("fail") != n_prod:
            raise ValueError("production verdicts are 'pass' or 'fail'")
        p_obs = k_prod / n_prod
        estimate = _theta(p_obs, r["tpr"], r["tnr"])
        # Resampling a list of binary labels with replacement only changes its count,
        # so each bootstrap draw is three binomial draws instead of len(list) choices.
        rng = random.Random(0)
        nf, npass = r["failures"], r["passes"]
        draws, undefined, b = [], 0, 2000
        for _ in range(b):
            tpr = rng.binomialvariate(nf, r["tpr"]) / nf
            tnr = rng.binomialvariate(npass, r["tnr"]) / npass
            p = rng.binomialvariate(n_prod, p_obs) / n_prod
            if tpr + tnr <= 1:
                undefined += 1
                continue
            draws.append(_theta(p, tpr, tnr))
        alpha = 1 - confidence
        if undefined > alpha / 2 * b:
            return estimate, 0.0, 1.0
        draws.sort()
        lo = draws[int(alpha / 2 * (len(draws) - 1))]
        hi = draws[int((1 - alpha / 2) * (len(draws) - 1))]
        return estimate, min(lo, estimate), max(hi, estimate)

## Question

<Callout kind="interview" label="As a public interview guide describes the take-home">
Build an automated eval from a prompt and thirty sample pairs, then check it against the human labels you are given.
</Callout>

The judge exists and has been run. You have the human labels and the judge's verdicts on the same labelled outputs, and the judge's verdicts on a production sample nobody labelled. Product wants one number for the dashboard: the share of production outputs that really pass, with an interval. Write two functions.

`judge_rates(human, judge)` returns the judge's TPR and TNR with failure as the positive class, and the counts of human failures and passes. It refuses inputs on which those rates are undefined or meaningless.

`corrected_pass_rate(human, judge, production, confidence=0.95)` returns `(estimate, low, high)`. The estimate is the true pass rate implied by the judge's production pass rate and its measured error rates, clamped to 0 to 1. The interval must carry the uncertainty in all three measured quantities: TPR, TNR and the production pass rate. How you compute it is your decision. It must be deterministic for the same inputs, because a release gate that flips on rerun is useless.

Constraints. The production sample can hold 2,000,000 verdicts and the labelled set 20,000 pairs; one call must finish in under three seconds in the browser runtime. Standard library only.

The visible tests show the interface. Hidden tests check properties across judges, labelled-set sizes and base rates, including whether your interval contains the true rate as often as a 95% interval should.

## Answer

**The rates.** One pass over the pairs counts the four cells. With failure positive, TPR is (human fail, judge fail) over human failures and TNR is (human pass, judge pass) over human passes. A labelled set without both classes has an undefined rate, so it raises; so does a label that is neither string, because a typo such as `"Pass"` otherwise lands silently in one cell.

**The estimate.** The judge passes a true pass with probability TNR and a true failure with probability 1 − TPR, so the production pass rate is p_obs = θ × TNR + (1 − θ) × (1 − TPR). Solving for θ gives (p_obs + TPR − 1) / (TPR + TNR − 1). The visible case has the judge failing 30 of 50 labelled failures (TPR 0.6) and passing 95 of 100 labelled passes (TNR 0.95), and passing 785 of 1,000 production outputs: (0.785 + 0.6 − 1) / (0.6 + 0.95 − 1) = 0.385 / 0.55 = 0.70. The judge says 78.5%; the estimate of the truth is 70%. This is judgy's formula with the classes named: judgy labels pass as 1, so its TPR is this problem's TNR. When TPR + TNR ≤ 1 the denominator is zero or negative, the judge carries no information about θ, and the function refuses.

**The interval.** Three quantities are uncertain, and at realistic sizes the smallest count dominates: with 50 labelled failures and 1,000 production verdicts, TPR is the widest input. An interval from the production sample alone, the binomial interval on p_obs pushed through the formula, is the tempting answer and the wrong one; in the hidden coverage test, 150 simulated judges and production samples, it contains the true rate in about 60% of them instead of 95%.

The reference solution bootstraps all three, which is judgy's method. The constraint rules out the naive bootstrap: one resample of 2,000,000 verdicts with `random.choices` took about 0.3 seconds in CPython 3.12 on the machine these tests were written on, so a thousand resamples take about five minutes. But a resample of a pass or fail list changes only its count, and the count of passes in n draws with replacement from a list with pass share p is Binomial(n, p). So each bootstrap iteration is three binomial draws, `random.binomialvariate` (Python 3.12 and later), whatever the list sizes. The work is one pass over the inputs plus a constant per iteration.

Two policy decisions are in the reference, and both have alternatives the tests accept. Resamples in which TPR + TNR ≤ 1 have no estimate; the reference drops them, and if more than the tail share of resamples (2.5% at 95%) are undefined it returns the whole range 0 to 1, because the data cannot bound the rate. Returning an error instead is defensible for a gate; it costs a dashboard that sometimes shows nothing. The generator is seeded with a constant so the interval is deterministic. A delta-method interval, with a small pseudo-count so a measured TPR of exactly 1 does not report zero variance, also passes every test and runs in microseconds; it costs accuracy near the 0 and 1 boundaries, where the bootstrap's asymmetric interval is closer to right.

```python
import random


def judge_rates(human, judge):
    if len(human) != len(judge):
        raise ValueError("human and judge must have the same length")
    tp = fn = tn = fp = 0
    for h, j in zip(human, judge):
        if h not in ("pass", "fail") or j not in ("pass", "fail"):
            raise ValueError(f"labels are 'pass' or 'fail', got {h!r} and {j!r}")
        if h == "fail":
            if j == "fail":
                tp += 1
            else:
                fn += 1
        elif j == "pass":
            tn += 1
        else:
            fp += 1
    if tp + fn == 0 or tn + fp == 0:
        raise ValueError("the human labels need at least one pass and one fail")
    return {"tpr": tp / (tp + fn), "tnr": tn / (tn + fp), "failures": tp + fn, "passes": tn + fp}


def _theta(p_obs, tpr, tnr):
    return min(1.0, max(0.0, (p_obs + tpr - 1) / (tpr + tnr - 1)))


def corrected_pass_rate(human, judge, production, confidence=0.95):
    r = judge_rates(human, judge)
    if r["tpr"] + r["tnr"] <= 1:
        raise ValueError("the judge is no better than chance on the labelled set")
    n_prod = len(production)
    if n_prod == 0:
        raise ValueError("no production verdicts")
    k_prod = production.count("pass")
    if k_prod + production.count("fail") != n_prod:
        raise ValueError("production verdicts are 'pass' or 'fail'")
    p_obs = k_prod / n_prod
    estimate = _theta(p_obs, r["tpr"], r["tnr"])
    # Resampling a list of binary labels with replacement only changes its count,
    # so each bootstrap draw is three binomial draws instead of len(list) choices.
    rng = random.Random(0)
    nf, npass = r["failures"], r["passes"]
    draws, undefined, b = [], 0, 2000
    for _ in range(b):
        tpr = rng.binomialvariate(nf, r["tpr"]) / nf
        tnr = rng.binomialvariate(npass, r["tnr"]) / npass
        p = rng.binomialvariate(n_prod, p_obs) / n_prod
        if tpr + tnr <= 1:
            undefined += 1
            continue
        draws.append(_theta(p, tpr, tnr))
    alpha = 1 - confidence
    if undefined > alpha / 2 * b:
        return estimate, 0.0, 1.0
    draws.sort()
    lo = draws[int(alpha / 2 * (len(draws) - 1))]
    hi = draws[int((1 - alpha / 2) * (len(draws) - 1))]
    return estimate, min(lo, estimate), max(hi, estimate)
```

Where it fails. The interval covers sampling error only. It assumes the labelled outputs are a fair sample of each class as production sees it; if the labelled failures are the obvious ones a human noticed, TPR is overstated and the interval is centred on the wrong value, however narrow.

## Follow-ups

- *Pushback: the interval is 25 points wide and product says it is useless. Do you narrow it by labelling more failures or more production outputs, and how do you decide?* Compute each input's contribution: with these sizes, failures. Each extra labelled failure costs an expert many random labels to find at a low failure share, so the follow-up decision is how to find failures without using the judge to find them.
- *Reversal: what would make you stop reporting the corrected rate and go back to the raw judge pass rate?* Nothing on a dashboard, but for a comparison of two releases on the same production sample with the same judge, the raw difference in judge pass rates has the right sign whenever TPR + TNR > 1, and a paired test on it is simpler.
- *To run this in a real eval pipeline, what changes?* Labels and verdicts are stored per item with the judge version and golden-set version, so a judge change invalidates the rates it produced; the bootstrap runs where the counts are computed, and the dashboard stores (estimate, low, high, judge version, label version), never the estimate alone.

## Common mistakes

- Treating pass as positive in the rates and fail as positive in the formula, or plugging this TPR into judgy's TPR slot.
- An interval from the production sample only, which ignores the widest input.
- A bootstrap that copies two million strings a thousand times.
- Measuring TPR and TNR on examples that appear in the judge's prompt.
