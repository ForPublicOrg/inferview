## Question

<Callout kind="interview" label="As a public question bank phrases it">
"Pairwise comparison or absolute scoring?"
</Callout>

You are choosing between two system prompts for a summariser. You run 300 pairwise comparisons with an LLM judge: each comparison shows the summary from prompt A first and the summary from prompt B second, and asks which is better. Prompt A wins 192 of 300, or 64%. Before you ship prompt A, what should you do first?

## Hints

<details class="hint"><summary>Hint 1</summary><p>Which answer did the judge see first in every single comparison?</p></details>
<details class="hint"><summary>Hint 2</summary><p>Two prompts for the same task often produce summaries of similar quality. What does that do to position bias?</p></details>

## Answer

Swap the order and keep only consistent verdicts. Every comparison put A first, so a judge that prefers the first position would produce exactly this result even if the prompts were equal. MT-Bench measured it: with the order swapped and the default prompt, GPT-4 gave a consistent verdict in 65.0% of cases and favoured the first position in 30.0%; a few-shot prompt raised consistency to 77.5%. A larger study across 15 judges found the inconsistency is worst when the two answers are close in quality, which describes two prompts for the same summarisation task. The fix costs one extra call per comparison: judge (A, B) and (B, A), count A as the winner only if it wins both, B only if B wins both, and everything else is a tie. If A still wins clearly on consistent verdicts, the preference is real.

Why the others are tempting. Moving to absolute scores is a fair long-term choice, and there is evidence for it: Tripathi and colleagues (COLM 2025) found pairwise preferences flipped in about 35% of cases under distractor features against about 9% for absolute scores. But a 1 to 10 scale brings its own noise, binary criteria are the better absolute format, and switching does not diagnose the result you already have. A larger judge is tempting because it feels like quality, but the strongest model in the MT-Bench study still had the bias. More comparisons shrink the interval around 64% without telling you whether 64% measures the prompts or the slot.

### Pairwise or pointwise, then?

Use pairwise, with both orders, when the question really is relative and subjective: which tone, which summary reads better. Use pointwise binary judges per failure mode when you need an absolute bar to gate a release on, such as "the summary omits no action items", because a pairwise win rate cannot tell you whether either option is good enough. You can run both: pointwise judges as gates, pairwise comparisons for preference.

## Follow-ups

- *After swapping, 40% of comparisons are ties. What does that mean?* The judge cannot separate the prompts on those cases; treat them as no preference, and look at the remaining consistent verdicts.
- *How would you also check for length bias?* Compare summary lengths between A and B and whether the winner is usually the longer one, then re-judge a sample with length equalised.
- *Would you trust the judge's preference over users'?* Only as a pre-filter. If the difference matters, confirm with a human-labelled sample or an A/B test.

## Common mistakes

- Running pairwise comparisons in a fixed order, which is the default in many quick scripts.
- Randomising the order once per comparison and never measuring how often verdicts flip. The aggregate win rate becomes fair, but you lose the signal that the judge cannot separate close cases.
- Treating a pairwise win as evidence that the winner is good, rather than better than the alternative.
