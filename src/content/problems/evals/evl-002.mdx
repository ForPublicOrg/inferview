## Question

<Callout kind="interview" label="As a public question bank phrases it">
"Your eval reports 82% pass on 100 examples. What does that number not tell you?"
</Callout>

Start with the part you can compute. The 100 examples are a sample of the inputs your system will see. Treating each example as an independent pass or fail, estimate the **lower end of a 95% confidence interval** for the true pass rate, in percent. Then list what else the number hides.

## Hints

<details class="hint"><summary>Hint 1</summary><p>The standard error of a proportion is the square root of p(1 - p)/n.</p></details>
<details class="hint"><summary>Hint 2</summary><p>A 95% interval is about 1.96 standard errors either side; the Wilson interval pulls it slightly towards 50%.</p></details>

## Answer

<Depth>
<Fragment slot="short">
<p>About 73 to 75%. With p = 0.82 and n = 100 the standard error is about 0.038, so the normal-approximation interval is roughly 74.5% to 89.5%, and the Wilson interval, better near the edges, is 73.3% to 88.3%. Beyond the width, the number does not tell you which failures make up the 18%, whether the 100 examples look like production, whether the grader is accurate, or whether a second run would give the same result.</p>
</Fragment>
<Fragment slot="long">
<p>The interval. A 15-point-wide band means a rival prompt scoring 86% on a different 100 examples is not evidence of anything. To halve the width you need four times the examples.</p>
<p>Representativeness. The interval only describes the population the 100 were drawn from. If they were written before launch, it says nothing about production traffic.</p>
<p>Grader error. If an LLM judge produced the passes, its TPR and TNR shift the observed rate; a judge that misses failures inflates it. Correct for measured judge error, or the interval sits around the wrong centre.</p>
<p>Composition. 18 failures could be 18 instances of one bug, which is one fix, or 18 different problems. Per-category counts matter more than the total.</p>
<p>Repeatability. With sampling, the same 100 cases can produce a different count on a re-run. Measure that noise by running the suite twice with no change.</p>
</Fragment>
<Fragment slot="followups">
<ul>
<li><em>How many examples for a plus or minus 3 point interval?</em> About 630, from n = 1.96² × 0.82 × 0.18 / 0.03².</li>
<li><em>How would you compare two prompts on these 100 cases?</em> Paired: count the cases that flipped each way and test the flips, rather than comparing two intervals.</li>
<li><em>Does a tighter interval mean a better eval?</em> No. It means a more precise estimate of whatever the set measures.</li>
</ul>
</Fragment>

### Worked calculation

Normal approximation:

- standard error = √(0.82 × 0.18 / 100) = √0.001476 = 0.0384
- half-width = 1.96 × 0.0384 = 0.0753
- interval = 0.82 ± 0.075, so 74.5% to 89.5%

Wilson score interval, with z = 1.96 and z² = 3.8416:

- centre = (0.82 + 3.8416 / 200) / (1 + 3.8416 / 100) = 0.8392 / 1.0384 = 0.808
- half-width = 1.96 × √(0.82 × 0.18 / 100 + 3.8416 / 40,000) / 1.0384 = 1.96 × √0.0015720 / 1.0384 = 0.0748
- interval = 73.3% to 88.3%

The accepted band, 72 to 76, covers both methods and rounding. The Wilson interval is the better default for pass rates because it never leaves 0 to 100% and behaves well near the edges, which is where regression suites live.

The sample size for a ±3 point half-width: n = 1.96² × 0.82 × 0.18 / 0.03² = 0.5670 / 0.0009 = 630.

## Follow-ups

- *The cases are not independent: 30 of them are paraphrases of the same five questions. What changes?* The effective sample size is smaller than 100, so the true interval is wider. Cluster the cases and treat each cluster as one unit, or deduplicate.
- *Your manager wants a single number for the dashboard.* Show the rate with its interval and sample size, and the per-category counts underneath.
- *When is 100 examples enough?* For finding failure categories and for must-pass regression cases, often yes. For telling apart two systems a few points apart, no.

## Common mistakes

- Reporting 82% as if it were exact, or comparing it with another run's 85% and declaring a win.
- Using the normal approximation at 99 of 100 and getting an upper bound above 100%.
- Forgetting that the interval covers sampling noise only, not a biased set or a biased grader.
- Answering only the statistics half. The interviewer usually cares more about representativeness and grader error.
