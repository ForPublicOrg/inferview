## A readable secret is a held secret

If a credential is in the sandbox's environment or on a path the agent can read, the agent holds it, and so does anyone who can put text in front of the agent. Anthropic's containment post gives the rate for the plainest case: in a February 2026 red-team exercise, a phished prompt asked Claude Code to read `~/.aws/credentials`, encode it and POST it out, and it did so in 24 of 25 retries, because the instruction came from the user and nothing looked anomalous to the model layer.

So the requirement is not "the agent should not leak the token". It is that the token's value is never in the agent's process, filesystem or context, while requests that need it still authenticate. Four patterns in public products meet some version of that. Three keep the value out by construction; the fourth catches values that got out anyway, at a rate.

## The incident: Nx, August 2025

The Nx advisory and StepSecurity's analysis describe the case that made this concrete for agent tooling. At 6:32 PM EDT on 26 August 2025 (22:32 UTC), a malicious `nx` 21.5.0 was published to npm; by the advisory's timeline, further versions of `nx` and several `@nx/*` packages followed, the last at 8:37 PM EDT; npm removed the affected `nx` versions at 10:44 PM EDT and the affected versions of the other packages at 6:20 AM EDT the next day. Nx's own reconstruction is that the npm token was taken through a `pull_request_target` workflow that interpolated a pull request title into a shell step. StepSecurity puts Nx at about 4 million weekly downloads.

The postinstall script, `telemetry.js`, exited on Windows. Elsewhere, per StepSecurity, it ran the `claude`, `gemini` and `q` CLIs with `--dangerously-skip-permissions`, `--yolo` and `--trust-all-tools` and asked them to find wallets, keys and `.env` files and list the paths in `/tmp/inventory.txt`. It read `gh auth token`, `npm whoami` and `~/.npmrc`, triple base64-encoded what it found, and pushed it as `results.b64` to a new public `s1ngularity-repository` in the victim's own GitHub account. From 28 August, a second wave used the leaked tokens to make private repositories public.

Nothing in the agents was exploited. Malware already running as the user borrowed an installed capability, a filesystem searcher that understands "find anything that looks like a credential", and the flags removed the only gate. The loot was long-lived tokens sitting in files and environment variables that every process of that user could read. The patterns below are about putting the agent's credentials somewhere that is not true.

## Pattern 1: a proxy that checks the operation and attaches the token

Claude Code on the web keeps git credentials and signing keys outside the sandbox. The sandboxed git client authenticates to a proxy with a scoped credential. The proxy checks the credential and the content of the git interaction, such as pushes going only to the configured branch, validates the repository, and only then attaches the real token and forwards to GitHub.

This is the strongest of the four because the proxy understands the protocol. It is not "add a header for this host"; it is "allow a push to this branch of this repository". A prompt-injected agent can push garbage to its own branch and nothing else. Anthropic's deployment guide generalises it as a custom tool or MCP server that forwards to a service outside the boundary, which needs no TLS interception because the authenticated request starts outside. **Holds by construction** for the operations the proxy parses. The cost is one proxy per protocol, and every protocol feature you do not parse is either blocked or a hole.

## Pattern 2: placeholder substitution at egress

Anthropic's Managed Agents vaults (beta, header `managed-agents-2026-04-01`) store an `environment_variable` credential in the sandbox as an opaque placeholder. When a request leaves, a proxy substitutes the real value, but only on hosts in the credential's `allowed_hosts` and only in the locations `injection_location` enables, header or body. A placeholder anywhere else is sent literally. Claude Code's sandbox `mask` mode is the same design for a local machine: a per-session sentinel, `injectHosts`, and TLS termination at the proxy.

The documentation is precise about the edges. Substitution is outbound only: if a client trades the secret for a session token, the returned token arrives in the sandbox unredacted, so you perform the exchange yourself and store the result. Clients that compute a signature from the secret, such as AWS SigV4, produce an invalid signature, though Claude Code's proxy detects a masked AWS key pair and re-signs from v2.1.221. Clients that validate the key format at start-up may reject the placeholder.

## Pattern 3: secrets that exist only during setup

Codex cloud environments run a setup phase and then an agent phase, and the documentation states that secrets configured for the environment "are available only during setup and are removed before the agent phase starts". The agent phase runs offline unless internet access is enabled for that environment. This fits credentials needed only to prepare the workspace: a private registry token for installs, a key to pull fixtures.

**Holds by construction** for the variables removed. It does not cover what setup leaves behind: a setup step that writes a token into a config file, or a package manager that caches credentials on disk, has put the secret on the agent's filesystem. Audit the workspace after setup for exactly that.

## Pattern 4: secret scanning on agent output

GitHub's Copilot cloud agent runs secret scanning, CodeQL and an Advisory Database check on what it produces, and tries to resolve findings before it finishes. It can push to one branch only, cannot run `git push` itself, and the workflows on its pull requests wait for someone with write access. Scanning catches a credential the agent wrote into code, a commit or a pull request.

**Lowers a rate.** Scanning detects known formats in the channels it watches. An encoded value, an unrecognised format, or a channel it does not watch, such as an outbound request, passes. It is the backstop for patterns 1 to 3, not a substitute.

## Redesigning a credential path

Scenario: an agent container receives five environment variables: `GITHUB_TOKEN` (an org-wide personal token with repository write), `NPM_TOKEN` (publish rights), `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` (read on a fixtures bucket), and `DATABASE_URL` (staging, read and write).

- **GitHub** moves to pattern 1: the sandbox gets a session credential for a git proxy that allows pushes only to the task's branch of the task's repository. Issue and pull request calls go through a tool outside the sandbox.
- **npm publish** leaves the agent entirely. Publishing is a pipeline step after review; if installs need a private registry, a read-only token is used in setup only (pattern 3).
- **AWS** fixtures are pulled during setup (pattern 3). If the agent must read the bucket mid-task, use a tool outside the boundary, or masking with SigV4 re-signing where the proxy supports it; plain placeholder substitution breaks signing.
- **The database** cannot use an HTTP proxy at all: Claude Code's documentation notes that most database drivers ignore proxy variables and fail inside the sandbox. It becomes a query tool outside the boundary with a read-only role.
- **Every push and pull request** goes through secret scanning (pattern 4).

The substitution rule itself is small enough to test in isolation:

```python
PLACEHOLDER = "vault-ph-7f3a"
CRED = {"value": "ntn_real", "hosts": {"api.notion.com"}, "header": True, "body": False}

def outbound(host, headers, body):
    """Runs in the proxy, outside the sandbox."""
    if host in CRED["hosts"]:
        if CRED["header"]:
            headers = {k: v.replace(PLACEHOLDER, CRED["value"]) for k, v in headers.items()}
        if CRED["body"]:
            body = body.replace(PLACEHOLDER, CRED["value"])
    return headers, body

def inbound(body):
    """Not in the vault docs: scrub the real value from responses, e.g. a server that echoes headers."""
    return body.replace(CRED["value"], PLACEHOLDER)

auth = {"Authorization": f"Bearer {PLACEHOLDER}"}
assert outbound("api.notion.com", auth, "")[0]["Authorization"] == "Bearer ntn_real"
assert outbound("uploads.example.net", auth, "")[0]["Authorization"] == f"Bearer {PLACEHOLDER}"
assert outbound("api.notion.com", {}, f'{{"text": "{PLACEHOLDER}"}}')[1].count(PLACEHOLDER) == 1
assert inbound('{"echo": "Bearer ntn_real"}') == f'{{"echo": "Bearer {PLACEHOLDER}"}}'
print("ok")
```

The `inbound` scrub is an addition: the vault documentation describes outbound substitution only, so a service that reflects request headers into its response would hand the real value back to the sandbox.

The proxy's host check only holds if the host it checks is the host it connects to. The lab [An egress policy that survives SSRF tricks](/labs/egress-policy) builds that check: allowlists, resolve then pin, private and link-local ranges, and redirects.

## When this is wrong

Keeping the value out stops theft of the value, not abuse of the authority. Patterns 1 and 2 both let an injected agent act with the credential inside their scope, and only pattern 1 narrows the scope to an operation rather than a host. A key with broad permissions behind a perfect proxy is still a broad capability.

The proxy concentrates risk. It holds every secret and parses traffic from code you do not trust, and Anthropic's containment post says the component that failed in its most consequential incident was its own custom proxy, not a standard primitive. Budget for it as a security-critical service.

These patterns protect credentials meant for the agent. They do nothing for credentials that happen to be on the machine the agent runs on, which is what the Nx script harvested: tokens in `~/.npmrc`, the `gh` configuration and `.env` files. On a developer machine the parallel controls are short-lived tokens, credential helpers instead of files, and denying or masking those paths for the agent, as the previous lesson set out.

And output scanning gives a false sense of coverage when it is the only control. It reports the leaks it recognises, which are the ones least likely to be deliberate.
