## The agent is an installer with your credentials

A coding agent on a developer laptop resolves dependencies, adds MCP servers, loads skills and runs whatever the project's scripts say, as the developer, with the developer's tokens in the environment and the developer's SSH keys on disk. Every one of those is a dependency in the supply-chain sense: code written by someone else, fetched at a version you may not have chosen, executed with your authority. The difference from the dependency review you already run is how many paths there are, and that two of them are new: the agent can choose a dependency on its own, and a dependency can drive the agent.

Four public cases cover the shapes.

## Nx: a dependency that drove the local agents

On 26 August 2025 at 6:32 PM EDT, nx 21.5.0 was published to npm with a malicious `postinstall` script; npm removed the affected versions and revoked publish tokens at 10:44 PM the same evening. The Nx advisory traces the publish rights to a GitHub Actions workflow on `pull_request_target`, merged five days earlier, that interpolated a pull request title into a shell command. That trigger runs with elevated permissions, including a `GITHUB_TOKEN`; the maintainers believe the attacker used it to trigger the publish workflow and send the npm token to a webhook.

The payload is the part that matters here. StepSecurity's analysis shows it looked for locally installed AI CLIs and ran them with their permission checks off: `claude --dangerously-skip-permissions -p`, `gemini --yolo -p`, `q chat --trust-all-tools --no-interactive`. The prompt asked the agent to search the filesystem for wallet and credential files and write the paths to `/tmp/inventory.txt`. The script then collected GitHub tokens from `gh auth token`, npm tokens from `~/.npmrc`, SSH keys and `.env` files, triple base64-encoded them, and published them to a new public repository named `s1ngularity-repository` under the victim's own GitHub account. It also appended `sudo shutdown -h 0` to `.bashrc` and `.zshrc`. (Gemini CLI's individual tiers stopped serving on 18 June 2026 in favour of Antigravity CLI; the flag pattern is what carries over, not the product.)

Three details are worth more than the headline:

- The agent did the reconnaissance. The malware did not need its own file-search logic; it delegated to a tool that the developer had already authenticated and that already had a mode for doing anything without asking.
- An editor extension did the install. Nx Console versions 18.6.30 to 18.65.1 installed the `latest` nx package to check its version, so developers who never ran `npm install` in that window could still be hit by opening their editor.
- The exfiltration used the victim's own credentials and a legitimate destination. A new public repository on github.com does not trip an egress filter that allows GitHub.

## Amazon Q Developer 1.84.0: the build token was the dependency

AWS's bulletin AWS-2025-015 (23 July 2025) describes a different entry point to the same place. The Amazon Q Developer extension for VS Code had an inappropriately scoped GitHub token in its CodeBuild configuration. A threat actor used it to commit malicious code to the extension's open-source repository, and that code shipped in release 1.84.0. AWS states the code failed to execute because of a syntax error; it revoked the credentials, released 1.85.0 and removed 1.84.0 from distribution.

The release came out of the legitimate pipeline. Any signature, provenance attestation or marketplace check on 1.84.0 would have described it correctly as built by the vendor's workflow. This is the limit from the previous lesson on signing, met in practice: the control that would have stopped it was the scope of a CI token, which no consumer of the extension can see.

## postmark-mcp: an MCP server is a dependency that reads your mail

The Register (29 September 2025), reporting Koi Security's finding, describes `postmark-mcp` on npm: a copy of Postmark's MCP server, whose real home is GitHub, not npm. The impostor published 15 versions that matched the original, then version 1.0.16 added one line that blind-copied every outgoing email to an address the attacker controlled. It was being downloaded about 1,500 times a week.

The trust model of an MCP server is a package's trust model plus a capability grant: the server runs locally with the user's environment, and the agent routes the user's data through its tools by design. An unpinned `npx postmark-mcp` in a client config is an auto-update channel for code that sees every email the agent sends. Pinning would not have helped a team that upgraded to 1.0.16 without reading the diff; reading the diff would have, because the change was one added line.

## Package hallucination: the agent names a package that does not exist yet

The last path has no attacker in the loop until the model creates the opening. Spracklen and colleagues (arXiv 2406.10279, USENIX Security 2025) generated 576,000 code samples in Python and JavaScript from 16 models and counted references to packages that do not exist in the registries. The paper reports hallucinated packages averaging at least 5.2% for commercial models and 21.7% for open-source models, 205,474 unique names in all, with GPT-4 Turbo lowest at 3.59%. Rates rose with temperature.

The number that turns this into a supply-chain problem is repeatability. Re-running 500 prompts ten times each, 43% of hallucinated package names came back in all ten runs, and 39% never repeated. A name that recurs is a name an attacker can find by running the same prompts and then register with a payload, after which the agent's next `pip install` succeeds. Mitigations in the paper lower the rate but cost something: fine-tuning cut DeepSeek's rate from 16.14% to 2.66% and its HumanEval pass@1 from 51.4% to 25.3%. The control that holds by construction is outside the model: an agent may not add a dependency that the team has not approved, or that is younger than a cooldown, whatever the model believes.

## A policy for a team running coding agents

Written as it would go into the engineering handbook, with each control labelled. "Construction" means the control removes the path; "rate" means it makes the path less likely to work.

| Path | Control | Holds by |
|---|---|---|
| Package installs by humans or agents | Lockfile required; `minimumReleaseAge` of at least 1,440 minutes, exclusions by named package with an owner | construction, for compromises caught inside the window |
| Install scripts | Dependency lifecycle scripts off by default (`allowBuilds` with `strictDepBuilds` in pnpm 11, `--ignore-scripts` elsewhere); each allowed build reviewed | construction, for the `postinstall` path |
| New dependencies proposed by an agent | Added only in a reviewed diff; CI rejects names absent from the registry or younger than the cooldown | construction for absent names, rate for typosquats |
| MCP servers | Project-scope `.mcp.json` in the repository, exact versions with integrity, installed from the publisher's own source, version bumps reviewed as diffs; remote server hosts on the egress allowlist | rate: a reviewed pin can still be malicious |
| Skills and plugins | Reviewed like code, including `allowed-tools`; `allowManagedPermissionRulesOnly` and `disableSkillShellExecution` in managed settings | construction for injected shell, rate for the rest |
| Permission-skipping flags | Only inside a container that runs as non-root, mounts no host secrets, and has an egress allowlist; `permissions.disableBypassPermissionsMode` set to `disable` in server-managed or MDM settings on laptops | construction on laptops; inside the container, rate |
| CI and release tokens | Least scope; no untrusted input in `pull_request_target` workflows; registry publishing by trusted publishing, not long-lived tokens | construction for the token-theft path |
| Detection | Shell history and endpoint telemetry alert on bypass flags outside containers; new public repositories created by developer accounts are reviewed | rate |

Two of these deserve their reasons written next to them. The Claude Code dev container documentation states that with `--dangerously-skip-permissions`, the container does not prevent a malicious project from exfiltrating anything inside it, including the agent's own credentials, and that edits to the bind-mounted workspace appear on the host. The container narrows what a hijacked agent reaches; it does not make the agent trustworthy, which is why the egress allowlist and the absence of host secrets are part of the same line. The same page notes that managed settings copied in by a repository Dockerfile can be removed by anyone with write access to the repository, which is why the laptop setting is delivered by server-managed settings or MDM.

The skills line exists because the Claude Code skills documentation says workspace trust does not gate a project skill's `allowed-tools`: they apply even in a non-interactive run in a folder you have never trusted, and a skill can grant itself broad tool access. A skill in a cloned repository is configuration that widens the agent's permissions, arriving through `git clone`. Setting `allowManagedPermissionRulesOnly` in managed settings makes Claude Code (v2.1.282 or later) ignore `allowed-tools` in project and personal skills, so only rules the organisation delivers pre-approve anything; `disableSkillShellExecution` replaces the shell commands that skills from user, project and plugin sources would run with a notice that policy disabled them.

## When this is wrong

A cooldown is a bet that someone else finds the compromise inside the window. It held for Nx because detection took hours. An attacker who builds trust with clean releases, as postmark-mcp did for 15 versions, can wait for adoption and then ship a payload nobody is looking for, and a fixed delay does not change that. It also delays your own security fixes by the same amount, and the exclusion list that solves that becomes a list of packages with no cooldown at all.

Pinning and review assume there is something to pin. A remote MCP server's code runs on someone else's machine and can change between two requests; the only controls are the scope of the credentials you give it and the data your agent routes through it. Treat it as a third-party SaaS integration, not a dependency.

The hallucination figures come from models and prompts of 2024 and early 2025, measured by the authors on their own prompt set. Newer models may hallucinate fewer names; the repeatability finding, which is what attackers rely on, is the part to re-measure against your own agents before relying on a rate in either direction.

Containers move the boundary; they do not remove it. The workspace is shared with the host, and a hijacked agent that writes a Git hook, an editor task that runs on folder open, or a project skill into the repository has put code on the developer's laptop that runs the next time a human opens it. That path goes through code review, and review is a rate.
