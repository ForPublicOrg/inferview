## The decision

A long-context model spends its serving memory on the KV cache, and the cache grows by a fixed number of bytes for every token of every live sequence. A state space layer, or any linear-attention layer, replaces that cache with a state whose size does not depend on sequence length. The question a serving or model team faces is not "transformer or SSM" but what fraction of layers can be recurrent before retrieval from context degrades, and what that buys in memory. Every shipped hybrid below answers it with one attention layer in four to one in eight.

## What a selective state space layer stores

A linear recurrence keeps a state `h_t = A_t h_(t-1) + B_t x_t` and reads `y_t = C_t h_t`. Classic SSMs fixed `A`, `B` and `C` per layer, which made the recurrence a convolution that trains in parallel but cannot decide, token by token, what to keep. Mamba makes `B`, `C` and the step size functions of the input, so the layer can write some tokens into the state strongly and let others pass. Input dependence rules out the convolution trick, and the paper replaces it with a hardware-aware parallel scan run in recurrent mode. The paper reports 5 times the inference throughput of Transformers and a Mamba-3B that matches Transformers twice its size.

Mamba-2 recasts the same computation as multiplication by a structured semiseparable matrix, the masked attention-like matrix a linear recurrence implies. That duality is what lets the core layer run as chunked matrix multiplications on tensor cores; the paper reports it 2 to 8 times faster than Mamba's. Gated DeltaNet and Kimi's KDA are in the same family with a different update. Instead of only decaying and adding, the delta rule overwrites the value stored under a key, and a gate erases memory quickly. The Gated DeltaNet paper argues the two are complementary and reports gains over Mamba2 on in-context retrieval, among other benchmarks.

For a serving engineer, the state is a fixed-size tensor per sequence per layer. Jamba's Mamba layers use `mamba_expand` 2 on a 4,096 hidden size and `d_state` 16, so each layer holds 8,192 × 16 = 131,072 state values plus a convolution buffer of 8,192 × 3 = 24,576 (kernel width 4, so three past inputs). It is a bounded-size cache entry that is overwritten in place, not appended to.

## What a fixed state cannot do

"Repeat After Me" proves that a two-layer transformer can copy strings of exponential length, while generalised SSMs are limited by their fixed-size latent state. The counting argument is short: a state of `S` bits can be in at most `2^S` configurations, and copying requires distinguishing every possible input string, so no state of `S` bits can copy a uniformly random string longer than `S / log2(V)` tokens from a vocabulary of `V`.

At production sizes the bound is loose. Jamba's 28 Mamba layers hold 28 × 155,648 = 4,358,144 values; at 16 bits that is about 69.7 million bits, enough in principle for millions of tokens. The theorem says a limit exists; it does not say where a trained model hits it. The paper's empirical findings carry the weight: on synthetic copying tasks transformers train more efficiently and generalise better, and pretrained transformers dramatically outperform SSMs at copying and retrieving information from context. A state is a lossy summary written before the question is known. Attention keeps every token, so a question asked at the end of the context can still reach a token the recurrence never prioritised.

That is the product risk: a pure recurrent model does well on perplexity and summarisation-style tasks and fails on "quote clause 14.2 exactly" or "which of these 300 functions calls `foo`".

## What shipped

Every production hybrid listed here keeps some full attention:

| model | layout | attention layers | source |
|---|---|---|---|
| Jamba (AI21) | 1 attention per 7 Mamba, MoE every 2 layers | 4 of 32 | paper and config |
| MiniMax-Text-01 | 1 softmax per 7 lightning attention | 10 of 80 | paper and config |
| Kimi Linear 48B | 3 KDA per 1 MLA, NoPE on MLA layers | 7 of 27 | paper and config |
| Qwen3.8-27B | 3 Gated DeltaNet per 1 gated attention | 16 of 64 | model card and config |

The memory effect is computable from the configs. Jamba's 4 attention layers with 8 KV heads of dimension 128 cache 4 × 2 × 8 × 128 × 2 bytes = 16,384 bytes per token in 16-bit. Mixtral 8x7B has the same attention shape on all 32 layers, 131,072 bytes per token. At 262,144 tokens that is 4 GiB against 32 GiB, the paper's Table 1 figures, recomputed. Kimi Linear's reported "up to 75%" also falls out of its layout: 7 MLA layers of 27 cache, so against an all-MLA stack of the same depth the saving is 1 − 7/27 = 74%.

The fixed state matters at the short end. Qwen3.8-27B's 72 MiB state equals its attention KV at 72 MiB / 64 KiB = 1,152 tokens, so for a chat workload with short prompts the recurrent state, not the KV cache, is most of each sequence's memory. Hybrids pay off at long context, and an engine that reserves the state per slot pays it even for a 50-token request.

MiniMax-01 shows where time goes once attention is a minority. The paper reports that at 1,024,000 tokens the softmax layers are about 95% of inference latency and the lightning layers under 12%: one layer in eight dominates cost at the length the hybrid exists for.

## A memory model you can run

```python
def per_sequence_bytes(tokens, attn_layers, kv_values_per_layer, state_values, bytes_per_value=2):
    """KV that grows with tokens plus recurrent state that does not."""
    kv = attn_layers * kv_values_per_layer * tokens * bytes_per_value
    state = state_values * bytes_per_value
    return kv, state

GIB = 2 ** 30
configs = {
    # name: (attention layers, cached values per attention layer, recurrent state values)
    "Jamba-v0.1": (4, 2 * 8 * 128, 28 * (8192 * 16 + 8192 * 3)),
    "Mixtral-8x7B": (32, 2 * 8 * 128, 0),
    "Kimi-Linear-48B": (7, 512 + 64, 20 * 32 * 128 * 128),
    "Qwen3.8-27B": (16, 2 * 4 * 256, 48 * 48 * 128 * 128),
}
for tokens in (4_096, 131_072):
    for name, (layers, per_layer, state) in configs.items():
        kv, st = per_sequence_bytes(tokens, layers, per_layer, state)
        print(f"{tokens:>7} {name:<16} kv {kv / GIB:6.2f} GiB  state {st / 2**20:6.1f} MiB")
```

Kimi Linear's line assumes the engine caches the 64-wide rotary key as DeepSeek-V3 does; the paper applies NoPE to its MLA layers, so an engine may cache 512 values instead of 576. Short convolution buffers are left out of every state figure except Jamba's.

## What the state does to the rest of the serving stack

Three features built for append-only KV caches need rework:

- Prefix caching. A KV prefix can be truncated at any token. A recurrent state cannot be rewound, so reusing a shared system prompt requires a snapshot of every layer's state at that boundary, and a snapshot every N tokens costs a full state copy each time (72 MiB per snapshot for Qwen3.8-27B in 16-bit).
- Speculative decoding. Rejecting drafted tokens means rolling back the state to before them, which again needs a snapshot or a recomputation.
- Preemption and swapping. The state is small to move, which helps; the attention layers' KV still dominates at long context and behaves as before.

Before adopting a hybrid, check that your engine supports the specific layer type (Mamba, Gated DeltaNet, KDA, lightning) with prefix caching and speculative decoding enabled together, and measure rather than assume.

## When this is wrong

The copying result concerns copying and retrieval. Hybrids with a minority of attention layers may close most of that gap, and the ratio that suffices depends on training; the shipped ratios are the vendors' choices, not a measured threshold.

The memory arithmetic assumes 16-bit caches and states. Engines may keep recurrent state in 32-bit for numerical stability, which doubles every state figure above; check the engine, not the config.

Throughput claims (Mamba's 5 times, Kimi Linear's 6 times at 1M) are the authors' measurements in their setups. At 4K-token workloads the attention share of cost is small and a hybrid's advantage mostly disappears.
