## The mechanism

An autoregressive model produces one token per forward pass and conditions each token on all earlier ones through a causal mask. A masked diffusion language model starts with the answer region fully masked and runs a fixed number of denoising steps. At each step a bidirectional Transformer predicts every masked position at once; the sampler keeps some predictions and leaves the rest masked for the next step.

LLaDA is the clearest public example. Training masks each token of a sequence independently with a ratio drawn at random between 0 and 1 and trains the network to predict the masked tokens. No causal mask is used, so every position sees the whole input. At inference, the number of steps and the generation length are both hyperparameters. LLaDA's default sampler uses low-confidence remasking: after each step's predictions, the most confident ones are kept and the rest are masked again. It also supports block sampling without retraining: the answer is split into blocks generated left to right, with diffusion inside each block. In the paper's ablation, block sampling scored higher on GSM8K and Math for the instruct model, which the authors attribute to early termination from end-of-sequence padding under low-confidence remasking.

The paper reports LLaDA 8B, trained from scratch on 2.3 trillion tokens with 0.13 million H800 GPU hours, as competitive with LLaMA3 8B on in-context learning. Mercury, from Inception Labs, is a commercial diffusion LM described as coarse-to-fine refinement of many tokens in parallel by a Transformer; its paper does not give its step count.

## The compute trade

The speedup is a trade of FLOPs for sequential steps. Take a scenario: a 1,000-token prompt, a 256-token answer.

An autoregressive model with a KV cache runs prefill over 1,000 positions, then 256 decode passes of one position each: 1,256 token-positions of compute, but 257 sequential passes, each of which reads every weight once.

A diffusion model without a cache, at 64 steps, runs 64 passes. Each pass processes the prompt plus the whole answer region, because every position can attend to every other and the answer changes between steps.

At batch size 1, an autoregressive decode step is limited by reading the weights, and the GPU's arithmetic units are mostly idle; a diffusion step uses that idle compute to fill several positions per weight read. LLaDA's Appendix B.7 measures exactly this regime: a single A100-80GB, batch 1, bf16, a 256-token output. At 32 to 256 steps (8 to 1 tokens per pass), the paper reports 1.5 and 1.8 times the throughput of LLaMA3 8B with a KV cache on GSM8K and Math at comparable quality, comparable quality at matched throughput on HumanEval, and LLaDA behind on MBPP.

At high batch, the autoregressive server already reuses each weight read across many sequences and its decode becomes compute-bound. A design that spends 64 times the token-positions then has to win back the difference in fewer steps, and the batch-1 result does not transfer. Ask any vendor for throughput at your concurrency, not at one request.

## What the headline speeds measure

Mercury's paper reports 1,109 output tokens per second for Mercury Coder Mini and 737 for Small on H100s, measured by Artificial Analysis, and states that the models outperform speed-optimised frontier models by up to 10 times on average. The comparison rows in its Table 1 are Artificial Analysis medians across cloud providers: Claude 3.5 Haiku at 61, GPT-4o Mini at 59 and Gemini 2.0 Flash Lite at 201 tokens per second, with prompts of about 1,000 input and 1,000 output tokens, and the Mercury API tested in February 2025.

Read that as a vendor paper quoting a third-party measurement, under these conditions:

- It is output throughput per request, not time to first token or end-to-end latency at a given concurrency.
- The comparison is against the competitors' public APIs, served on hardware and load the paper does not state, against Mercury on H100s.
- The models compared are coding models on 2025 benchmarks; a 2026 chat product is a different workload.
- The paper's Copilot Arena latency is 0.25 seconds in Table 4 and 25 ms in the text. Until the vendor resolves which is right, neither belongs in a design document.

## What changes in the serving stack

Streaming. An autoregressive stream can show each token as soon as it is sampled, and a token once shown is final. With pure diffusion over the whole answer, the first position is final only when the sampler decides to keep it, which may be late; showing tokens in position order means waiting for the leftmost undecided one. Block sampling restores a left-to-right stream at block granularity: nothing in a block is shown until the block is finished. Time to first visible token becomes the time to finish the first block, and the stream arrives in bursts of block length. If the sampler can revise a kept token, as a coarse-to-fine refiner may, the client must handle a token that changes after display, or the server must withhold output until it is final.

KV caching. The LLaDA paper states that the model is incompatible with KV caching, because without a causal mask the representation of every position, prompt included, depends on the current answer region. Its memory table shows the cost: at 1,024 tokens in and 2,048 out, 19.02 GB for LLaDA against 16.74 GB for LLaMA3 with a KV cache, but compute is the larger issue, as the prediction above shows. Prompt caching across requests, which makes long shared system prompts cheap on autoregressive APIs, has no direct equivalent, so price the product with the full prompt processed on every step.

Constrained output. Grammar-constrained decoding as usually built walks a state machine left to right and masks the next token's logits. A sampler that fills position 40 before position 3 has no well-defined "next token" state. Block sampling helps if the grammar can be checked per block; otherwise the server falls back to generate, validate, retry. For tool calls and JSON output, test the vendor's structured-output mode with your schemas and measure the invalid rate and the retries it causes.

Length. The generation length is a hyperparameter set before sampling. The answer region is allocated up front, and an answer that needs more room needs another block or another request; an answer that needs less pads with end-of-sequence tokens that still cost compute.

## When this is wrong

This lesson describes masked diffusion as LLaDA publishes it. A vendor's serving stack may cache, sample or stream differently, and Mercury's paper does not say how it handles caching or streaming, so each cost above is a question to put to the vendor rather than a fact about every diffusion model. The numbers are the papers' own, under the conditions listed.

LLaDA's throughput comparison uses no inference optimisations for LLaDA and a KV cache for LLaMA3 at batch 1; it says nothing about either at serving batch sizes.

Quality claims are benchmark results from the authors (LLaDA) and from Artificial Analysis as quoted by the vendor (Mercury). Neither measures a chat or agent workload, so they set the bar for a trial, not the outcome.
