## The decision

Every framework choice reduces to one question: which abstractions are you willing to debug in production at 2 a.m., with a failed run in front of you and no time to read the framework's source? An abstraction you can see through, such as a thin wrapper whose rendered request you can print, costs little when it breaks. An abstraction that writes prompts, adds model calls, retries on its own schedule or caps steps with a default you never set costs a debugging session the first time its behaviour diverges from your mental model.

Anthropic's agent guidance from December 2024 states the default: start with the model APIs directly, because many patterns are a few lines of code, and "incorrect assumptions about what's under the hood are a common source of customer error." That is a default, not a rule. A framework pays when it owns a hard problem you would otherwise build: durable state across pauses, a multi-provider gateway, or streaming UI plumbing.

## The inputs that change it

**Pauses and checkpoints.** If a run must stop for a human decision that can arrive hours or days later, survive a deploy while it waits, and resume without repeating side effects, you need a checkpointed runtime. LangGraph 1.x gives you that (state saved per thread at super-step boundaries, `interrupt()` and `Command(resume=...)`), as do workflow engines such as Temporal and the AI SDK 7 `WorkflowAgent`. Without this requirement, most of LangGraph's value goes unused.

**Provider coupling.** The provider agent SDKs carry their provider's assumptions. The OpenAI Agents SDK uses the Responses API by default for OpenAI models and exports traces to OpenAI's backend by default, with inputs and outputs included (`trace_include_sensitive_data` defaults to true). The Claude Agent SDK runs the Claude Code binary, with Claude Code's tools, loop and context management. If you are still choosing between model vendors, or must keep two qualified for failover, a provider SDK puts that decision inside your runtime.

**Team familiarity.** The engineers who will be paged need to know what the framework does underneath. A team fluent in LangGraph debugs a stuck thread by reading its checkpoints; a team that adopted it last month reads source code during the incident.

**Cost of leaving.** Count what moves if you leave: prompts held in framework templates, state stored in the framework's checkpoint format, tools written against its decorator, traces in its schema. Prompts in your repository and business logic in plain functions keep the exit cheap whatever you choose.

**Release cadence.** As of 28 October 2026, LangChain and LangGraph promise no breaking changes until 2.0 (announced with 1.0 on 22 October 2025), and langgraph 1.2.18 shipped on 26 October 2026. Both provider agent SDKs are pre-1.0 on PyPI (openai-agents 0.24.0, claude-agent-sdk 0.2.174), so minor versions can change APIs.

## The options and when each wins

**Plain code over the provider client.** Wins when the application is a fixed sequence of a few calls, when you need provider features on the day they ship (cache breakpoints, new tool types, effort settings), and when the team must read every request. You own retries, validation, tracing and the tool loop. A tool loop with a step cap, a budget and logging is short; durable waiting is not.

**LangChain 1.x `create_agent`.** A standard tool-calling agent on the LangGraph runtime with middleware for approvals, summarisation and PII redaction. Wins when your agent is the standard shape and you want those middlewares without writing them. Structured output now runs inside the main loop, which the 1.0 post says removes an extra model call. The compiled agent binds a recursion limit of 9,999 super-steps in `factory.py`, so a looping agent is stopped by your own budget or by nothing; set a limit you chose.

**LangGraph directly.** Explicit state, reducers, conditional edges, checkpointers and interrupts. Wins when the control flow is yours (approval gates, parallel fan-out with `Send`, branches that are not "call the model again") and must survive crashes. The cost is a second state model to learn: reducers decide how updates merge, and a resumed node re-runs from its start.

**OpenAI Agents SDK.** Agents, handoffs, guardrails, sessions, human-in-the-loop with serialisable run state, tracing and sandbox agents, with few primitives. Wins on an OpenAI-first stack that wants handoffs and approvals without building them, and pairs with Temporal for durability: the Python integration, in which each agent invocation runs as a Temporal Activity, has been generally available since 23 March 2026. Its default turn cap is `DEFAULT_MAX_TURNS = 10` in `run_config.py`; exceeding it raises `MaxTurnsExceeded`.

**Claude Agent SDK.** Claude Code as a library: file and shell tools, permissions, hooks, subagents, MCP, sessions with resume and fork. Wins when the agent's work looks like Claude Code's (files, commands, repositories) and you want Anthropic's harness rather than your own. The cost is coupling to Claude models and to a harness whose prompts you do not write.

**Vercel AI SDK 7.** The TypeScript option. Version 7 (25 June 2026) added `WorkflowAgent` for durable runs that survive restarts, deploys and delayed approvals, an experimental `HarnessAgent` over Claude Code, Codex and Pi, and separate total, step, chunk and tool timeouts that raise `TimeoutError`. Wins in a TypeScript product with streaming UI. Migration from version 6 runs through `npx @ai-sdk/codemod v7`.

<Callout kind="gotcha">
Step caps are framework defaults that change. LangGraph's fallback recursion limit in source was 25 until 12 January 2026, then 10,000, then 10,007 from 30 March 2026, while the Graph API page states 1,000 from version 1.0.6. Code that relied on the old 25 to stop runaway loops lost that guard on upgrade. Set the limit explicitly and alert when a run reaches it.
</Callout>

## A worked decision

Scenario, labelled as such: a claims-intake service at an insurer, with five Python engineers and a tool-using agent with six tools (policy lookup, document OCR, fraud score, payout calculation, case notes, payment). Payments above a threshold need an adjuster's approval, which can take up to three days. The company is qualifying both Claude and OpenAI models and wants either to serve the agent. The security team requires an audit record of every tool call kept in the company's own store. The service must ship in one quarter.

The pause is the hard requirement: three days, across deploys, without paying a claim twice. That rules out plain code unless the team builds a state table, a resume path and idempotent payment calls, which is a large share of the quarter on its own. It points to LangGraph (checkpointer plus `interrupt()`) or to the company's workflow engine if one already runs.

The two-vendor requirement weighs against a provider agent SDK as the runtime. The OpenAI Agents SDK lists non-OpenAI providers, but its defaults (Responses API, trace export to OpenAI) are built around one vendor, and the audit rule means tracing must be redirected or disabled anyway. The Claude Agent SDK is Claude-only.

Decision: LangGraph for the graph and checkpoints, with model calls made through the team's own thin client interface inside the nodes, so the prompt and the provider adapter live in the repository. The recursion limit is set explicitly, sized from the longest successful run in testing with headroom, and the payment tool carries an idempotency key derived from the claim and the approval. LangChain's `create_agent` is acceptable for the tool loop inside one node if the team wants its middleware, provided the rendered request is logged.

What the team gives up: a second state model (reducers, super-steps, re-run on resume) that every on-call engineer must learn, and a dependency on langgraph's release train. If the company already ran Temporal, the decision flips to Temporal workflows with the same thin client inside activities, because the on-call team already debugs Temporal at night.

## What to measure after deciding

The choice is a hypothesis about debugging cost. Measure it from the first incident.

- **Time to root cause for a failed run**: from alert to a named cause, per incident, with a note on whether the cause was in your code, the prompt, the model or the framework. If framework-layer causes dominate after a quarter, the abstraction is costing more than it saves.
- **Glue code**: lines in wrappers, adapters and overrides that exist to work around the framework (custom serializers, patched defaults, re-implemented features the framework does not expose). Growing glue is the framework failing to match the problem.
- **Calls per request**: model calls observed at the HTTP layer against the calls your code makes on purpose. A gap means retries, re-prompts or summarisation you did not budget for.
- **Upgrade cost**: engineer-days per minor upgrade, and how many upgrades changed a default you depended on.
- **Provider features blocked**: features you wanted and could not use until the framework exposed them, with the delay.

## When this is wrong

The playbook assumes the team operates the runtime. If a hosted agent platform runs the loop for you, the question changes from which abstraction you debug to which controls you keep; the next lesson covers that.

It also assumes framework behaviour is knowable from documentation. Several facts here came from source code because the documentation disagreed with it (LangGraph's recursion default). Version-specific claims were checked on 28 October 2026 and will drift; the method (print the rendered request, set every cap yourself, measure debug time) does not.

Finally, plain code is not free. A team that writes its own loop, checkpoints and retry logic owns the bugs in them, and a home-grown checkpoint store is a framework without documentation. The measure that settles it is the same in both directions: time to root cause.
