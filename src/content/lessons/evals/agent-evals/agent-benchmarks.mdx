## A score is five things

A public agent benchmark score fixes a task set, an environment, a harness, a grader and a date. Whether it predicts anything about your agent depends on how many of those five match your setting. The analogy is a vendor's TPC benchmark run on hardware you will never buy: a real measurement of a different system. The difference is that two of the five decay. Public tasks leak into training data, and graders built from one reference solution reject correct alternatives, so the same benchmark measures different things at different ages.

The harness track's [benchmark map](/learn/harness/evaluating-harnesses/coding-benchmarks) compares the coding benchmarks by what each holds fixed, and [attribution](/learn/harness/evaluating-harnesses/attribution) covers separating the harness from the model. This lesson covers the wider family and the question a team actually asks: why does an agent that wins a benchmark fail on our work?

## SWE-bench Verified: the audit and the retirement

SWE-bench (2023) takes resolved issues from 12 Python repositories. The agent sees the issue text and the repository before the fix; hidden tests that the human fix made pass must pass, and regression tests must keep passing. Verified (2024) is the 500 problems kept after expert engineers reviewed 1,699, three reviewers each.

On 2026-02-23 OpenAI stopped reporting Verified and recommended other labs do the same. State of the art had moved only from 74.9% to 80.9% in the previous six months, and OpenAI asked whether the remaining failures were the models' or the dataset's. It audited the 138 problems, 27.6% of the set, that o3 did not solve consistently across 64 runs, with at least six engineers per problem. 59.4% had material issues in their tests or descriptions. 35.5% had narrow tests that require implementation details the issue never states: in pylint-dev__pylint-4551 the tests import a function named `get_annotation` that the issue never mentions, so correct fixes fail on an import error. 18.8% had wide tests that check behaviour the issue never asked for: sympy__sympy-18199 comes from a pull request that fixed three issues, its description covers one, and its tests cover all three. 5.1% had other problems.

The second finding was contamination. OpenAI's automated red-teaming found that every frontier model it probed, its own included, could reproduce the gold patch or verbatim problem details for some tasks, and GPT-5.2 solved 31 tasks the audit had judged almost impossible, in one case citing Django release notes for a parameter the tests required. Those two findings interact: a narrow test is passable if the model has seen the reference patch, so near the ceiling, score gains measure exposure to the benchmark. OpenAI now reports the public split of SWE-bench Pro, where its pipeline found contamination rarer and less severe and no model produced a complete verbatim gold patch.

## SWE-bench Pro and Terminal-Bench 2.0

SWE-bench Pro (September 2025) has 1,865 problems from 41 repositories: 731 public from 11 copyleft repositories, 858 held out from 12 repositories to detect overfitting later, and 276 commercial problems from 18 startup codebases, kept private with results published. The languages are Python, Go, JavaScript and TypeScript. Reference fixes average 107.4 lines across 4.1 files. Every problem statement is augmented with requirements and an interface, so Pro measures implementing a specified change more than triaging an ambiguous issue. Under one scaffold (SWE-Agent, 50 turns, one prompt for all models), Claude Sonnet 4.5 resolved 43.6% of the public set; the best result on the commercial set was Claude Opus 4.1 at 17.8%. With a $2 cost cap per task, the best public result fell to 25.9%.

The public-to-commercial gap is the most direct published evidence on transfer: same scaffold, same task construction, and unfamiliar codebases cut the best score by more than half.

Terminal-Bench 2.0 (January 2026) is 89 tasks chosen from 229 submitted by 93 contributors, each with a container, an instruction, tests over the final container state and a reference solution, reviewed for about three reviewer-hours per task. Its Harbor harness runs Claude Code, Codex CLI, OpenHands, Mini-SWE-Agent and the authors' neutral Terminus 2 on the same tasks. Codex CLI with GPT-5.2 scored highest at 63%. The authors conclude that model choice usually matters more than scaffold, while reporting that Gemini 2.5 Pro's resolution rate was 17% higher with Terminus 2 than with OpenHands. Agents may reach the internet, and the paper notes that machine resources and container enforcement vary the environment. The authors expect it may saturate within the next year.

## Beyond code: GAIA, WebArena, OSWorld, BrowseComp

**GAIA** (November 2023) is 466 questions for a general assistant with tools, in three levels by number of steps and tools. Each answer is a short string, number or list, scored by quasi exact match, which makes grading cheap and leaves the path unexamined. The authors released 166 annotated questions and withheld answers to 300 for the leaderboard. Humans scored 92% and GPT-4 with plugins 15%; with tools GPT-4 stayed under 30% on Level 1 and at 0% on Level 3.

**WebArena** (2023) runs 812 tasks, instantiated from 241 templates, on four self-hosted sites: e-commerce, a forum, a GitLab-style development site and a content management system. Grading checks functional correctness, such as the contents of the repository after the agent acted, with a gpt-4-0613 fuzzy match for free-form answers, and some tasks are unachievable by design and expect "N/A". The best GPT-4 agent reached 14.41% against 78.24% for humans. The template structure exposes consistency: GPT-4 solved every variant of only 4 of 61 templates, the pass^k problem in another form.

**OSWorld** (April 2024) runs 369 tasks on a real Ubuntu virtual machine, with 302 distinct initial states and 134 evaluation functions that inspect files, configurations and application state. The best model reached 12.24% against more than 72.36% for humans, failing mostly on GUI grounding. The reward function has a property worth checking in any benchmark you adopt.

**BrowseComp** (April 2025) is 1,266 questions whose answers are hard to find and easy to check. Trainers wrote questions another person could not solve within ten minutes; a model grades each short answer for semantic equivalence with the reference. Human trainers, given about two hours, solved 29.2% and gave up on 70.8%, and on the questions they solved, their answer matched the reference 86.4% of the time. That last number is the grader's noise floor: either the reference or the trainer is wrong on roughly one solved question in seven. GPT-4o scored 0.6%, 1.9% with browsing, o1 9.9% without browsing, and Deep Research 51.5%, with the paper's footnote that Deep Research was trained on data for this kind of task. The paper states what it leaves out: long answers and ambiguous queries.

## How much each score can move by chance

A single run's interval depends on task count. At the worst case p = 0.5, the 95% half-width is 1.96 × √(0.25 / n):

```python
from math import sqrt

sizes = {"Terminal-Bench 2.0": 89, "GAIA (test)": 300, "OSWorld": 369,
         "SWE-bench Verified": 500, "SWE-bench Pro (public)": 731,
         "WebArena": 812, "BrowseComp": 1266}
for name, n in sizes.items():
    print(f"{name:24} n={n:5}  ±{100 * 1.96 * sqrt(0.25 / n):.1f} points")
# Terminal-Bench 2.0 ±10.4, GAIA ±5.7, OSWorld ±5.1, Verified ±4.4,
# Pro public ±3.6, WebArena ±3.4, BrowseComp ±2.8
```

These are lower bounds on the uncertainty of a published number. They count only task sampling, and leave out harness, resource limits, reasoning effort and date, each of which the papers above show can move a score by more.

Every row moves the score, and Pro's public-to-commercial drop measures the last row alone. Contamination is the general case of that row. Any benchmark built from public material can leak; OpenAI's post recommends password-protected distribution and canary strings, and Pro's copyleft licensing is a deterrent, not a guarantee. Held-out splits exist to measure the leak later. For your own decisions the defence is tasks the model cannot have seen: fixes merged in your repositories after the model's training cutoff, graded with your tests and a sample of human review.

Version changes are the last trap. tau2-bench released v2.0.0 on 2026-10-20 with six languages and voice, and its maintainers state that 2.0 scores are not comparable with the 1.x leaderboard, which now sits on a separate tab. A benchmark name without a version is not a measurement.

## When this is wrong

The five-part frame says public scores transfer poorly; it does not say they carry no information. Between models far apart, a 20-point gap on WebArena or OSWorld is real at those task counts, and public benchmarks remain the cheapest screen before a private eval. The failure is reading small gaps near the top as rankings.

Private sets have the same problems at smaller scale. A few dozen tasks give wide intervals, tests from one human fix are narrow tests, and an internal repository mirrored to a public host is training data. The audit discipline that exposed Verified applies to your own set: rerun the consistently failed tasks, read them, and expect a share of them to be broken.

And every number in this lesson has a date. The 2023 and 2024 scores above describe models that are no longer offered; they are here for what they reveal about the benchmarks, not about current agents. Check a benchmark's status and version before quoting it.
