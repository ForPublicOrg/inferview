## Guessing is the optimal policy under the grader

A model that answers "I don't know" scores zero on almost every benchmark it is trained and selected against. A guess scores zero when wrong and one when right, so under that grader a guess weakly dominates abstention at every confidence level, and an optimiser learns to guess. Kalai, Nachum, Vempala and Zhang (September 2025) state this as an observation, note that its proof is trivial, and then check the leaderboards: of the ten benchmarks they examine (GPQA, MMLU-Pro, IFEval, Omni-MATH, WildBench, BBH, MATH level 5, MuSR, SWE-bench and HLE), nine grade strictly right or wrong with no credit for abstaining, and WildBench gives partial credit. Their argument is that a new hallucination benchmark does not fix this while the benchmarks that decide which model ships keep scoring abstention as failure.

The same paper explains why errors exist before post-training. It reduces generation to a binary "is this output valid?" classification and shows the generative error rate is at least roughly twice that classifier's error rate, minus terms for calibration and the size of the answer space. For facts with no learnable pattern, the bound comes from how often each fact appears in training: if 20% of birthday facts appear exactly once in the pretraining data, a base model should be expected to hallucinate on at least 20% of birthday questions. The paper reprints the GPT-4 technical report's calibration plot, where the pretrained model is well calibrated, and notes that post-trained models may move away from that.

The engineering reading is the same as for a service whose SLO counts an empty result as an error: it learns to return something. The difference is that the model has no flag on the something.

## Pricing an abstention

The paper's proposal is to put the price in the instruction: answer only if you are more than t confident, since mistakes are penalised t/(1-t) points, correct answers receive 1 point, and "I don't know" receives 0. The expected score of answering at confidence p is p - (1-p) × t/(1-t), which is zero at p = t, so answering pays exactly when p is above t. The paper lists three natural values: t = 0.5 with penalty 1, t = 0.9 with penalty 9, and t = 0.75 with penalty 2. The last one does not match the formula, which gives 0.75 / 0.25 = 3. Check the arithmetic in any threshold table before it becomes a policy.

A production system needs one more term, because abstaining is not free: a handoff costs an agent's time, a refusal costs a user who leaves. With value v for a right answer, cost c for a wrong one and cost a for abstaining, answering beats abstaining when p × v - (1-p) × c > -a, which rearranges to p > (c - a) / (v + c). With v = 1 and a = 0 it reduces to the paper's rule: c = t/(1-t) gives p > t.

## Three numbers, not one

An abstaining system has three outcome shares that sum to one: right, wrong and abstained. A single accuracy figure hides the trade, and a single "hallucination rate" invites gaming, because the cheapest way to halve the wrong share is to abstain on half the traffic. Report all three per route, and choose the cut on labelled traffic from the costs, not from the formula alone. The formula assumes the confidence is calibrated; the sample tells you whether it is.

```python
def answer_threshold(value_right: float, cost_wrong: float, cost_abstain: float) -> float:
    """Answer when p * value_right - (1 - p) * cost_wrong > -cost_abstain."""
    return (cost_wrong - cost_abstain) / (value_right + cost_wrong)

def operating_point(sample, cut):
    """Shares of all questions that are answered right, answered wrong, and abstained."""
    n = len(sample)
    right = sum(1 for conf, ok in sample if conf >= cut and ok)
    wrong = sum(1 for conf, ok in sample if conf >= cut and not ok)
    return right / n, wrong / n, (n - right - wrong) / n

def best_cut(sample, value_right, cost_wrong, cost_abstain):
    """Cut with the lowest cost on a labelled sample; 1.01 means answer nothing."""
    def cost(cut):
        r, w, a = operating_point(sample, cut)
        return -r * value_right + w * cost_wrong + a * cost_abstain
    return min(sorted({c for c, _ in sample} | {1.01}), key=cost)

# (confidence, correct) on a labelled sample; same toy set as the widget above
SAMPLE = [(0.98, True), (0.95, True), (0.93, True), (0.91, False), (0.88, True),
          (0.85, True), (0.82, False), (0.80, True), (0.77, True), (0.74, False),
          (0.70, True), (0.66, False), (0.62, True), (0.58, False), (0.55, False),
          (0.51, True), (0.45, False), (0.40, False), (0.33, True), (0.25, False)]

print(answer_threshold(1, 3, 0))              # 0.75, the paper's t = 0.75
print(answer_threshold(1, 9, 1))              # 0.8
cut = best_cut(SAMPLE, 1, 9, 1)
print(cut, operating_point(SAMPLE, cut))      # 0.93 (0.15, 0.0, 0.85)
print(operating_point(SAMPLE, 0.0))           # (0.55, 0.45, 0.0): accuracy-only grading answers everything
```

The formula says 0.8; the sample says 0.93, because two of the eight answers at or above 0.80 are wrong (the 0.91 and the 0.82). On real traffic that gap is the measurement you are after. On 20 rows it is noise, and a cut chosen from 20 rows will move when the next 20 arrive.

## Where the confidence comes from

The rule needs a p, and the model's stated confidence is only one source. The paper's own target is behavioural calibration: the model answers only when it is at least t confident, and you audit that by comparing the right and wrong shares across several values of t, without the model ever printing a probability. The other signals in use are agreement across several samples of the same question, a separate verifier's score on the draft, and retrieval coverage (whether any retrieved passage supports the claim at all). Each one is a classifier for "this answer is right", so each needs labelled traffic from the route it guards before its threshold means anything.

## Grounding with citations

Citations change the check from "is this true?" to "does this span say this?", which a second model or a person can answer quickly. Anthropic's Citations feature, as documented on 2026-10-28, chunks plain text and PDFs into sentences and returns character ranges (0-indexed) or page ranges (1-indexed); custom content documents are cited by block index with no further chunking, which is how you cite whole RAG chunks or transcript turns. The returned `cited_text` does not count toward output tokens, nor toward input tokens when passed back on a later turn. Citations must be enabled on all or none of the documents in a request, only text can be cited (a scanned PDF with no text layer cannot), and combining citations with structured outputs (`output_config.format`) returns a 400 error.

The docs promise that every citation is a valid pointer into your documents. They do not promise that the span supports the sentence it is attached to. Support has to be checked per claim: a judge model or classifier that reads the claim and the cited span together, with its own measured error rate.

## Verification chains and what they cost

Chain-of-Verification (Dhuliawala et al., 2023) drafts an answer, plans verification questions about its claims, answers each question, and revises. The variant that matters is the factored one: each verification question is answered in a fresh context without the draft, because the authors found that models attending to their own earlier hallucinations tend to repeat them. The paper's motivating measurement is that on Wikidata list questions only about 17% of the few-shot baseline's entities were correct, while about 70% of the same entities were answered correctly when asked about one at a time.

The results table shows the coverage trade in one row. For Llama 65B on Wikidata, two-step CoVe raised precision from 0.17 to 0.36. Hallucinated entities per answer fell from 2.95 to 0.68, a 77% drop ((2.95 - 0.68) / 2.95), and correct entities fell from 0.59 to 0.38, a 36% drop ((0.59 - 0.38) / 0.59). It behaves like an abstention filter that also drops right items. On long-form biographies the factor+revise variant raised FactScore from 55.9 to 71.4. The authors' limitations section says the method addresses only directly stated factual errors, not reasoning errors, costs extra generated tokens, and is bounded by what the model knows; they name retrieval in the verification step as the extension.

## Four kinds of wrong

Sort errors by the check that catches them.

**Unfaithful to the context.** The answer contradicts or goes beyond the documents the system supplied. Caught by checking each claim against its cited span.

**Fabricated.** The answer invents an entity: a case, an API, a package. Spracklen et al. generated 576,000 code samples from 16 models and found hallucinated package names in at least 5.2% of outputs from commercial models and 21.7% from open-source ones, with 205,474 unique invented names; a name that is invented consistently can be registered by an attacker. Caught by looking the entity up in its registry.

**Stale.** The answer was true for a version of the world or the document that no longer holds. Caught by dates and versions on sources and a rule for which one wins.

**Reasoning errors.** Every fact is right and the conclusion is not. Caught by recomputing with code or a tool; CoVe does not address these.

Retrieval addresses stale and fabricated errors only for questions the index can answer, and it creates the unfaithful kind.

## When this is wrong

The cost model gives every wrong answer in a route the same price. Real costs vary inside a route: a wrong answer the user can check in one click costs less than one they act on, and an expected-cost threshold says nothing about tail cost. Where one wrong answer is unacceptable, the control belongs on the action, which is the subject of the next lesson, not on a threshold.

Abstention is not neutral to users. A user who gets "I don't know" often rephrases until the system answers, which moves the question into a lower-confidence region with no record that it was asked before. Count abstentions per session, not only per question.

The singleton-rate bound is about base models and arbitrary facts with no pattern. It says little about a retrieval system answering from documents it was handed, where the dominant failures are unfaithfulness and retrieval misses. Likewise, the CoVe numbers are for Llama 65B on 2023 benchmarks; the mechanism transfers, the magnitudes need re-measuring on your model and traffic.

Calibration is measured on a distribution. A threshold chosen on last quarter's labelled set drifts when the traffic mix, the model version or the corpus changes, so the cut is a configuration value with an owner and a re-measurement date, not a constant.
