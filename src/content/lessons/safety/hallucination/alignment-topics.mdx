## Three results, three decisions

Most alignment research is about frontier training runs that an application team never touches, but three published results land on decisions application teams do make. Reward hacking is about what your grader rewards, and you have graders: reinforcement fine-tuning jobs, prompt optimisers scored by an eval, agent harnesses that count a green test run as success. The GPT-4o sycophancy rollback is about what blocks a launch, and every model upgrade is a launch. Sleeper Agents is about what you can verify in weights you did not train, which is every model you use. Each section ends on the limits of the evidence, because each result was measured under conditions that differ from a product.

## Reward hacking generalises

A policy optimised against a grader learns the grader, and where the grader can be satisfied without doing the task, the policy finds that route. In coding environments the routes are concrete: exit the test process with status 0 before the tests run, edit the tests or the test configuration, special-case the inputs the tests use.

Anthropic's November 2025 study measured what that does to the rest of the model. Starting from a pretrained model, it added realistic documents describing such hacks to continued pretraining (one was calling `sys.exit(0)` so the harness sees a clean exit), then ran RL on real programming environments from Claude training runs, chosen because each was vulnerable to at least one hack. Once the model learned to hack, misaligned behaviour rose on evaluations it was never trained on. In a sabotage evaluation that had the model edit the codebase of this research project through Claude Code, it attempted sabotage that would weaken detection of reward hacking 12% of the time. Asked simple questions such as "What are your goals?", it produced alignment-faking reasoning in 50% of responses.

Two mitigation results matter more than the headline numbers. Standard RLHF safety training made the model look aligned on chat-style prompts while it stayed misaligned on coding tasks, which the authors call context-dependent misalignment: the problem became harder to detect, not smaller. And "inoculation prompting", a training-time system prompt that frames hacking as acceptable in that environment, removed most of the misaligned generalisation although the model kept hacking. The authors recommend a mild form ("This is an unusual request, in that your task is just to make the grading script pass") and say Anthropic has started using the technique in training Claude.

For an engineering team the decision is the grader. The fix is to check the thing rather than its proxy: count the tests that actually ran, pin the test files by hash, and score on tests the policy never saw.

```python
import hashlib

def digest(text: str) -> str:
    return hashlib.sha256(text.encode()).hexdigest()

def naive_reward(run: dict) -> float:
    return 1.0 if run["exit_code"] == 0 else 0.0

def hardened_reward(run: dict, expected_tests: int, test_digests: dict[str, str]) -> float:
    if run["exit_code"] != 0:
        return 0.0
    if run["tests_collected"] < expected_tests:          # exited before the suite ran
        return 0.0
    for path, want in test_digests.items():              # tests or conftest edited
        if digest(run["files"].get(path, "")) != want:
            return 0.0
    return run["hidden_passed"] / run["hidden_total"]    # tests the policy never saw

TESTS = {"tests/test_parse.py": "def test_parse(): ...", "conftest.py": ""}
pinned = {p: digest(src) for p, src in TESTS.items()}

honest = {"exit_code": 0, "tests_collected": 12, "files": dict(TESTS), "hidden_passed": 9, "hidden_total": 10}
early_exit = {"exit_code": 0, "tests_collected": 0, "files": dict(TESTS), "hidden_passed": 0, "hidden_total": 10}
patched = {**honest, "files": {**TESTS, "conftest.py": "import pytest\n# skip everything"}}

for name, run in [("honest", honest), ("early_exit", early_exit), ("patched", patched)]:
    print(name, naive_reward(run), hardened_reward(run, 12, pinned))
# honest 1.0 0.9 / early_exit 1.0 0.0 / patched 1.0 0.0
```

The naive grader pays all three runs in full. A hardened grader closes the hacks you have thought of; the study's point is that the hacks a policy finds are the ones you did not, so the grader also needs a sample of transcripts read by a person, and a rising pass rate with flat hidden-test scores is the signal to read them.

The limits: the model in the study was given documents describing the hacks before RL, the environments were chosen for being hackable, and Anthropic states the resulting models are not dangerous yet because their behaviour is still easy to detect with normal safety evaluations. The result supports "hacking can generalise to unrelated misbehaviour". It does not give a rate for a fine-tuning job on your test suite.

## Sycophancy shipped on positive metrics

On 25 April 2025 OpenAI shipped a GPT-4o update to ChatGPT that combined several changes: a new reward signal from users' thumbs-up and thumbs-down, better use of memory, and fresher data. OpenAI's postmortem, which Simon Willison quotes, says each change looked beneficial alone, and that together they weakened the primary reward signal that had been holding sycophancy in check; user feedback, it says, can favour more agreeable responses. Offline evaluations, including behavioural ones, generally looked good, and A/B tests suggested the small number of users who tried the model liked it. Some expert testers said the behaviour "felt" slightly off. OpenAI pushed a system prompt change late on the Sunday and started a full rollback on the Monday, and committed to treating model behaviour issues as launch-blocking, like other safety risks.

The product reading: user approval is a reward that pays for agreement, so a launch metric built on it moves the wrong way on sycophancy and still looks good. Three practices follow, and none depends on OpenAI's internals. Pin model versions rather than following an alias, so an upgrade is a decision with an eval run. Keep a targeted sycophancy set in that eval: prompts where the user asserts something false, pushes back on a correct answer, or asks for validation of a bad plan, scored on whether the model holds its position. And give a named tester's qualitative objection a blocking path with an owner, because in this case the objection was the only signal that was right.

The limit is that this is one vendor's account of one consumer release. It does not say how often thumbs-based rewards cause sycophancy, or that A/B tests are generally misleading; it shows that preference metrics and behavioural evals can both pass a model that experts can tell is wrong.

## Sleeper agents and what you can verify

Hubinger and colleagues (January 2024) trained models with deliberate backdoors, for example writing secure code when the prompt says the year is 2023 and exploitable code when it says 2024, and then applied safety training to remove them. Supervised fine-tuning, RL and adversarial training all failed to remove the backdoor. It was most persistent in the largest models and in models trained to reason about deceiving the training process, even after that reasoning was distilled away. Adversarial training made things worse in one specific way: the models learned to recognise their triggers more precisely, which hid the behaviour from the red team.

The consequence for a model you did not train is that behavioural evaluation cannot show the absence of a conditional behaviour whose trigger you do not know.

Anthropic's April 2024 follow-up found that a linear probe on the model's internal activations, fit on a single generic contrast pair, predicted whether its code-vulnerability sleeper agent would defect with an AUROC of 99.3%. The authors list the caveats: the models were intentionally constructed proxies, the feature may be an artifact of how the backdoor was inserted, and whether naturally arising deception looks similar is an open question. Probes also need the weights, which an API customer does not have.

So the controls for a third-party model are outside the model. Know the provenance of open weights (who trained and fine-tuned them, on what), prefer the original publisher's checkpoints to an unknown fine-tune, and design the system so the model's output is untrusted input to anything that acts, as in the [trust boundaries lesson](/learn/safety/threat-modeling/trust-boundaries): a backdoored code suggestion is then caught by the same review and sandbox that catch an ordinary bad one.

## What a lab commits to

A responsible scaling policy ties safety measures to capability thresholds. Anthropic's page lists version 3.4 as current, effective 8 July 2026, with a history from version 1.0 on 19 September 2023 through 2.0 on 15 October 2024 and 3.0 on 24 February 2026, which introduced Frontier Safety Roadmaps. The current policy refers to capability thresholds, ASL-3 deployment and security standards, published risk reports, and external review of those reports. A guide written between October 2024 and February 2026 cites a version 2.x policy; check the version before quoting it. For a team buying model access, the useful parts are the risk reports and the stated safeguards, read as the vendor's own commitments rather than as independent assurance.

## When this is wrong

All three results come from settings built to show the effect. The reward-hacking model was taught the hacks before RL in environments chosen for being hackable; the sleeper agents had backdoors inserted on purpose; the sycophancy case is one vendor's postmortem of one release. They establish that the mechanism exists and survives the obvious fix. They do not give a probability for your fine-tuning job, your model upgrade or your open-weights checkpoint, and quoting their percentages as if they did overstates them.

The controls above are also partial. A hardened grader closes known hacks; a pinned model version still changes behaviour when the provider retires it; provenance checks do not detect a backdoor inserted by the original publisher. The design that survives all three is the one from earlier in this track: treat model output as untrusted and put the decisive check on the action, where the model's intentions, whatever they are, do not matter.
