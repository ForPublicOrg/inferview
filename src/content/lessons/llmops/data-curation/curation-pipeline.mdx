def luhn_ok(digits):

        d = int(ch)
        if i % 2 == 1:
            d *= 2
            if d > 9:

        total += d
    return total % 10 == 0

    text = CARD.sub(card, text)
    return PHONE.sub("<PHONE>", text)

def dedup(records, threshold=0.6):
    """Keep the earliest record (by ts, then id) of each exact or near-duplicate group.
    Returns (kept, dropped) where dropped maps id to "exact" or "near"."""
    kept, dropped, seen = [], {}, set()
    sigs = []
    for r in sorted(records, key=lambda r: (r["ts"], r["id"])):
        key = hashlib.sha256(normalise(r["text"]).encode()).hexdigest()
        if key in seen:
            dropped[r["id"]] = "exact"
            continue
        s = shingles(r["text"])
        if any(jaccard(s, t) >= threshold for t in sigs):
            dropped[r["id"]] = "near"
            continue
        seen.add(key)
        sigs.append(s)
        kept.append(r)
    return kept, dropped

def split_by_user(records, eval_share=0.2):
    """Every record of a user lands on the same side; the side is a stable hash of the user id."""
    train, eval_ = [], []
    for r in records:
        h = int(hashlib.sha256(r["user"].encode()).hexdigest()[:8], 16) / 0x100000000
        (eval_ if h < eval_share else train).append(r)
    return train, eval_

    """Return sorted (eval id, train id) pairs whose texts have Jaccard similarity at or above threshold."""
    tsigs = [(t["id"], shingles(t["text"])) for t in train]
    pairs = []
    for e in eval_:
        s = shingles(e["text"])
        pairs += [(e["id"], tid) for tid, t in tsigs if jaccard(s, t) >= threshold]

## The pipeline is a sequence of decisions about copies

A curation pipeline turns logged conversations into two artefacts with opposite requirements. The fine-tuning set should hold each behaviour once, at high quality, with nothing that identifies a person. The eval set should hold the traffic the model will see, weighted the way production weights it, and share nothing with the fine-tuning set that would let a model pass by recall. Most of the engineering is the order of the stages, because each stage changes what the next one sees:

1. **Scrub at the logging boundary**, so the labelling tool, the annotators, every snapshot and every training job inherit scrubbed text.
2. **Draw candidates by stratum**, per intent and outcome, oversampling the strata the model is weak on.
3. **Deduplicate in increasing cost**: exact, then MinHash, then embeddings, each on the survivors of the last, within the batch and against every existing dataset version.
4. **Label with a rubric and a measured agreement rate.**
5. **Split by user or by time, never by row.**
6. **Run the leakage check as a gate** that fails the build when an eval item has a near-duplicate in training.

The analogy is an ETL job feeding a warehouse with a test fixture carved out of it. The difference is that the consumer of the training side is a model that memorises, so a duplicate is not wasted storage: it is extra weight on that example, and a near-copy across the split is an exam question with the answer in the textbook.

## Why quality beats volume, with the conditions

LIMA (Zhou et al., May 2023) fine-tuned a 65B LLaMa model on 1,000 examples: 800 drawn from Stack Exchange, wikiHow, r/WritingPrompts and Super-Natural Instructions, and 200 written by the authors. In their human study LIMA's responses were equivalent to or preferred over GPT-4's in 43% of cases, Bard's in up to 58% and DaVinci003's in 65%. Their ablations on 7B models are the more useful part. Quality-filtered Stack Exchange beat unfiltered Stack Exchange at the same size of 2,000 examples by 0.5 points on their helpfulness scale, while scaling the training set up to 16-fold from the same source produced a plateau. And 30 multi-turn dialogue chains added to the 1,000 single-turn examples raised the share of excellent responses in conversations from 45.2% to 76.1%. Thirty examples of a missing format did what thousands of examples of a present one did not, which is the case for stratification in one number.

AlpaGasus (Chen et al., 2023, revised February 2024) scored each of Alpaca's 52,002 generated examples for accuracy on a 0 to 5 scale with ChatGPT, kept those at 4.5 or above, and trained on the 9,229 that survived: 9,229 / 52,002 = 17.7% of the data. Training the 7B model took 14 minutes instead of 80 on four A100s, the paper's 5.7 times speed-up. The control that makes the result credible is a random subset of the same size: on MMLU the 7B model scored 38.78 with the filtered set and 36.93 with the random one, and on BBH 33.76 against 31.89. Those are gains of about two points, smaller than the headline win rates the paper reports with GPT-4 as judge. A size-matched random baseline is the experiment to copy: without one, a filter's effect cannot be told apart from the effect of training on less data.

Both results are about instruction-following data for general assistants, and LIMA's own reading is that tuning mostly teaches format and style on top of pretrained knowledge. A domain fine-tune does not inherit the 1,000-example figure; it inherits the method of measuring quality per stratum and stopping when the curve flattens.

## Scrubbing: what the detector returns and what it costs

Presidio, now a community project under Data Privacy Stack, finds entities with named-entity recognition, regular expressions, rules and checksums, and applies an operator per entity type (replace, redact, mask, hash, encrypt, keep or custom). Its own documentation says there is no guarantee it finds all sensitive information, so the scrubber is a detector with a miss rate you measure on a labelled sample; the [redaction lesson in the security track](/learn/security/output-data/pii-telemetry-residency) covers measuring it.

Two choices in the scrubber change the rest of the pipeline.

**Replace with the entity type before deduplicating.** Templated tickets differ only in the customer's email or order number. Replacing an email with `<EMAIL>` makes ten thousand copies of one template exact duplicates, which is what they are for training purposes. Deduplicating first and scrubbing second keeps all ten thousand.

**Pseudonymise the user id with a stable key.** The split by user and the deletion path both need to find every record of one person. Presidio's hash operator has generated a random salt per entity by default since version 2.2.361, and its documentation says that keeping referential integrity requires supplying a consistent salt yourself. A pipeline that hashes user ids with the default produces a different pseudonym for each record of the same user, and the user split silently becomes a row split. Use a keyed hash with a key held outside the dataset, so pseudonyms are stable, cannot be reversed by hashing a guessed email, and can be looked up when a deletion request arrives.

Checksums are the cheap false-positive control. A 16-digit order number and a card number have the same shape; only the card passes the Luhn check. The exercise below asks for it.

## Deduplication: three stages, three thresholds, one scope decision

Exact deduplication is a hash of normalised text: lowercase, collapsed whitespace, scrubbed identifiers. Near-duplicate detection is MinHash with locality-sensitive hashing, and the banding parameters set the similarity at which pairs are caught. Lee et al. (ACL 2022) used word 5-grams and 9,000 hashes in 450 bands of 20, confirming candidate pairs by edit similarity above 0.8. FineWeb (Penedo et al., 2024) used 5-grams and 112 hashes in 14 bands of 8, targeting documents at least 75% similar.

A pair with Jaccard similarity s becomes a candidate with probability 1 − (1 − s^r)^b for b bands of r rows. For FineWeb's 14 bands of 8 that is 56% at s = 0.70, 77% at 0.75, 92% at 0.80 and 98.8% at 0.85, the figures in their appendix. For Lee et al.'s 450 bands of 20 it is 30% at 0.70, 76% at 0.75 and 99.5% at 0.80: a steeper curve bought with 80 times as many hashes. The [ingestion lesson](/learn/rag/ingestion/ingestion-pipelines) works through the same curve for retrieval corpora. For curation, the threshold is a statement about which paraphrases count as the same example, and it is chosen, not discovered.

The evidence that this stage matters for training: Lee et al. removed 3.04% of C4's training examples as near-duplicates, and their XL model trained on the original C4 data emitted memorised text in 1.926% of 100,000 unprompted generations after one epoch, against 0.189% for the near-deduplicated data. For evaluation, 4.60% of C4's validation examples had a near-duplicate in its training split.

Semantic deduplication catches paraphrases that share few n-grams. NVIDIA's NeMo Curator (v1.4.0) embeds each document with `google/embeddinggemma-300m` by default, clusters with K-means into 100 clusters, and flags pairs within a cluster at cosine similarity of at least 1 − eps, with eps defaulting to 0.01. The documentation recommends a first run with eps unset to inspect the similarity distribution before choosing. In a support log, "cancel my plan" and "how do I stop my subscription" are duplicates for an intent classifier and distinct examples for a model learning to handle phrasing; eps is that decision.

The scope decision is the one FineWeb's ablations warn about. Deduplicating globally across all 96 Common Crawl snapshots removed up to 90% of the oldest snapshots, and the roughly 10% that survived from the 2013-48 snapshot, about 31B tokens, was worse data than the roughly 460B tokens removed: more ads and keyword lists. The common, well-formed pages had copies elsewhere; the oddities were unique and survived. Deduplicating each snapshot independently matched RefinedWeb's quality. Deduplicating a year of production logs as one pool fails the same way. On the training side, deduplicate within time windows and cap copies per cluster instead of keeping exactly one. On the eval side, keep one representative per cluster and record the cluster size as its weight, so the reported score is weighted by traffic while the set holds each case once.

## Labels and splits

Labels for an eval set are verdicts; labels for a fine-tuning set are target responses, accepted, edited or rewritten by an expert against a rubric. Both need an agreement rate measured against chance on an overlap sample, and the [labelling lesson](/learn/evals/eval-thinking/labelling-operation) covers kappa and the expert-hours budget. AlpaGasus shows that a model can do the first pass, scoring every candidate on one criterion, provided someone measures that filter against expert labels before trusting its threshold.

The split is where row-level thinking leaks. Production conversations cluster: the same user asks the same question in three sessions, the same tenant runs the same template, a retry produces a second copy of a failed exchange. A random row split puts cluster members on both sides.

**By user** (or by tenant, for a business product) stops the model from passing eval items on the strength of one person's phrasing. Its cost appears when traffic is concentrated: if one tenant sends a third of the traffic, whichever side it lands on is dominated by it, so large tenants are assigned deliberately and the assignment is written into the dataset card.

**By time** trains on an earlier window and evaluates on a later one, the way the model will be used, so intents that appeared after the cutoff show up as eval failures. Its cost is seasonality. Splitting by both, later window and unseen users, is the strictest version and usually the right one for a release gate.

## When this is wrong

The pipeline assumes the logged conversations are good examples of the behaviour you want. For fine-tuning targets that is often false: the logged assistant turns are the current model's outputs, so training on accepted logs teaches the model to imitate itself, failures included, unless the targets are reviewed or rewritten. Logs are a more reliable source of inputs than of outputs.

Deduplication thresholds borrowed from pretraining corpora are tuned for web pages of hundreds of words. Support messages are short, and a word 5-gram MinHash over a two-sentence message is noisy; short texts need smaller shingles, character n-grams, or a semantic stage with a measured threshold.

A clean leakage check is a lower bound: paraphrases across users pass it. What it misses is covered only by an eval slice from a later window than any training data.

When the task needs coverage of a long tail, such as rare product configurations, volume in the tail is the quality, and filtering on a generic accuracy score removes the unusual examples the model needed.
