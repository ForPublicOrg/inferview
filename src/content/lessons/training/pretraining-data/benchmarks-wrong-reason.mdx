A benchmark score is a measurement with a known set of confounders, and a data change can move it through any of them without changing what the model can do. Four account for most of the false movement: the test items or their near-copies are in the training data; the team has tuned decisions against a fixed set of benchmarks until the set stops predicting anything else; the training data was selected for resemblance to the benchmark; and the metric changed (pass@1 against pass@k against majority vote, greedy against sampled). Each has a detection method, and a regression check that runs those methods is the deliverable of this lesson.

## Contamination

Lee et al. found that 4.60% of C4's validation examples had a near-duplicate in its training set. Llama 3 measured the effect on its own benchmarks: an example counts as contaminated if enough of its tokens fall inside an 8-gram that appears in the pretraining corpus, with the threshold chosen per benchmark, and the estimated gain is the score on the full set minus the score on the clean subset.

| Benchmark | Contaminated | Estimated gain, 8B | 70B | 405B |
|---|---|---|---|---|
| BIG-Bench Hard | 95% | 26.0 | 36.0 | 41.0 |
| AGIEval | 98% | 8.5 | 19.9 | 16.3 |
| HellaSwag | 85% | 14.8 | 14.8 | 14.3 |
| PiQA | 55% | 8.5 | 7.9 | 8.1 |
| GSM8K | 41% | 0.0 | 0.1 | 1.3 |
| MATH | 1% | 0.0 | -0.1 | -0.2 |

Two things in this table matter more than the headline. High overlap does not imply high gain: GSM8K is 41% contaminated by this measure and shows almost no gain, while HellaSwag's gain is about 14 points at every size. And for MBPP, HumanEval, MMLU and MMLU-Pro, 8-gram overlap flagged so much of the set that no clean subset was large enough to estimate a gain, which means the method fails on exactly the benchmarks most often quoted. The response is to decontaminate the training data against every evaluation before training, using the same n-gram machinery as [dedup](/learn/training/pretraining-data/dedup-levels) with the evaluation sets on one side, and to keep a private held-out set that has never been published.

## Optimising a fixed set

DeepSeek-V3's report lists, among its future directions, the need to "prevent the tendency towards optimizing a fixed set of benchmarks", saying it can give a misleading impression of capability. The mechanism is selection: every ablation in this module picks the variant that wins on a fixed suite, and over hundreds of decisions the suite becomes training signal. It is the familiar overfitting-to-the-validation-set problem, with the difference that the "model" being fitted is the whole data pipeline and nobody holds out a test set for it.

A related effect is data that resembles the benchmark. FineWeb-Edu's classifier selects educational text, and its gains are largest on MMLU and ARC (from 33% to 37% and from 46% to 57% at 350B tokens), benchmarks of school knowledge and science questions. The gain is real on those tasks. It is also a corpus shifted toward their register, and the shift shows up as losses on whatever the reference set did not resemble. DeepSeek-V3 documents the allocation version openly: it trails GPT-4o and Claude-Sonnet on SimpleQA and is strong on Chinese SimpleQA, which the report attributes to spending more training tokens on Chinese knowledge.

## Metric choice

The same samples give different numbers under different aggregations. With n samples per problem, c of them correct, the unbiased pass@k estimate is 1 - C(n - c, k) / C(n, k).

<Predict id="trn-ptd-pass-at-8" question="A model draws 16 samples on a problem and 4 are correct. Using the estimator above, what is pass@8? Give a probability between 0 and 1." answer={0.96} tolerance={0.01}>
C(12, 8) = 495 and C(16, 8) = 12,870, so pass@8 = 1 - 495 / 12,870 = 0.962. The same samples give pass@1 = 4 / 16 = 0.25. Majority vote depends on how the twelve wrong answers split: if they scatter, the correct answer can win with only 4 votes; if they concentrate on one wrong answer, it loses. One model, one set of samples, three numbers from 0.25 to 0.96.
</Predict>

```python
from collections import Counter
from math import comb

def pass_at_k(n, c, k):
    # unbiased estimate from n samples with c correct
    return 1.0 if n - c < k else 1 - comb(n - c, k) / comb(n, k)

def majority(answers):
    return Counter(answers).most_common(1)[0][0]

# one problem, 16 samples, 4 correct ("42"); the wrong answers scatter
samples = ["42"] * 4 + ["41"] * 3 + ["40"] * 3 + ["7"] * 2 + ["9"] * 2 + ["1"] * 2
print(pass_at_k(16, 4, 1), round(pass_at_k(16, 4, 8), 3), majority(samples) == "42")
# 0.25 0.962 True

# same correct count, the wrong answers concentrate
samples = ["42"] * 4 + ["41"] * 6 + ["40"] * 6
print(pass_at_k(16, 4, 1), round(pass_at_k(16, 4, 8), 3), majority(samples) == "42")
# 0.25 0.962 False
```

The choice changes conclusions, not just numbers. Yue et al. report that RL-trained reasoning models beat their base models at small k, while the base models reach higher pass@k at large k; a team comparing a data change at pass@1 and another at pass@64 can reach opposite conclusions from the same checkpoints. Decoding settings are part of the metric too: DeepSeek-V3 scores AIME at temperature 0.7 averaged over 16 runs and MATH-500 with greedy decoding, with an 8,192-token output limit. A comparison is valid only with metric, k, temperature, sample count and output limit fixed and written beside the number.

## The regression check

A candidate report on PracHub for an NVIDIA product manager loop, posted in June 2026, includes the follow-up this section answers: a new model scores higher on public benchmarks, and users report it got worse in a language the team cares about. The check that catches that before release has five parts.

**A private held-out set per user-facing slice.** For each supported language and each major task type, a set of human-written items that has never been published or used in any ablation. Its only job is to say whether public gains transfer.

**Decontamination both ways.** Training data against all evaluations before training; evaluations against training data after, with the n-gram overlap and estimated gain reported per benchmark as Llama 3 does.

**Held-out perplexity per language and domain.** Cheap, available for every checkpoint and every ablation, and sensitive to the mix shifts that benchmarks miss. A language whose share fell in the mix, or whose documents a classifier or an English-tuned heuristic filtered more aggressively, shows up here first.

**A frozen metric specification.** k, temperature, sample count, output limit, prompt template and answer extraction, versioned with the harness.

**A gate.** The release is blocked when any slice regresses beyond its paired noise floor, regardless of the aggregate.

For the reported case, the first diagnostic is the data diff between the two models, per language: token share in the mix, filter pass rates per language (the classifier and the heuristics in the [first lesson](/learn/training/pretraining-data/crawl-to-tokens) are English-tuned), and dedup removal rates. Then the private set and per-language perplexity on both checkpoints, to confirm the regression is real and not a template change.

## When this is wrong

Contamination estimates rest on the detection method. 8-gram overlap misses paraphrased and translated items and over-flags benchmarks built from common text; Llama 3 chose thresholds per benchmark to maximise the measured gain, which is a reasonable procedure and also one that makes the estimates hard to compare across reports.

A clean held-out set ages. Once its scores drive decisions, the set becomes another fixed benchmark; rotating items and limiting who sees per-item results slows that, and nothing stops it entirely.

Not every benchmark gain from resemblance is false. If the product's users ask school-science questions, data that resembles ARC is the right data. The failure is assuming the gain transfers to slices the data did not resemble, which the per-slice check measures directly.

And the regression in the reported case may not be in pretraining at all. Post-training data, a tokenizer change, a system prompt or a serving template can each degrade one language; the data diff is the first place to look, not the only one.
