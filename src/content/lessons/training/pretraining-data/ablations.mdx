Every data decision in this module was made by an experiment far smaller than the run it informed. The design of that experiment, not the data, is where most of the engineering judgement goes: which model size and token count, which control, how many seeds, which evaluations, and what difference counts. The published practice has converged on two tools. Train small models from scratch on each variant when the question is about the bulk of the corpus, and run short anneals from a checkpoint (micro-annealing) when the question is about a source that will enter late or in small proportion.

## From-scratch ablations

FineWeb trained a 1.71B-parameter model for 28B tokens per filter variant and 350B tokens for deduplication and cumulative comparisons, with two models per variant, each on a different random subset and seed. Over 70 models cost about 80,000 H100 hours. DCLM turned the same idea into fixed compute scales:

| Scale | Parameters | Tokens | H100 hours |
|---|---|---|---|
| 400M-1x | 412M | 8.2B | 26 |
| 1B-1x | 1.4B | 28.8B | 240 |
| 3B-1x | 2.8B | 55.9B | 740 |
| 7B-1x | 6.9B | 138B | 3,700 |
| 7B-2x | 6.9B | 276B | 7,300 |

The case for small scales rests on rank transfer. Across 10 filtering methods, DCLM reports that rankings at 400M-1x, 1B-1x and 3B-1x correlate with rankings at 7B-1x with Pearson r of 0.838, 0.956 and 0.982. That is a statement about ordering methods with sizeable differences, not about measuring a one-point effect; small scales screen, larger scales confirm.

Small models also limit which evaluations can be used. A benchmark on which the screening model scores at chance has no signal for any data change, so the evaluation set for an ablation is chosen at the ablation's scale, and that choice is recorded with the results.

## Micro-annealing

For a source that will be added late, from-scratch ablations ask the wrong question and cost too much. Llama 3's procedure takes the 8B model at 50% of its training, anneals the learning rate linearly to zero over 40B tokens with 30% of the mix from the new source and 70% from the default mix, and compares benchmark results. OLMo 2's microanneals are smaller still: mostly a 50/50 mix of the candidate math source and DCLM web text with a linear decay, with the proportion varied in one experiment, 19 runs totalling 130B tokens, which the paper notes is fewer tokens than three of its full 50B anneals. That averages about 6.8B tokens per run (130 / 19).

What OLMo 2 learned from them shows why they are worth running:

| Microanneal | GSM\* |
|---|---|
| baseline in the table | 28.5 |
| math at 35% (576M math tokens) | 63.5 |
| math at 10% (1.72B math tokens) | 61.0 |
| math source twice | 66.0 |
| math source four times | 65.0 |
| TinyGSM with inline code | 25.0 |
| TinyGSM rewritten with MIND | 65.5 |
| MIND-rewritten, twice | 70.0 |

Three decisions came out of one cheap table: the source needs to be present but not dominant, a little repetition helps, and the same problems in a different format can be worth nothing or a great deal. MMLU stayed around 60 to 62 throughout, which is the regression check: the source did not crowd out general knowledge at these proportions.

A micro-anneal is cheap relative to the run. Scaling DCLM's 7B-1x cost (3,700 H100 hours for 138B tokens on 6.9B parameters) to a Llama 3-style test, 40B tokens on an 8B model, gives 3,700 × (40 / 138) × (8 / 6.9) = about 1,240 H100 hours at DCLM's efficiency.

## The noise floor

An ablation result is a difference between two noisy numbers, and both noise sources matter: item sampling (the benchmark is a finite sample of questions) and training variance (seeds and data order). FineWeb's two seeds per variant measure the second; the first can be computed.

<Predict id="trn-ptd-noise-floor" question="Two models are scored on the same 1,000-question benchmark at about 60% accuracy. Treating the two scores as independent, what is the half-width of a 95% interval on their difference, in accuracy points?" answer={4.3} tolerance={0.3} unit="points">
One score has standard error √(0.6 × 0.4 / 1,000) = 0.0155, 1.55 points. The difference of two independent scores has √2 times that, 2.19 points, and 1.96 × 2.19 = 4.3 points. Most data ablations report differences smaller than this. Pairing by question shrinks it a lot, because the two models agree on most items; the code below computes the paired interval, and training-seed variance comes on top of either.
</Predict>

```python
import random

def paired_delta(control, candidate, iters=1000, seed=0):
    # per-item 0/1 scores on the same items; returns mean gain and a 95% bootstrap interval
    rng = random.Random(seed)
    d = [b - a for a, b in zip(control, candidate)]
    n = len(d)
    boots = sorted(sum(d[rng.randrange(n)] for _ in range(n)) / n for _ in range(iters))
    return sum(d) / n, boots[int(0.025 * iters)], boots[int(0.975 * iters)]

rng = random.Random(1)
control = [int(rng.random() < 0.60) for _ in range(1000)]
candidate = [c if rng.random() < 0.9 else int(rng.random() < 0.75) for c in control]
print(paired_delta(control, candidate))  # (0.008, -0.004, 0.02)
```

The simulated candidate changes its answer on about 10% of items and is slightly better on those. The paired interval runs from -0.4 to +2.0 points, about 1.2 points either side, against 4.3 unpaired; it still contains zero, so this result decides nothing. Requiring the gain to exceed both the paired interval and the spread between seeds is the decision rule most published ablations imply and few state.

## Designing the ablation for a new source

The question: does a new source, say 30B tokens of technical documentation, enter the mix? The design that answers it fixes six things before running.

**Hygiene first.** Deduplicate the source against the current mix and decontaminate it against every evaluation in the plan. An ablation on a source that contains benchmark items measures the leak.

**The form of the test.** If the source enters in the late phase, a micro-anneal from a mid-run checkpoint, as Llama 3 and OLMo 2 do. If it enters the bulk mix, from-scratch runs at a screening scale. Mixing the two answers neither question.

**The control.** The same anneal or run with the same token count from the default mix. Without it, the improvement from the learning-rate decay itself is credited to the new source.

**Proportions and repetition.** At least two proportions, because OLMo 2's table shows the response is not monotone, and a repetition arm if the source is small.

**Evaluations and noise.** Target evaluations for what the source is meant to teach, general evaluations that must not regress, and held-out perplexity on domains the new source displaces. Two data-order seeds per arm. Paired comparisons on the same items.

**The rule.** Written in advance: the source enters if the target gain exceeds the paired interval and the seed spread at both proportions, and no general evaluation regresses by more than its own noise floor. Then one confirmation at a larger scale or in a full anneal before the decision is final.

Scaling-law extrapolation extends this. Llama 3 chose its mix by training small models on candidate mixes and predicting large-scale performance from fits, the approach covered in the [scaling laws lesson](/learn/training/compute-scaling/scaling-laws). It predicts loss well inside the fitted range; whether it predicts a specific benchmark gain from a specific source is weaker ground.

## When this is wrong

Rank transfer is measured for filtering methods with large effects. DCLM's correlations come from 10 methods whose differences span several points; nothing published says a 1B ablation ranks two mixes that differ by half a point correctly at 70B. For small effects, the confirmation scale has to be close to the target.

Micro-anneals answer a late-phase question. A source that enters the bulk mix affects representations built over trillions of tokens, which a 10B-token anneal from a fixed checkpoint does not exercise; the anneal can overstate a source that teaches a format quickly and understate one whose value is broad knowledge.

The noise model here covers item sampling and seeds. It does not cover evaluation drift (prompt templates, few-shot examples, answer extraction), and a harness change between arms confounds the comparison; freeze the harness version with the results.

And the arithmetic of the budget assumes DCLM's throughput. A team's own cluster, model and sequence length set the real cost; measure one run before planning seven.
