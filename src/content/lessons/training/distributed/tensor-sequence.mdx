## Two ways to split a matmul

ZeRO shards storage but still computes every layer in full on every GPU. Tensor parallelism shards the computation of a single layer. Everything follows from the two ways to split Y = X W over t GPUs.

**Column-parallel.** Split W by output columns, W = [W_1 ... W_t]. Each GPU holds the full input X and computes Y_i = X W_i, a slice of the output's columns. The forward pass needs no communication. In the backward pass, each GPU computes dW_i = X^T dY_i locally, but dX = sum over i of dY_i W_i^T: every GPU holds one term of the sum, so a full dX needs an all-reduce.

**Row-parallel.** Split W by input rows, and the input X by the matching columns. Each GPU computes X_i W_i, a full-sized partial result, and Y is their sum: an all-reduce in the forward pass. The backward pass is local, because each GPU's dX_i = dY W_i^T needs only the replicated dY.

The pairing is the trick. Put a column-parallel matmul first and a row-parallel one second, and the first's column-sharded output is exactly the row-sharded input the second wants. Any elementwise operation between them, GeLU or the SwiGLU gate, works on the shards without communication. The MLP block becomes: column-parallel up-projection, local activation, row-parallel down-projection, one all-reduce at the end of the forward pass and one at the start of the backward pass. The Megatron operators name this as f (identity forward, all-reduce backward) at the block entry and g (all-reduce forward, identity backward) at the exit.

Attention fits the same pattern because heads are independent. The QKV projection is column-parallel by heads, each GPU runs attention for its heads, and the output projection is row-parallel. The Playbook notes the consequence: the tensor-parallel degree should not exceed the number of attention heads, and with grouped-query attention, fewer key-value heads than GPUs means key-value heads are replicated.

Per transformer layer that is two all-reduces forward and two backward, the four Korthikanti et al. count, each on a tensor of size s x b x h. Every one sits on the critical path: the next matmul cannot start until it finishes.

## The cost, computed

Take a scenario layer with h = 8192, a 4h MLP, s = 4096 tokens, b = 1, BF16 activations and t = 8. Each all-reduce moves an s x b x h tensor of 2 x 4096 x 8192 = 67.1 MB.

<p>Per all-reduce, 2 x 7/8 x 67.1 MB = 117.4 MB. Four of them: <b>469.8 MB</b> per GPU per layer. Compare the compute: a layer has about 12h^2 = 805M parameters, so forward plus backward is 6 x 805M x 4096 tokens = 1.98e13 FLOPs, 2.47e12 per GPU at t = 8. At the A100's 312 TFLOP/s peak that is 7.9 ms. At NVIDIA's quoted 600 GB/s NVLink figure the traffic takes 0.78 ms, about a tenth of compute. Over a 50 GB/s inter-node link it takes 9.4 ms, more than the compute.</p>
</Predict>

That arithmetic is the whole placement rule. Stretch TP to 16 across two nodes and the compute per GPU halves to 4.0 ms while the traffic, now partly on the slower link, becomes 4 x 67.1 MB x 2 x 15/16 = 503 MB, about 10.1 ms at 50 GB/s. The ratio of communication to compute goes from 0.1 to above 2.

The Playbook measured this. It reports significant drops in throughput moving from TP=8 to TP=16 and an even steeper decline from TP=16 to TP=32, with the biggest drop at the step from NVLink inside a node to EFA between nodes, and cites around 43% degradation for cross-node tensor parallelism against 14% for pipeline parallelism stretched from one node to two. Llama 3's 405B run used TP 8 in every configuration it published and ordered its dimensions TP innermost so that the most frequent communication rides the fastest links.

## Sequence parallelism: the regions TP left alone

Tensor parallelism shards the activations inside the matmuls, but the layer norms, dropouts and residual adds between blocks still run on the full s x b x h tensor on every GPU. That is the 10 in Korthikanti's per-layer formula with TP, sbh(10 + 24/t + 5as/(ht)): bytes no TP degree reduces.

Sequence parallelism shards those regions along the sequence dimension instead. Layer norm and dropout are per token, so each GPU can process s/t tokens of them independently. The transitions change: entering a TP region, the GPUs all-gather the sequence shards into the full tensor (Korthikanti's g, a reduce-scatter in backward); leaving it, they reduce-scatter the partial sums back into sequence shards (g-bar, an all-gather in backward). Each all-reduce of plain TP has become a reduce-scatter and an all-gather, which is the same traffic, so SP is free in bandwidth.

The memory win is the 10 becoming 10/t: the formula becomes sbh(34/t + 5as/(ht)), and the Playbook states the maximum activation size drops to b x s x h / tp. At t = 8 the linear part goes from 10 + 3 = 13 to 4.25 bytes per sbh, a 3 times cut in that term. TorchTitan bundles TP and SP under one degree for that reason; there is no setting in which you want TP without SP.

## The interview derivation, in code

The reported OpenAI question asks for Y = X @ W with W column-sharded over P devices: the forward pass, the backward pass, and the collectives for a replicated dX with dW left sharded. The derivation above answers it; the code checks it with numpy on simulated devices.

```python
import numpy as np

rng = np.random.default_rng(0)
B, D, H, P = 4, 6, 8, 4                       # H divisible by P
X = rng.standard_normal((B, D))
W = rng.standard_normal((D, H))
dY = rng.standard_normal((B, H))              # upstream gradient

W_sh = np.split(W, P, axis=1)                 # device p holds W[:, p*H/P:(p+1)*H/P]
dY_sh = np.split(dY, P, axis=1)               # and the matching slice of dY

Y_sh = [X @ Wp for Wp in W_sh]                # forward: no communication, Y is column-sharded
dW_sh = [X.T @ dYp for dYp in dY_sh]          # dW stays sharded: local
dX_partial = [dYp @ Wp.T for dYp, Wp in zip(dY_sh, W_sh)]
dX = sum(dX_partial)                          # all-reduce (sum) gives every device the full dX

assert np.allclose(np.concatenate(Y_sh, axis=1), X @ W)
assert np.allclose(np.concatenate(dW_sh, axis=1), X.T @ dY)
assert np.allclose(dX, dY @ W.T)
print("forward: none; dW: none; dX: one all-reduce of", dX.nbytes, "bytes per device")
```

If the next layer wants the full Y, the forward pass adds an all-gather of the Y shards. If the next layer is row-parallel, it consumes the shards directly and the all-gather disappears, which is the column-then-row pairing again. The standard debugging check for this code in a real framework is the one the asserts encode: compare every sharded result, concatenated, against an unsharded reference on a small shape, and count collectives per step against the derivation, since a duplicated all-reduce doubles the gradient silently.

## What has changed recently

Two developments shift where TP sits. First, communication overlap inside TP: TorchTitan's AsyncTP overlaps the tensor-parallel collectives with the matmuls they feed, and the paper reports Llama 3.1 70B on 256 GPUs going from 897 to 1,010 tokens per second per GPU, 12.59%, with FSDP 32 and TP 8. It requires H100-class GPUs with NVSwitch. Second, large MoE models have dropped TP entirely: DeepSeek-V3 trained with pipeline, expert and ZeRO-1 data parallelism and calls TP costly. Megatron-LM's 2021 composition, TP inside the node and pipeline across, at 502 petaFLOP/s on 3,072 GPUs, remains the dense-model baseline those choices are measured against.

## When this is wrong

The cost arithmetic uses peak FLOP/s and headline bandwidth. Achieved matmul throughput at small per-GPU shapes falls as t grows, because each GPU's matmul gets thinner, so TP efficiency drops before communication dominates. Measure tokens per second per GPU at each TP degree rather than extrapolating from the ratio.

The 8-GPU node is a property of the hardware, not of tensor parallelism. Systems whose NVLink domain spans many more GPUs move the boundary where TP's per-layer collectives leave the fast fabric, and the published TP 8 configurations are a consequence of 8-GPU nodes.

Sequence parallelism as described here shards only the non-attention regions. It does not split attention's own sequence dimension; for that, and for sequences whose attention activations dominate, context parallelism is the next lesson.

The column-then-row pattern assumes the block is a sequence of matmuls with elementwise operations between them. MoE layers break it: experts are routed, not split, and expert parallelism replaces TP for them.
