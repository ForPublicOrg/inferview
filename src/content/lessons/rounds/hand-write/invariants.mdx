export const invCode = String.raw`import math, random

def online_normalizer(xs):
    # one pass: running max m and running sum d, rescaled whenever the max grows
    m, d = float("-inf"), 0.0
    for x in xs:
        m_new = max(m, x)
        d = d * math.exp(m - m_new) + math.exp(x - m_new)
        m = m_new
    return m, d

def merge(a, b):
    # combine the (m, d) states of two blocks; associative, so blocks can run in any grouping
    (ma, da), (mb, db) = a, b
    m = max(ma, mb)
    return m, da * math.exp(ma - m) + db * math.exp(mb - m)

def softmax(xs):
    m, d = online_normalizer(xs)
    return [math.exp(x - m) / d for x in xs]

def attend(q, K, V):
    # one query row against keys and values 0..len(K)-1
    scale = 1 / math.sqrt(len(q))
    w = softmax([sum(a * b for a, b in zip(q, k)) * scale for k in K])
    return [sum(w[j] * V[j][c] for j in range(len(V))) for c in range(len(V[0]))]

def causal_attention(Q, K, V):
    # row i sees keys 0..i only: the mask is applied by never scoring j > i
    return [attend(Q[i], K[: i + 1], V[: i + 1]) for i in range(len(Q))]

def top_p(probs, p):
    # keep the smallest prefix (by probability, ties by index) whose mass reaches p, then renormalise
    order = sorted(range(len(probs)), key=lambda i: (-probs[i], i))
    kept, mass = [], 0.0
    for i in order:
        kept.append(i)
        mass += probs[i]
        if mass >= p:
            break
    return {i: probs[i] / mass for i in kept}

## What a hidden test can check

A grader cannot compare a hand-written attention or sampler with a reference output bit for bit. Summation order changes the last bits, two correct top-p implementations can keep different tokens when probabilities tie, and two correct samplers draw from the random stream in different orders. So hidden tests check properties: what a masked position may influence, what must sum to one, what must stay finite, and which slow path a fast path must equal. The same holds for code you review in a serving engine, where the reference is a Python loop and the candidate is a fused kernel; it is differential testing, except that the oracle is often a property rather than a second implementation.

The set of algorithms is small and stable. One public, synthesised question bank (Apache-2.0, no company attribution) lists causal scaled dot-product attention, multi-head attention converted to grouped-query attention, a KV cache with single-step decode, BPE training and encoding, and top-k, top-p and temperature sampling. Before reading further, attempt [rnd-003](/problems/rnd-003), AUC with ties, whose hidden tests compare your answer with a brute-force pair count.

The skill being graded is picking invariants that fail on the defects these functions actually have. A test that changing a future value leaves every earlier row unchanged fails on every masking defect at once, and it treats the implementation as a black box, so it also works on code you did not write.

## The invariants, per algorithm

| Function | Invariant to test | The defect it catches |
|---|---|---|
| Causal attention | changing `V[j]` or token `j` leaves rows before `j` unchanged; row 0 equals `V[0]` | masking after the softmax; masking `j >= i`; filling masked scores with 0 instead of minus infinity |
| Causal attention with padding | a row whose keys are all masked returns the value your policy states, never NaN | softmax over a row of minus infinity, which is 0 divided by 0 |
| KV cache decode | the new token's output equals the last row of a full recompute | caching queries; forgetting to append the new K and V; position offset reset to 0 |
| Blockwise softmax | the normaliser from any split of the row, merged, equals the one-pass value | rescaling only one side when the running maximum changes |
| Cross-entropy | equals log-sum-exp minus the target logit, finite for logits like `[0, 1000]` | taking the log of a softmax that underflowed to 0 |
| Top-p | the kept mass reaches p, and dropping the smallest kept token falls below p; output renormalised | keeping tokens whose own probability exceeds p; stopping before the token that crosses p |
| Min-p | the top token is always kept; the kept set is unchanged when a constant is added to every logit | treating p_base as an absolute floor |
| Temperature | order of tokens preserved; temperature 0 is an argmax, not a division | dividing by zero; applying temperature after a filter in one path and before it in another |
| BPE encode | merges apply in learned order; `decode(encode(s)) == s` | greedy longest match against the vocabulary |
| BPE train | vocabulary size equals initial symbols plus merges; ties broken by a stated rule | a tie-break that depends on dictionary iteration order |
| AUC | ties between a positive and a negative count one half; only the order of scores matters | dropping ties; 0-based ranks in the rank-sum formula |

Three of these deserve more than a row.

**Masking.** Vaswani et al. implement the decoder mask inside scaled dot-product attention by setting the softmax inputs for illegal connections to minus infinity (section 3.2.3). The perturbation test in the first row checks exactly that contract without looking at the weights, which matters because several wrong masks produce weights that look plausible: filling with 0 instead of minus infinity still gives rows that sum to one, they just put weight on the future. The padding row is a policy decision. Combine a padding mask with the causal mask and a left-padded sequence's first row may have no visible key; you choose whether it returns zeros or copies the input, and you write a test for that choice.

**Scale.** The divisor is `sqrt(d_k)`. The paper's footnote gives the reason: with independent unit-variance components, `q · k` has mean 0 and variance `d_k`, so unscaled scores grow with the head width and push the softmax towards one-hot rows. In the base model `d_k` is 64, so the divisor is 8. No property test pins the scale, because a wrongly scaled softmax still masks and normalises correctly. One hand-computed weight on a two-token example does.

**Samplers.** Holtzman et al. define the top-p vocabulary as the smallest set whose total probability reaches p, and rescale the kept probabilities by that set's mass; their experiments use p = 0.95, and their figure 9 caption notes that p is usually in [0.9, 1). "Smallest set" makes the test two-sided: the kept mass reaches p, and removing the least probable kept token takes it below p. When probabilities tie at the boundary the smallest set is not unique, so either the test accepts any minimal set or the implementation states a tie rule and the test checks it. Min-p (Nguyen et al., ICLR 2025) keeps tokens with probability at least `p_base × p_max`, with `p_base` recommended between 0.05 and 0.1. Because the threshold is relative to the top probability, the kept set depends only on logit differences, which gives the shift test in the table.

The vocabulary-size invariant is stated in the paper: the final symbol vocabulary is the initial character vocabulary plus the number of merges, which is the algorithm's only hyperparameter. Encoding has its own contract: at test time the paper splits each word into characters and applies the learned merge operations, so the encoder's input is the ordered merge list, not the final vocabulary. A greedy longest-match encoder against the final vocabulary passes most hand examples and fails on words where an early merge and a later, longer symbol compete.

## The online normaliser

The safe softmax that frameworks use subtracts the row maximum before exponentiating. Milakov and Gimelshein count its cost in memory traffic: one pass for the maximum, one for the normaliser, one to write outputs, 4 memory accesses per element. The naive version does 3 but can overflow. Their online normaliser computes the maximum `m` and the normaliser `d` in one pass, rescaling `d` whenever the maximum grows:

```
m_j = max(m_{j-1}, x_j)
d_j = d_{j-1} * exp(m_{j-1} - m_j) + exp(x_j - m_j)
```

That brings safe softmax down to 3 accesses per element. Two further facts from the paper make it the basis of blockwise attention. The state `(m, d)` of two blocks combines with an operator that takes the larger maximum and rescales each side's `d` by `exp(m_side - m)`, and the paper states that this operator is associative and commutative, so blocks can be reduced in any grouping and order. And `d` is bounded by 1 and the number of elements seen, so a float32 `d` holds up to 1.7e37 elements before overflow.

</Fragment>
<p>After 2: m = 2, d = 1. After 4: the maximum moves, so the old d is rescaled by exp(2 &minus; 4) before adding exp(0): d = 0.1353 + 1 = 1.1353. After 3: m stays 4, d = 1.1353 + exp(&minus;1) = 1.5032. The two-pass answer is exp(&minus;2) + exp(0) + exp(&minus;1) with the maximum 4 known in advance, the same 1.5032. The defect this exposes is forgetting the rescale on the line where the maximum changes: that version returns 1 + 1 + exp(&minus;1) = 2.3679, and every probability computed from it is wrong by the same factor, so rows keep the right ranking and a test that checks only the argmax passes.</p>
</Predict>

The paper's benchmarks are on a Tesla V100 with batches of 4,000 and 10 vectors. With 4,000 vectors, online softmax reaches about 1.3 times the speed of safe softmax at a vector size of 4,000, close to the 4 to 3 ratio of memory accesses; with 10 vectors the gain is about 1.15 for sizes from 1,000 up, because the device is latency bound. Fused with a top-k of K = 5, the combination needs one memory access per element and runs up to 5 times faster than safe softmax followed by top-k at a vector size of 25,000, which the authors split into 2.5 from fusion and 2 from the online normaliser. The gain falls as K grows: 3.5 at K = 10, 2 at K = 15, 1.4 at K = 30, because maintaining the running top-k dominates.

## When this is wrong

Invariants are necessary, not sufficient. An attention that ignores Q entirely passes the masking, normalisation and cached-decode tests, and a softmax with the wrong scale passes all of them too. Each suite needs at least one value computed by hand or one differential comparison with a trusted implementation on random inputs, compared with a tolerance.

Tolerances in this lesson are float64 tolerances on pure Python. A fused kernel in bf16 reduces in a different order and cannot meet 1e-9; the tolerance has to come from the dtype and the magnitude of the values, and a test copied from a float64 reference into a bf16 suite is either always red or loosened until it catches nothing.

The table assumes textbook algorithms. Production tokenizers pre-split text with a regular expression, work on bytes and add special tokens, so `decode(encode(s)) == s` holds only up to the tokenizer's own normalisation. Production samplers add repetition penalties, logit biases and grammar masks, and the order those apply in is a product decision. Rounds that allow NumPy or PyTorch add batch and head dimensions, where the common defects move from logic to broadcasting; the third lesson in this module covers that.
