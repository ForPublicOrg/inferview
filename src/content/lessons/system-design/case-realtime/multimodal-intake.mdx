## The decision per file: text, page images or retrieval

A file attached to a chat ends up in the model's context in one of three forms. Extracted text is cheap and loses layout, figures and anything in a scan. Page images keep all of that and cost image tokens per page. Retrieval keeps neither in context: the file is indexed once and each question pulls the pages it needs. The pipeline's job is to choose one per file, from the file's type and a token estimate, before the model is called, and to tell the person what is happening while it works.

The choice depends on the model family, because each one counts the same file differently. On the Claude API, a PDF in a document block is sent both ways at once: each page is converted to an image and its text is extracted alongside, so a page costs its text tokens (the docs give 1,500 to 3,000 for typical pages) plus its image tokens. Gemini counts an image up to 384 px on both sides as 258 tokens and tiles anything larger into 768 × 768 tiles at 258 tokens each. A per-page figure without the model family attached is not a number you can plan with.

## Image tokens are arithmetic

Claude reads images in 28 × 28 px patches, so an image costs ⌈width / 28⌉ × ⌈height / 28⌉ visual tokens, up to a per-model limit. Claude 4.7 and later models are on a high-resolution tier (2,576 px on the long edge, 4,784 tokens); other models are on a standard tier (1,568 px, 1,568 tokens). Above either limit the API downscales the image before counting.

The per-request figure is the one that compounds. Every request in a conversation resends the history, so a photo attached at turn one is paid for again at every later turn unless the prefix is cached. The Vision docs add a payload point: base64 images go over the wire on every turn, while a Files API `file_id` keeps the request small.

A 200-page contract on a model with a 200k-token window shows how these combine. At 1,500 to 3,000 text tokens a page it is 300,000 to 600,000 tokens of text before any page images, and the page limit for that window is 100. It cannot be attached whole; it has to be split or retrieved. The 1,500 figure is the docs' typical low end, so a sparse document may fit where a dense one does not, and the token-counting endpoint gives the real number for a given file.

## The pipeline

**Upload.** The client uploads straight to object storage with a short-lived signed URL, in parts for large files so a dropped connection resumes rather than restarts. The application server never proxies the bytes. The client resizes images to the model tier's long edge before upload, because the provider would downscale them anyway and the bytes cost upload time on a phone.

**Identify.** On the storage completion event, a worker reads the file's magic bytes rather than trusting its extension, records type, size and page count, and rejects what the pipeline cannot route. A PDF with a text layer and one without are different types for routing purposes.

**Route.** Born-digital PDFs and text files go to text extraction, with page images kept for pages that carry figures or tables. Scans go to page images or to OCR, chosen by what the questions will be (layout and handwriting favour page images; long scanned text favours OCR, which is cheaper per page and searchable). Office files are converted. Audio becomes a transcript; Gemini counts raw audio at 32 tokens a second, which is the comparison to make before sending audio as audio.

**Budget.** Before the file is attached, the worker estimates tokens per file and for the conversation. Under the budget, the file goes into context, cached so follow-up questions read it from the cache. Over it, the file is indexed and each question retrieves pages. For visually rich documents, retrieval can run over page images instead of extracted text: ColPali embeds page images directly, and its authors report that it beats text-extraction pipelines on their ViDoRe benchmark while being simpler to index. The cost is a multi-vector index, many vectors per page rather than one per chunk, which is larger to store.

**Progress.** Each stage emits an event (uploaded, identified, pages processed out of total, ready), streamed to the client. A person who sees "page 31 of 120" waits; a person who sees a spinner re-uploads, and a re-upload is a second copy of the file going through every stage unless uploads are deduplicated by content hash.

```python
import math

# Claude vision, checked 2026-10-28: 28 px patches; (max long edge px, max visual tokens) per tier.
TIERS = {"high": (2576, 4784), "standard": (1568, 1568)}

def image_tokens(w, h, tier):
    edge, cap = TIERS[tier]
    tokens = math.ceil(w / 28) * math.ceil(h / 28)
    if max(w, h) > edge or tokens > cap:
        return None          # the API downscales it; count with the token-counting endpoint
    return tokens

def route(kind, pages=0, text_layer=False, size=(0, 0), budget=100_000, tier="high"):
    if kind == "image":
        t = image_tokens(*size, tier)
        return f"inline image, {t} tokens" if t else "resize client-side, then count"
    if kind == "pdf" and text_layer:
        low, high = 1_500 * pages, 3_000 * pages      # Claude PDF text range per page, before page images
        if high <= budget:
            return f"whole document, {low:,}-{high:,} text tokens plus page images"
        return f"extract and index; retrieve pages per question ({low:,}-{high:,} text tokens is over budget)"
    return "page images or OCR in a background job, then the same budget check"

print(route("image", size=(1400, 1000)))
print(route("image", size=(1400, 1000), tier="standard"))
print(route("pdf", pages=20, text_layer=True))
print(route("pdf", pages=40, text_layer=True))
print(route("pdf", pages=12, text_layer=False))
```

```text
inline image, 1800 tokens
resize client-side, then count
whole document, 30,000-60,000 text tokens plus page images
extract and index; retrieve pages per question (60,000-120,000 text tokens is over budget)
page images or OCR in a background job, then the same budget check
```

The 100,000-token attachment budget is a choice, not a limit. It leaves room in a 200k window for the system prompt, the conversation and the reply; a team on a 1M-token model could set it higher and pay for every token on every turn that is not served from the cache.

## When this is wrong

The token figures are Claude's and Gemini's as documented on 28 October 2026, and they change with model tiers; a new tier can triple the cost of the same photo. Count with the provider's token-counting endpoint on a sample of your own files before committing to a budget, because the PDF text range is the docs' "typical" and your documents may not be.

The routing above treats the model's own document understanding as the expensive path and extraction as the cheap one. For layout-heavy documents (forms, invoices, slides) extracted text can be wrong in ways that are hard to detect, and page images may be the only reliable input; the cheaper path then costs more in wrong answers than it saves in tokens. ColPali's reported advantage is on its authors' benchmark, and a multi-vector index has a storage and serving cost to measure before adopting it.
