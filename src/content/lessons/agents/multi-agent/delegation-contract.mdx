## The failure is at the boundary

In Anthropic's research system the lead agent first delegated with short instructions such as "research the semiconductor shortage". One sub-agent researched the 2021 automotive chip crisis; two others duplicated each other's work on 2025 supply chains. None of them failed at its own task. The brief failed: it did not say which shortage, did not say who covered what, and did not say what to return. Anthropic's fix was to make the lead state, for every sub-agent, an objective, an output format, guidance on tools and sources, and clear task boundaries.

MAST names the same thing from traces: inter-agent misalignment modes sum to 32% of the failures in its Figure 1, and much of what it records under system design (disobeyed task and role specifications, missed termination) starts in what one agent told another. The delegation contract is the artefact that prevents both. It is an RPC interface: request schema, deadline, response schema, error codes. The difference is that the callee interprets the request in natural language, its deadline is counted in tool calls and tokens, and its response is unverified unless the caller checks it.

## Six fields

Objective, with the definition of done and every shared definition. "Board members of these three companies as of the latest proxy statement" is a contract; "look into the boards" is not. When workers must agree on a definition (which quarter, which revenue line, which API version), it goes into every brief, because a worker cannot honour a decision it never saw. That is Cognition's second principle, actions carry implicit decisions, applied to the brief instead of the trace.

Out of scope, and who owns it. The duplicated supply-chain work came from two briefs that overlapped. Naming what another worker covers costs a sentence and removes the overlap.

Allowed tools and sources. Least privilege for the worker's tool list, plus source guidance. Anthropic's human testers found early agents chose SEO-optimised content farms over authoritative but lower-ranked sources such as academic PDFs, and the fix was source-quality heuristics in the prompt. A code-review worker that only reads has no write tools; a research worker has search and fetch, not a code interpreter, unless the task needs one.

Budget. A ceiling on tool calls, and on tokens or wall-clock time where the runtime can enforce them. Anthropic embedded its effort rules in the lead's prompt: one agent with 3 to 10 tool calls for a fact, 2 to 4 sub-agents with 10 to 15 calls each for a comparison, more than 10 sub-agents for complex research. Early agents without them spawned 50 sub-agents for simple queries. A prompt budget is advice; the runtime's turn limit is the contract.

Output format. A schema the lead can merge without rereading the worker's sources: claims, each with a source URL, plus an as-of date and a status. For large outputs, Anthropic's sub-agents write their work to external storage and return a lightweight reference, so the lead does not relay everything through its own context.

Verification and the failure channel. Who checks the result, against what, and what the worker returns when it cannot finish. "not_found" and "blocked" are valid results. A worker with no legitimate way to say "this does not exist" keeps searching, which is the endless search for nonexistent sources Anthropic saw in early agents.

## Both ends of the contract in the OpenAI Agents SDK

The OpenAI Agents SDK (openai-agents 0.24.0, released 15 October 2026) has two delegation primitives, and they put the contract in opposite places.

Agents as tools. `Agent.as_tool()` turns a specialist into a tool the manager calls; the manager keeps the conversation and answers the user. The nested agent does not inherit the parent's conversation: it receives the tool input, by default one string field named `input`, or a structured `parameters` type you define. The brief is therefore the specialist's entire context, which makes the contract explicit by construction: a Pydantic model for `parameters` with fields for objective, scope and budget is the contract in code. `custom_output_extractor` decides what comes back to the manager, `max_turns` bounds the nested run, and `needs_approval` pauses it for a human. The risk is the one Cognition describes: whatever the manager knows and did not put in the input, the specialist does not know.

Handoffs. A handoff appears to the model as a tool named `transfer_to_<agent>`, and the receiving agent becomes the active agent for the rest of the turn. By default it sees the entire previous conversation. `input_filter` transforms that history, and `handoff_filters.remove_all_tools` strips tool calls and results, but the docs warn that it does not redact tool content already copied into ordinary messages. `input_type` carries small model-generated metadata such as a reason or priority; it is not the main input. Here the contract is implicit: the receiver inherits everything, including decisions it should not act on and data it should not see, and nothing forces a structured result.

Verification is yours in both. Input guardrails run only for the first agent in a run, and in parallel with it by default, so a tripwire can fire after tokens are spent and tools are called; set `run_in_parallel=False` when the check must come first. Output guardrails run only for the agent that produces the final output. Tool guardrails apply to function tools but not to the handoff call, and `as_tool()` does not expose tool-guardrail options. The guardrails page recommends tool guardrails for checks across managers, handoffs and delegated specialists rather than agent-level ones alone. `is_enabled` hides a tool or handoff from the model; the docs say it is not an authorization check. For a handoff, validate parsed arguments in `on_handoff` and raise to block the transfer.

The choice follows from who should answer the user and how much context should cross. Bounded subtasks with a result to merge: agents as tools, with the contract in `parameters`. A specialist that should take over the conversation, such as a refunds agent after triage: a handoff, with an `input_filter` that passes what the specialist needs and nothing else.

## The contract in code

The check at the join is ordinary code. This one accepts or rejects a worker's result against its contract before the lead merges it.

```python
from dataclasses import dataclass, field

@dataclass
class Contract:
    objective: str
    out_of_scope: list[str]
    allowed_tools: set[str]
    max_tool_calls: int
    required_fields: list[str]
    statuses: set[str] = field(default_factory=lambda: {"done", "not_found", "blocked"})

def check(contract: Contract, result: dict, calls: list[str]) -> list[str]:
    """Return contract violations for one worker result; an empty list means accept."""
    problems = []
    if result.get("status") not in contract.statuses:
        problems.append(f"status {result.get('status')!r} is not one of {sorted(contract.statuses)}")
    if len(calls) > contract.max_tool_calls:
        problems.append(f"{len(calls)} tool calls, budget {contract.max_tool_calls}")
    if extra := set(calls) - contract.allowed_tools:
        problems.append(f"tools outside the contract: {sorted(extra)}")
    if result.get("status") == "done":
        problems += [f"missing field {f}" for f in contract.required_fields if f not in result]
        problems += [f"claim without a source: {c['text'][:40]}" for c in result.get("claims", []) if not c.get("url")]
    return problems

brief = Contract(
    objective="Directors of Northwind and Contoso as of each company's latest proxy statement",
    out_of_scope=["executive officers who are not directors", "any other company"],
    allowed_tools={"web_search", "fetch"},
    max_tool_calls=15,
    required_fields=["claims", "as_of"],
)
result = {"status": "done", "as_of": "2026-09", "claims": [
    {"text": "Northwind: director list from the proxy statement", "url": "https://example.com/northwind-proxy"},
    {"text": "Contoso: director list from a news summary", "url": ""},
]}
print(check(brief, result, ["web_search"] * 9 + ["fetch"] * 4 + ["python"]))
# ["tools outside the contract: ['python']", 'claim without a source: Contoso: director list from a news summa']
```

The check is structural: it catches a worker that left its tool list, ran over budget or returned an unsourced claim. It cannot tell whether a sourced claim is true. That needs a second check, by a citation pass, a verifier model or a human, and the contract says which.

## Write one

Write the contract for a worker in a pull-request review system: the lead splits a 30-file change by file group and sends each group to a worker. Write the six fields before opening the reference.

<details>
<summary>A reference contract</summary>

```yaml
objective: >
  Find defects in the files listed below that a reviewer would block the merge for:
  injection, missing authorisation checks, unhandled errors on external calls, and
  behaviour that contradicts the linked ticket. Done when every listed file has been read.
shared_definitions:
  ticket: PAY-412, linked below; its acceptance criteria define intended behaviour
  severity: block | should_fix | note
out_of_scope:
  - files not in this group (other workers own them)
  - style and naming (the linter owns them)
  - cross-file interactions: list suspected ones under handoff_notes, do not investigate
tools: [read_file, grep, git_diff]          # no write tools, no network
budget: {max_tool_calls: 25, max_turns: 12}
output:
  status: done | blocked
  findings: [{file, line, severity, claim, evidence}]   # evidence quotes the lines
  handoff_notes: [string]
verification:
  - the join rejects findings whose evidence lines do not exist in the diff
  - block findings are re-checked by one synthesis agent that reads the full diff
```

The field most often left out is the cross-file rule. Workers that each see one group cannot find an authorisation check that one file adds and another bypasses; the contract makes that someone's job by passing suspicions to the synthesis agent instead of asking each worker to chase them.

## When this is wrong

A tight contract can make the system worse at what it is for. Anthropic's lead agents were told to start with short, broad queries and narrow down, and much of a research worker's value is the pivot it was not told to make. A contract that lists every allowed source turns a researcher into a scraper. Scope the ownership and the output tightly; leave the search strategy open.

Contracts do not transfer implicit decisions. For coupled work, such as code that must agree with a migration another worker is writing, the decision does not exist yet when the brief is written, and no field captures it. That is Cognition's case for one agent with one context, and a contract does not answer it.

The structural check proves conformance, not truth. A worker can return a schema-valid finding with a real URL that does not support the claim; that is MAST's incorrect verification mode, and only a semantic check catches it. Budget for that check where the stakes need it rather than assuming the schema covers it.

The SDK details here are for openai-agents 0.24.0 as documented in October 2026. Default history behaviour for handoffs, guardrail placement and nested-history options are version-specific (nested handoff history is an opt-in beta in this release) and are the facts most likely to go stale; check the docs for your version before relying on a default.
