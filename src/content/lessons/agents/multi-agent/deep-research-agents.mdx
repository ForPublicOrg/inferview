## What it is and who runs it

A deep-research agent takes one question, runs many searches and reads over minutes, and returns a report with citations. Four vendors shipped one between December 2024 and April 2025: Google's Deep Research in Gemini (11 December 2024), OpenAI's deep research in ChatGPT (2 February 2025), Perplexity Deep Research (14 February 2025) and Claude's Research (15 April 2025). They share a product shape and publish very different amounts about how they work. OpenAI has published the most: a launch post with dated updates, a system card, a help-centre page and an API guide. Anthropic's engineering post on its orchestration has its own teardown in this module. Google and Perplexity have published launch posts and little else on internals.

One distinction matters before the diagram. OpenAI describes its product as one model, a version of o3, trained with end-to-end reinforcement learning to plan and execute a long browsing trajectory. Anthropic describes a lead agent with parallel sub-agents. The products look the same from outside; one public design is a trained single agent and the other an orchestrated multi-agent system.

User and question. The input is a prompt plus optional context: uploaded files and a list of sites in ChatGPT, and connected sources (Google Workspace in Claude's April 2025 launch; connected apps and any MCP server in ChatGPT since the 10 February 2026 update).

Clarify and rewrite. OpenAI's API guide says ChatGPT runs two steps before the research model: an intermediate model asks clarifying questions, and another expands the prompt. The API skips both, does not ask for missing context, and suggests running a smaller model first if you want them. The help centre describes the user-facing half: ChatGPT may ask clarifying questions before it starts.

Research plan. Google's launch post and OpenAI's help centre both describe a proposed multi-step plan the user can edit or approve before the research starts. Perplexity's post describes a plan the agent refines as it learns, with no user step mentioned.

Search and read loop. The core of every product. Perplexity describes dozens of searches and hundreds of sources per task; OpenAI's model searches, interprets text, images and PDFs, and pivots on what it finds; Google's searches, reads and searches again; Anthropic's runs searches that build on each other. OpenAI's launch post shows pass rate rising with the maximum number of tool calls allowed.

Browsing tools. In the API, the output items name the browsing actions: `search`, `open_page` and `find_in_page`. The system card adds one restriction that matters more than any of them: the model may not navigate to or construct arbitrary URLs.

File and data analysis. OpenAI's model reads uploaded files and runs Python in a sandbox to compute and plot. Perplexity's launch post mentions coding capability without detail.

Connectors. In ChatGPT, connected apps contribute read actions only; the help centre says deep research does not use app write actions. In the API, an MCP server for deep research exposes two read-only tools, `search` and `fetch`, and must be configured with `require_approval` set to `never`, because human approval of each call is not supported there.

Site restriction. Since February 2026 ChatGPT's Sites menu restricts research to the listed domains or prioritises them while allowing the full web. How the restriction is enforced is not documented.

Progress view. OpenAI's sidebar shows a summary of steps and sources; the system card says a second, custom-prompted o3-mini summarises the research model's chain of thought for it. Since February 2026 the user can interrupt to change focus or sources.

Report with citations. OpenAI's model cites specific sentences or passages; in the API, citations are annotations carrying a URL, a title and character offsets into the report. ChatGPT creates citation metadata from an MCP result only when its `url` is non-empty, so a connector without URLs produces uncited text.

## Context strategy

None of the vendors documents how a long run stays inside a context window. Google's launch post credits Gemini's 1M-token context window, together with its agentic system, for the reports. OpenAI's post says the model learned through training to plan, backtrack and react to what it reads, and the system card says training rewarded both auto-gradable answers and rubric-graded reports; neither says whether the trajectory is compacted. Anthropic's design, covered in its own teardown, answers the question with sub-agents that each read in a fresh context and return condensed findings, plus a plan saved to memory. That is the one published context strategy among the four.

## Tools and permission model

The public permission model is read-only by design. ChatGPT's connected apps contribute read actions only; MCP servers expose `search` and `fetch`. The two documented controls against injection are structural rather than model-based: the research model cannot construct arbitrary URLs, which removes the channel of an API key or a document smuggled out in a query string, and the API guide's staged workflow runs public web research first and the private MCP call second with web access off, so injected instructions from the web never share a run with private data.

The MCP guide is blunt about the limits. Even read-only servers can return injection payloads in search results; an attacker can try to pull data from one MCP server and send it out through another; and trusting a server's developer does not make its content safe.

## Cost and latency

Latency ranges by vendor and by year. OpenAI's launch post quoted 5 to 30 minutes, and its API guide says tasks can take tens of minutes and recommends background mode with webhooks. Perplexity quoted 2 to 4 minutes at launch, with most tasks under 3. Google said a few minutes.

OpenAI is the only vendor to publish a cost lever. In the API, `max_tool_calls` caps the total number of searches, page opens and MCP calls, and the guide calls it the primary way to constrain cost and latency. In ChatGPT, cost shows up as quotas: from April 2025, 25 tasks a month on Plus, Team, Enterprise and Edu, 250 on Pro and 5 on Free, with overflow to a lightweight version on an o4-mini model.

The GAIA table shows the price of reliability. Deep research scored 67.36 averaged over levels with one attempt (pass@1) and 72.57 with cons@64, the consensus answer over 64 attempts: 5.21 points for 64 times the runs. The headline number to compare with your own system is the pass@1.

## Failure modes

The vendors' own lists. OpenAI's launch post names its limitations: it can hallucinate facts or make incorrect inferences (at a lower rate than ChatGPT models in OpenAI's internal evaluations), it may fail to distinguish authoritative information from rumour, its confidence calibration is weak, and at launch reports and citations could carry minor formatting errors. Anthropic's engineering post reports that its early research agents preferred SEO-optimised content farms over authoritative sources until source-quality heuristics were added.

Injection through what it reads. The system card names the two harms: an attacker steers the answer (the wrong product, the wrong fact) or exfiltrates data the user did not mean to share. Its mitigations were safety training plus the URL restriction, and it states that residual risk remains.

Citation without support. A citation proves that a passage was linked, not that it says what the report claims. The vendors describe how citations are attached. Apart from Anthropic's citation agent, which attributes claims to sources, none of the documents above describes how a citation is checked against its claim before the report is shown.

Scope drift across a long run. A run of dozens of searches can drift from the question the user meant, which is what plan editing, clarification and interruption exist to catch. Those controls depend on a user who reads the plan and the progress view.

## What is not public

How OpenAI's, Perplexity's and Google's products orchestrate a run: whether any of them uses several agents in parallel, how many, and how work is divided. OpenAI's public description is a single trained model; whether today's product, described as powered by the latest models, still works that way is not stated.

Which models power the current products. OpenAI's help centre says the latest models, without naming them; Google's and Perplexity's public descriptions are their launch posts from December 2024 and February 2025.

How citations are verified, by any of the four, except for what Anthropic publishes about its citation agent.

How the trusted-site restriction is enforced (a search filter, a fetch-time block, or both), and whether it constrains pages reached by following links.

Per-task token usage and cost distributions, and how the quotas map to compute. Context management during long runs, for all but Anthropic.

## In the room

<Callout kind="interview" label="Interview question">
**"Build an internal deep-research feature over the public web and two internal MCP servers, a wiki and a CRM. Security says no CRM data may reach any external host. Product wants a report in under ten minutes that combines market data with account history. You have one quarter."**
</Callout>

<Depth>
<Fragment slot="short">
<p>Split the run. A public research pass with web tools and no internal connectors, then a private pass with the wiki and CRM and no web access that takes the public findings as input, and a final write-up in the private context. That is OpenAI's documented staged workflow, and it puts the security property in the topology rather than in the model's behaviour. The cost is that the private pass cannot go back to the web for a lead it finds; I would cap each pass's tool calls to hold the ten minutes.</p>
</Fragment>
<Fragment slot="long">
<p>The constraint is exfiltration, and the documented mitigations are structural: no URL construction, and no run where untrusted web content and private data coexist with a network path. So the public pass runs first with web search and fetch, read-only, under a tool-call cap. Its output is text and citations, treated as untrusted input to the next stage.</p>
<p>The private pass has the wiki and CRM servers, read-only, with no web tool and no egress, and gets the public findings as a document. Prompt injection in that document can still distort the report, so the report's claims about accounts are checked against CRM records in code before release, not by the model.</p>
<p>Latency: the two passes are sequential, so each gets a budget. Measure tool-call counts against wall time on 20 real questions and set the caps so the 90th percentile lands under ten minutes; a cap that cuts quality on comparisons is a product decision to escalate, not to hide.</p>
<p>What I give up: a single reasoning pass over both sources, which is what product actually asked for. I write down that the private pass cannot follow a new public lead, and offer a second public pass on request as the escape hatch.</p>
