## What it is and who runs it

ChatGPT is OpenAI's consumer and workplace assistant. This teardown covers two features that meet in one product: memory, which carries context about the user from one conversation to the next, and agent mode, which gives the model a virtual computer with browsers, a terminal and connectors to the user's apps.

Memory started as a test in February 2024 and reached Free, Plus, Team and Enterprise users in September 2024. In April 2025 it gained a second mechanism, reference to past chat history, for Plus and Pro, with a lighter short-term version for free users from June 2025. Agent mode launched on 17 July 2025 for Pro, Plus and Team, as the successor to Operator (web actions) and deep research (multi-step research and reports).

Everything here comes from OpenAI's posts, help pages and the agent system card, plus one external security write-up, all checked on 2026-10-28. Two dating notes matter. The memory FAQ had been revised within the week before that check and describes an "improved memory" experience alongside legacy saved memories, so control names are moving. And OpenAI's agent launch post now marks itself as outdated and points readers to Workspace agents and ChatGPT Work, which are not covered here; the agent described below is the one documented at launch.

Saved memories. Details the user asks ChatGPT to remember, or that ChatGPT saves as useful context. Since September 2024 the interface shows a Memory updated notice with a link to manage memories. Saved memories are stored separately from chat history: deleting the chat in which something was said does not delete a memory created from it. Depending on plan, the controls include search, sorting, automatic prioritisation and version history.

Chat-history reference. Added in April 2025: ChatGPT draws on past conversations without anything being saved explicitly. OpenAI's post calls these insights gathered from past chats; the FAQ says they can change as ChatGPT updates what is most useful to remember, that there is no separate storage limit for them, and that ChatGPT does not search history for every response, only when it is likely to help. Turning the setting off schedules what was remembered from past chats for deletion within 30 days, and the chats themselves stay. Depending on plan and region, the sources memory draws on also include custom instructions, files in the Library and connected apps such as Gmail.

Memory controls and temporary chat. The memory summary is a high-level view the user can correct; "Don't mention this again" suppresses a fact in future answers without deleting the source it came from. Sources can appear under a response to show which chat, memory, file or email shaped it. A temporary chat neither creates nor updates memories, and the user decides before it starts whether it may use existing memories; saving it turns it into a regular chat that follows the account's settings. Workspace admins manage memory for their members, and in regulated workspaces improved memory is off by default, with a Project-only option that confines memory to one project.

Connectors. First-party integrations (the posts name Gmail, GitHub and Google Drive) that let ChatGPT read the user's data once authenticated. In agent mode they are read paths: the launch post says that to take action on those sites the user is still prompted to log in by taking over the browser.

Agent model and virtual computer. The system card describes the agent as a model in the o3 family that combines deep research's multi-step research with Operator's remote visual browser. It runs on its own virtual computer, which keeps state across tools, so the model can open a page, download a file, process it in the terminal and view the result in the visual browser within one task.

Visual browser, text browser, terminal and API access. The visual browser acts on pages built for people. The text browser handles reasoning over large amounts of text more efficiently. The terminal runs code and analysis, and at launch its network access was limited to GET requests that download images or certain datasets, such as official government datasets. Direct API access covers cases such as reading a calendar.

Confirmation and watch mode. The agent is trained to ask before actions with real-world consequences, such as a purchase or sending an email, and to refuse some tasks outright, such as bank transfers. When it uses the visual browser in a sensitive context (the system card's examples are being logged into email or a bank), watch mode applies for the rest of the task: execution pauses if the user becomes inactive or leaves the conversation.

Injection monitors. The system card lists multiple automated monitors and filters for prompt injection, which OpenAI says it can update quickly as new attacks appear. Their models, thresholds and placement are not described.

## Context strategy

ChatGPT has two kinds of cross-conversation context with different write paths. Saved memories are written per item, in the hot path, with a visible notice. Chat-history reference is derived from past conversations by a process OpenAI does not describe, and the FAQ frames it as a changing summary rather than a list of facts. Read selection is relevance-based in both cases: the FAQ says ChatGPT decides which available information is relevant, and that the memory summary may omit details. For the user, the controls are correction, suppression and deletion; for an engineer reading the docs, the important property is that the derived layer has no visible list of entries to audit.

Agent mode keeps task context on the virtual computer. The user can interrupt to change instructions and the agent continues without losing progress, can pause and ask for a progress summary, or stop and receive partial results. At launch it did not load memory at all. The system card gives the reason in one line: memory was disabled to mitigate prompt injections that try to exfiltrate data from memory. That is the main architectural decision in this product: the long-lived personal context and the tool-using agent that reads untrusted pages were kept apart rather than guarded together.

## Tools and permission model

The controls are layered, and each covers a different failure.

Consent for data access is per connector and per site. Connectors read after the user authenticates; acting on a logged-in site requires the user to log in through takeover, so credentials pass through a channel OpenAI says it does not collect or store. One setting deletes all browsing data and logs out of every website session; otherwise cookies persist according to each site's policy.

Confirmation covers consequential actions. In OpenAI's own evaluation, the agent confirmed before a relevant action 91.0 percent of the time, which OpenAI calls an underestimate because many failures were false negatives in the evaluation. For critical actions the figures were 100.0 percent for editing permissions, 99.9 percent for sending high-stakes communications and 100.0 percent for completing financial transactions.

Supervision covers sensitive sessions through watch mode. Refusal covers categories OpenAI decided the agent should not perform: researching people's private data, buying regulated goods, gambling and moving money between financial accounts.

Injection resistance is a stack, and OpenAI published model-only numbers for the bottom layer, which exclude the monitors and other mitigations. On synthetic text-browser pages, the agent disregarded irrelevant instructions or exfiltration attempts in 99.5 percent of cases. In the visual browser it did so in 95 percent, resisted exfiltration of data already in its context in 78 percent, and resisted attacks requiring it to fetch sensitive data actively in 67 percent. The last figure means 33 percent of those synthetic active-exfiltration attempts were not stopped by the model alone, which is why the rest of the stack exists: monitors, confirmations, terminal network limits and memory off.

## Cost and latency

At launch, Pro subscriptions included 400 agent messages a month and other paid plans 40, with more available through credit-based options. Agent access did not include the European Economic Area or Switzerland at launch. OpenAI publishes no per-task token, time or compute figures; the product's latency answer is asynchrony: tasks run on their own computer, the user can leave, and the phone app notifies on completion. Completed tasks can be scheduled to recur.

Memory carries no separate price. The FAQ states that chat-history reference has no separate storage limit, and the read cost is OpenAI's: whatever memory adds to a prompt is not billed to the user per token.

## Failure modes

Memory as a persistence channel. Rehberger's September 2024 spAIware write-up showed an untrusted page making ChatGPT store a memory that told it to send later conversations to an attacker's server through image URLs. ChatGPT macOS 1.2024.247 closed that exfiltration channel; the author reported that writing memories through prompt injection was not fixed. A stored instruction outlives the page that planted it and waits for the next channel out.

Deletion that does not reach derived data. A user who deletes a chat has not necessarily deleted the saved memory created from it, "Don't mention this again" is suppression rather than deletion, chat-history-derived information takes up to 30 days to be removed after the setting is turned off, and OpenAI may keep logs of deleted saved memories for up to 30 days. Each is documented; together they mean "I deleted it" can be false in three different ways.

Confirmation misses and model mistakes. The system card's example of a mistake is buying the wrong product. Its confirmation evaluation leaves 9 percent of relevant actions without a confirmation, a figure OpenAI says overstates the misses; for a feature used at ChatGPT's scale, even the critical-action figure of 99.9 percent for high-stakes communications is a rate, not a guarantee.

Exfiltration through what the agent can reach. Connectors and sites the user has logged into put private data inside a context that also reads untrusted pages. The model-only figures above show the bottom layer stops most but not all attempts; the residual depends on monitors whose design is not public.

Sessions that persist. A site session created through takeover keeps its cookies unless the user deletes browsing data, so a later task on the same site acts with the user's logged-in session.

## What is not public

OpenAI does not publish how memories are selected for a given prompt, what retrieval sits behind chat-history reference (what is stored as an insight, how it is indexed and ranked, or how the memory summary is generated), or how saved memories and history-derived context are weighted against each other. It does not describe the models, classifiers, thresholds or placement of the prompt-injection monitors, or how quickly they are updated in practice. The system card says memory was disabled in agent mode at launch and might be revisited; none of the sources checked here says whether it has been. Nor do they describe the virtual computer's isolation or how connector data is retained after a task.

On the write side, none of these sources describes a control that stops untrusted content from writing a memory in ordinary chat. The spAIware case shows that such a write is a persistence channel for injection, and the fixes OpenAI shipped in that case were to the exfiltration channel.

<Fragment slot="long">
<p>Why OpenAI's choice applies. The agent combines untrusted input (web pages, inbound email), private data (client records) and outbound actions (browsing, sending, CRM writes). Memory adds a fourth ingredient: instructions or data that persist across tasks. Removing memory from that context was the cheap control for OpenAI, and it is cheap here too.</p>
<p>Two defensible positions. Full memory in agent mode, guarded by provenance, taint tracking and monitors, maximises value and puts the bank's injection defences on the critical path in eight weeks. Structured preferences from the CRM give a smaller, reviewable read surface: fields such as preferred contact channel or risk profile, written by people through existing workflows, not by the model.</p>
<p>What goes in the risk note: the agent will not remember things a manager said in chat last month; the CRM fields will be incomplete at first; writes from the agent to the CRM need confirmation and an audit trail, because they become the next task's memory.</p>
<p>Measurement before reversing: rate of tasks where the agent asked for a preference that existed in past conversations, injection attempts caught by monitors in inbound email, and false-confirmation rates on CRM writes.</p>
<p>Failure mode of the recommendation: the CRM becomes the memory, and an agent that can write CRM fields from email content has rebuilt the poisoning path. Keep model-proposed CRM edits in a review queue.</p>
