## What it is and who runs it

Aider is a terminal tool for editing code with a model, released under the Apache License 2.0 and developed in the open on GitHub. Its design differs from the agentic harnesses elsewhere in this track: the user decides which files the model may edit, the harness supplies a compact map of the rest of the repository, the model answers with edits in a fixed text format, and every accepted change becomes a git commit. Because the source is public, the mechanisms below are taken from the documentation and from `aider/repomap.py` as of its last change in February 2026.

**Chat files and read-only files.** The user adds the files the model may edit with `/add` (or on the command line) and reference files with `/read-only`; `/drop` removes files to free context. Both kinds are sent in full. The docs advise adding only the files that need editing, because more files cost tokens and can overwhelm the model.

**Tree-sitter tags.** Since October 2023 the map has been built from tree-sitter syntax trees rather than ctags: for each file, where functions, classes, variables and types are defined and where they are referenced. Tags are cached on disk and reused while a file's modification time is unchanged.

**Personalised PageRank.** Files are nodes; an edge runs from a file that references an identifier to the file that defines it. Edge weights come from hand-set multipliers (×10 for an identifier the user mentioned, ×10 for long snake, kebab or camel case names, ×0.1 for private or widely defined names, ×50 when the referencing file is in the chat, times the square root of the reference count). PageRank runs with extra restart probability on chat files, files the user named and files whose path contains a mentioned identifier. The finding-code lesson works one edge weight through.

**Repo map.** The ranked definitions are rendered as file names with the key lines of each definition, and fitted to the budget by binary search on how many to include, accepting a token count within 15% of the target. The default budget is 1,024 tokens; with no chat files it is multiplied by 8, capped at the model's context window minus 4,096. Chat files are left out of the map because their full text is already present. The map is sent with every change request.

**Model and edit format.** The model returns edits as text in one of several formats, which Aider picks per model: `whole` (the full updated file), `diff` (search and replace blocks), `diff-fenced` (the same with the path inside the fence, mainly for Gemini models), `udiff` (a simplified unified diff, mainly used with GPT-4 Turbo), and streamlined `editor-diff` and `editor-whole` for architect mode, where one model describes the change in plain text and a second model writes the edit.

**Edit applier and git.** Aider applies the edits to the files, then commits. If the files had uncommitted changes, it first commits those with their own message. Commit messages are written by the configured weak model from the diff and the chat history, and Aider appends "(aider)" to the author and committer names unless told otherwise. `/undo` reverts the last commit if Aider made it.

## Context strategy

Aider's context has three parts with different owners. The user owns the chat and read-only files and pays for them in full. The harness owns the map, a fixed-size summary of everything else, recomputed toward whatever the conversation names. The model owns nothing: the docs describe no search loop, so the model sees the map and the files the user added. With no files added, Aider tries to work out from the request which files need editing, and the map is what it has to go on.

This is a push model. A grep-driven agent pulls context with tool calls and pays in turns; Aider pushes a ranked summary on every request and pays in a constant slice of context. The cap on the map's growth depends on the model.

## Tools and permission model

Aider has no tool-calling loop to permission in the sense of the other teardowns. The model's only action is to propose edits in text; Aider applies them to the files the user added. The safety net is git: every change is a commit, the user's own uncommitted work is committed separately before Aider edits, and `/undo` reverts Aider's last commit. `--no-auto-commits` and `--no-dirty-commits` turn those behaviours off.

## Cost and latency

The map costs its budget on every request: 1,024 tokens by default, up to 8,192 with an empty chat on a large-window model. Tag extraction is cached by modification time, so after the first run only changed files are re-parsed.

The edit format is the larger cost lever on output. With `whole`, the model returns every line of every file it changes. A one-line change to a 4,000-token file costs about 4,000 output tokens; as a search and replace block it is a few lines plus markers, about 150 tokens in this scenario. At Claude Opus 5.5's $20 per million output tokens, that is 8 cents against 0.3 cents per edit, and output tokens also set latency. The trade is reliability: a search block that does not match the file exactly fails to apply, while a whole-file reply always applies.

Aider's docs do not publish latency or per-request cost figures.

## Failure modes

- **The map favours what is named.** Personalisation and the ×10 and ×50 multipliers pull the map toward files and identifiers already in the conversation. A file linked to the task by behaviour rather than by name, such as a configuration file that changes what the edited function does, ranks low.
- **The user picks the files.** The 2023 post describes automatic selection of files to edit as future work. If the user adds the wrong file, the model edits what it was given.
- **Dirty commits.** By default the user's uncommitted work is committed before Aider edits, with a message written by a model. Teams that review commit history can find work in progress committed under a generated message.
- **Format mismatch.** A model that drifts from its edit format, or a search block that no longer matches because the file changed, produces a failed edit; which format suits which model is a property of the model, which is why Aider selects it per model.
- **Small-window models.** On a short context window the empty-chat map can take half the window, as the prediction above shows.

## What is not public

Little is hidden: the ranking, budgets, formats and git behaviour are all in the source and docs. What is not public is how Aider performs on its users' repositories: usage figures, and success rates by edit format or map budget on real projects rather than benchmarks. Anyone choosing a map budget or format for their own repository has to measure it there.

<Depth>
<Fragment slot="short">
<p>After the stable prefix (system prompt, tools, memory files) and as late in the request as possible, so a map change invalidates only what follows it. Its budget is set from a paired measurement of wrong-file edits against map size, and it is recomputed only when the chat files change, not on every mention, so it stays byte-identical across most turns.</p>
</Fragment>
<Fragment slot="long">
<p>The conflict is real because the map is valuable exactly when it changes: it re-ranks toward what the conversation is about. A prefix cache only helps content that is identical from the start of the request, so anything after a changed map is re-processed at the uncached rate.</p>
<p>Placement is the first lever. With the system prompt, tool definitions and memory files first, and the map after them but before the conversation, a map change costs the map plus the conversation; putting the map at the very end costs only the map but separates it from the instructions that refer to it. I would measure both with the pilot's tasks.</p>
<p>Stability is the second. Aider-style personalisation includes mentioned identifiers, so every new message can move the ranking. Recomputing only when the set of chat files changes keeps the map stable for most turns, at the cost of reacting more slowly to new names. The budget comes from the pilot: wrong-file edit rate at, say, 512, 1,024 and 2,048 tokens, paired per task.</p>
<p>What I give up: a less responsive map. The failure mode is a long session where the user's focus moves without changing the chat files, so the map keeps pointing at the old area; a forced refresh after a set number of turns bounds it.</p>

## When this is wrong

This describes the main branch as of February 2026 and the docs as checked in October 2026. The multipliers, budgets and padding are constants in the source, and any release can change them.

The cost comparison between edit formats uses a scenario file size and a single model's output price. The ratio depends on how large the edited files are and how often a search block fails to apply and has to be retried, which Aider does not publish for its users' work.
