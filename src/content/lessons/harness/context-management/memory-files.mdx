## Three loaders, three precedence rules

A memory file is text the harness prepends to the model's context without the model asking for it. The closest systems analogy is a layered configuration lookup (system, user, repository, directory), and the difference matters more than the analogy: nothing parses or enforces the result. Claude Code's memory documentation says it plainly: Claude treats CLAUDE.md files as context, not enforced configuration, and anything that must be blocked regardless of the model's choice belongs in a hook.

The three tools that most teams run side by side discover, order and cap these files differently. As of October 2026:

| | Claude Code | Codex | Cursor |
|---|---|---|---|
| Files | CLAUDE.md, CLAUDE.local.md, `.claude/rules/*.md`; AGENTS.md only when no CLAUDE.md exists on the path | AGENTS.override.md, AGENTS.md, configured fallback names | `.cursor/rules/*.mdc` (a plain `.md` there is ignored), AGENTS.md, team and user rules |
| Discovery | Every file from the filesystem root down to the working directory at launch; subdirectory files when Claude reads, writes or edits a file in that subdirectory | Project root (typically the git root) down to the working directory, at most one file per directory | Rule type set by frontmatter: always, by description, by glob, or by @-mention |
| Order and precedence | Concatenated root first, so closer files are read last | Concatenated root first, so closer files override by position | Team, then project, then user; earlier sources win on conflict; nested AGENTS.md, more specific wins |
| Size | Launch files loaded whole up to 4 MiB; on-demand files cut at 40,000 characters with a 200K window; target under 200 lines | Stops adding files once the total reaches `project_doc_max_bytes`, default 32 KiB | Keep each rule under 500 lines |
| When it is read | Once at session start; a mid-session edit applies only after `/clear`, `/compact` or a restart | Once per run | Per request, by rule type |

Three details in that table cause most of the surprises.

**A mid-session edit does nothing.** Claude Code reads project-root and user CLAUDE.md once at session start and holds them in memory. Editing the file mid-session neither invalidates the prompt cache nor reaches the model until the next `/clear`, `/compact` or restart. Nested files and path-scoped rules are the exception: they load later, so an edit made before they load does apply.

**Imports organise but do not shrink.** Claude Code expands `@path` imports up to four hops deep, and the docs note that imported files load with the file that imports them, so splitting a 600-line file into six imports costs the same context. Block-level HTML comments are stripped before injection, which makes them the one place to leave maintainer notes for free.

**The byte cap drops the most specific file first.** Codex concatenates from the root down and stops adding files once the total reaches 32 KiB. The file closest to the working directory has the highest precedence by position and is also the last to be considered, so a large root file starves the team-level file under it. The script below reproduces the documented discovery rules; the docs do not say whether the file that crosses the cap is truncated or dropped, so it reports the whole file as at risk.

```python
from pathlib import Path
import tempfile

def codex_chain(root, cwd, fallbacks=(), max_bytes=32 * 1024):
    root, cwd = Path(root).resolve(), Path(cwd).resolve()
    parts = cwd.relative_to(root).parts
    dirs = [root.joinpath(*parts[:i]) for i in range(len(parts) + 1)]
    loaded, at_risk, total = [], [], 0
    for d in dirs:
        for name in ("AGENTS.override.md", "AGENTS.md", *fallbacks):
            p = d / name
            if p.is_file() and p.stat().st_size > 0:
                size, rel = p.stat().st_size, p.relative_to(root).as_posix()
                if at_risk or total + size > max_bytes:
                    at_risk.append((rel, size))
                else:
                    loaded.append((rel, size))
                    total += size
                break  # at most one file per directory
    return loaded, at_risk, total

with tempfile.TemporaryDirectory() as t:
    t = Path(t)
    (t / "svc" / "payments").mkdir(parents=True)
    (t / "AGENTS.md").write_text("x" * 30_000)
    (t / "svc" / "AGENTS.md").write_text("y" * 1_500)
    (t / "svc" / "payments" / "AGENTS.md").write_text("z" * 2_000)
    print(codex_chain(t, t / "svc" / "payments"))
# loaded: AGENTS.md (30,000) and svc/AGENTS.md (1,500), total 31,500 bytes
# at risk: svc/payments/AGENTS.md (2,000), because 33,500 exceeds 32,768
```

Run it in CI against every directory that has an AGENTS.md and fail the build when a file lands in `at_risk`. The equivalent check for Claude Code is `wc -m` on every nested CLAUDE.md and path-scoped rule against the 40,000-character on-demand limit, past which Claude receives only the start of the file and a note to read the rest.

## What the evidence says about content

Two published results and two vendor reports bear on what goes in the file.

The ETH Zurich and LogicStar.ai study (arXiv 2602.11988, first posted February 2026, revised September 2026) ran Claude Code with Sonnet 4.5, Codex with GPT-5.2 and GPT-5.1 mini, and Qwen Code on two sets: SWE-bench Lite's 300 tasks with context files written by an LLM, and 138 tasks from 12 Python repositories whose developers had committed their own context files. The paper reports:

- LLM-generated files changed the resolution rate by -0.5% and -2% on the two sets, neither significant, while raising cost by about 20% and 23% and adding 2.45 and 3.92 steps per task.
- Developer-written files raised resolution by 2.4% on average (p = 0.21, so not significant either), added 3.34 steps and raised cost by at most 19%.
- Agents follow what the files say: when a file mentioned `uv`, agents used it 1.6 times per task, against under 0.01 times when it did not. Repository-specific tools went from under 0.05 uses to 2.5.
- Repository overviews did not reduce the steps needed to reach the relevant files.
- With the repository's own documentation removed, LLM-generated files improved resolution by 2.7%.

Read together: the files change behaviour reliably and outcomes weakly. They buy more testing and exploration, which costs steps, and they help most where the repository does not explain itself.

Chroma's context-rot report (July 2025) tested 18 models and found performance falls as input length grows even on simple retrieval tasks; on LongMemEval, focused prompts of about 300 tokens scored significantly higher than full prompts of about 113k tokens for every model. That is not a coding-agent result, but it is the mechanism behind every vendor's size advice.

OpenAI's harness-engineering post (February 2026) is the field report. Its team tried one large AGENTS.md and lists four ways it failed: it crowded out the task and the code, it made every rule equally important, it went stale, and a single blob could not be checked mechanically. The replacement is an AGENTS.md of roughly 100 lines that works as a table of contents into a versioned `docs/` tree, with linters and CI jobs that check the tree is current and cross-linked, and a recurring agent that opens pull requests for stale documents.

Claude Code's best-practices page draws the same line from the vendor side: the file should hold the commands that verify work, places where the code misleads (a live legacy directory whose patterns must not be copied), decisions that are not in the repository, and anything corrected twice. It leaves out file layout, conventions and the test framework, because current models find those by reading the code, and it says adding IMPORTANT to a line the model keeps missing probably will not fix it. A missed line is either buried in a file that is too long or a rule with no exceptions, which belongs in a hook.

## What the file costs

The obvious cost is the file's own tokens on every request. With prompt caching it is small.

<Fragment slot="prompt">
<p>Scenario inputs: a 3,000-token CLAUDE.md, a 60-request session on Claude Opus 5.5 with an API key, so the 5-minute cache. The first request writes the file to cache at $5 per million tokens; the other 59 read it at $0.20 per million.</p>
</Fragment>
<p>Write: 3,000 × $5/M = $0.015. Reads: 59 × 3,000 × $0.20/M = $0.0354. Total <b>about 5.0 cents</b>. Now set it beside the paper's measured effect. If the same session costs $4 (scenario), a 20% increase is 80 cents, sixteen times the file's own tokens. The expense of a memory file is the behaviour it causes: the extra test runs and exploration the paper counted as steps. That is money well spent when the file names the right test command and wasted when it narrates the architecture.</p>
</Predict>

The decision rule follows. A line earns its place if the agent cannot recover it from the repository within a step or two and getting it wrong is costly: the one command that runs a single test file, the directory that looks dead and is not, the error helper the team chose, the environment variable integration tests need. Everything the agent can read, it will read when it needs it; writing it down again costs behaviour on every task, including the ones it is irrelevant to.

Where a line applies to one part of the tree, all three tools now have a scoped home: Claude Code's path-scoped rules (a `paths:` glob in frontmatter, loaded when Claude reads or edits a matching file), Cursor's glob rules, and a nested AGENTS.md. Scoping trades context for timing. A path-scoped rule is absent until the matching file is touched, and in Claude Code it is summarised away by compaction until it matches again, which the compaction lesson in this module covers.

<Callout kind="gotcha" label="Two loaders, one file">
Claude Code reads AGENTS.md only when no CLAUDE.md, `.claude/CLAUDE.md` or CLAUDE.local.md exists on the path (v2.1.277 or later). A developer who adds a personal CLAUDE.local.md to a repository that relies on AGENTS.md silently stops loading the team file. An `@AGENTS.md` import from CLAUDE.md, or the `claude-md-and-agents-md` setting, loads both.
</Callout>

## When this is wrong

The study's tasks are Python issue fixes with tests, and its developer-file set is 138 tasks from 12 repositories. A repository in a less common language, with an unusual build, or with no documentation at all is exactly where the paper found files help, so its average is not your repository's answer.

The size targets (under 200 lines for Claude Code, under 500 per Cursor rule, about 100 lines in OpenAI's report) are vendor guidance without a published curve behind them. Treat them as starting points for your own paired measurement, not thresholds.

Loading behaviour is version-specific and has moved several times in 2026: AGENTS.md support in Claude Code needs v2.1.277, the 40,000-character limit on on-demand files arrived in v2.1.309, and Cursor ignores a plain `.md` file placed in `.cursor/rules`. Re-check the table against each tool's current docs before relying on it.

Finally, "only what the agent cannot infer" depends on the model. A weaker or cheaper model infers less, and a line that is redundant for one model is the line that saves another.
