## The error string is the next prompt

When a tool fails inside an agent loop, the failure text becomes a tool result, the model reads it, and its next action is conditioned on those words. No human reads the message first. A compiler diagnostic with a fix-it hint is the nearest familiar thing; the difference is that the reader here acts on the hint automatically, in a loop, with a budget, and has no documentation open beside it unless the message points to some.

Four public systems show the effect from different angles.

**SWE-agent (2024)** put a linter in front of its edit command. An edit that introduced a syntax error was discarded, the agent was shown the error, and it was asked to try again. In the paper's ablation the interface with linting resolved 18.0% against 15.0% without it. The same paper shows why this matters: 51.7% of trajectories had at least one failed edit, an edit's chance of eventually succeeding fell from 90.5% to 57.2% after one failure, and cascading failed edits accounted for 23.4% of unresolved instances. SWE-agent also replaced empty output with an explicit sentence, "Your command ran successfully and did not produce any output", because silence is ambiguous to a model.

**OpenAI's harness engineering post (February 2026)** describes a product built with no hand-written code: about a million lines and about 1,500 merged pull requests over five months. Each business domain has fixed layers (Types, Config, Repo, Service, Runtime, UI, in that dependency order), enforced by custom linters and structural tests. The post's sentence on errors is the whole technique: "Because the lints are custom, we write the error messages to inject remediation instructions into agent context."

**Cursor (February 2026)** found, while comparing sandboxed and unsandboxed agents on its internal benchmark, that agents repeatedly retried the same terminal command without changing permissions when the sandbox blocked it. The fix was in the tool result: it now names the sandbox constraint responsible for the failure and, in some cases, suggests requesting elevated permissions. Cursor reports that offline evaluation improved significantly after the change, without publishing figures.

**goose** treats this as architecture. An error in a tool call, such as invalid JSON arguments or a tool name that does not exist, becomes an error tool result passed back to the model instead of stopping the loop, and the docs say the messages give the model instructions on how to recover. Its extension design guide states the rule in one line: return specific errors when possible, because the errors become prompts.

## Two channels, and which one the model sees

MCP's 2025-11-25 specification draws the line every harness needs. Protocol errors are JSON-RPC errors for requests that are malformed or name an unknown tool; tool execution errors come back as a normal result with `isError: true` and cover API failures, input validation and business rules. The spec says execution errors contain actionable feedback the model can use to self-correct, that clients should pass them to the model, and that protocol errors are less likely to lead to recovery. Its example validation error reads "Invalid departure date: must be in the future. Current date is 08/08/2025." That message states the rule and the fact the model was missing.

A harness should normalise both channels into one shape before the model sees them, because the model cannot act on a transport detail. goose does this for its own agent errors; the Agent SDK does it for permission denials, which arrive as a rejection message in the tool result.

## Anatomy of an instructive error

Five parts, in this order, each one short:

1. **What failed, by name.** The constraint, rule or check, not the symptom. "Blocked by the sandbox's network policy", not "Could not resolve host".
2. **Why, with the fact the model lacks.** The rule and the specific violation: which file imported which layer, which path is outside the workspace.
3. **Whether retrying unchanged can succeed.** One word is enough: retryable or not. This single field is what stops the Cursor failure mode.
4. **The next action.** A concrete alternative inside the rules, or the escalation path if there is none (ask the user, stop with a reason).
5. **Where to read more.** A path or doc anchor, so the model can load the rule just in time instead of carrying it in the prompt.

The goal is not politeness or length. A good instructive error is often two sentences.

## Three rewrites

A sandbox network denial. The raw shell result:

```text
curl: (6) Could not resolve host: registry.npmjs.org
exit 6
```

To the model, that reads like a flaky DNS problem, and a flaky problem invites a retry. Rewritten:

```text
Blocked by sandbox: network access is off for this session (policy: workspace writes only).
Not retryable: the same command will fail the same way.
Next: use the packages already in node_modules, or ask the user to approve network access for this command.
```

A layering lint, in the style the OpenAI post describes:

```text
error[layers/forward-only]: src/settings/types.ts:3
```

Rewritten:

```text
src/settings/types.ts:3 imports src/settings/service.ts. In each domain, code may depend only on
earlier layers: Types, Config, Repo, Service, Runtime, UI. Types is first, so it cannot import Service.
Move the shared type into types.ts and import it from service.ts. Cross-cutting needs (auth,
telemetry, flags) go through Providers. Rule: docs/ARCHITECTURE.md#layers
```

An edit that cannot apply. Claude Code's Edit requires `old_string` to match the file exactly and only once. A bare "old_string not found" invites the model to guess at whitespace. Rewritten:

```text
No edit made: old_string matched 0 times in src/auth.ts. The file changed after your last read
(a Bash command wrote it). Not retryable with this old_string. Next: read src/auth.ts lines 40-80
again and retry with the current text.
```

Each rewrite moves information the harness already had (the sandbox policy, the layer rule, the file's write history) into the one place the model looks.

## Measuring retries

The metric that shows whether an error message works is the identical-retry rate: of the tool calls that failed, the share followed immediately by the same call with the same arguments. Alongside it, the longest streak of identical retries per tool, because one long streak is what exhausts a budget.

```python
import json
from collections import Counter

def retry_stats(calls: list[dict]) -> dict:
    """calls: one run's tool calls in order, each {"tool", "args", "is_error"}."""
    failed = identical = 0
    streaks, run = Counter(), 0
    for prev, cur in zip(calls, calls[1:]):
        if not prev["is_error"]:
            continue
        failed += 1
        same = (cur["tool"], json.dumps(cur["args"], sort_keys=True)) == \
               (prev["tool"], json.dumps(prev["args"], sort_keys=True))
        identical += same
        run = run + 1 if same else 0
        streaks[prev["tool"]] = max(streaks[prev["tool"]], run)
    return {"failed": failed,
            "identical_retry_rate": identical / failed if failed else 0.0,
            "longest_identical_streak": dict(streaks)}

blocked = {"tool": "bash", "args": {"cmd": "npm install"}, "is_error": True}
trace = [blocked] * 4 + [{"tool": "bash", "args": {"cmd": "npm ci --offline"}, "is_error": False}]
print(retry_stats(trace))
# {'failed': 4, 'identical_retry_rate': 0.75, 'longest_identical_streak': {'bash': 3}}
```

Run it over recorded traces before and after rewriting a message, on the same task set, and compare per error class. A rewrite that works shows up as a lower identical-retry rate and fewer turns from the first failure to the first successful call.

The cost of not doing this is mostly the run, not the tokens.

## When this is wrong

An instruction channel is also an injection channel. A tool result that embeds third-party text, such as an HTTP error body from an external API or a failing test's output from untrusted code, can carry instructions the harness did not write. Remediation text should come from the harness, be marked as such, and stay separate from echoed content.

Remediation must never point around a control. A message that suggests `--no-verify`, `sudo`, or disabling the sandbox teaches the model the bypass. Cursor's version suggests requesting elevated permissions, which goes through the user, not around them.

Instructions in errors go stale. A lint message that names a file or doc path that has since moved sends the model to read something that no longer exists. Errors with remediation need the same freshness checks as the docs they cite, which is why the OpenAI post pairs its custom lints with CI jobs that validate the knowledge base.

Some errors should end the run, not instruct. A revoked credential, a quota exhausted for the day, or a policy that forbids the task entirely has no next action inside the loop. Returning those as retryable-looking text produces exactly the loops this lesson is about.

The published evidence is thin on numbers. SWE-agent's ablation and Cursor's unquantified "significantly" are the measurements available, on their own benchmarks. Your identical-retry rate on your traces is the number to trust.
