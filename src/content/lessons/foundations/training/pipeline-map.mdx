## The decision this map serves

When a model misbehaves in your product, the first question is which training stage owns the behaviour, because that decides whether you can fix it from your side (a prompt, retrieval, an adapter) or have to change models. Refusing too often, drifting out of a JSON format, getting long-winded on easy questions and not knowing last quarter's API are four defects with four different owners.

The pipeline behaves like a multi-stage build where each stage reads the previous stage's artefact and writes a new one. The difference from a build system is that there is no interface contract between stages: a later stage can overwrite behaviour an earlier stage produced, and nothing fails loudly when it does. Every published recipe below includes a step that exists only to repair damage done by another step.

| Stage | Input data | What it fixes | What it can break |
| --- | --- | --- | --- |
| Pretraining | Trillions of web, code and book tokens | Knowledge, language, raw skill | Nothing downstream yet; it sets the ceiling |
| Mid-training | Curated or long-document tokens, reweighted | Long context, maths and code depth | Gains that do not transfer across scale |
| SFT | Prompt and response pairs, increasingly model-generated | Format, instruction following, persona | Style tics copied from generated data |
| Preference tuning | Chosen and rejected pairs | Which of two plausible answers people prefer | Repetition, formatting, benchmark skill |
| RL with verifiable rewards | Prompts plus a checker | Pass rate on checkable tasks | Readability, language mixing, length |

## Pretraining and mid-training

Meta pretrained the Llama 3 flagship on 15.6T text tokens at an 8K context window. Context length then grew in a separate phase: about 800B tokens across six stages, from 8K to 128K. In the last 40M tokens the learning rate was annealed linearly to zero at 128K context and checkpoints were averaged.

That annealing phase is what most reports now call mid-training: a short, deliberately reweighted slice at the end of pretraining. The Llama 3 paper ran it as an experiment on the 8B model, 40B tokens with 30% weight on a new dataset, and reports GSM8K up 24.0% and MATH up 6.4% on validation. The same procedure gave negligible gains on the 405B. A mid-training gain measured at one scale is a hypothesis about another scale, not a result.

For an application team the consequence of this stage is plain: knowledge and its cut-off date are fixed here. No later stage you can run adds a quarter's worth of facts reliably; that is retrieval's job.

## SFT, run in rounds

Llama 3's post-training ran six rounds. Each round collected new preference and SFT data, ran SFT, then DPO. The SFT data came largely from rejection sampling: for each prompt the current model generated 10 to 30 outputs and a reward model picked the best. SFT itself used a learning rate of 1e-5 for 8.5K to 9K steps.

This is a self-hosting bootstrap: round n's model writes round n+1's training data. Unlike a compiler bootstrap, defects compound instead of being caught by a test suite. The paper describes a cleaning pass that removes overused apologetic phrases, excessive emojis and exclamation points from the data, which is the visible cost of training on your own outputs. Rejection sampling was also expensive enough that the authors report PagedAttention improving its throughput by over 2x.

## Preference tuning

InstructGPT set the template in 2022: SFT on labeller demonstrations, a reward model trained on rankings, then RL against that reward model. Labellers preferred outputs of the 1.3B InstructGPT to those of the 175B GPT-3, which the abstract describes as 100x fewer parameters (175 / 1.3 is about 135). The abstract reports minimal regressions on public NLP datasets, and minimal is not zero: the preference stage traded some benchmark capability for preference wins.

Llama 3 tried PPO and chose DPO, reporting that DPO needed less compute at large scale and performed better, especially on instruction-following benchmarks such as IFEval. The published settings: learning rate 1e-5, beta 0.1, and an extra negative log-likelihood term on the chosen response with coefficient 0.2. Two details show stages fighting each other. Formatting tokens were masked out of the DPO loss because including them caused tail repetition and abrupt termination tokens. And at each of the reward model, SFT and DPO stages, models from runs with different data versions or hyperparameters were averaged, a hedge against any single run's regressions.

## RL with verifiable rewards

GRPO, introduced in DeepSeekMath, removes PPO's value model: it samples a group of outputs per question and uses the group's average reward as the baseline, with the KL penalty against a reference model added to the loss rather than to the reward. DeepSeekMath's RL run used 64 samples per question, a 1e-6 learning rate and a KL coefficient of 0.04, and moved MATH from 46.8% (the Instruct model) to 51.7%. The same paper reports that RL improved Maj@K but not Pass@K: the policy became more consistent at answers it could already reach, rather than reaching new ones.

DeepSeek-R1-Zero applied GRPO directly to a base model with rule-based rewards: 16 outputs per question, 32 questions per step, learning rate 3e-6, KL coefficient 0.001, a maximum length of 32,768 tokens raised to 65,536 after step 8.2k, and 10,400 steps. AIME 2024 pass@1 rose from about 15.6% to 77.9%, and to 86.7% with majority voting, which costs one full generation per vote.

R1-Zero's outputs were hard to read and mixed languages, so DeepSeek-R1 is a repair pipeline around the same RL core. Thousands of cold-start examples fix readability before RL. A language-consistency reward, the share of target-language words in the chain of thought, fixes language mixing; the paper's ablation shows it causes a slight performance degradation, kept because people prefer the output. Rejection sampling then builds an SFT set of 804,745 rows, about 600k reasoning and 200k non-reasoning, to restore writing and general skills. A final RL stage targets helpfulness and harmlessness. R1 reaches 79.8% pass@1 on AIME 2024.

A group in which every sample gets the same reward has zero advantage everywhere, so it contributes no gradient. That makes prompt difficulty a throughput parameter.

```python
def dead_group_share(p, g=16):
    return p ** g + (1 - p) ** g

for p in (0.05, 0.5, 0.9, 0.97):
    print(p, round(dead_group_share(p), 3))
# 0.05 0.44   0.5 0.0   0.9 0.185   0.97 0.614
```

The curve is symmetric: prompts the policy almost always fails are as wasteful as prompts it almost always solves, and the share of both moves as training proceeds, so a difficulty filter set at step 0 drifts out of calibration.

## When this is wrong

The table is a vocabulary for published recipes. Closed labs do not publish theirs, real recipes interleave stages (Llama 3 runs SFT and DPO six times; R1 alternates SFT and RL), and the same defect can have several owners. Stage attribution for a closed model is a hypothesis you test with your own eval, not a diagnosis.

Every score above is the authors' own evaluation on their own harness, and the conditions (sampling temperature, number of samples, majority voting or not) change the numbers by more than many method changes do. R1-Zero's 77.9% and 86.7% are the same model under two decoding budgets.

The Maj@K result cuts both ways. If RL mostly sharpens what the base model could already reach, a reasoning model's gains on your task are bounded by its base model's coverage of your domain, and no effort setting changes that.
