## The negatives are the curriculum

An embedder learns the distinctions its negatives force on it and nothing else. The loss is a softmax over one positive and a set of negatives; whatever separates the positive from those negatives is what gradient descent builds into the vectors. So the questions that decide what a fine-tune teaches are about data plumbing: which passages share a batch, which are mined as hard negatives, and how many of those negatives are actually correct answers nobody labelled. E5 shows how far the approach goes, since the paper reports the first model to beat BM25 on BEIR without labelled data, trained contrastively on curated pairs. This lesson covers the loss, the batch, the miner and the false negatives, and ends with when a domain fine-tune pays for itself.

## InfoNCE and what the temperature does

For a batch of N pairs, score every query against every document, divide by a temperature τ, and take the cross-entropy with the matching document as the label. Sentence Transformers calls the one-directional version `MultipleNegativesRankingLoss` and parameterises it by a scale, 1 / τ, with a default of 20.0 on cosine similarity, so τ = 0.05. CLIP learns τ, initialises it at the equivalent of 0.07, and clips it so logits are never scaled by more than 100. `GISTEmbedLoss` defaults to τ = 0.01.

The temperature sets how much of the gradient goes to the hardest negative. Take two negatives whose cosines with the query differ by 0.1. At scale 20 their logits differ by 2, so the closer one carries e² ≈ 7.4 times the softmax weight. At scale 100 the logits differ by 10, and the ratio is e¹⁰ ≈ 22,000. A low temperature makes the loss nearly a max over negatives: the model spends its updates on the one or two most similar passages in the batch. That is efficient when those passages are true negatives, and it is exactly the setting in which a false negative does the most damage, because the passage that looks most like the answer is the one most likely to be another answer.

CLIP's version is symmetric: the cross-entropy over each row of the N by N matrix (image to text) averaged with the cross-entropy over each column (text to image), over N real pairs and N² minus N incorrect pairings. At CLIP's batch of 32,768, each image is contrasted with 32,767 texts. For text retrieval, the one-directional loss is the default, and the symmetric form helps when both sides are queried, for example question-to-question deduplication.

```python
import math

def logsumexp(v):
    m = max(v)
    return m + math.log(sum(math.exp(x - m) for x in v))

def clip_loss(sim, temperature):
    """sim: N x N cosine matrix with matching pairs on the diagonal."""
    n, s = len(sim), 1.0 / temperature
    rows = sum(logsumexp([s * x for x in sim[i]]) - s * sim[i][i] for i in range(n))
    cols = sum(logsumexp([s * sim[i][j] for i in range(n)]) - s * sim[j][j] for j in range(n))
    return (rows + cols) / (2 * n)

print(round(clip_loss([[0.9, 0.2], [0.1, 0.8]], 0.05), 4))   # 0.0
print(round(clip_loss([[0.5, 0.5], [0.5, 0.5]], 0.05), 4))   # 0.6931, log 2: no signal
```

The second line is the case to remember. When every candidate scores the same, the loss is log N and the gradient carries no preference, which is what a batch of duplicates produces.

## The batch decides the negatives

With in-batch negatives, each query's negatives are the other positives in its batch. DPR trained with a batch of 128 and added one BM25 negative per question: a passage that scores high under BM25 and does not contain the answer.

<p>127 gold passages of the other questions, plus 128 BM25 negatives (one per question, all shared), so 127 + 128 = <b>255</b>. DPR's table labels this setting "127+128".</p>
</Predict>

DPR's ablation on NQ shows what each part buys. Seven BM25 negatives per question without in-batch training reached 63.3 top-20 accuracy. In-batch negatives plus one BM25 negative reached 77.3 at a batch of 32 and 78.0 at a batch of 128. The paper reports that a single BM25 negative improves results substantially and a second does not help further. So the move from no in-batch negatives to in-batch negatives was large, and the move from 32 to 128 was small on this task.

The batch size runs into memory, because every example's loss depends on every embedding in the batch. Gradient caching breaks that dependency: encode the batch in sub-batches without gradients, compute the loss and its gradient with respect to the embeddings, then re-encode each sub-batch with gradients and backpropagate the cached embedding gradients. The GradCache paper reports almost constant memory in the batch size. The cost is a second forward pass per example. Sentence Transformers ships it as `CachedMultipleNegativesRankingLoss` with a default sub-batch of 32 and describes it as slightly slower.

Duplicates are the batch's own false negatives. If two pairs in a batch share a positive, each is a negative for the other query and the loss pushes a correct match away. Sentence Transformers recommends its no-duplicates batch sampler for this; it catches exact string matches, not paraphrases or near-duplicate pages, which need a fingerprint or a similarity threshold.

## Mined negatives, refreshed negatives

In-batch negatives are mostly easy: a random passage from another topic. Mined negatives are close to the query by some retriever, so the model has to learn finer distinctions. Three generations of the idea differ in where the negatives come from.

- **Static, from another retriever.** DPR used BM25. The negatives are fixed before training and are hard for BM25, which is not the same as hard for the model being trained.
- **Refreshed, from the model itself.** ANCE draws negatives from an ANN index over the corpus built with the model under training and updated in parallel with training, so the negatives stay hard as the model improves. The paper's argument is that training negatives should look like the irrelevant documents the model meets at test time. The cost is re-encoding the corpus periodically during training, and the index is always somewhat stale.
- **Static, from a teacher, with a ceiling.** NV-Retriever mines with a stronger embedder and rejects candidates that score too close to the positive. That last step is the subject of the next section.

The Sentence Transformers miner exposes the knobs: `range_min` and `range_max` choose a band of ranks, `max_score` caps the absolute score, `margin` requires a gap below the positive, and `num_negatives` sets the count. The reranker write-up's example skips the top 10 ranks and keeps 5 negatives from ranks 10 to 100 with a margin of 0.1.

## False negatives

The passages a strong retriever ranks just below the labelled positive are often unlabelled positives. NV-Retriever cites an estimate by Qu et al. that about 70% of the passages most similar to MS MARCO queries should be labelled positive. The authors' own LLM-judged analysis found that naive top-k mining picked false negatives at 38.8% on NQ and 47% on StackExchange.

Their fix anchors the ceiling on the positive's score: TopK-MarginPos rejects candidates scoring above the positive minus a margin (0.05 worked best), and TopK-PercPos rejects candidates above a percentage of it (95% worked best). These mined 57% and 50% fewer false negatives on the two datasets. With an e5-large-unsupervised base, average NDCG@10 over NQ, HotpotQA and FiQA went from 0.5407 with naive top-k to 0.5835 and 0.5856. The resulting model scored 60.9 on MTEB Retrieval and was first on that leaderboard when published in July 2024. `GISTEmbedLoss` applies the same idea inside the batch: a guide model scores the in-batch negatives and drops those it rates above the positive.

The ceiling is a heuristic with its own failure. It is anchored on the labelled positive, so a weak label (a positive the teacher scores low) drags the ceiling down and rejects most candidates for that query. Log how many negatives each query keeps, and audit a sample of mined negatives by hand, stratified by rank, before every large training run. The lab builds the miner and the audit on toy vectors: [Contrastive training on toy vectors](/labs/embedding-training).

## When a domain fine-tune is worth it

A fine-tune changes the space, so every vector in the index has to be re-embedded afterwards; that migration cost belongs in the decision. The fine-tune is worth it when three things hold:

- **The failures are in recall, not ordering.** If the right passage is in the top 50 and ranked low, a reranker fixes it without re-embedding. If it is not in the top 50, only the embedder or the chunks can.
- **You have pairs, or can mine them safely.** DPR reports that 1,000 training examples already beat BM25 on its data. With a few thousand domain pairs and an audited miner, a fine-tune is in reach; without an audit, the false-negative rate decides the outcome.
- **The query distribution differs from what the model was trained on.** BRIGHT measured SFR-Embedding-Mistral at 59.0 nDCG@10 on MTEB and 18.3 on reasoning-intensive queries, and found that reasoning about the query first improved retrieval by up to 12.2 points. When queries need reasoning, query rewriting can be the cheaper lever.

## When this is wrong

The lesson treats retrieval as the target. Embedders trained for clustering or similarity scoring use different losses, such as CoSENT on graded similarity labels, and the advice on hard negatives does not transfer directly.

The published numbers come from public benchmarks where the labels are sparse by construction: one marked positive per query and many unmarked ones. That is why false negatives are so common in mined sets there. A domain with complete labels, such as a catalogue where every relevant item is known, has fewer false negatives, and naive mining may be fine.

The gains from mining are measured with specific teachers and bases. NV-Retriever's best teacher was a 7B embedder; a teacher weaker than the model you are training mines negatives that are easy for your model and the ceiling then filters little. Check the teacher's recall on your held-out set before trusting its scores as a ceiling.

Finally, a fine-tune is not the only way to adapt. If the failures are in ordering, a reranker is cheaper; if they are in chunk boundaries, no embedder fixes them. The playbook covers that choice.
