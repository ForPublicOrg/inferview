      def load(files, package):
          """Write files into a fresh directory, make it importable and return the freshly imported package.
          Modules from an earlier load of the same package must not leak into this one."""
          old = _LOADED.pop(package, None)
          if old:
              if old in sys.path:
                  sys.path.remove(old)
              shutil.rmtree(old, ignore_errors=True)
          for name in list(sys.modules):
              if name == package or name.startswith(package + "."):
                  del sys.modules[name]
          root = tempfile.mkdtemp(prefix="lab-repo-")
          for path, text in files.items():
              full = os.path.join(root, *path.split("/"))
              os.makedirs(os.path.dirname(full), exist_ok=True)
              with open(full, "w", encoding="utf-8") as f:
                  f.write(text)
          sys.path.insert(0, root)
          _LOADED[package] = root
          importlib.invalidate_caches()
          return importlib.import_module(package)


      def patch(files, path, old, new):
          """A copy of files with old replaced by new in files[path]. Raise ValueError unless old occurs exactly once."""
          if path not in files:
              raise ValueError(f"{path} is not in the package")
          count = files[path].count(old)
          if count != 1:
              raise ValueError(f"expected the old text once in {path}, found it {count} times")
          out = dict(files)
          out[path] = files[path].replace(old, new)
          return out

This lab practises the bug-squash round on one small library. `batchkit` is a client for a batch embeddings API in four modules: paginated listing, an embedding cache, batch submission with retries, and the fakes its tests use. It arrives as a dictionary of files, and step 1 makes it importable the way a repo round's runner does: write the files into a fresh directory, import them, and make sure a second import sees the new code rather than the modules Python cached the first time.

Steps 2 to 4 each start from a user report, not from the cause. Each bug sits in a different module, and each fix is a `patch` on top of the previous one, so a fix that breaks an earlier one fails the later steps. Step 2 asks for the reproduction as a test before the fix: a test that fails on the shipped code and passes on the fixed code is the evidence the round asks for, and it is also what stops the bug coming back. Step 4's bug only shows when a request is sent twice.

Step 5 turns to review. A colleague's PR adds retries for rate-limited requests; its tests pass. You answer the review in code: one test per thing that breaks, each failing on the PR and passing on a version that does what the PR description promises.

All the servers are fakes with scripted behaviour, so every test is deterministic and asserts behaviour (jobs created, keys sent, seconds slept), never timing. Your code is saved with your progress as you type. Passing a step's tests unlocks the next step and counts toward your streak. Python runs in your browser with the standard library only.
