  - title: Level assignment
    brief: |
      A node lives on layers 0 to its level, and the level comes from an exponentially decaying distribution: int(-ln(1 - U) x mL) with mL = 1 / ln(M) and U uniform in [0, 1), so about one node in M reaches layer 1 and one in M squared reaches layer 2. Using 1 - U keeps the logarithm defined when U is 0. add_node registers a node on every layer up to its level with no links yet, and moves the entry point when the node reaches a layer above the current top. Every draw comes from the seeded generator, so two builds with the same seed and the same insert order produce the same graph, which later steps rely on when they compare recall.

      import math
      import random


      def distance(a, b):
          return math.dist(a, b)


      class HNSW:
          def __init__(self, M=8, ef_construction=64, seed=0):
              self.M = M
              self.ef_construction = ef_construction
              self.rng = random.Random(seed)
              self.vectors = {}
              self.levels = {}
              self.layers = []
              self.entry = None
              self.mL = 1.0 / math.log(M)

          def random_level(self):
              # 1 - random() is in (0, 1], so the log is always defined.
              return int(-math.log(1.0 - self.rng.random()) * self.mL)

          def add_node(self, key, vector):
              if key in self.vectors:
                  raise ValueError(f"key {key!r} is already in the index")
              level = self.random_level()
              self.vectors[key] = tuple(vector)
              self.levels[key] = level
              while len(self.layers) <= level:
                  self.layers.append({})
              for layer in range(level + 1):
                  self.layers[layer][key] = []
              if self.entry is None or level > self.levels[self.entry]:
                  self.entry = key
              return level
  - title: Greedy search from the top layer
    brief: |
      search_layer is best-first search over one layer: a min-heap of candidates to expand and a max-heap of the ef best found so far. It stops when the nearest unexpanded candidate is farther than the worst of the ef best, and that stopping rule is what keeps a search from visiting the whole layer. search descends from the entry point with ef 1 on every layer above 0, then searches layer 0 with max(ef, k). insert is given: it runs your search_layer on each layer, links the new node both ways, and prunes any list that passes its cap (2M on layer 0, M above). The tests build 1,500 random vectors of 16 dimensions, require recall@10 of 0.95 at ef 64 against brute force, and count distance calls: a search may compute at most 40% of the index's distances, so scoring everything fails.

      class HNSW(HNSW):
          def search_layer(self, q, entry_points, ef, layer):
              """Best-first search of one layer from entry_points.
              Return up to ef (distance, key) pairs for the nearest nodes found, nearest first."""
              raise NotImplementedError

          def search(self, q, k, ef):
              """The k nearest keys to q, nearest first. Return [] for an empty index."""
              raise NotImplementedError

          # Given: the rule step 3 replaces, and insertion built on your search_layer.
          def select_neighbours(self, q, candidates, m):
              """candidates are (distance to q, key) pairs, nearest first. Keep the m nearest."""
              return [key for _, key in candidates[:m]]

          def insert(self, key, vector):
              old_entry = self.entry
              level = self.add_node(key, vector)
              if old_entry is None:
                  return
              q = self.vectors[key]
              entry = [old_entry]
              top = self.levels[old_entry]
              for layer in range(top, level, -1):
                  entry = [self.search_layer(q, entry, 1, layer)[0][1]]
              for layer in range(min(top, level), -1, -1):
                  found = self.search_layer(q, entry, self.ef_construction, layer)
                  cap = 2 * self.M if layer == 0 else self.M
                  links = self.select_neighbours(q, found, self.M)
                  self.layers[layer][key] = list(links)
                  for other in links:
                      theirs = self.layers[layer][other]
                      theirs.append(key)
                      if len(theirs) > cap:
                          v = self.vectors[other]
                          ranked = sorted((distance(v, self.vectors[n]), n) for n in theirs)
                          self.layers[layer][other] = self.select_neighbours(v, ranked, cap)
                  entry = [k for _, k in found]

      import heapq


      class HNSW(HNSW):
          def search_layer(self, q, entry_points, ef, layer):
              visited = set(entry_points)
              candidates = [(distance(q, self.vectors[e]), e) for e in visited]
              heapq.heapify(candidates)
              best = [(-d, e) for d, e in candidates]       # max-heap of the ef nearest so far
              heapq.heapify(best)
              while len(best) > ef:
                  heapq.heappop(best)
              links = self.layers[layer]
              while candidates:
                  d, node = heapq.heappop(candidates)
                  if len(best) >= ef and d > -best[0][0]:
                      break                                  # nothing left can improve the result
                  for n in links[node]:
                      if n in visited:
                          continue
                      visited.add(n)
                      dn = distance(q, self.vectors[n])
                      if len(best) < ef or dn < -best[0][0]:
                          heapq.heappush(candidates, (dn, n))
                          heapq.heappush(best, (-dn, n))
                          if len(best) > ef:
                              heapq.heappop(best)
              return sorted((-d, e) for d, e in best)

          def search(self, q, k, ef):
              if self.entry is None:
                  return []
              entry = [self.entry]
              for layer in range(self.levels[self.entry], 0, -1):
                  entry = [self.search_layer(q, entry, 1, layer)[0][1]]
              return [key for _, key in self.search_layer(q, entry, max(ef, k), 0)[:k]]

  - title: Neighbour-selection heuristic
    brief: |
      Keeping a node's M nearest candidates links it only into its own neighbourhood. On clustered data, whole clusters end up with no inbound link from the rest of the graph, and no ef reaches them. The paper's heuristic keeps a candidate only if it is closer to the base node than to every neighbour already kept, so each new link points somewhere the others do not. Whether you fill free slots with the nearest pruned candidates is your call; the tests accept either. insert calls select_neighbours both to link a new node and to prune a full list, so this one method changes both. The tests build 2,000 vectors in 30 tight clusters and require every node to be reachable from the entry point on layer 0 and recall@10 of 0.95 at ef 64. With the step 2 rule, the same build left more than half of the 2,000 nodes unreachable when we ran it.

    solution: |
      class HNSW(HNSW):
          def select_neighbours(self, q, candidates, m):
              chosen = []
              for d, key in candidates:
                  if len(chosen) == m:
                      break
                  v = self.vectors[key]
                  # Keep a candidate only if it is closer to q than to every neighbour already kept.
                  if all(d < distance(v, self.vectors[c]) for c in chosen):
                      chosen.append(key)
              # Fill any free slots with the nearest pruned candidates, so sparse regions keep their links.
              for d, key in candidates:
                  if len(chosen) == m:
                      break
                  if key not in chosen:
                      chosen.append(key)
              return chosen
  - title: Recall against brute force at several efSearch values
    brief: |
      A recall number means something only against exact search on the same queries. brute_force scores every vector; recall_sweep runs the index at each ef and reports mean recall@k against it; smallest_ef returns the cheapest ef in a list that reaches a target, or None.     solution: |
      def brute_force(vectors, q, k):
          return [key for _, key in sorted((distance(q, v), key) for key, v in vectors.items())[:k]]


      def recall_sweep(index, queries, k, efs):
          truth = [set(brute_force(index.vectors, q, k)) for q in queries]
          out = {}
          for ef in efs:
              hits = sum(len(set(index.search(q, k, ef)) & t) / len(t) for q, t in zip(queries, truth))
              out[ef] = hits / len(queries)
          return out


      def smallest_ef(index, queries, k, target, efs):
          curve = recall_sweep(index, queries, k, sorted(efs))
          for ef in sorted(efs):
              if curve[ef] >= target:
                  return ef
          return None
  - title: Add a filter and measure recall
    brief: |
      Many vector stores filter after the graph search: take the ef candidates, drop the ones the filter rejects, return what is left. Add that as search(q, k, ef, allowed), where allowed is a set of keys or None, and measure it with filtered_recall against the exact k nearest allowed keys. With 5% of keys allowed and ef 40, about 40 x 0.05 = 2 candidates survive on average. The tests check that your measurement shows the collapse: fewer than 5 results returned on average and filtered recall under 0.5, while the same index without a filter stays at 0.95 or better. pgvector's README describes the same behaviour for approximate indexes when iterative scans are off.

      class HNSW(HNSW):
          def search(self, q, k, ef, allowed=None):

              Post-filtering: take the ef candidates the unfiltered search finds, keep the allowed ones, return up to k."""

    solution: |
      class HNSW(HNSW):
          exact_below = 400          # allowed sets this small are scored exactly; tune it against your latency budget
          max_scan = 20000           # nodes a filtered traversal may visit before it returns what it has

          def search(self, q, k, ef, allowed=None):
              if allowed is None:
                  return super().search(q, k, ef)
              live = [key for key in allowed if key in self.vectors]
              if not live:
                  return []
              if len(live) <= self.exact_below:
                  return [key for _, key in sorted((distance(q, self.vectors[key]), key) for key in live)[:k]]
              entry = [self.entry]
              for layer in range(self.levels[self.entry], 0, -1):
                  entry = [self.search_layer(q, entry, 1, layer)[0][1]]
              return [key for _, key in self._filtered_layer0(q, entry, max(ef, k), allowed)[:k]]

          def _filtered_layer0(self, q, entry_points, ef, allowed):
              # Traverse through every node, but only allowed nodes enter the result set; stop when the result set is
              # full and no candidate can improve it, or when the scan budget runs out.
              visited = set(entry_points)
              candidates = [(distance(q, self.vectors[e]), e) for e in visited]
              heapq.heapify(candidates)
              best = [(-d, e) for d, e in candidates if e in allowed]
              heapq.heapify(best)
              links = self.layers[0]
              while candidates and len(visited) < self.max_scan:
                  d, node = heapq.heappop(candidates)
                  if len(best) >= ef and d > -best[0][0]:
                      break
                  for n in links[node]:
                      if n in visited:
                          continue
                      visited.add(n)
                      dn = distance(q, self.vectors[n])
                      if len(best) < ef or dn < -best[0][0]:
                          heapq.heappush(candidates, (dn, n))
                          if n in allowed:
                              heapq.heappush(best, (-dn, n))
                              if len(best) > ef:
                                  heapq.heappop(best)
              return sorted((-d, e) for d, e in best)

This lab builds an HNSW index in standard-library Python and then breaks it the way production filters break it. The six steps follow the paper's construction, then the measurement and the filter.

Steps 1 to 3 build the graph: levels, the search that descends from the top layer, and the neighbour-selection rule. Step 3 is where the paper's heuristic stops being a footnote. On clustered data, the simple rule of linking each node to its nearest neighbours leaves whole clusters with no way in, and recall stays low at any ef.

Step 4 measures recall against brute force across several values of ef, the measurement every later decision depends on. Step 5 adds the filter most vector stores apply after the graph search and measures what it does at 5% selectivity. Step 6 fixes it, and leaves the choice between an exact path for small allowed sets and a traversal that respects the filter to you.

Every distance goes through one function, `distance()`, called by that name. The tests replace it with a counter, so cost limits are checked as distance calls, not wall-clock time, and give the same answer in the browser and on a laptop. The data is random vectors from seeded generators, so every run of a step sees the same points.

Each step subclasses the last (`class HNSW(HNSW)`), so a later step can call what an earlier one wrote through `super()`. Your code is saved with your progress as you type, and passing a step's tests unlocks the next one. Python runs in your browser, with the standard library only.
