  - title: Byte-level vocabulary
    brief: |
      Start from UTF-8 bytes rather than characters, so the base vocabulary is the 256 byte values and no input is ever out of vocabulary. The cost moves into sequence length: a Devanagari code point is three bytes, so until merges cover a script, its text is several ids per character. This is the base alphabet of the tiktoken encodings (cl100k_base, o200k_base) and of Llama 3, which reuses 100K tiktoken tokens.

      def text_to_ids(text):

          raise NotImplementedError

      def base_vocab():
          """Map each id 0 to 255 to the one-byte bytes object it stands for."""
          raise NotImplementedError

      def text_to_ids(text):
          return list(text.encode("utf-8"))

      def base_vocab():
          return {i: bytes([i]) for i in range(256)}
  - title: Pair counting
    brief: |
      Training needs two primitives: count adjacent pairs, and replace one pair with a new id. Make the counter accept an existing dict, because step 6 counts across many pre-tokenised chunks into one table, and pairs must never be counted across a chunk boundary. The merge scans left to right without overlaps, so three equal ids merge into one new id and one leftover.
    starter: |
      def count_pairs(ids, counts=None):
          """Count adjacent pairs in ids. If counts is given, add to it and return it, so one dict can span many chunks."""
          raise NotImplementedError

      def merge(ids, pair, new_id):
          """Return a new list with each occurrence of pair replaced by new_id, scanning left to right without overlaps."""
          raise NotImplementedError
    tests: |
      assert count_pairs([1, 2, 1, 2, 3]) == {(1, 2): 2, (2, 1): 1, (2, 3): 1}
      shared = count_pairs([1, 2])
      assert count_pairs([1, 2, 5], shared) is shared and shared[(1, 2)] == 2, "counts accumulate across chunks"
      assert count_pairs([7]) == {} and count_pairs([]) == {}
      assert merge([1, 2, 1, 2, 3], (1, 2), 256) == [256, 256, 3]
      assert merge([5, 5, 5], (5, 5), 300) == [300, 5], "left to right, no overlapping matches"
      ids = [1, 2, 3]
      merge(ids, (1, 2), 256)
      assert ids == [1, 2, 3], "merge must not modify its input"

    solution: |
      def count_pairs(ids, counts=None):
          counts = {} if counts is None else counts
          for pair in zip(ids, ids[1:]):
              counts[pair] = counts.get(pair, 0) + 1
          return counts

      def merge(ids, pair, new_id):
          out, i = [], 0
          while i < len(ids):
              if i + 1 < len(ids) and ids[i] == pair[0] and ids[i + 1] == pair[1]:
                  out.append(new_id)
                  i += 2
              else:
                  out.append(ids[i])
                  i += 1
          return out
  - title: Merge loop
    brief: |
      The training loop: count pairs, take the most frequent, give it the next id, replace it everywhere, repeat until the vocabulary reaches its target size. The tie-break is yours to choose, but it must be deterministic, because two training runs that disagree on one tie produce different vocabularies and every id after it shifts. Stop when no pair occurs twice: a merge seen once compresses nothing and spends a vocabulary slot, which in a model is an embedding row and an output column. This loop rescans the whole corpus per merge; production trainers update only the affected counts.
    starter: |
      def train(text, vocab_size):
          """Learn up to vocab_size - 256 merges on the bytes of text.
          Return a dict from (left_id, right_id) to new_id, new ids 256, 257, ... in the order learned.
          Pick the most frequent pair each round with a deterministic tie-break of your choice.
          Stop early when no pair occurs at least twice."""
          raise NotImplementedError
    tests: |
      merges = train("aaabdaaabac", 259)
      assert list(merges.values()) == [256, 257, 258], "new ids are consecutive from 256"
      assert list(merges)[0] == (97, 97), "aa occurs 4 times, more than any other pair"
      assert train("abc", 300) == {}, "no pair occurs twice"
      assert train("hello hello", 256) == {}, "vocab_size 256 means no merges"
    hidden: |
      import random
      _r = random.Random(3)
      _text = "".join(_r.choice(["the ", "then ", "there ", "cache ", "queue ", "token ", "हिंदी ", "\n"]) for _ in range(400))
      _m = train(_text, 300)
      assert _m == train(_text, 300), "training is deterministic"
      assert list(_m.values()) == list(range(256, 256 + len(_m)))
      def _greedy(text, m):
          ids = text_to_ids(text)
          for pair, new in m.items():
              c = count_pairs(ids)
              if c.get(pair, 0) != max(c.values()) or c[pair] < 2:
                  return False
              ids = merge(ids, pair, new)
          return True
      assert _greedy(_text, _m), "every merge is a most frequent pair, seen at least twice, when it is learned"
      assert all(x < new for (a, b), new in _m.items() for x in (a, b)), "a merge only uses ids that already exist"
    solution: |
      def train(text, vocab_size):
          ids = text_to_ids(text)
          merges = {}
          for new_id in range(256, vocab_size):
              counts = count_pairs(ids)
              if not counts:
                  break
              best = min(counts, key=lambda p: (-counts[p], p))
              if counts[best] < 2:
                  break
              merges[best] = new_id
              ids = merge(ids, best, new_id)
          return merges
  - title: Encoding by merge rank
    brief: |
      Encoding does not replay the merge list. It repeatedly finds the adjacent pair with the lowest rank (the earliest-learned merge, here the smallest new id) and merges it, until no adjacent pair has a rank. That is how tiktoken encodes, and its cost depends on the length of the text rather than on the size of the merge table, which matters at 100,000 or 200,000 merges. The hidden tests check that your encoder agrees with a full replay on random text and leaves no mergeable pair behind.
    starter: |
      def encode(text, merges):
          """Encode text to ids: start from its bytes, then repeatedly merge the adjacent pair with the lowest
          new id in merges, until no adjacent pair is in merges."""
          raise NotImplementedError
    tests: |
      merges = train("aaabdaaabac", 259)
      assert encode("aaabdaaabac", merges) == [258, 100, 258, 97, 99]
      assert encode("", merges) == [] and encode("a", merges) == [97]
      assert encode("xyz", merges) == [120, 121, 122], "text with no learned pairs stays as bytes"
      m = train("low lower lowest newest widest " * 20, 300)
      assert len(encode("lowest newest", m)) < len(text_to_ids("lowest newest")), "seen pieces compress"
    hidden: |
      import random
      def _replay(text, merges):
          ids = text_to_ids(text)
          for pair, new in merges.items():
              ids = merge(ids, pair, new)
          return ids
      _r = random.Random(4)
      _corpus = "".join(_r.choice(["ab", "abc", "bca", "cab", " ", "abab"]) for _ in range(500))
      _m = train(_corpus, 320)
      _texts = ["".join(_r.choice("abc d") for _ in range(_r.randint(0, 40))) for _ in range(150)]
      _encoded = [encode(t, _m) for t in _texts]
      assert all(e == _replay(t, _m) for t, e in zip(_texts, _encoded)), "rank order gives the same ids as replaying merges in training order"
      assert all((a, b) not in _m for e in _encoded for a, b in zip(e, e[1:])), "no mergeable pair is left in the output"
    solution: |
      def encode(text, merges):
          ids = text_to_ids(text)
          while len(ids) >= 2:
              counts = count_pairs(ids)
              pair = min(counts, key=lambda p: merges.get(p, float("inf")))
              if pair not in merges:
                  break
              ids = merge(ids, pair, merges[pair])
          return ids
  - title: Decoding and round trip
    brief: |
      Decoding is a table lookup: each id stands for a byte string, built bottom-up from the two ids it merged. Join the bytes, then decode UTF-8 once at the end. A single token can end in the middle of a multi-byte character, so decoding token by token, which is what a naive streaming client does, emits replacement characters that the full sequence never contains. Streaming decoders buffer incomplete UTF-8 for this reason.
    starter: |
      def build_vocab(merges):
          """Map every id, base and merged, to the bytes it stands for."""
          raise NotImplementedError

      def decode(ids, merges):
          """Join the bytes of the ids and decode as UTF-8, replacing invalid sequences with U+FFFD."""
          raise NotImplementedError
    tests: |
      merges = train("aaabdaaabac", 259)
      vocab = build_vocab(merges)
      assert vocab[256] == b"aa" and vocab[258] == b"aaab" and len(vocab) == 259
      assert decode([258, 100], merges) == "aaabd"
      for text in ["aaab", "naïve café", "पुनर्विचार", "日本語", "🙂 ok", ""]:
          assert decode(encode(text, merges), merges) == text, f"round trip failed for {text!r}"
      assert decode([0xE0], merges) == "\ufffd", "one byte of a three-byte character is not valid UTF-8 on its own"

    solution: |
      def build_vocab(merges):
          vocab = base_vocab()
          for (a, b), new_id in merges.items():
              vocab[new_id] = vocab[a] + vocab[b]
          return vocab

      def decode(ids, merges):
          vocab = build_vocab(merges)
          return b"".join(vocab[i] for i in ids).decode("utf-8", errors="replace")
  - title: Pre-tokenisation regex and special tokens
    brief: |
      Two production details close the gap to tiktoken. First, a regex splits text into chunks before BPE runs, and merges never cross a chunk boundary: that is what keeps the leading space attached to a word and caps digit runs at three. Python's re has no \p{L}, so the pattern below approximates the tiktoken shape with [^\W\d_]. Second, special tokens get ids after the merges and are emitted only when the caller allows them. The default must treat a special-token string in the input as ordinary text, which is tiktoken's encode_ordinary behaviour; anything else lets a user who types the string inject a control token.
    starter: |
      import re

      PATTERN = r"""'(?:[sdmt]|ll|ve|re)| ?[^\W\d_]+| ?\d{1,3}| ?(?:[^\s\w]|_)+|\s+(?!\S)|\s+"""

      class Tokenizer:
          def __init__(self, special=()):
              self.special_names = list(special)   # e.g. ["<|endoftext|>"]
              self.merges = {}
              self.special = {}                    # name -> id, assigned after training

          def train(self, text, vocab_size):
              """Split text with PATTERN, then learn merges over all chunks at once (pair counts summed across chunks,
              never across a boundary). Special tokens take the ids right after the last merge."""
              raise NotImplementedError

          def encode(self, text, allowed_special=frozenset()):
              """Special-token strings in allowed_special become their ids; every other character,
              including special-token strings that are not allowed, is encoded as ordinary text, chunk by chunk."""
              raise NotImplementedError

          def decode(self, ids):
              raise NotImplementedError
    tests: |
      tok = Tokenizer(special=["<|endoftext|>"])
      tok.train("the cat sat on the mat. the cat ate 1234567 dates. " * 10, 320)
      eot = tok.special["<|endoftext|>"]
      assert eot == 256 + len(tok.merges), "special ids follow the merges"
      assert eot not in tok.encode("hello <|endoftext|> world"), "by default the string is ordinary text"
      assert tok.encode("<|endoftext|>", allowed_special={"<|endoftext|>"}) == [eot]
      assert tok.decode(tok.encode("a<|endoftext|>b", allowed_special={"<|endoftext|>"})) == "a<|endoftext|>b"
      assert all(len(tok.decode([i]).strip()) <= 3 for i in tok.encode("1234567") if tok.decode([i]).strip().isdigit()), "digit runs split in threes"

    solution: |
      import re

      PATTERN = r"""'(?:[sdmt]|ll|ve|re)| ?[^\W\d_]+| ?\d{1,3}| ?(?:[^\s\w]|_)+|\s+(?!\S)|\s+"""

      class Tokenizer:
          def __init__(self, special=()):
              self.special_names = list(special)
              self.merges = {}
              self.special = {}

          def train(self, text, vocab_size):
              chunks = [text_to_ids(c) for c in re.findall(PATTERN, text)]
              merges = {}
              for new_id in range(256, vocab_size):
                  counts = {}
                  for ids in chunks:
                      count_pairs(ids, counts)
                  if not counts:
                      break
                  best = min(counts, key=lambda p: (-counts[p], p))
                  if counts[best] < 2:
                      break
                  merges[best] = new_id
                  chunks = [merge(ids, best, new_id) for ids in chunks]
              self.merges = merges
              first = 256 + len(merges)
              self.special = {name: first + i for i, name in enumerate(self.special_names)}

          def _ordinary(self, text):
              out = []
              for chunk in re.findall(PATTERN, text):
                  out.extend(encode(chunk, self.merges))
              return out

          def encode(self, text, allowed_special=frozenset()):
              allowed = [s for s in self.special if s in allowed_special]
              if not allowed:
                  return self._ordinary(text)
              out = []
              splitter = "(" + "|".join(re.escape(s) for s in sorted(allowed, key=len, reverse=True)) + ")"
              for part in re.split(splitter, text):
                  if part in self.special and part in allowed_special:
                      out.append(self.special[part])
                  elif part:
                      out.extend(self._ordinary(part))
              return out

          def decode(self, ids):
              vocab = build_vocab(self.merges)
              names = {i: s.encode("utf-8") for s, i in self.special.items()}
              return b"".join(names[i] if i in names else vocab[i] for i in ids).decode("utf-8", errors="replace")
---

This lab builds the byte-level tokenizer from the BPE mechanics lesson as one program. Each step adds functions to the same file, and its tests run against everything written so far: step 6 trains with the `count_pairs` and `merge` from step 2 and encodes each chunk with the `encode` from step 4.

Steps 1 to 3 are training: byte ids, pair counts and the greedy merge loop. Steps 4 and 5 are inference: encoding by merge rank, which is how tiktoken encodes, and decoding through a byte table built from the merges. Step 6 adds the two pieces that make a tokenizer a security and cost surface: a pre-tokenisation regex that bounds where merges can happen, and special tokens that the encoder emits only when the caller allows them.

The visible tests are examples. The hidden tests check properties on seeded random text: the round trip, agreement between rank-order encoding and a full replay of the merges, every merge being a most frequent pair when it was learned, and special ids never appearing in ordinary encoding. The tie-break in step 3 is yours; any deterministic rule passes.

The training loop here rescans the whole corpus for every merge, which is fine for a few kilobytes. Training a 100,000-merge vocabulary on gigabytes needs pair counts that are updated incrementally for the words a merge touches, and a priority queue over the counts; that change, and moving the encoder's inner loop out of Python, are the two differences between this program and a production tokenizer.
