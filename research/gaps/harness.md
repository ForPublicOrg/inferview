## 1. What exists today and what is missing

### 1.1 Summary

Harness engineering is taught today as one section of one lesson ("The harness is most of the product" in the agents track's coding-agents lesson) plus scattered facts in five other lessons. There is no track, module, teardown, lab or paper walkthrough on it. The existing material is accurate and sourced, but it explains the harness at the level of "it has search, tests, permissions and a sandbox". It does not cover how a production harness assembles a prompt, decides what survives compaction, keeps a cache warm, enforces rules the model cannot talk its way past, verifies its own work, or how anyone measures whether one harness beats another. None of the 14 tools in the research angle has a teardown. Two statements in the current content are now wrong or outdated (section 5, items 1 and 2).

## 2. Material to add

Proposal: a tenth track, slug `harness`, title "Harness engineering and agentic coding tools", written for senior and staff readers. Eight modules plus a teardown set. Every lesson teaches one decision or mechanism (SPEC section 5). Each module also gets critique and workflow problems (SPEC section 6), because the owner wants less "read a lesson, answer questions". Kind is one of lesson, teardown, playbook, paper (SPEC section 5) or lab (SPEC section 10). All sources were read on 2026-10-28.

### Module 1: `harness-anatomy` (what the harness owns)

**1.1 Model plus harness: what each one decides** (lesson, senior). The harness is everything between the user and the sampler: prompt assembly, tool set and descriptions, context management, permissions and sandbox, verification, budgets, persistence. Claude Code's docs call the layer that provides tools and manages what the model sees the "agentic harness"; OpenAI's Codex post calls its agent loop the harness; Böckeler (Thoughtworks) splits a user-built harness into guides (feedforward) and sensors (feedback), each computational or inferential, and names behaviour checks as the unsolved part. Teach with one table that assigns each common failure to the layer that fixes it. Sources: https://code.claude.com/docs/en/how-claude-code-works ; https://openai.com/index/unrolling-the-codex-agent-loop/ ; https://martinfowler.com/articles/harness-engineering.html ; https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents (secondary).

**1.2 The request lifecycle: how a harness builds each model call** (lesson, senior). Codex sends `instructions`, `tools` and an `input` list to the Responses API; the server orders the first items; AGENTS.md is concatenated root to working directory up to 32 KiB by default; an environment-context message carries cwd and shell; config changes are appended as new messages rather than editing earlier ones; Codex does not use `previous_response_id`, to stay stateless and support Zero Data Retention. Claude Code orders a request as system prompt plus tool definitions, then project context (CLAUDE.md, auto memory, unscoped rules), then the conversation; plan mode and skill loading are appended as messages so the prefix holds. Teach with a `<Trace>` of one real turn for each tool. Sources: https://openai.com/index/unrolling-the-codex-agent-loop/ ; https://learn.chatgpt.com/docs/agent-configuration/agents-md ; https://code.claude.com/docs/en/prompt-caching ; https://code.claude.com/docs/en/agent-sdk/agent-loop .

**1.3 Deterministic vs model-decided controls** (lesson, staff). Claude Code's best-practices page sorts controls into "Claude decides" (prompt, CLAUDE.md, skills Claude picks up, auto mode's classifier, `/goal`, effort) and "the harness enforces" (hooks, deny rules, strict sandbox, managed settings, tests and a Stop hook, `--max-turns`, `--max-budget-usd`, branch protection). Its rule: if something has to happen every time, make it a hook, a deny rule or a managed setting, and keep the enforced set small. Pair with OpenAI's practice of promoting a rule into a custom lint whose error message carries the fix. Sources: https://code.claude.com/docs/en/best-practices ; https://openai.com/index/harness-engineering/ .

**1.4 Paper walkthrough: SWE-agent and the agent-computer interface** (paper, senior). Yang et al., arXiv 2405.15793 (2024). LM agents as a new class of user that needs purpose-built interfaces: search capped at 50 results, a 100-line file viewer, an edit command guarded by a linter that rejects syntax errors, old observations collapsed to one line except the last five, a $4 per-instance budget. The ablations on SWE-bench Lite with GPT-4 Turbo are the payload (18.0% full; 15.0% without the linter; 10.3% with no edit command; 14.3% with a 30-line window and 12.7% with the whole file; 15.0% with full history). Sources: https://arxiv.org/abs/2405.15793 ; https://arxiv.org/html/2405.15793v3 .

**1.5 Paper walkthrough: the minimal harness (mini-swe-agent, CodeAct, Agentless)** (paper, staff). mini-swe-agent is about 100 lines for the agent class, bash only, no tool-calling API, linear history, each action an independent `subprocess.run` (which makes swapping in `docker exec` easy), and claims over 74% on SWE-bench Verified. CodeAct (ICML 2024) argues for code as the action space ("up to 20% higher success rate" across 17 LLMs). Agentless (2024) uses a fixed localise, repair, validate pipeline with no agent loop (32.00% on SWE-bench Lite). The interview point: how much harness a strong model needs, and what you lose by deleting it. Sources: https://github.com/SWE-agent/mini-swe-agent ; https://arxiv.org/abs/2402.01030 ; https://arxiv.org/abs/2407.01489 .

**1.6 Lab: build a mini agent harness** (lab, senior; the SPEC section 10 example). Steps with tests that run in Pyodide against a scripted mock model: (1) the loop with `max_turns` and the final-turn rule; (2) tools with output truncation to a character budget and a file-path fallback; (3) a deny, ask, allow gate using `shlex`, which refuses to split scripts containing substitution or redirection, as Codex does; (4) concurrent execution for read-only tools, sequential for mutating ones; (5) cache-friendly prompt assembly that appends config changes; (6) compaction that keeps the first N and last M events and re-injects memory files; (7) a Stop check that sends the agent back with the failing test output; (8) a spend cap. Sources: the Agent SDK loop page, Codex rules page and OpenHands condenser page cited in modules 1 and 3.

### Module 2: `tools-aci` (tool sets for coding agents)

**2.1 Playbook: bash-only vs specialised tools** (playbook, staff). Inputs: model strength, portability across models, need for structured permission checks, observability. Options: bash only (mini-swe-agent); bash plus a string-replace editor (the Claude 4 SWE-bench scaffold used only these two); a broad built-in set (Claude Code: Read, Edit, Write, Glob, Grep, Bash, WebFetch, Agent and more); code as action (CodeAct, programmatic tool calling). Worked decision on a stated case. Sources: https://www.anthropic.com/news/claude-4 ; https://github.com/SWE-agent/mini-swe-agent ; https://code.claude.com/docs/en/tools-reference ; https://www.anthropic.com/engineering/advanced-tool-use .

**2.2 Tool output budgets and tool-result pruning** (lesson, senior). Claude Code's Read returns at most 25,000 tokens per call by default and refuses whole files over 256 KB; Bash output over about 30,000 characters becomes a saved file path plus a 2,000-character preview; Glob caps at 100 files with a truncation flag. Anthropic's tool-writing post: Claude Code restricts tool responses to 25,000 tokens by default; add a `response_format` of concise vs detailed (72 vs 206 tokens in its Slack example); write actionable errors. Clearing old tool results is the lightest form of compaction. Teach as "every tool result is a write into a bounded buffer". Sources: https://code.claude.com/docs/en/tools-reference ; https://www.anthropic.com/engineering/writing-tools-for-agents ; https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents ; https://platform.claude.com/docs/en/build-with-claude/context-editing .

**2.3 Many tools: deferred loading, tool search, code execution** (lesson, staff). Anthropic measured 58 tools across five MCP servers at about 55K tokens before the conversation starts; tool search with `defer_loading` cut about 77K to 8.7K tokens and raised MCP eval accuracy (Opus 4 from 49% to 74%, Opus 4.5 from 79.5% to 88.1%). Programmatic tool calling cut average tokens from 43,588 to 27,297. Code execution with MCP (tools exposed as files) cut one workflow from 150,000 to 2,000 tokens. Claude Code now defers MCP tools by default, which also keeps the cache intact when a server connects mid-session. Sources: https://www.anthropic.com/engineering/advanced-tool-use ; https://www.anthropic.com/engineering/code-execution-with-mcp ; https://code.claude.com/docs/en/prompt-caching .

**2.4 Errors and lints as instructions** (lesson, senior). SWE-agent's linter rejects a bad edit and shows the error with before and after; OpenAI's harness team writes custom lint messages that inject remediation into the agent's context; Cursor found agents retried a failing sandboxed command unchanged until the shell result named the sandbox constraint that caused it; Goose returns invalid-JSON and missing-tool errors to the model as tool results. Sources: https://arxiv.org/html/2405.15793v3 ; https://openai.com/index/harness-engineering/ ; https://cursor.com/blog/agent-sandboxing ; https://goose-docs.ai/docs/goose-architecture/ .

**2.5 Parallel tool calls** (lesson, senior). The Agent SDK runs read-only tools (Read, Glob, Grep, MCP tools with `readOnlyHint`) concurrently and mutating tools (Edit, Write, Bash) sequentially; custom tools default to sequential. Anthropic's research system cut research time by up to 90% with parallel sub-agents and parallel tool calls. Cognition's SWE-grep issues up to 8 parallel tool calls per turn for at most 4 turns. Sources: https://code.claude.com/docs/en/agent-sdk/agent-loop ; https://www.anthropic.com/engineering/multi-agent-research-system ; https://cognition.com/blog/swe-grep .

### Module 3: `context-management` (what the model sees, turn by turn)

**3.1 Memory files: CLAUDE.md, AGENTS.md, rules** (lesson, senior). Claude Code loads CLAUDE.md and CLAUDE.local.md from the working directory and every parent at launch, subdirectory files on demand when a file there is read; `@path` imports up to four hops; target under 200 lines; `.claude/rules/` files with `paths:` frontmatter load only for matching files; AGENTS.md is read when there is no CLAUDE.md. Codex concatenates `AGENTS.override.md` or `AGENTS.md` from the git root down to cwd, one per directory, capped at 32 KiB by `project_doc_max_bytes`. Cursor: `.mdc` rules with four application types, keep each under 500 lines. OpenAI's harness team keeps AGENTS.md at roughly 100 lines as a map into a structured `docs/` tree that linters and a doc-gardening agent keep fresh. The ETH Zurich study (arXiv 2602.11988) found context files do not generally improve success and raise inference cost by over 20%. Sources: https://code.claude.com/docs/en/memory ; https://learn.chatgpt.com/docs/agent-configuration/agents-md ; https://cursor.com/docs/context/rules ; https://openai.com/index/harness-engineering/ ; https://arxiv.org/abs/2602.11988 ; https://agents.md/ .

**3.2 Playbook: CLAUDE.md, skill, rule, hook, sub-agent or MCP?** (playbook, senior). The decision is where a piece of knowledge or policy lives. Inputs: does it apply to every task, is it a procedure, does it have exceptions, must it be enforced, what does it cost in context every turn. Options and when each wins, from Claude Code's best-practices and memory pages: CLAUDE.md for facts the agent cannot infer from the code; skills for procedures (name and description every session, body on demand, `disable-model-invocation: true` for side-effecting ones); path-scoped rules for area conventions; hooks for zero-exception rules; deny rules for "never"; sub-agents for noisy or independent work; a CLI before an MCP server when one exists. Sources: https://code.claude.com/docs/en/best-practices ; https://code.claude.com/docs/en/memory ; https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills ; https://agentskills.io/specification .

**3.3 Compaction: what survives and what it costs** (lesson, staff). Claude Code: system prompt stays; project-root CLAUDE.md, unscoped rules and auto memory are re-injected from disk; the plan from plan mode is re-injected; up to five most recently modified files are re-read (over 5,000 tokens comes back as a reference); invoked skill bodies are re-injected up to 5,000 tokens each and 25,000 total; path-scoped rules and nested CLAUDE.md are summarised away; a thrashing guard stops auto-compaction when one output refills the window. Codex uses a `/responses/compact` endpoint whose returned item is opaque and encrypted. OpenHands' `LLMSummarizingCondenser` triggers above 120 events, keeps the first 4, halves the view, and records a `Condensation` event in an append-only log. Cognition's alternative is a separate fine-tuned compression model. Sources: https://code.claude.com/docs/en/context-window ; https://code.claude.com/docs/en/how-claude-code-works ; https://openai.com/index/unrolling-the-codex-agent-loop/ ; https://docs.openhands.dev/sdk/arch/condenser ; https://cognition.com/blog/dont-build-multi-agents .

**3.4 Paper walkthrough: context resets vs compaction** (paper, staff). Anthropic's 2026-03-24 harness-design post: "context anxiety" (Sonnet 4.5 wrapping up early as it neared its believed limit) made full resets with a structured handoff necessary; with Opus 4.5 resets were dropped and the SDK's automatic compaction was enough. The general lesson: harness components encode assumptions about one model and must be re-tested per model. Source: https://www.anthropic.com/engineering/harness-design-long-running-apps .

**3.5 Sub-agents as context firewalls** (lesson, senior). Claude Code sub-agents start with a fresh context (their system prompt, the delegation message, CLAUDE.md, a git status snapshot), return only a summary, nest up to three levels by default, run up to 20 at once by default, can be limited to `tools: Read, Grep, Glob` so a reviewer cannot edit, and can run in a temporary worktree. The docs say delegation does not make the answer smarter; a fresh reviewer helps because it has not seen the reasoning. Cursor's Explore sub-agent and Cognition's SWE-grep (over 60% of the first turn was spent retrieving context) are the same idea. Sources: https://code.claude.com/docs/en/sub-agents ; https://code.claude.com/docs/en/best-practices ; https://cursor.com/docs/agent/tools/search ; https://cognition.com/blog/swe-grep .

**3.6 Finding code: grep, repo maps, embeddings** (lesson, senior). Aider builds a tree-sitter tag graph and ranks it with networkx PageRank personalised toward chat files and mentioned identifiers, fitting the result into `--map-tokens` (docs: default 1k). Anthropic's Agent SDK post recommends starting with agentic search (grep and the file system) and adding semantic search only if needed. Cursor reported a 12.5% average accuracy gain from semantic search in 2025-11; its current docs say Instant Grep indexes locally and no embeddings are stored for search. Teach the trade as a lexer vs an index, and how to measure it on your own repository. Sources: https://aider.chat/docs/repomap.html ; https://github.com/Aider-AI/aider/blob/main/aider/repomap.py ; https://claude.com/blog/building-agents-with-the-claude-agent-sdk ; https://cursor.com/en-US/blog/semsearch ; https://cursor.com/docs/agent/tools/search .

**3.7 Paper walkthrough: context rot and "Evaluating AGENTS.md"** (paper, senior). Chroma tested 18 models: performance degrades with input length even on simple tasks; a focused prompt of about 300 tokens beat a full prompt of about 113k tokens on LongMemEval. ETH Zurich: context files raise cost by over 20% without a general success gain. Together they argue for small, specific memory files. Sources: https://www.trychroma.com/research/context-rot ; https://arxiv.org/abs/2602.11988 .

### Module 4: `cache-cost-latency` (the harness's bill)

**4.1 Prompt caching inside a harness** (lesson, staff). Exact-prefix matching means a change anywhere recomputes everything after it. Claude Code's cache breakers: switching models, changing effort on most models, toggling fast mode, connecting or removing an MCP server when tools load upfront, enabling a plugin that adds MCP servers, denying a whole tool without tool search, compaction (conversation layer only), image eviction, an upgrade. Editing CLAUDE.md mid-session does not break the cache and does not apply until `/clear`, `/compact` or restart. Codex's breakers: changing tools, model, sandbox config, approval mode or cwd; an MCP tool-ordering bug once caused misses, and honouring an MCP `list_changed` mid-conversation is expensive. TTL: Claude Code requests one hour for the main conversation on a subscription and five minutes on an API key. `/rewind` returns to an already cached prefix. Sources: https://code.claude.com/docs/en/prompt-caching ; https://openai.com/index/unrolling-the-codex-agent-loop/ ; https://platform.claude.com/docs/en/build-with-claude/prompt-caching .

**4.2 What a harness costs** (lesson plus estimate problems, senior). Published runs: Anthropic's retro game maker, solo 20 min and $9 vs full three-agent harness 6 hours and $200; the DAW build 3 h 50 min and $124.70 with a per-phase table; the C compiler, nearly 2,000 sessions, 2 billion input and 140 million output tokens, just under $20,000; multi-agent research at about 15x chat tokens. Turn each into an estimate problem with stated assumptions. Sources: https://www.anthropic.com/engineering/harness-design-long-running-apps ; https://www.anthropic.com/engineering/building-c-compiler ; https://www.anthropic.com/engineering/multi-agent-research-system .

**4.3 Playbook: cost and runaway controls** (playbook, senior). Agent SDK `max_turns` (count one extra turn for the final text or the run ends `error_max_turns`) and `max_budget_usd`; Claude Code `-p` with `--max-turns` and `--max-budget-usd`; auto-mode fallback after 3 consecutive or 20 total denials; the Stop-hook cap of eight consecutive blocks; SWE-agent's $4 per instance with auto-submit; effort levels (Anthropic's 2026-03-04 change of default effort from high to medium was reverted as "the wrong tradeoff"). Sources: https://code.claude.com/docs/en/agent-sdk/agent-loop ; https://code.claude.com/docs/en/best-practices ; https://code.claude.com/docs/en/permission-modes ; https://www.anthropic.com/engineering/april-23-postmortem .

**4.4 Latency: decouple the brain from the hands** (teardown section, staff). Managed Agents provisions a container only when a tool needs it; p50 time to first token fell about 60% and p95 over 90%. Source: https://www.anthropic.com/engineering/managed-agents .

### Module 5: `permissions-sandboxing` (what the agent can touch)

**5.1 Rule engines for shell commands** (lesson, senior). Claude Code: deny, then ask, then allow; deny applies in every mode; compound commands split on shell separators and every part must pass; protected paths (`.git`, `.claude`, shell startup files, `.mcp.json` and others) never auto-approve outside bypass. Codex: Starlark `.rules` files with `prefix_rule`, decisions `allow`, `prompt`, `forbidden`, strictest wins; `bash -lc` scripts are split only when they are a linear chain of plain words, otherwise evaluated whole; test with `codex execpolicy check`. Cursor: Allowlist, Auto-review, Run Everything. Sources: https://code.claude.com/docs/en/permissions ; https://code.claude.com/docs/en/permission-modes ; https://learn.chatgpt.com/docs/agent-configuration/rules ; https://cursor.com/docs/agent/security/run-modes .

**5.2 OS sandboxes compared** (lesson, staff). Claude Code: bubblewrap on Linux, Seatbelt on macOS, network through a proxy outside the sandbox over a Unix socket; open-sourced as sandbox-runtime. Codex: Seatbelt, bubblewrap on Linux and WSL2, a native Windows sandbox under PowerShell; network off by default in `workspace-write`. Cursor: Seatbelt, Landlock plus seccomp (kernel 6.2 or later), the Linux sandbox inside WSL2 on Windows; protects `.git/config` and `.git/hooks`. Gemini CLI: six Seatbelt profiles or Docker/Podman. The Agent SDK secure-deployment guide compares containers, gVisor and Firecracker or QEMU, and states the proxy's limits (shared kernel, no TLS inspection, domain fronting). Sources: https://www.anthropic.com/engineering/claude-code-sandboxing ; https://learn.chatgpt.com/docs/sandboxing ; https://cursor.com/docs/agent/security/run-modes ; https://cursor.com/blog/agent-sandboxing ; https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/sandbox.md ; https://code.claude.com/docs/en/agent-sdk/secure-deployment .

**5.3 Paper walkthrough: classifiers as approvers** (paper, staff). Anthropic's auto mode post: users approved 93% of prompts anyway; two layers (a server-side injection probe on tool outputs and a Sonnet 4.6 transcript classifier); the classifier sees user messages and tool calls, with Claude's prose and all tool results stripped; FPR 8.5% at stage 1 and 0.4% for the full pipeline on 10,000 real actions; FNR 17% on 52 real overeager actions and 5.7% on 1,000 synthetic exfiltrations; called "not a drop-in replacement for careful human review on high-stakes infrastructure". Compare Cursor Auto-review (Gemini 3.5 Flash Lite with a Haiku fallback; "not a security boundary") and Codex auto-review (a reviewer swap, not a permission grant). Sources: https://www.anthropic.com/engineering/claude-code-auto-mode ; https://cursor.com/docs/agent/security/run-modes ; https://learn.chatgpt.com/docs/sandboxing/auto-review .

**5.4 Teardown: how Anthropic contains Claude across products** (teardown, staff). Three containment patterns (a gVisor container for claude.ai code execution, OS sandbox plus approvals for Claude Code, a local VM for Cowork) and the published incidents: project config that could run before the trust prompt (mid-2025 to January 2026), a phished prompt that read `~/.aws/credentials` and posted it in 24 of 25 retries, a Files API upload to an attacker's account through an allowlisted domain. Lessons stated in the post: contain at the environment first, an allowlisted domain is a capability grant, custom proxies failed where standard primitives held. Source: https://www.anthropic.com/engineering/how-we-contain-claude .

**5.5 Credentials outside the sandbox** (lesson, senior). Claude Code on the web keeps git credentials outside the sandbox behind a git proxy that checks the operation and attaches the real token. Managed Agents uses the repo token only at initialisation and keeps MCP OAuth tokens in a vault behind a proxy. Codex Cloud (legacy) exposes secrets only during setup and removes them before the agent phase. Copilot's agent can only make simple pushes to one branch and cannot run `git push` itself. Sources: https://www.anthropic.com/engineering/claude-code-sandboxing ; https://www.anthropic.com/engineering/managed-agents ; https://learn.chatgpt.com/docs/agent-approvals-security ; https://docs.github.com/en/copilot/concepts/agents/coding-agent/risks-and-mitigations .

**5.6 Hooks as policy, and how they fail** (lesson, senior). Claude Code has 33 hook events and five handler types (command, http, mcp_tool, prompt, agent); exit code 2 blocks, exit 1 does not; hooks fail open by default unless `onFailure: "block"`; `prompt` and `agent` hooks are another model deciding, not enforcement; `if` filters are best-effort. The Stop hook running the typecheck is the canonical verification gate. Sources: https://code.claude.com/docs/en/hooks ; https://code.claude.com/docs/en/best-practices .

**5.7 Critique set: model-rated risk** (problems of type critique, staff). Cline's "Execute safe commands" relies on a `requires_approval` flag the model sets per command; OpenHands' `LLMSecurityAnalyzer` reads a `security_risk` field the model fills in on its own tool call, with `ConfirmRisky` at HIGH by default. The reader finds what an injected instruction does to a self-rated risk field. Sources: https://docs.cline.bot/features/auto-approve ; https://docs.openhands.dev/sdk/arch/security .

### Module 6: `verification` (how the agent knows it is done)

**6.1 Give the agent a check to run** (lesson, senior). Claude Code best practices: the most useful CLAUDE.md line is the command that runs the checks; enforce it with a Stop hook (exit 2 sends Claude back with stderr); `/code-review` runs in a fresh sub-agent; review against the spec and say "skip style", because a reviewer asked to find problems always finds some. The Agent SDK post orders verification as rules (lint, types), visual feedback (screenshots, Playwright), then an LLM judge, which it calls "generally not a very robust method". Sources: https://code.claude.com/docs/en/best-practices ; https://claude.com/blog/building-agents-with-the-claude-agent-sdk .

**6.2 Paper walkthrough: generator and evaluator agents** (paper, staff). The 2026-03-24 harness post: self-evaluation is lenient; out of the box Claude was "a poor QA agent"; a separate evaluator tuned with few-shot score breakdowns, Playwright against the running app, hard thresholds per criterion; sprint contracts negotiated in files (27 criteria in one sprint); the planner and evaluator were kept after Opus 4.6 made sprints unnecessary. Source: https://www.anthropic.com/engineering/harness-design-long-running-apps .

**6.3 Teardown: oracles and test output written for agents** (teardown, staff). The C compiler build: GCC as the known-good oracle, delta debugging across files, test output kept to a few lines with full logs in files, `ERROR` on the same line for grep, a `--fast` mode running a deterministic 1% or 10% sample per agent, CI added late to stop regressions. Source: https://www.anthropic.com/engineering/building-c-compiler .

**6.4 Benchmarks that grade the oracle, not the task** (lesson, senior). OpenAI's SWE-bench Verified audit: 59.4% of 138 hard problems had material issues; frontier models could reproduce gold patches; OpenAI recommends SWE-bench Pro. The long-running harness tells agents it is "unacceptable to remove or edit tests" because agents do. Sources: https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/ (read via curl for `research/tracks/agents.md`) ; https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents .

### Module 7: `long-running-parallel` (hours of work, many agents)

**7.1 The long-running harness** (lesson, staff). An initializer agent writes `init.sh`, `claude-progress.txt` and a JSON feature list (over 200 features, all failing; JSON because models overwrite it less than Markdown); each coding session runs `pwd`, reads git log and progress, picks one feature, runs a basic end-to-end check first, commits and updates progress; both agents share the system prompt and tools and differ only in the first user prompt. OpenAI's harness team reports single Codex runs of upwards of six hours. Sources: https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents ; https://openai.com/index/harness-engineering/ .

**7.2 Teardown: durable sessions, the log outside the harness** (teardown, staff). Managed Agents: the session as an append-only event log (`getSession`, `emitEvent`, `getEvents`, `wake`), a stateless harness, sandboxes behind `execute(name, input) -> string`, a dead container returned to Claude as a tool error, credentials kept out of reach of generated code. The research system used rainbow deployments for in-flight agents. The OpenHands SDK paper describes an event-sourced design with "negligible event-sourcing overhead". Sources: https://www.anthropic.com/engineering/managed-agents ; https://www.anthropic.com/engineering/multi-agent-research-system ; https://arxiv.org/abs/2511.03690 .

**7.3 Paper walkthrough: parallel agents without an orchestrator** (paper, staff). 16 Claude instances in Docker containers, a bare git upstream, task claims as lock files in `current_tasks/` resolved by git conflicts, no orchestration agent, specialised roles (dedupe, performance, docs). Compare Claude Code worktrees (`claude -w`, `.worktreeinclude`), `/batch` splitting work into 5 to 30 units each in its own worktree and PR, and Cognition's argument against splitting context. Sources: https://www.anthropic.com/engineering/building-c-compiler ; https://code.claude.com/docs/en/best-practices ; https://cognition.com/blog/dont-build-multi-agents .

**7.4 Paper walkthrough: parallel attempts and test-time scaling** (paper, staff). Large Language Monkeys: SWE-bench Lite coverage rose from 15.9% at one sample to 56% at 250 with DeepSeek-Coder-V2; without automatic verifiers, voting and reward models plateau beyond several hundred samples. Claude 4's "parallel test-time compute": sample several attempts, discard patches that fail visible regression tests, pick with an internal scoring model (Opus 4 from 72.5% to 79.4%). The point: selection needs a verifier, and "high compute" numbers are a different quantity from pass@1. Sources: https://arxiv.org/abs/2407.21787 ; https://www.anthropic.com/news/claude-4 .

**7.5 Teardown: an agent-first repository** (teardown, staff). OpenAI's internal product: first commit late August 2025; about a million lines and about 1,500 merged PRs in five months; three engineers growing to seven; 3.5 PRs per engineer per day; the app bootable per git worktree; Chrome DevTools Protocol and an ephemeral per-worktree observability stack queried with LogQL and PromQL; a layered architecture enforced by custom lints and structural tests; a doc-gardening agent; "golden principles" with background cleanup PRs replacing a Friday of cleanup (20% of the week); minimal blocking merge gates. Not public: the product, the code, any defect or incident rate. Source: https://openai.com/index/harness-engineering/ .

### Module 8: `evaluating-harnesses` (is harness B better than harness A?)

**8.1 Attributing a score to model, harness or infrastructure** (lesson, staff). On Terminal-Bench 2.0, moving from strict 1x resource limits to uncapped lifted success by 6 points (p < 0.01) while infra errors fell from 5.8% to 0.5%; on SWE-bench the RAM effect was 1.54 points; Anthropic advises skepticism for leaderboard gaps under 3 points until configs match. Terminal-Bench 2.0 runs Claude Code, Codex CLI, OpenHands, mini-swe-agent and its own Terminus 2 through the Harbor harness, which makes harness swaps measurable with the model held fixed. Sources: https://www.anthropic.com/engineering/infrastructure-noise ; https://arxiv.org/abs/2601.11868 .

**8.2 The coding-agent benchmark map** (lesson, senior). SWE-bench Verified (500 tasks; OpenAI stopped reporting it on 2026-02-23); SWE-bench Pro (1,865 problems from 41 repositories in public, held-out and commercial splits); Terminal-Bench 2.0 (89 tasks, frontier under 65% at publication); tau-bench (pass^k; gpt-4o under 50% and pass^8 under 25% in retail at publication); mini-swe-agent's bash-only leaderboard as a harness-controlled comparison. Sources: https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/ ; https://arxiv.org/abs/2509.16941 ; https://arxiv.org/abs/2601.11868 ; https://arxiv.org/abs/2406.12045 ; https://github.com/SWE-agent/mini-swe-agent .

**8.3 Playbook: shipping a harness change safely** (playbook, staff). Anthropic's 2026-04-23 postmortem: three harness changes (default effort lowered; a thinking-clearing bug that cleared reasoning every turn and caused cache misses; a verbosity limit in the system prompt that cost 3% on a broad eval) each passed review, tests or dogfooding. Commitments: a broad per-model eval suite for every system-prompt change, line-by-line ablations, soak periods and gradual rollouts, model-specific changes gated to their model. Pair with rainbow deployments for in-flight agents. Sources: https://www.anthropic.com/engineering/april-23-postmortem ; https://www.anthropic.com/engineering/multi-agent-research-system .

**8.4 Lab: a harness eval runner** (lab, staff). Steps: run N trials per task; compute pass@k and pass^k; attach cost and turns per trial; record the resource config; compare two harness variants with a paired test; flag gaps inside the noise band. Sources: https://arxiv.org/abs/2406.12045 ; https://www.anthropic.com/engineering/infrastructure-noise ; https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents .

## 5. Misconceptions a reviewer should check

1. **"Editing CLAUDE.md or AGENTS.md mid-session changes the prompt prefix and costs a cache miss."** Wrong for Claude Code: project-root and user CLAUDE.md are read once at session start; a mid-session edit neither invalidates the cache nor applies until `/clear`, `/compact` or a restart (https://code.claude.com/docs/en/prompt-caching). Fix the sentence in `src/content/lessons/agents/coding-agents/overview.mdx` (section "Finding the right files") and misconception 19 in `research/tracks/agents.md`.
2. **Cursor described as using embedding-based semantic search today.** Cursor's current search page says Instant Grep indexes locally and Cursor "does not store embeddings of your codebase for search" (https://cursor.com/docs/agent/tools/search). The 12.5% figure is from 2025-11-06 and must be dated as historical in the coding-agents lesson.
3. **"The context window is the main constraint; manage it aggressively."** Claude Code's best practices list this as outdated: most current models have a 1M-token window and compaction is automatic; `/clear` is now about focus and cost. Context rot is still the reason a focused context answers better.
4. **"Delegating to a sub-agent gives a better answer."** Claude Code's docs: the same or a smaller model on the same task gives parallelism, not intelligence; a fresh reviewer helps because it has not seen the reasoning. Sub-agents cost tokens and can be slower because they gather context again.
5. **"Write IMPORTANT or ALL CAPS so the agent follows a rule."** Listed as outdated on the same page; a zero-exception rule belongs in a hook or deny rule, and a line that gets lost means the file is too long.
6. **CLAUDE.md, AGENTS.md or skills treated as enforcement.** They are context the model weighs; Claude Code's memory page says to use a PreToolUse hook to block an action regardless of what the model decides.
7. **Hooks treated as a security boundary by default.** Claude Code hooks fail open on crash or timeout unless `onFailure: "block"`; exit 1 does not block; `prompt` and `agent` hooks are another model deciding; `if` filters are best-effort.
8. **Classifier approvers described as safe.** Anthropic publishes a 17% FNR on real overeager actions and says auto mode is not a drop-in replacement for careful review on high-stakes infrastructure; Cursor says Auto-review "is not a security boundary"; Codex auto-review never widens the sandbox.
9. **Plan mode taught as a hard boundary.** In an interactive terminal session where bypass permissions are available, plan-mode edits and commands are not blocked; Claude is only instructed not to edit (https://code.claude.com/docs/en/permission-modes).
10. **Model-rated risk treated as a control.** Cline's safe-command flag and OpenHands' `security_risk` come from the same model an injection can steer. Teach them as hints that sit behind a sandbox.
11. **Compound commands handled the same everywhere.** Claude Code splits on shell separators; Codex splits only linear chains of plain words and evaluates anything with substitution or redirection as one command. A regex split is not a parser, as the current lesson says.
12. **"An egress allowlist stops exfiltration."** An allowlisted domain with an upload API is a capability grant (the Cowork Files API incident); the sandbox proxy does not inspect TLS and is open to domain fronting (https://code.claude.com/docs/en/agent-sdk/secure-deployment).
13. **"Copilot's firewall covers everything the agent runs."** It applies only to processes started through the agent's Bash tool, not MCP servers or setup steps.
14. **"Codex sandboxes MCP tools."** The Codex loop post says tools from MCP servers are not sandboxed by Codex.
15. **Gemini CLI described as Google's current consumer coding CLI**, and Copilot's agent as "coding agent". Gemini CLI's individual tiers stopped on 2026-06-18 in favour of Antigravity CLI; GitHub's docs now say "Copilot cloud agent".
16. **The `think` tool taught as current practice.** Anthropic's 2025-12-15 update recommends extended thinking instead in most cases (https://www.anthropic.com/engineering/claude-think-tool).
17. **Comparing harnesses across different models.** SWE-agent's 12.5% (2024) and mini-swe-agent's over 74% use different models; a fair comparison holds the model fixed (Terminal-Bench's Harbor runs, the bash-only leaderboard).
18. **"High compute" or best-of-n scores quoted as pass@1.** Claude 4's 79.4% uses parallel attempts and a scoring model; Large Language Monkeys' 56% is coverage, which equals success only with a perfect verifier.
19. **Leaderboard gaps of one to three points read as capability.** Resource limits alone move Terminal-Bench 2.0 by up to 6 points; Anthropic advises skepticism below 3 points until configurations match.
20. **"A harness is a fixed asset."** Anthropic dropped context resets for Opus 4.5 and sprints for Opus 4.6; a system-prompt line cost 3% on a broad eval (postmortem). Harness components need per-model evals.
21. **"With a good harness the agent finishes long tasks."** Anthropic's harness post reports stubbed features and bugs in nested features; OpenAI says its result depends on that repository's structure and should not be assumed to generalise.
22. **Vendor numbers presented as independent.** 84% (Anthropic), 40% (Cursor), SWE-grep speed (Cognition) and "1/10th the time" (OpenAI) are vendors measuring their own products.
23. **Secondary numbers copied into lessons.** HumanLayer's claim that Opus 4.6 ranked 33rd in Claude Code but 5th in another harness on Terminal-Bench 2.0 could not be checked (the leaderboard loads dynamically). The ETH study's "about 4%" and "2 to 3%" figures are from secondary write-ups; the abstract gives only "over 20%" more cost. OB question-bank questions embed unverified figures (for example "2 to 3x faster task completion" with a CLAUDE.md). Use none of these without the primary.
24. **Jules' plan approval treated as a hard gate.** Google's docs say you can review and approve before changes; a secondary source says web plans auto-approve after a delay. Check before teaching.
25. **sandbox-runtime repository named inconsistently.** The 2025-10-20 post points to `anthropic-experimental/sandbox-runtime`; the current secure-deployment docs link `anthropics/sandbox-runtime`. Confirm the canonical URL before citing.
26. **Sub-agent nesting stated as impossible.** Current Claude Code docs allow three levels by default (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`); older tutorials may say otherwise. Attach a version or date to any such rule.
27. **Compaction assumed free.** Claude Code's `/compact` is itself a request over the whole conversation: cheap while the cache is warm, expensive after the TTL; `/rewind` reuses a cached prefix instead.
28. **"Checkpoints undo what the agent did."** Claude Code checkpoints cover file changes only; databases, APIs and deployments cannot be rolled back.
29. **Teardowns that guess.** System prompts, classifier training data, compaction prompts, and the internals of Antigravity and Devin are not public. SPEC requires a teardown to say so rather than infer.
30. **Interview loops from aggregators presented as fact.** Every company attribution in section 3 is a secondary report; lessons must label them "reported".
